\section{Introduction}
\label{sec:intro}

GPT-6 Astra 같은 API 기반 대형 모델로 로봇을 명령 기반으로 제어하는 연구가 늘고 있다~\cite{agp2026,robodojo2026}. 이런 모델은 과제를 잘게 나누어 계획하고, 처음 보는 장면에서도 비교적 잘 버틴다. 반면 과제 데이터로 미세조정한 학습 정책(VLA 포함)은 다른 환경으로 옮겨 가면 크게 떨어진다. RoboDojo~\cite{robodojobench2026}에서 $\pi_{0.5}$의 점수는 깨끗한 장면 20.92에서 바뀐 장면 5.82로 72\% 떨어진다. 같은 벤치마크의 공개 원자료로 우리가 계산한 값에서 Astra는 \tentative{$-$11.1\%}만 떨어졌다(\cref{sec:prelim}, 조건이 같지 않은 예비 분석). LLM은 일반화되고 학습 정책은 잘 일반화되지 않는다는 이 차이가 이 연구의 출발점이다.

우리는 이 차이를 다음과 같이 읽는다. 이것은 문헌이 지지하는 범위로 보정한 가설이며, 우리 데이터로는 아직 시험하지 않았다. 좁고 파편화된 시연 데이터로 VLA를 end-to-end 미세조정하면, 모델은 과제의 의미(무엇을, 어느 단계에서) 대신 시점·배치·초기 자세와 묶인 국소 영상$\rightarrow$행동 지름길을 배우기 쉽다. 과제와 무관한 요인이 데이터 안에서 과제와 상관되면 지름길이 생긴다는 통제 실험이 있고~\cite{shortcut2025}, 목표 물체나 지시를 바꿔도 학습한 궤적을 되풀이하는 현상~\cite{liberoplus2025}과 연속 행동 학습이 VLM 백본의 지식을 훼손해 지시를 무시하게 만든다는 보고~\cite{kinsulate2025}가 있다. 다만 이것은 목적함수의 필연이 아니다. 같은 end-to-end 목적함수로도 학습 환경을 크게 늘리거나~\cite{pi05_2025} VLM 지식을 보존하면~\cite{kinsulate2025} 새 환경과 지시를 따라간 사례가 있고, 저수준과 정합된 단계 라벨이나 추론은 실행 때 생성하지 않고 학습 때만 주어도 이득의 상당 부분이 남았다~\cite{pi05_2025,ecotlite2025}. 관측 창을 늘리는 것은 표준 일반화에서 이득이 작았다~\cite{hamlet2026}. 그래서 근거가 지지하는 처방은 셋이다. 데이터 다양성, VLM 지식 보존, 정합된 단계·목표 라벨이다. 또 테스트 때 영점 프런티어 모델을 실행 중 상위 계획기로 쓰면 학습한 작은 상위 단보다 나빴다~\cite{pi05_2025,hirobot2025}. 따라서 프런티어 모델의 자리는 매 순간 흐름을 불러 주는 해설자가 아니라, 새 과제의 계획자와 라벨·규칙의 교사다. 우리 설계는 이 읽기를 따른다.

그러나 Astra를 로봇 제어 루프에 그대로 넣으면 두 가지 문제가 생긴다. 첫째, 느리다. effort를 가장 낮게 두어도 첫 토큰까지 약 3\,s, high로 두면 약 73\,s가 걸린다(Artificial Analysis 공개 측정, 2026-09-23 기준이며 우리가 잰 값이 아니다). 둘째, 실행이 끊긴다. 기존 LLM 기반 로봇 하네스는 상위 모델이 결과를 기다리는 동기 루프로 돌거나~\cite{harnessvla2026,inspectrobots2026}, 상위 모델을 실행 루프 밖에 둔다. 앞으로 몇 센티미터를 어느 방향으로 움직일지 같은 순간 판단은 초 단위 API로는 내릴 수 없고, 실패가 판정될 때마다 로봇을 멈추고 기다리면 실제 배포에서 쓸 수 없다.

이 문제가 어려운 이유는 속도와 일반화가 서로 당기기 때문이다. 빠른 판단을 위해 작은 모델을 과제 데이터로 학습하면 그 모델은 학습 정책의 약점(환경 변화에 약함)을 그대로 물려받는다. 그리고 빠른 모델을 1초에 여러 번 겹쳐 부르면, 서로 다른 시각에 받은 답 가운데 무엇을 실행에 확정할지를 정해야 한다. 같은 모델의 반복 답이 서로 일치해도 틀릴 수 있다. 보기 이름만 바꿔도 판별력이 AUC .94에서 .23으로 떨어지는 체계적 오류는 반복 질문의 합의로 걸러지지 않는다는 보고가 있다(심사 전 프리프린트)~\cite{typesafe2026}.

계층 구조 자체는 새롭지 않다. Gemini Robotics 1.5~\cite{geminirobotics15_2025}는 오케스트레이터가 하위 VLA에 단계를 넘기고, Gemini Robotics-ER 문서~\cite{geminier_docs2026}는 약 1\,Hz 하트비트로 상위 모델에 명시적 결정을 강제한다. $\pi_{0.5}$~\cite{pi05_2025}와 Hi Robot~\cite{hirobot2025}은 같은 VLM 또는 상위 VLM이 하위 과제를 예측한다. 느린 모델을 멈추지 않고 겹쳐 부르는 방식(Slow Brain~\cite{slowbrain2026})과 여러 청크의 합의로 앞 구간을 확정하는 방식(A3~\cite{a3commit2026})도 있다. 하지만 시간차로 겹쳐 부른 결정의 합의에 \emph{실행 뒤 측정}을 결합해 확정을 정하는 규칙은 없고, 같은 과제·같은 장면 짝 위에서 위층 LLM과 아래층 학습량이 환경 변화 강건성에 각각 얼마나 기여하는지 가르는 평가도 없다(\cref{tab:related}).

우리는 Harvest를 제안한다(\cref{fig:teaser}). 핵심 설계 의도는 \textbf{VLA를 VLA처럼 쓰지 않는 것}이다. 일반적인 VLA는 VLM을 end-to-end로 학습해 과제 전체의 연속 행동 생성기로 쓴다. 위의 약점은 바로 이 쓰임에서 나온다. Harvest에서 VLA는 과제 전체를 맡지 않고, 지금 이 순간 목표에 대해 말단을 어느 방향으로 얼마만큼 움직일지만 정하는 순간순간의 정밀 보정기다. 그 안의 VLM은 오락실 조이스틱처럼 쓴다. 방향, 크기 구간, 단계, 대상 같은 닫힌 보기 가운데 하나를 고르고, 확정 규칙 M4가 그 선택을 확정하면, 연속 행동 expert가 고른 보기 안에서 동작을 채운다. 과제의 이해와 흐름, 어디로 갈지는 위에서 준다. 느린 Astra는 작은 모델로 대신할 수 없는 일에만 쓴다. 과제 전에는 과제를 계약으로 컴파일하고, 실패하면 진단과 복구안을 쓰며, 과제 뒤에는 경험을 작은 모델의 규칙과 라벨로 증류하는 교사가 된다. 과제 중에 Astra가 지연을 견디며 움직임 자체에 개입하는 인터페이스(M4의 느린 투표자와 물체 기준 경로)는 \tentative{시험을 준비 중}이다. 조이스틱 선택을 연속 행동이 실제로 따르는지는 융합 경로에서 아직 강제하지도 재지도 않았다(\tentative{진단 E-SR0 예정}, \cref{sec:safety}). 아래층은 모듈을 따로 두지 않고 하나의 VLA로 융합한다. 융합 VLA는 머리 카메라와 활성 팔 손목 카메라를 보고 typed 결정 토큰과 연속 행동 청크를 함께 낸다. 결정 토큰은 코드가 만든 보기 가운데 하나를 고르는 형식이라, 확률이 보기 집합 안에서 정의되고 보정과 conformal 집합을 붙일 수 있다. 결정 토큰 호출은 1초에 약 3번 계단식으로 겹치며, 확정 규칙 M4가 겹친 답의 합의와 실행 뒤 측정을 함께 보고 무엇을 실행에 확정할지 정한다. 모델 밖에는 융합할 수 없는 세 부분만 남긴다. 느린 API 계획기 Astra, 추론 때의 규칙인 M4, 그리고 코드 안전 투영이다. 명시적 인식과 스크립트 스킬은 모듈형 기준선이자 학습 데이터의 교사로 쓴다.

\paragraph{기여.} 이 원고는 실험 전 설계 단계이며, 아래 기여는 사전 등록한 실험으로 검증할 주장이다. 주황색 글자는 아직 확정되지 않은 임시 값(계획값, 가정값, 파이프라인 시험 값, 결과 예정 칸)이다.
\begin{enumerate}
  \item \textbf{시간차 확정 규칙 M4.} 시간차로 겹쳐 부른 typed 결정 호출 사이의 합의(a)에 실행 뒤 예상 상태 대 측정 상태의 확인(b)을 결합하고(측정 = 고유 감각 코드 + 같은 백본의 확인 헤드), (b)가 전제를 깨면 전제 판본을 올려 그 전제에 기댄 미확정 답을 버린 뒤 유지·교체·수리 가운데 하나를 고른다. 멈추지 않는 겹침 요청~\cite{slowbrain2026}과 합의 확정~\cite{a3commit2026}은 선행이 있으며, 우리의 새로움은 시간차 합의와 (b)의 결합에 있다. 검증 가능한 주장: 호출 수를 맞춘 조건에서 M4가 최신 답만 쓰는 방식과 같은 시각 합의 방식보다 섭동 성공률이 높거나 잘못 확정이 적다(\cref{sec:plan_m4}).
  \item \textbf{같은 장면 짝 위의 강건성 평가 프로토콜.} 같은 layout의 standard와 random 장면을 짝지어 상대 하락(RD)을 재고, 위층(Astra 켬·끔)과 아래층 학습량(영점 C, 결정층 학습 A, A+RL, 융합 B)을 축으로 바꾸어 각 요소의 기여를 가른다. 지연을 실제대로 반영하는 시계와 생각 시간을 공짜로 두는 시계를 같은 표에 둔다. 판정 기준은 실행 전에 고정하고, 평가 코드가 사전 등록의 숫자와 조건 문장을 그대로 구현하는지를 독립 검증자가 원문에서 대조표를 새로 만들어 확인하는 적합성 감사를 두 번 연속 통과해야 실행한다(\cref{sec:plan}, \cref{sec:supp_audit}).
  \item \textbf{수단: 조이스틱형 결정 토큰 VLA와 Astra 전용 일.} 결정 토큰, action expert, 보조 기하 헤드를 한 백본에 두고, Astra만 할 수 있는 일(J1--J6)에만 부르는 위층 API 계획기와 비동기로 잇는 시스템을 만든다. 구성 요소 각각은 선행이 있으므로 새로움으로 주장하지 않고, 두 기여를 시험하는 수단으로 둔다. Astra가 그 자리에 꼭 필요한지는 같은 자리에 로컬 VLM을 넣는 E-Astra-necessity로 따로 잰다(\cref{sec:plan_astra}).
\end{enumerate}
