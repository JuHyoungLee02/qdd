\section{Limitations}
\label{sec:limits}
첫째, 본 실험 결과가 아직 없다. 이 원고의 주장은 모두 사전 등록한 실험으로 검증할 가설이다. 둘째, 학습한 결정층은 $\pi_{0.5}$의 상위 단이나 Hi Robot과 같은 ``학습된 계층 정책''이 된다. 그래서 ``LLM은 일반화된다''는 주장은 위층 Astra(영점)와 학습량 축의 RD 비교에만 걸고, 학습한 아래층이 일반화된다고는 주장하지 않는다. 셋째, 융합 런타임의 세계 쪽 측정은 같은 백본의 확인 헤드에 기대며, 이 헤드는 시뮬 특권 라벨로 학습해 실물 전이를 확인하지 않았다. 측정원을 정한 시험도 백본을 얼린 소규모 시험이었고 운반 중 충돌 같은 유형의 재현율은 낮았다(\tentative{0.6}). 확인 헤드가 놓치는 실패는 하트비트와 감시기 밖 실패 섭동으로만 잰다. 넷째, 지금 결정 호출은 결정 종류마다 질문 하나를 묻기 때문에 $H=1$과 $H=3$을 입력 길이로 비교하는 판정, 경계 적응형 합의 문턱, 복구 사다리 전체는 이 원고의 범위 밖(SCOPED)으로 두었다(\cref{sec:supp_scoped}). 다섯째, 학습 데이터는 시뮬 렌더(세 과제)와 공개 실물 데이터 약 9\,GB로 작다. 시뮬에서 실물로의 전이는 AI Worker 최소판으로만 확인한다. 여섯째, Astra는 API라 같은 입력에도 답과 지연이 날마다 달라진다. 반복 실행, 판본 고정, 매일 고정 입력 확인으로 이를 통제하지만 완전히 없앨 수는 없다. CPU 물리 엔진도 같은 시드를 직전 실행 이력에 따라 다른 궤적으로 재생할 수 있어, 스냅샷 복원은 저장 상태와 비트 단위로 맞는지 확인한 행만 쓰고, 짝지은 폐루프 비교는 매 에피소드 앞에서 물리 장면을 다시 만드는 빌드로만 돌린다. 이 빌드는 서로 다른 이력 뒤에도 새 프로세스와 비트 단위로 같은 궤적을 냈지만(\tentative{24/24}), 도메인 무작위화, random 장면, GPU 물리, P2 섭동에서의 결정성은 \tentative{아직 확인하지 않았다}. 옛 빌드로 녹화한 풀은 새 빌드로 재생되지 않아 풀 라벨 일부(\tentative{29편})를 다시 만들어야 하고, 렌더 픽셀은 물리가 같아도 비트 단위로 같지 않다. 일곱째, (b) 범주 되먹임을 배울 데이터에서 비 OK 범주가 드물고 잔차 범주가 없어, C5 대 C5$'$ 비교가 되먹임의 효과를 작게 잴 수 있다. 여덟째, 결정 입력에 과거 프레임을 더하는 시간 맥락 변경(\cref{sec:temporal})의 이득은 2$\times$2 시험(\cref{sec:plan_temporal}) 결과가 나오기 전까지 가설이며, 시각 토큰 수가 같다는 것은 비용에 관한 사실일 뿐 정확도에 관한 근거가 아니다. 아홉째, 안전은 이 논문의 범위가 아니며, 안전 투영은 결정 권위와 관절 한계를 지키는 최소 장치일 뿐이다.

\section{Conclusion}
\label{sec:conclusion}
우리는 느린 API 계획기 Astra와 typed 결정 토큰을 내는 융합 VLA를 잇는 Harvest를 설계했다. 결정은 1초에 약 3번 시간차로 겹쳐 나오고, 확정 규칙 M4가 호출 사이 합의와 실행 뒤 측정을 결합해 무엇을 실행할지 정하며, 로봇은 첫 계획 뒤에는 멈추지 않는다. 평가는 같은 장면 짝의 상대 하락으로 위층 LLM과 아래층 학습량의 기여를 가른다. 예비 시험은 이 설계의 전제 몇 가지를 이미 바꾸었다. 학습하지 않은 선택기는 최빈 기준선보다 낮았고, 그 원인의 일부는 모델이 아니라 잘못 정의된 정답에 있었다. 명시적 인식은 측정원으로 쓰기에 부정확해, 실행 뒤 확인을 같은 백본의 확인 헤드와 고유 감각 코드로 나누었다. 평가 코드를 사전 등록 문서와 한 줄씩 대조하는 감사는 실행 확인만으로는 보이지 않던 불일치(부트스트랩 횟수, 합의 비율의 경계, 기준선 정의, $H=1$의 뜻, (b) 되먹임의 부재)를 찾아냈다. 같은 시드가 같은 궤적을 낸다는 시뮬 가정도 확인해 보니 리셋만으로는 성립하지 않아, 라벨과 짝지은 비교의 재현성 규칙을 새로 두었다. 공개 실물 데이터의 소규모 학습에서 결정 오답이 주로 움직임의 유무와 크기에서 나왔으므로, 결정 입력에 0.3\,s 전 프레임을 더하는 변경을 사전 등록 시험으로 검증한다(\tentative{검증 중}). 다음 단계는 감사를 두 번 연속 통과한 뒤 E0.5, E-M4, 본 평가를 사전 등록한 기준대로 실행하는 것이다.
