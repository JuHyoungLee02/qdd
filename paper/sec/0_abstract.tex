\begin{abstract}
GPT-6 Astra 같은 API 기반 대형 모델은 로봇 과제를 계획하고 장면이 바뀌어도 성능이 덜 떨어지지만, 호출 한 번에 수 초가 걸린다. 과제 데이터로 미세조정한 VLA는 빠르지만 다른 환경으로 옮겨 가면 크게 무너진다. 우리는 느린 Astra를 위층 계획기로 두고, 아래층의 인식·결정·연속 행동을 하나의 VLA로 융합한 Harvest를 제안한다. 융합 VLA(Qwen3-VL-4B 백본)는 머리 카메라와 지금 작업 중인 팔의 손목 카메라를 직접 보고, 방향·센티미터 구간·대상·단계를 typed 결정 토큰으로 내며(보기 집합 안에서 재정규화한 확률), 같은 백본에 붙은 action expert가 확정된 결정을 조건으로 연속 행동 청크를 낸다. 결정 토큰 호출은 1초에 약 3번 시간차로 겹치고, 확정 규칙 M4는 호출 사이의 합의와 실행 뒤 예상 상태 대 측정 상태의 확인을 결합해 확정·유지·교체·수리 가운데 하나를 고른다. 측정은 로봇 쪽 술어를 고유 감각 코드로, 세계 쪽 술어를 같은 백본의 확인 헤드로 판정한다. Astra는 첫 계획 뒤에도 하트비트, 단계 경계, 실패 때 비동기로 불리며, 그동안 로봇은 멈추지 않는다. 우리의 기여는 M4 확정 규칙과, 깨끗한 장면에서 무작위 장면으로 갈 때의 짝지은 상대 하락(RD)으로 위층 LLM과 아래층 학습량의 기여를 가르는 평가 프로토콜이다. 이 원고는 실험 전에 고정한 설계와 판정 기준을 담으며, 본 실험 결과는 아직 없다. 평가 코드는 독립 검증자가 사전 등록 문서와 한 줄씩 대조하는 감사를 거치며, 실행 확인만으로는 보이지 않던 불일치를 여러 건 찾아 고쳤다. 구성 요소 예비 시험에서 학습하지 않은 선택기는 질문별 최빈 답 기준선보다 낮았고(\tentative{0.48 대 0.67}), 원인이 관측으로 정의되지 않은 정답에 있음을 확인해 관측 상태로 정의한 정답으로 바꾸었다. 머리와 손목 이미지 두 장을 넣은 결정 호출의 p95 지연은 선행 시퀀스 호출 방식에서 \tentative{0.18--0.28\,s}였다.
\end{abstract}
