\begin{abstract}
GPT-6 Astra 같은 API 기반 대형 모델은 로봇 과제를 계획하고 장면이 바뀌어도 성능이 덜 떨어지지만, 호출 한 번에 수 초가 걸린다. 과제 데이터로 미세조정한 VLA는 빠르지만 다른 환경으로 옮겨 가면 크게 무너진다. 우리는 VLA를 과제 전체를 end-to-end로 맡는 정책으로 쓰지 않는다. 과제의 이해와 흐름, 어디로 갈지는 위층 Astra가 주고, 아래층 VLA는 오락실 조이스틱처럼 지금 이 순간 말단을 어느 방향으로 얼마만큼 움직일지를 typed 보기로 고른 뒤 그 보기 안에서 연속 동작을 채우는, 순간순간의 말단 정밀 보정기로만 쓴다. 이 설계가 Harvest다. 아래층의 인식·결정·연속 행동은 하나의 VLA로 융합한다. 융합 VLA(Qwen3-VL-4B 백본)는 머리 카메라와 지금 작업 중인 팔의 손목 카메라를 직접 보고, 방향·센티미터 구간·대상·단계를 typed 결정 토큰으로 내며(보기 집합 안에서 재정규화한 확률), 같은 백본에 붙은 action expert가 확정된 결정을 조건으로 연속 행동 청크를 낸다. 결정 토큰 호출은 1초에 약 3번 시간차로 겹치고, 확정 규칙 M4는 호출 사이의 합의와 실행 뒤 예상 상태 대 측정 상태의 확인을 결합해 확정·유지·교체·수리 가운데 하나를 고른다. 측정은 로봇 쪽 술어를 고유 감각 코드로, 세계 쪽 술어를 같은 백본의 확인 헤드로 판정한다. Astra는 작은 모델로 대신할 수 없는 일(과제 컴파일, 실패 진단과 복구안, 검사 술어 합성, 새 물체 이름, 저빈도 진행 감사, 경험 증류)에만 비동기로 불리며, 그동안 로봇은 멈추지 않는다. 그 필요성은 같은 자리에 로컬 VLM을 넣는 대조 실험으로 따로 잰다. 우리의 기여는 M4 확정 규칙과, 깨끗한 장면에서 무작위 장면으로 갈 때의 짝지은 상대 하락(RD)으로 위층 LLM과 아래층 학습량의 기여를 가르는 평가 프로토콜이다. 이 원고는 실험 전에 고정한 설계와 판정 기준을 담으며, 본 실험 결과는 아직 없다. 평가 코드는 독립 검증자가 사전 등록 문서와 한 줄씩 대조하는 감사를 거치며, 실행 확인만으로는 보이지 않던 불일치를 여러 건 찾아 고쳤다. 구성 요소 예비 시험에서 학습하지 않은 선택기는 질문별 최빈 답 기준선보다 낮았고(\tentative{0.48 대 0.67}), 원인이 관측으로 정의되지 않은 정답에 있음을 확인해 관측 상태로 정의한 정답으로 바꾸었다. 머리와 손목 이미지 두 장을 넣은 결정 호출의 p95 지연은 선행 시퀀스 호출 방식에서 \tentative{0.18--0.28\,s}였다. 공개 실물 데이터의 소규모 입력 절제에서는 결정 입력에 거친 움직임 줄을 더하는 변경이 사전 등록 채택 규칙을 통과했고(정확도 \tentative{+0.025}), 과거 프레임을 더한 2프레임 비디오는 통과하지 못했다.
\end{abstract}
