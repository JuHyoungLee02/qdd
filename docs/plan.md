## 1. 두 모델 (원문 확인한 설계 제약)

### Jev (TypeSafe AI, `jev-1.13.0`)
- 입력 텍스트/JSON만("No image, audio, or video input", 공식). 영어가 가장 정확(CJK 덜 정확, 공식). 이미지 입력 Jev는 공식으로 없다.
- 한도: 요청 64k, state + 가장 긴 질문 32k 토큰. 질문 개수 상한 없음. 1,200 요청/분, 250k 토큰/초(변동 가능).
- 출력: Choice(≤255 보기, 보기별 확률), Score(2~10단계), Noul(예/아니오 확률).
- 지연: 업체 수치는 미국 서부. OpenRouter P50 0.37초. 한국 측정 없음.
- 공식 약점(jaggedness, 2026-09-17): 수치·날짜 비교 약함 / 관련 없는 내용 늘면 정확도 하락 / **#2(c) Score 기댓값으로 단계 사이 값 보간 금지** / **#8 질문 사이 확률 항등식 불성립(긍정·부정 Noul 합 1.19)**.
- 보정: 기준이 정답이 아니라 최상위 LLM 판단(Astra + Fable 5.1 평균)에 가깝다. 곡선·논문 미공개.
- 실험 규칙: 버전 고정·`model` 기록, 영어, 평평한 상태, 보기 이름 형식 점검(극성 효과, LOW).
- **확률 사용 규칙(모든 모듈 공통)**: 보정 측정(E1) 전에는 확률을 **게이트(임계값)로만** 쓴다. 양(가중 평균, 가중 합의)으로 쓰는 설계는 E1 뒤에 켠다. 확률 비교는 같은 문구·같은 보기·같은 유형 질문끼리만.

### M1. 이미지 → Jev 입력
- [사용자] Jev는 이미지를 못 본다. AI 전 분야에서 가장 효율적인 변환을 가져온다. **변환 방법은 사용자가 정한다.**
- [제안] 원칙: 문법보다 내용(길이만으로 13.9~85% 하락, 약 3만 토큰 조건, 2510.05381 EMNLP 2025 Findings / JSON↔XML ±3%p, FloorplanQA ICML 2026).
- [제안] 후보(확정 아님): (1) ID 객체 목록 + 코드가 계산한 범주 관계 + 술어, 작업 관련만(GUI의 OmniParser V2와 같은 구조, 기간 밖) (2) 작업 지향 장면 부분 그래프 (3) Astra 설명(계획 시점만).
- [제안] 인식 앞단: SAM 3.1(여전히 1순위, 중간 물체 수 16→32 FPS) / 6D 자세 FoundationPose(BOP 2025 "최고 공개 소스" 0.734, **기간 밖**) 또는 WAPR.v2.1(MUSE) 0.806·0.72초 / 깊이 Fast-FoundationStereo(CVPR 2026, 4090 30ms) / 관계 술어는 코드 3D 기하(지연·결정성 때문).
- **주의(v4)**: M2·M4(b)·M7·M9·§2.5는 "코드가 기하를 계산해 술어를 만든다"를 전제로 쓰였다. 이 전제는 M1 결정에 달려 있다. [결정 필요]

### M2. Astra → Jev 전달
- [사용자] M1과 같은 문제로 본다.
- [제안] Astra 출력 = "세션 계약"(PhyAgentOS): 객체 ID(텍스트판 Set-of-Mark) / 단계 원장(완료 술어 + 예상 시간) / 단계별 스킬 + stop 술어(Harness VLA) / 결정 지점 typed 질문 / 금지 술어 / 계획이 본 상태의 시각 / 단계·분기 ID. 제약은 Astra가 코드로 쓰고(Code-as-Monitor, CVPR 2025, 기간 밖 개념) Jev에는 참/거짓만.
- 근거: COPE(TMLR 2026) 작은 실행기에는 "어떻게"보다 "무엇을"(1B MATH-500 목표형 30.2 / 절차형 23.2 / 없음 25.2 — **1B가 자기 계획을 만든 조건**, 큰 계획기가 목표형을 준 조건은 미시험. 원문 결론은 "작은 계획기가 큰 실행기를 해친다"). AgileThinker(ICLR 2026) 빠른 실행기가 느린 계획기를 기다리지 않고 최신 출력 참조(0.88→0.50 대 0.89→0.15는 8k 토큰/스텝·게임 3개 평균. 우리가 옮길 "최종 출력만 참조" 축소판은 압박이 셀 때만 이득: 8k 0.31 대 0.25, 4k 0.26 대 0.05, 16k·32k는 차이 없음).

### M3. 행동 표현
- [사용자] 촘촘하게 가도 된다. Jev 방식이면 충분히 가능하다.
- [제안] 원안: 순서 없는 보기는 최빈값, 크기는 이름 붙은 구간(최빈 구간). 차원당 ≤255 보기 1회(VLA-0: 해상도 250 대 1000 −1.5점, 미세조정 모델). 제어점 단위(BEAST, NeurIPS 2025).
- **반대 증거**(원문 확인): 학습 없는 모델은 잘게 여러 번보다 목표 지점을 한 번에 가리킬 때 훨씬 잘했다 — SPF(CoRL 2025, Table 2·§4.2, Gemini 2.0 Flash) 연속 수치를 글로 쓰기 7% / 후보 선택(PIVOT) 40% → 목표 지점 지정 87~100% / GUI-Cursor(ICML 2026) GPT-4o 상대 이동 10스텝 25.5%, GUI 학습 7B 상대 이동 4스텝 1.3%(절대 좌표 방식 36.3%) / Show-Harness 보기도 거친 설계(방향 + 2/4cm).
- [제안] 비교 조건 "목표 지정형"(Jev가 목표 물체·부분·영역을 고르고 크기·경로는 코드). [결정 필요: 기본안]
- 보조: PIVOT 텍스트판(코드가 후보와 예상 결과 술어를 만들고 Jev가 고름; PIVOT **기간 밖**, 같은 발상 공개 데모 있음), KnowNo식 conformal 보기 집합(**기간 밖**) → 집합이 여러 개면 Astra 호출.

### M4. 연속 동작 1단계: 계단식 겹침 호출 + 자기 검증 ★
- [사용자] 1초에 Jev를 여러 번(예: 3번) 계단식으로 겹쳐 호출한다. **겹친 구간의 움직임이 제대로 반영됐는지 스스로 확인하고 업데이트하는 시스템이 반드시 있어야 한다. 가장 중요.** RTC를 많이 참고한다.
- [제안] 확인을 둘로 나눈다.
  - (a) 호출 사이 합의: LocalAgreement(동시통역 표준, **기간 밖**, 확정 지연 약 2배) + 순서형 보기 완화 수용(Spec-VLA EMNLP 2025 — 원문 허용 폭 256 중 9/5, 우리 폭은 실험으로). 같은 질문끼리만.
  - (b) 실제 반영 확인: 확정 실행 스텝의 예상 상태 대 측정 상태를 코드로 비교 → 범주를 다음 입력에. (a)만으로는 부족하다(같은 모델은 같은 오답 반복).
- [제안] 갱신: Speculative Actions(ICLR 2026) 추측→검증→확정/수리 틀. RTC 3구간(고정 = 실측 Jev p95 지연 / 중간 = 이전 선택 유지 가중이 점점 줄어듦 / 끝 = 새 선택). 확률 가중은 E1 뒤.
- [제안] 스케줄러: SmolVLA 큐 임계값 + bounded queue(크기 3) + 조건부 분기 스텝 + 상태 변화 P90 연속 2회면 조기 호출.
- **M3 결정과의 의존(v4)**: M3가 "목표 지정형"이 되면 겹쳐 합의할 스텝 열이 짧아진다. 그 경우 M4의 대상은 **결정 지점 열**(다음 스킬, 전이 시점, critic 수락, 목표 선택 갱신)로 옮긴다. 두 변형을 함께 설계한다.
- 정정 기록: VLASH·A2C2는 학습형이라 발상만(A2C2 ICLR 2026 거절).
- **새로움의 범위(v3/18, 검색어 53개 + Jev 저장소 8곳, 확신 MED)**: 비정지·겹침 요청은 전제(Slow Brain, Jev 데모). 새로움은 **합의(a) + 실행 결과(b) 둘 다로 확정/유지/교체/수리를 고르는 규칙**을 학습 없는 API typed 결정 모델에 붙인 것. (b)의 예상 상태는 Jev가 아니라 코드가 만든다. 대상은 "미래 결정 스텝"이라 M3가 목표 지정형이어도 성립. "확률 기반"이라는 말은 뺀다.
- 가장 가까운 선행: Slow Brain(겹침 + 최신 답 감쇠, (a)(b) 없음) / Jev 데모(요청 하나 + 유지) / Speculative Actions(추측 대 권위 모델 일치, 물리 실행 뒤 확인 없음) / 2512.17250(예측 대 실제 잠재 상태로 유지·수정·재계획, 학습 세계 모델, LOW) / DiscreteRTC·2606.13355(학습 정책 내부).
- **M4 실험 설계(v3/18 §7)**: 호출 예산 동일, 실행 중 섭동. C0 멈춰 기다림 / C1 요청 하나 + 유지 / C2 겹침 + 최신 답 / C2' 겹침 + 감쇠 융합 / C3 (a)만 / C4 (b)만 / C5 (a)+(b) 제안 / C5' (b) 결과를 Jev 입력에서 뺌("(b)는 그냥 MPC" 반론 분리) / C6 (a)+(b) 겹침 끔. 핵심 비교 C5 대 C2. C4≈C5면 주장을 (b) 중심으로 좁힌다. 3시드 이상, 판정 기준 사전 기록.
- 위험: Jev p95 지연이 결정 간격보다 짧으면 겹칠 이유가 약해진다(jev-drone 중앙값 0.11초, jev-realtime-sdk pipelined 초당 21회) → E0로 한국 기준 지연을 먼저 잰다. Slow Brain의 감쇠 융합이 80%를 지켜 "간단한 융합이면 충분" 반론 가능.

### M6. 스킬과 Jev 결합
- [사용자] 기존 스킬은 Jev와 최대한 밀접하게. LLM이 스킬을 부르고 끝이 아니라 잘게 엮는다. 1년 이내 GitHub 스타 상위 5개 논문을 참고해 파이프라인을 대충 짜 본다.
- 스타 상위(2026-09-23 측정, arXiv ≥ 2025-09-23): PhyAgentOS 2,481 / Zetta 1,252 / Harness VLA 962 / CaP-X 819(ICML 2026) / ROSClaw 625 또는 Show-Harness 451. [결정 필요: 5위 — ROSClaw 저장소 공식 여부 추정]
- [제안] 참고는 결합 세밀도 순: Zetta(런타임 critic은 코드, 액션 청크마다 판정. **Orchestrator에 대해 원문이 엇갈린다**: §2.1·부록 C는 LLM Orchestrator가 온라인으로 모든 개입을 승인, 인프라 절은 온라인은 VLA + critic만. Jev를 승인자로 두는 것은 우리 접목안. 적응 예산 개발 시드 50) / Show-Harness(단위마다 피드백. 로봇이 모델을 기다리는지 원문 명시 없음, 설정값 유지 방식으로 추정) / Harness VLA(기존 스킬 작동 범위를 기억으로, 저자 스스로 "계획기–하위 루프가 열려 있다"는 한계, 실험은 전부 시뮬레이터) / CaP-X(원문: 턴 = 프로그램 한 편 끝까지 실행. **코드 안 `jev_choice()` typed 선택은 우리 제안**).
- **"기존 스킬"의 정의 [결정 필요]**: 사용자 문제 설정은 "물체를 보고 스킬을 생성해서 잡는 기존 방법". (a) 보유 스킬 라이브러리 / (b) 코드 에이전트가 생성한 스킬(CaP-X식) / (c) 새로 만든 라이브러리. 벤치마크가 양팔(RoboDojo)이면 양팔 스킬이 필요.
- 대략 파이프라인은 §2.5.

### M7. 진행 판별
- [사용자] 프레임별로 Astra 계획대로 되는지 판별. VLA에서 "계획대로"를 무엇으로 정의했는지 참고.
- [제안] 완료 = 센서·술어, 진행 = 완료까지 남은 시간(RECAP 개념; π*0.6·π0.7의 진행 정의는 학습 신호일 뿐 실행 중 판정엔 안 쓰임).
- [제안] **실패 판정은 한 곳(코드 critic)에서만** 한다(v4 정리): 입력 = 마일스톤 술어, 정체 규칙(N번 연속 멈춤 / 최고 진행을 M번 못 넘음, FaRe 방식, 잡기·놓기 전환 중 보류), 마감 초과, M4 불일치 크기, Jev 진행 범주 {유효 진행, 허용 변화, 실패, 복구 중}. critic이 "실패"를 내면 M8·M9가 동시에 시작한다.
- 보조: SAFE(NeurIPS 2025) conformal 시간 임계값, 가끔 Astra로 GVL(ICLR 2025, **기간 밖**), Astra 단계 원장(R²VLM CVPR 2026 형식).

### M8. Astra 호출 시점과 다중 프레임
- [사용자] 적어도 실패 판정이 나면 Astra를 부른다. 그 순간 한 장이 아니라 연속 프레임을 준다(**예: 한 이미지에 프레임 10개**). 호출 방식은 비교 평가한다: (1) Hz 단위 주기 (2) 정해 둔 필요한 순간마다 (3) **"이때쯤 결과가 나왔어야 하는데 안 나오네"라는 자체 판단**. VLA에서 실패 시 되돌아갈 곳을 정하는 프레임워크를 참고. 처음 계획할 때만 멈추고 이후는 웬만하면 멈추지 않는다.
- [제안] 호출 구조: 트리거 → 문지기(부를지·모드·토큰 예산·지연 목표, BRACE ICML 2026) → 호출, 복구 직후 cooldown. **실패 트리거는 문지기를 거치지 않고 항상 호출**(사용자 원칙).
- [제안] (3) "자체 판단"의 구현 후보 둘을 비교한다 [결정 필요]:
  - (3a) 코드가 M2 예상 시간으로 마감 계산(self-triggered 개념, 기간 밖) — 근거: "필요할 때만 계획하라" 프롬프트 실패 정성 서술(Learning When to Plan, ICLR 미채택), Jev 시간 비교 약점.
  - (3b) 모델(Jev 또는 Astra)이 경과 시간·예상 시간을 받아 스스로 판단 — 사용자 표현에 더 가깝다. 선례 Sentinel(CoRL 2024, 기간 밖, 효과 미측정).
  - 구분할 것: 진행 정체 시간 초과(Critic in the Loop에 있음) 대 예상 시간 마감.
- [제안] 다중 프레임: **사용자 예시(격자 한 장에 10프레임)를 기본 조건**으로 두고, 개별 이미지 6~10장(KITE ICRA 2026 움직임 키프레임, 감지 순간·현재는 high)과 "변화 요약 텍스트"(CaP-X에서 원시 RGB보다 나음 — 원문에서 변화 텍스트는 코드가 아니라 VLM(Gemini-3-Pro, VDM)이 이전·현재 이미지 차이를 서술)를 비교 조건으로 둔다. 격자 대 개별은 일관된 승자 없음. 비용은 둘 다 약 3,000 토큰(512px 가정). 하위 작업 시작 프레임 포함(LIBERO-RECOVER 0.103→0.247). [결정 필요: 기본값]
- **"웬만하면 멈추지 않는다"에 대한 반대 증거(v3/16)**: WAM 실물 정밀 끼우기에서 멈추고 기다리는 동기 실행 72.5점이 비동기(40)보다 훨씬 높았다. 단 동적 과제(컨베이어)에서는 동기 20점. 사용자 방향은 유지하고 정밀 구간의 정지 허용 여부를 [결정 필요]로 둔다.
- 실험: 호출 수를 맞춘 비교(CheckVLA: 10.1 대 10.2회에서 +8.5%p, 검증 시점 기여 +3.9%p), 적시 재현율, 호출 지연 p95, 정지 시간, 결정 수. "Astra 없음", "이미지 없는 Astra" 조건 포함.

### M9. 실패 복구
- [사용자] VLA에서 가장 좋은 실패 복구 방법을 찾는다. 1년 반 이내.
- 사실: 2026-09 기준 로봇 복구 기법끼리 같은 벤치마크 직접 비교는 없다 → "최고"는 수치로 못 정한다.
- [제안] **v4 구조 (사용자 원칙 "실패할 때마다 Astra 개입" 반영)**: critic이 실패를 내는 순간 **Astra를 비동기로 바로 부른다**(연속 프레임 + 사건 문맥). Astra 응답을 기다리는 동안 아래 층이 로봇을 움직인다(멈추지 않음): 스킬 재시도·재스테이징 → Jev 선택 {계속, 체크포인트 k 재개, 리셋 스킬}. Astra 응답이 오면 그 계획이 우선한다(재계획 필요 시에만 정지).
  - v3의 "Astra는 맨 마지막" 사다리는 사용자 원칙과 어긋나 폐기했다(v3/17 치명 2).
- [제안] 복구 = "언제 / 어디로 / 무엇을 남길지"(FaRe 2609.18016 로봇·학습 없음 RoboTwin 91.5→93.2%, 실물 43/60→50/60 / RIR 2609.18304 LLM·환경 복원 전제, 로봇 미적용, 둘 다 MED-LOW). "어디로" = 사전조건 술어가 모두 참인 가장 늦은 체크포인트. 남길 것 = 목표·환경 지식·시도 이정표·실패 분석.
- 보조: FLARE(CVPR 2026) ID/OOD 구분, WebRollback(EACL 2026) 체크포인트 복귀 대 리셋 분리, FailSafe 실패 자동 생성(평가용).
- 반대 증거: 반성 메모리가 단순 재시도보다 나쁜 설정(VRL-Bench) → 기준 방법에 "메모리 없는 재시도", "완전 리셋".

### M10. 경험 축적
- [사용자] 경험 축적이 제대로 되어야 한다. API 모델의 경험 축적을 어떻게 해야 효율적인지 1년 반 이내 논문에서 찾는다.

- [제안] Jev 쪽: 교훈 목록을 넣지 않는다. Astra가 typed 규칙으로 컴파일하고 (스킬, 결정 지점, 술어)가 정확히 맞는 0~2개만(MemCompiler: 통째 주입이 조합 절반 넘게에서 음수, 최대 −83.3%). 경험 → 규칙 컴파일 자체는 선행 있음(Kintsugi 등).

- 반대 증거: 2606.15017(EMNLP 2026) 예산 맞춘 메모리 없는 방법이 AWM·ReasoningBank보다 나았다(웹, 작업 독립). → 예산 맞춘 기준 방법, "규칙만 실행(Kintsugi식)", 3회 이상 평균 ± 표준편차.
- [결정 필요] Astra 메모리 주입 방식(top-k / 필요 시 조회 / 비교).

  - Astra(RoboDojo, 2609.24170): 28.97 / 22.48%로 공개 정책 전부 위지만 Gen·Open 축 덕분, Precision·Long·Memory는 DM0.5보다 낮음. Astra에게만 wiki 레시피, GPT-5.5는 0.88% → "LLM"이 아니라 "Astra"의 결과. **Astra의 Gen standard/random 분리 수치는 없다.**
- [제안] 주장 문구: "같은 인식 앞단 위에서, 과제 데이터로 미세조정한 VLA는 배경·조명·방해물·물체가 바뀌면 성능 대부분을 잃는다. 학습 없는 API 모델 + 스킬 결정 층은 같은 변화에서 상대 하락폭이 작다." 절대 성공률 우위는 주장하지 않는다. **인식 상태 조건에서는 환경 변화에 맞서는 것이 인식 앞단이므로, 같은 인식 위에서 "룰 결정 층 대 LLM 결정 층"을 반드시 비교한다.** [결정 필요]
- [제안] 벤치마크: 주 RoboDojo-Sim(Gen 12 standard/random 분리 + Open 8, 양팔, Isaac Sim) / 보조 LIBERO-Plus·LIBERO-PRO(범주 5·6 공개 수치) / 선택 AGNOSTOS·MolmoSpaces. 공개 수치는 조건이 다르면 같은 열에 놓지 않는다(RoboDojo의 Astra는 wiki 제공·호출 100회). 환경 축은 인식 상태 조건에서만. [결정 필요]
- [제안] M4 전용 비교 조건 C0~C6(§2 M4). 특히 C1(Jev 커뮤니티 표준: 요청 하나 + 직전 행동 유지)과 C2(Slow Brain식 겹침 + 최신 답).
- [제안] 기준 방법: VLA(π0, π0.5, OpenVLA, RDT) / LLM+스킬(X-ICM — LLM+스킬 1년 창 밖, VoxPoser — **기간 밖**, 둘 다 AGNOSTOS 공식 기준이라 예외 요청; Show-Harness, Harness VLA) / Astra 기존(재현 가능한 것) / 룰베이스(같은 술어 위 규칙) / logprob 선택기(GPT-6 Sol/Luna `none` 또는 system-one-adapter) / 예산 맞춘 메모리 없음.
- [제안] 지표: 성공률, 0% 작업 수, standard→random 상대 하락폭 / 완료 시간, 정지 시간, 결정 수, Astra 호출 수·비용·응답 시간, Jev 호출 수·지연 p50/p95, 적응 예산 / 적시 재현율, 복구 성공률, jerk / 3회 이상 평균 ± 표준편차.

## 4. 컨트리뷰션 후보
1. **M4**: 겹쳐 부른 Jev 호출들을 같은 미래 결정 스텝의 표로 보고, (a) 호출 사이 typed 합의 + (b) 이미 실행한 스텝의 코드 예상 상태 대 측정 상태로 확정/유지/교체/수리를 고르는 규칙. 비정지·겹침 요청 자체는 선행(Slow Brain, Jev 데모)이라 **전제로 내린다.** 확정 규칙은 선행 못 찾음(v3/18, 검색어 53개, MED). 핵심 비교 C5 대 C2. **가장 강한 후보. 단 E0(지연)·E2(마차) 결과가 전제.**
2. **평가**: "같은 인식 위에서 LLM 결정 층이 VLA보다 새 환경에서 덜 무너지는가"를 처음 잰다(빈칸 확인, MED).
3. **M8**: 비정지 로봇에서 호출 방식(주기 / 정한 순간 / 예상 시간 마감 / 정체 시간 초과) × effort를 호출 수 맞춰 비교하는 평가·분석. 새로움 중간~낮음(CheckVLA, BRACE, Critic in the Loop 등 선행).
4. **M6**: 스킬 내부 결정 지점을 typed 질문으로(로봇 선점 없음, 비로봇 선례 있음).
5. **M10**: Astra 컴파일 규칙을 Jev 결정 지점에 정확히 맞춰 0~2개(좁음).
