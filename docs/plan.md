## 1. 두 모델 (원문 확인한 설계 제약)

### Jev (TypeSafe AI, `jev-1.13.0`)
- 입력 텍스트/JSON만("No image, audio, or video input", 공식). 영어가 가장 정확(CJK 덜 정확, 공식). 이미지 입력 Jev는 공식으로 없다.
- 한도: 요청 64k, state + 가장 긴 질문 32k 토큰. 질문 개수 상한 없음. 1,200 요청/분, 250k 토큰/초(변동 가능).
- 출력: Choice(≤255 보기, 보기별 확률), Score(2~10단계), Noul(예/아니오 확률).
- 지연: 업체 수치는 미국 서부. OpenRouter P50 0.37초. 한국 측정 없음.
- 공식 약점(jaggedness, 2026-09-17): 수치·날짜 비교 약함 / 관련 없는 내용 늘면 정확도 하락 / **#2(c) Score 기댓값으로 단계 사이 값 보간 금지** / **#8 질문 사이 확률 항등식 불성립(긍정·부정 Noul 합 1.19)**.
- 보정: 기준이 정답이 아니라 최상위 LLM 판단(Astra + Fable 5.1 평균)에 가깝다. 곡선·논문 미공개.
- 실험 규칙: 버전 고정·`model` 기록, 영어, 평평한 상태, 보기 이름 형식 점검(극성 효과, LOW).
- **확률 사용 규칙(모든 모듈 공통)**: 보정 측정(E1) 전에는 확률 게이트를 모두 끄고 **최빈 선택만** 쓴다(00 §6). 확률은 기록만 한다. 게이트는 E1 판정을 통과한 질문군에서만 켜고, 양(가중 평균·가중 합의)으로 쓰는 설계는 E1 판정 2를 통과할 때만 켠다. 확률 비교는 같은 문구·같은 보기·같은 유형 질문끼리만.

### M3. 행동 표현
- [사용자] 촘촘하게 가도 된다. Jev 방식이면 충분히 가능하고 할 만하다고 본다.

### M4. 연속 동작 1단계: 계단식 겹침 호출 + 자기 검증 ★
- [사용자] 1초에 Jev를 한 번이 아니라 3번 정도 계단식으로 겹쳐 쓴다. **겹치는 부분의 움직임이 제대로 반영됐는지 스스로 감지하고 업데이트하는 시스템이 자동으로 있어야 한다. 이게 굉장히 중요하다.** Jev가 빠르다지만 로봇 동작에서는 빠르지 않으니, 연속 동작처럼 내뱉게 하는 법을 RTC에서 많이 참고한다.
- [제안] 확인을 둘로 나눈다.
  - (a) 호출 사이 합의: LocalAgreement(동시통역 표준, **기간 밖**, 확정 지연 약 2배. **잠정 기본**, [결정 필요] 4) + 순서형 보기 완화 수용(Spec-VLA EMNLP 2025 — 원문 허용 폭 256 중 9/5, 우리 폭은 실험으로). 같은 질문끼리만.
  - (b) 실제 반영 확인: 확정 실행 스텝의 예상 상태 대 측정 상태를 코드로 비교 → 범주를 다음 입력에. (a)만으로는 부족하다(같은 모델은 같은 오답 반복).
- [제안] 갱신: Speculative Actions(ICLR 2026) 추측→검증→확정/수리 틀. RTC 3구간의 이산판(고정 = 실측 Jev p95 지연 / 중간 = 바꾸려면 합의가 필요하고 고정 경계에 가까울수록 교체 문턱이 엄격(W·γ, 가중 평균 없음, M4 §3 #5) / 끝 = 가장 새 표를 가확정). 확률 가중은 E1 뒤.
- [제안] 스케줄러: SmolVLA 큐 임계값 + in-flight 상한 N_max = ⌈d_p95/T_c⌉+1(M4 §4.3) + 조건부 분기 스텝 + 상태 변화 P90 연속 2회면 조기 호출.
- **M3 결정과의 의존(v4)**: M3가 "목표 지정형"이 되면 겹쳐 합의할 스텝 열이 짧아진다. 그 경우 M4의 대상은 **결정 지점 열**(다음 스킬, 전이 시점, critic 수락, 목표 선택 갱신)로 옮긴다. 두 변형을 함께 설계한다.
- 정정 기록: VLASH·A2C2는 학습형이라 발상만(A2C2 ICLR 2026 거절).
- **새로움의 범위(v3/18, 검색어 53개 + Jev 저장소 8곳, 확신 MED)**: 비정지·겹침 요청은 전제(Slow Brain, Jev 데모). 새로움은 **합의(a) + 실행 결과(b) 둘 다로 확정/유지/교체/수리를 고르는 규칙**을 학습 없는 API typed 결정 모델에 붙인 것. (b)의 예상 상태는 Jev가 아니라 코드가 만든다. 대상은 "미래 결정 스텝"이라 M3가 목표 지정형이어도 성립. "확률 기반"이라는 말은 뺀다.
- 가장 가까운 선행: Slow Brain(겹침 + 최신 답 감쇠, (a)(b) 없음) / Jev 데모(요청 하나 + 유지) / Speculative Actions(추측 대 권위 모델 일치, 물리 실행 뒤 확인 없음) / 2512.17250(예측 대 실제 잠재 상태로 유지·수정·재계획, 학습 세계 모델, LOW) / DiscreteRTC·2606.13355(학습 정책 내부).
- **M4 실험 설계(v3/18 §7)**: 호출 예산 동일, 실행 중 섭동. C0 멈춰 기다림 / C1 요청 하나 + 유지 / C2 겹침 + 최신 답(Slow Brain VLM Stream 원문판) / C2' Probability Fusion + 스트리밍(Slow Brain 원문판) / C2'-S Score Fusion / C2'' 겹침 + 표 나이 감쇠 가중 최빈(옛 C2', 우리 변형) / C3 (a)만 / C3' (a)의 베이즈 정지판(C_thresh 0.9) / C3'' 보기 순서 돌리기 / C4 (b)만 / C5 (a)+(b) 제안 / C5' (b) 결과를 Jev 입력에서 뺌("(b)는 그냥 MPC" 반론 분리) / C5-A3 A3식 같은 시각 다중 샘플 합의만((b) 없음) / C-FIX 격자 탐색 최적 고정 확정 길이 / C6 (a)+(b) 겹침 끔. 핵심 비교 C5 대 C2·C2' + C5 대 C5-A3(D11 정정, 정본 §18~§20). C4≈C5면 주장을 (b) 중심으로 좁힌다. 3시드 이상, 판정 기준 사전 기록.
- 위험: Jev p95 지연이 결정 간격보다 짧으면 겹칠 이유가 약해진다(jev-drone 중앙값 0.11초, jev-realtime-sdk pipelined 초당 21회) → E0로 한국 기준 지연을 먼저 잰다. 이때도 겹침은 끄지 않고 목적을 "같은 스텝 여러 표"로 옮긴다(00 §9 C1). Slow Brain의 감쇠 융합이 80%를 지켜 "간단한 융합이면 충분" 반론 가능.

### M8. Astra 호출 시점과 다중 프레임
- [사용자] 적어도 실패 판정이 나면 Astra를 부른다. 그 순간 한 장이 아니라 연속 프레임을 준다(**예: 한 이미지에 프레임 10개**). 호출 방식은 비교 평가한다: (1) Hz 단위 주기 (2) 정해 둔 필요한 순간마다 (3) **"이때쯤 결과가 나왔어야 하는데 안 나오네"라는 자체 판단**. VLA에서 실패 시 되돌아갈 곳을 정하는 프레임워크를 참고. Astra가 처음 생각할 때는 멈추는 게 맞지만, 그 이후는 웬만하면 멈추지 않는다. 실패로 생각해야 하는 경우만 어쩔 수 없다.
- [제안] 호출 구조: 트리거 → 문지기(부를지·모드·토큰 예산·지연 목표, BRACE ICML 2026) → 호출, 복구 직후 cooldown. **실패 트리거는 문지기를 거치지 않고 항상 호출**(사용자 원칙).
- [제안] (3) "자체 판단"의 구현 후보 둘을 비교한다 [결정 필요]:
  - (3a) 코드가 M2 예상 시간으로 마감 계산(self-triggered 개념, 기간 밖) — 근거: "필요할 때만 계획하라" 프롬프트 실패 정성 서술(Learning When to Plan, ICLR 미채택), Jev 시간 비교 약점.
  - (3b) 모델(Jev 또는 Astra)이 경과 시간·예상 시간을 받아 스스로 판단 — 사용자 표현에 더 가깝다. 선례 Sentinel(CoRL 2024, 기간 밖, 효과 미측정).
  - 구분할 것: 진행 정체 시간 초과(Critic in the Loop에 있음) 대 예상 시간 마감.
- [제안] 다중 프레임: **사용자 예시(격자 한 장에 10프레임)를 기본 조건**으로 두고, 개별 이미지 6~10장(KITE ICRA 2026 움직임 키프레임, 감지 순간·현재는 high)과 "변화 요약 텍스트"(CaP-X에서 원시 RGB보다 나음 — 원문에서 변화 텍스트는 코드가 아니라 VLM(Gemini-3-Pro, VDM)이 이전·현재 이미지 차이를 서술)를 비교 조건으로 둔다. 격자 대 개별은 일관된 승자 없음. 비용은 둘 다 약 3,000 토큰(512px 가정). 하위 작업 시작 프레임 포함(LIBERO-RECOVER 0.103→0.247). [결정 필요: 기본값]
- **"웬만하면 멈추지 않는다"에 대한 반대 증거(v3/16)**: WAM 실물 정밀 끼우기에서 멈추고 기다리는 동기 실행 72.5점이 비동기(40)보다 훨씬 높았다. 단 동적 과제(컨베이어)에서는 동기 20점. 사용자 방향은 유지하고 정밀 구간의 정지 허용 여부를 [결정 필요]로 둔다.
- 실험: 호출 수를 맞춘 비교(CheckVLA: 10.1 대 10.2회에서 +8.5%p, 검증 시점 기여 +3.9%p), 고정 창 재현율(τ=2 s), 호출 지연 p95, 정지 시간, 결정 수. "Astra 없음", "이미지 없는 Astra" 조건 포함.

### M9. 실패 복구
- [사용자] VLA에서 가장 좋은 실패 복구 방법을 찾는다. 1년 반 이내.
- 사실: 2026-09 기준 로봇 복구 기법끼리 같은 벤치마크 직접 비교는 없다 → "최고"는 수치로 못 정한다.
- [제안] **v4 구조 (사용자 원칙 "실패할 때마다 Astra 개입" 반영)**: critic이 실패를 내는 순간 **Astra를 비동기로 바로 부른다**(연속 프레임 + 사건 문맥). Astra 응답을 기다리는 동안 아래 층이 로봇을 움직인다(멈추지 않음): 스킬 재시도·재스테이징 → Jev 선택(`dp.critic_accept`: M9 복구 제안 {아래 층 결과 인정, 체크포인트 k 재개, 리셋 스킬, 안전 대기} + 모름). Astra 응답이 오면 그 계획이 우선한다(적용 중에도 정지하지 않음, 정지는 L3 안전 대기뿐이며 그 자체가 [결정 필요] 13, 00 §16).
  - v3의 "Astra는 맨 마지막" 사다리는 사용자 원칙과 어긋나 폐기했다(v3/17 치명 2).
- [제안] 복구 = "언제 / 어디로 / 무엇을 남길지"(FaRe 2609.18016 로봇·학습 없음 RoboTwin 91.5→93.2%, 실물 43/60→50/60 / RIR 2609.18304 LLM·환경 복원 전제, 로봇 미적용, 둘 다 MED-LOW). "어디로" = 사전조건 술어가 모두 참인 가장 늦은 체크포인트. 남길 것 = 목표·환경 지식·시도 이정표·실패 분석.
- 보조: FLARE(CVPR 2026) ID/OOD 구분, WebRollback(EACL 2026) 체크포인트 복귀 대 리셋 분리, FailSafe 실패 자동 생성(평가용).
- 반대 증거: 반성 메모리가 단순 재시도보다 나쁜 설정(VRL-Bench) → 기준 방법에 "메모리 없는 재시도", "완전 리셋".

### M10. 경험 축적
- [사용자] 경험 축적이 제대로 되어야 한다. API 모델의 경험 축적을 어떻게 해야 효율적인지 1년 반 이내 논문에서 찾는다.

- [제안] Jev 쪽: 교훈 목록을 넣지 않는다. Astra가 typed 규칙으로 컴파일하고 (스킬, 결정 지점, 술어)가 정확히 맞는 0~2개만(MemCompiler: 통째 주입이 조합 절반 넘게에서 음수, 최대 −83.3%). 경험 → 규칙 컴파일 자체는 선행 있음(Kintsugi 등).
- [제안] 라벨: 센서 술어로 확정한 것만 Jev 규칙 재료(LLM 판정 "성공"의 30~60%가 실제 실패, 2606.15017).
- 반대 증거: 2606.15017(EMNLP 2026) 예산 맞춘 메모리 없는 방법이 AWM·ReasoningBank보다 나았다(웹, 작업 독립). → 예산 맞춘 기준 방법, "규칙만 실행(Kintsugi식)", 3회 이상 평균 ± 표준편차.
- [결정 필요] Astra 메모리 주입 방식(top-k / 필요 시 조회 / 비교).

## 4. 컨트리뷰션 후보
1. **M4**: 겹쳐 부른 Jev 호출들을 같은 미래 결정 스텝의 표로 보고, (a) 호출 사이 typed 합의 + (b) 이미 실행한 스텝의 코드 예상 상태 대 측정 상태로 확정/유지/교체/수리를 고르는 규칙. 비정지·겹침 요청 자체는 선행(Slow Brain, Jev 데모)이라 **전제로 내린다.** "합의가 되면 앞 구간을 확정한다"는 A3(2605.11567)가 먼저 했다. 새로움은 결합이다: 시간차로 겹쳐 부른 블랙박스 typed 결정 호출 사이의 합의에 실행 뒤 코드 예상 상태 대 측정 상태 비교를 결합해 전제가 깨진 표를 무효화하고 keep/replace/repair를 고른다. 차별점은 (b)가 합의 원장의 전제 무효화·확정에 쓰인다는 점이다(정본 §18·§19, D11 정정). 핵심 비교 C5 대 C2·C2' + C5 대 C5-A3. **가장 강한 후보. 단 E0(지연)·E2a(마차) 결과가 전제.**
2. **평가**: "같은 인식 위에서 LLM 결정 층이 VLA보다 새 환경에서 덜 무너지는가". 같은 인식·같은 실행기 위에서 결정 층만 바꿔 짝지은 낙폭 비교는 없다(2026-09-22 색인 기준, 정본 §18. D11 정정: "처음 잰다" 표현 삭제).
3. **M8**: 비정지 로봇에서 호출 방식(주기 / 정한 순간 / 예상 시간 마감 / 정체 시간 초과) × effort를 호출 수 맞춰 비교하는 평가·분석. 새로움 중간~낮음(CheckVLA, BRACE, Critic in the Loop 등 선행).
4. **M6**: 스킬 내부 결정 지점을 typed 질문으로(로봇 선점 없음, 비로봇 선례 있음).
5. **M10**: Astra 컴파일 규칙을 Jev 결정 지점에 정확히 맞춰 0~2개(좁음).

- **평가**: RoboDawn은 같은 인식 비교가 아니다(하네스 추가 카메라·격자 주석·계획기 실행) → 우리 "같은 인식 앞단 위에서 결정 층만 바꾼 비교"가 여전히 빈칸. 또 같은 Astra가 RoboDojo에서 22.58%(자체 평가)와 35.67%(RoboDawn 하네스)로 갈린 것은 "인터페이스가 점수를 크게 바꾼다" = 앞단을 같게 맞춰야 하는 이유.
- **M3 ("촘촘하게")**: RoboDawn에서 성능을 가장 움직인 것은 공간 근거(격자 제거 47.0→32.4%)와 결정 횟수(예산 확장 +16%p)였고, 저자는 "이산 명령이 미세 보정에 너무 거칠다"를 한계로 적었다 → 사용자 "촘촘하게"를 결정 빈도·공간 근거로 살리고, 접촉 근처는 미세 조정(H안) 방향을 지지. RoboDawn식 "한 축 한 명령 + 한 호출 여러 명령"을 비교 조건으로 추가.
