# Harvest 연구 계획 (v1, 2026-09-23)

이 문서는 사용자와 대화하며 정한 방향과, 그 방향을 채우기 위해 조사한 참고 연구를 모은 계획서다.
- **[사용자]**: 사용자가 직접 정한 것
- **[제안]**: Claude가 조사 결과를 바탕으로 제안한 것. 사용자가 확정해야 한다.
- 조사 한계: arxiv.org 등 논문 원문 접근이 막혀 검색 요약(snippet)으로만 확인했다. 수치는 인용 전에 원문으로 다시 확인해야 한다.

---

## 0. 한 줄 요약
기존 스킬 기반 조작이 실패할 때 GPT-6 Astra(느리지만 똑똑한 상위)가 개입하고, 매 순간의 엔드포인트 판단은 Jev(빠른 객관식 결정 모델, 하위)가 촘촘하게 내리는 계층 구조를 만든다. 핵심 메시지는 **VLA는 새 환경으로 일반화가 안 되지만, LLM 기반은 일반화된다**는 것이다. [사용자]

## 1. 전체 구조

```
사용자 명령
  └─ Astra (상위, 느림, 이미지 봄)
       ├─ 명령 분해 + 계획 (이때는 로봇 정지 허용)            [사용자]
       ├─ 단계별 하위 목표 명세 (JSON) + 스킬 바인딩          [제안]
       └─ 실패 시 다중 프레임 보고 재계획/복구                [사용자]
  └─ 상태 인코더: 카메라 → 텍스트 상태(JSON)                  [제안]
  └─ Jev (하위, 빠름, 텍스트만)
       ├─ 촘촘한 객관식 동작 선택                              [사용자]
       ├─ 계단식 겹침 호출 + 겹침 구간 자기 검증/업데이트      [사용자]
       └─ 진행 판별 (계획대로인가)                             [사용자]
  └─ 액션 스무딩 → 저수준 제어기                               [사용자]
  └─ 경험 메모리 (성공 계획 재사용, 실패 교훈)                 [사용자 방향 / 방법은 제안]
```

속도 계층 예시 [제안]: 저수준 제어 수백 Hz → 스무딩 → Jev 수 Hz(계단식) → Astra는 시작/실패/비교 실험 조건에서만.
참고: jev-drone은 500Hz 제어기 / 50Hz 안전 반사 / 15Hz 비전→장면 변환 / 2.5Hz Jev로 계층을 나눴다.

## 2. 모듈별 계획

### M1. 상태 표현: 이미지 → Jev 입력
- [사용자] VLA에 국한하지 않고 AI 전 분야에서 가장 효율적인 방법을 쓴다.
- [제안] **객체 중심 수치 JSON + 진행 술어(predicate) + 이전 프레임 대비 변화(diff)**
  - 작업에 관련된 물체만 넣는다. 각 물체에 ID, 3D 위치(필요하면 자세), 그리퍼 상태를 둔다.
  - `grasped`, `above_target`, `in_contact` 같은 참/거짓 술어를 둔다. Jev의 예/아니오(Noul) 질문과 바로 연결된다.
  - 전체 기록 대신 이전 프레임과의 차이만 준다.
  - "목표 − 그리퍼" 같은 상대 벡터는 미리 계산해서 넣는다. LLM이 자기 기준 좌표계 추론에 약하기 때문이다.
- 근거
  - 좌표 입력이 ASCII나 자연어보다 기하 판단에서 일관되게 우수했다: From Text to Space (arXiv 2502.16690, 2025)
  - 텍스트 전용 LLM이 물체 자세 텍스트만으로 엔드포인트 행동을 예측했다(RLBench 16개 작업 평균 51.8%): RoboPrompt (arXiv 2410.12782)
  - 성능이 낮은 모델일수록 입력이 짧을수록 좋고, 변화분만 주는 방식이 토큰 효율적이다: Read More, Think More (arXiv 2604.01535, 2026)
  - 술어 기반 장면 그래프가 상태 접지 정확도를 높였다: Domain-Conditioned Scene Graphs (arXiv 2504.06661)
  - 장면 그래프 → 텍스트 요약으로 LLM이 실패를 설명했다: REFLECT (arXiv 2306.15724)
  - 키포인트 관계 제약으로 장면을 압축했다: ReKep (arXiv 2409.01652)
  - 주의점: 텍스트 LLM은 에이전트 기준 좌표계에 약하다: GSU (arXiv 2603.17333)
- 실험: 표현 형식 비교(좌표 JSON / 자연어 / 격자 / 장면 그래프)를 정확도, 토큰 수, 지연 시간으로 비교한다. 조작 작업에서 이런 비교는 찾지 못했다. 컨트리뷰션 후보다.
- 미정 (사용자 결정 필요): 인식 앞단(검출기, 자세 추정기, 깊이 등)을 무엇으로 할지

### M2. Astra → Jev 인수인계
- [사용자] M1과 거의 같은 문제로 본다. Astra는 이미지를 보고 명령하지만 Jev는 이미지를 못 보므로, 전달 방식을 효율적으로 설계해야 한다.
- [제안] Astra가 M1과 **같은 스키마**로 하위 목표 명세를 낸다.
  - 대상 물체 ID
  - 완료 조건: 술어 집합 (예: `grasped(cup)=true`)
  - 중간 이정표(milestone) 상태: M8 복구의 되돌아갈 지점
  - 예상 소요 시간: M7의 "이때쯤 됐어야 하는데" 판단에 쓴다
  - 허용 동작 집합: 방향과 크기의 범위
  - 연결할 스킬과 파라미터 범위
  - 참고: ReKep(관계 제약을 텍스트로), B2FF(이정표 상태를 미리 생성, arXiv 2606.09258)

### M3. 행동 표현: 촘촘한 객관식
- [사용자] 촘촘하게 가도 된다. Jev라면 충분히 가능하다.
- [제안]
  - 방향(3축 ±), 크기(여러 단계), 회전, 그리퍼 열고 닫기를 각각 Choice 질문으로 나눈다.
  - Jev는 한 번의 호출에 여러 질문을 병렬로 답할 수 있으므로, 여러 축을 한 번에 묻는다.
  - 각 보기의 확률을 받아서, 1위 보기만 쓰지 않고 확률 가중 평균으로 연속값을 만들 수 있다(M4, M5와 연결).

### M4. 연속 동작 1단계: RTC 방식의 계단식 Jev 호출 ★
- [사용자]
  - 1초에 Jev를 한 번이 아니라 여러 번(예: 3번) 계단식으로 겹쳐 호출한다.
  - 겹치는 구간의 움직임이 제대로 반영됐는지 스스로 확인하고 업데이트하는 시스템이 반드시 있어야 한다. 이 부분이 굉장히 중요하다.
  - RTC를 많이 참고한다.
- [제안] 구체안
  1. 매 호출에서 Jev는 앞으로 k스텝의 동작 조각(chunk)을 낸다. 스텝마다 Choice 질문을 하나씩 둔다.
  2. 호출은 시간을 어긋나게 시작해서 조각들이 겹치게 한다(계단식).
  3. **고정(freeze)**: 이미 실행하기로 확정된 앞 d스텝은 새 호출에서 바꾸지 않는다. 확정된 앞부분을 입력에 넣어 준다(Training-time RTC의 prefix 조건과 같은 발상).
  4. **겹침 구간 일관성 검사**: 이전 조각과 새 조각이 같은 구간에서 낸 선택과 확률을 비교한다.
     - 일치하면 확정한다.
     - 불일치하면 RTC의 soft mask처럼 가까운 미래는 이전 조각 가중치를 크게, 먼 미래는 새 조각 가중치를 크게 섞는다.
     - 불일치가 크게 반복되면 M7(진행 판별)에 이상 신호로 보낸다.
  5. **자기 검증 업데이트**: 실행 후 관측된 상태 변화(M1의 diff)와 예측된 변화를 비교한다. 오차를 다음 호출 입력에 보정값으로 넣는다(A2C2의 스텝별 잔차 보정 발상).
  6. 후보 여러 개 중 이전 결정과 가장 잘 이어지는 것을 고르는 방식도 가능하다(BID의 backward coherence).
- 근거
  - RTC: "Real-Time Execution of Action Chunking Flow Policies" (Black, Galliker, Levine, arXiv 2506.07339, NeurIPS 2025). 확정 동작 고정 + 겹침 구간 inpainting + soft mask. 300ms 이상 지연에도 강건했고, temporal ensembling보다 부드러웠다.
  - Training-time RTC (arXiv 2512.05964): 추론 오버헤드 없이 확정된 앞부분을 조건으로 준다.
  - A2C2 (arXiv 2509.23224): 매 스텝 작은 보정 헤드로 잔차를 보정했다. RTC 대비 Kinetix +23점.
  - 비교 연구 (arXiv 2605.08168, 2026): A2C2가 전반적으로 가장 강했다. 추론 시점 RTC는 긴 조각, 큰 지연에서 성능이 떨어졌다.
  - BID (arXiv 2408.17355, ICLR 2025, 1.5년 기준보다 오래됨): 이전 결정과의 일관성으로 후보를 고른다.
  - SmolVLA (arXiv 2506.01844): 동작 큐가 임계값 아래로 내려가면 다음 조각을 요청하는 비동기 방식.
  - Event-Triggered Async Inference (arXiv 2609.22587, 요약만 확인): 장면 변화량에 따라 추론 간격을 바꾼다.
- **빈 곳 (컨트리뷰션 후보)**: RTC식 겹침 조각을 텍스트 결정 모델(LLM)에 적용한 연구는 찾지 못했다.

### M5. 연속 동작 2단계: 액션 스무딩
- [사용자] 아주 작은 움직임은 액션 스무딩이나 VLA에서 쓰는 부드럽게 만드는 방법으로 처리한다. 두 단계로 나눈다.
- [제안] 1순위는 B-스플라인 적합이다. Jev 조각의 경유점을 B-스플라인으로 이어 고주파 명령을 만들고, 조각 경계의 튐을 줄인다.
  - 참고: ABPolicy (arXiv 2602.23901), SMILE (arXiv 2608.29432), LiPo (arXiv 2506.05165)
  - 비교용 기준 방법: temporal ensembling (ACT, arXiv 2304.13705), 지수 평활
  - 최근 연구는 사후 평균보다 생성 단계에서 일관성을 맞추는 쪽을 선호한다. 그래서 M4가 주, M5는 보조다.

### M6. 스킬과 Jev를 잘게 엮기
- [사용자] 기존 스킬은 Jev와 최대한 밀접하게 엮는다. LLM이 스킬을 불러오고 끝나는 방식이 아니어야 한다.
- 참고 (1년 이내, GitHub 스타 기준. 스타 수는 검색 요약 수치라 재확인 필요)
  - CaP-X (arXiv 2603.22435, ICML 2026, 약 800★): 여러 추상화 수준의 스킬 API, 여러 번의 실행 피드백, 실행 전후 이미지 비교, 새 스킬 자동 합성
  - ASPIRE (NVIDIA, arXiv 2607.00272): 실행 추적으로 실패를 진단하고 수리한 뒤, 검증된 수리를 스킬로 저장한다. 처음 보는 긴 작업에서 31% 대 4%.
  - VLCP (arXiv 2608.16978): K스텝마다 다시 관측해서 제어 코드를 에피소드 안에서 고쳐 쓴다. 3.5%에서 35.1%로.
  - RoboOS (arXiv 2505.03673, 약 600★, 1년보다 오래됨): 계층형 두뇌-소뇌 구조, 실시간 공유 메모리(장면 그래프, 기록, 상태)
  - Agentic Robot (arXiv 2505.23450): 하위 목표 + 시간적 검증기로 진행과 복구를 관리한다.
- [제안] 엮는 방식
  - 스킬을 파라미터가 있는 함수로 만든다. 스킬 내부의 결정 지점(접근 방향, 잡는 위치, 힘, 다음 단계로 넘어갈지)을 Jev 객관식 질문으로 노출한다.
  - 스킬이 매 스텝 자기 상태와 술어를 M1 형식으로 내보내서 Jev와 M7이 읽게 한다.
  - Astra가 복구하면서 고친 내용을 검증한 뒤 새 스킬이나 파라미터로 저장한다(ASPIRE 방식, M9와 연결).

### M7. 진행 판별: "계획대로"의 정의
- [사용자] VLA에서 "계획대로"를 어떻게 정의했는지 많이 참고한다.
- 참고 (1.5년 이내)
  - VLAC (arXiv 2509.15937): 관측 쌍과 목표를 넣으면 진행 변화량과 완료 신호가 나온다. 퇴보와 정체도 감지한다.
  - π*0.6 / RECAP (arXiv 2511.14759): 가치 함수의 차이 V(s')−V(s)를 "좋아지는 중/나빠지는 중"으로 이진화한다.
  - TOPReward (arXiv 2602.19313): 토큰 확률을 진행도로 쓴다. Jev의 확률 출력과 잘 맞는다.
  - ProcVLM (arXiv 2605.08774): 하위 작업 구조의 진행도 + 남은 단계 추론
  - SAFE (arXiv 2506.09937): 시간에 따라 달라지는 임계값을 conformal prediction으로 정한다.
  - FailBench (arXiv 2609.03611): VLM 실패 판별기 최고가 균형 정확도 0.77이었다. 접촉이 많은 작업은 0.60 이하. 애매하면 "성공"으로 치우친다.
- [제안] 정의
  - "계획대로" = (a) 현재 하위 목표의 완료 술어 쪽으로 진행 변화량이 양수이고 (b) Astra가 준 예상 시간 안에 있으며 (c) M4의 겹침 불일치가 작다.
  - Jev에게 두 질문을 한다. 예/아니오: "이전 대비 진행했나", Choice: "진행 / 정체 / 퇴보 / 실패".
  - 한 프레임이 아니라 짧은 구간으로 판정해서 일시적 가림 등의 오탐을 줄인다.

### M8. Astra 호출 시점과 다중 프레임
- [사용자]
  - 최소한 실패 판정이 나면 Astra를 부른다.
  - 그때는 한 장이 아니라 연속 프레임을 준다. 예: 한 이미지에 프레임 10개.
  - 호출 방식은 비교 실험으로 정한다: (1) 일정 주기(Hz), (2) 사용자가 정한 순간마다, (3) "이때쯤 결과가 나왔어야 하는데 안 나왔다"는 자체 판단.
  - 처음 계획할 때만 로봇이 멈추고, 그 이후에는 웬만하면 멈추지 않는다. 실패로 다시 생각해야 할 때만 예외다.
- 근거
  - STAR (arXiv 2503.06060): 9프레임을 3×3 격자 한 장으로 API VLM에 줬다. 정확도는 비슷했고 응답은 빨랐으며 비용은 낮았다.
  - Guardian (arXiv 2512.01946): 격자는 세부 정보를 잃는다며 따로 넣는 방식을 택했다. 증거가 엇갈리므로 격자 대 개별 이미지도 비교 실험 항목이다.
  - Sentinel-VLA (arXiv 2605.01191, ICML 2026): 매 스텝 추론 대신, 처음 계획과 이상 감지 때만 깊게 추론한다.
  - FPC-VLA (arXiv 2509.04018): 키프레임에서만 VLM 감독자를 호출한다.
  - Sentinel (arXiv 2410.04640, 오래됨): VLM에 경과 시간을 주면 제때 끝날지 판단하는 데 도움이 된다. (3)번 방식의 근거다.
- **빈 곳 (컨트리뷰션 후보)**: 주기 호출, 이벤트 호출, 시간 초과 호출을 정량 비교한 연구는 찾지 못했다.
- [제안] Astra가 생각하는 동안(실패가 아닐 때) Jev는 현재 계획으로 계속 움직인다. Astra 결과가 오면 M4의 겹침 방식으로 이어 붙인다.

### M9. 실패 복구
- [사용자] VLA에서 가장 좋은 실패 복구 방법을 찾는다 (1.5년 이내).
- 참고
  - B2FF (arXiv 2606.09258): 실행 전에 이정표 상태를 미리 만들어 두고, 실패하면 하나를 골라 목표로 삼는다(되돌리기). 실패를 주입한 LIBERO에서 56.3%에서 74.0%로, 하위 정책 미세조정 없이.
  - FailSafe (arXiv 2510.01642): 실패 사례와 복구 행동을 자동 생성해서 학습한다. 최대 +22.6%.
  - Sentinel-VLA: 오류 복구 궤적을 합성한다. π0 대비 30% 이상 향상.
  - FAR (arXiv 2607.01111): 재시도 + 동작 섭동(diffusion policy 기준)
  - 기법 간 공통 벤치마크 비교는 없어서, "가장 좋은" 방법은 아직 정해지지 않았다.
- [제안] 3단계 복구 사다리
  1. Jev 수준: 같은 하위 목표를 약간 바꾼 동작으로 재시도한다(섭동).
  2. 되돌리기: M2에서 Astra가 준 가장 가까운 이정표 상태로 돌아간다(B2FF 방식, 학습 없음 → 일반화 유지).
  3. Astra 재계획: 다중 프레임과 실패 기록을 주고 새 계획을 받는다.
  - 학습 기반 방법(FailSafe, Sentinel-VLA)은 VLA 특화라서 일반화 메시지와 충돌한다. 개념만 가져온다.

### M10. 경험 축적 (API 모델 기반)
- [사용자] 경험 축적이 제대로 되어야 한다. API 모델의 경험 축적 방법을 찾는다 (1.5년 이내).
- 참고
  - ACE (arXiv 2510.04618): 전략 목록(playbook)을 통째로 다시 쓰지 않고 조금씩 덧붙이고 고쳐서(delta) 문맥 붕괴를 막는다.
  - ReasoningBank (arXiv 2509.25140): 성공과 실패 모두에서 교훈을 뽑아 유사도로 꺼내 쓴다. WebArena +8.3%.
  - Memento (arXiv 2508.16153): 사례 은행 + 작은 사례 선택 정책. LLM은 고정.
  - ViReSkill (arXiv 2509.24219): 성공한 계획을 저장해 두고 같은 작업이면 LLM 호출 없이 재사용한다.
  - MTP (arXiv 2509.24160): 실패하면 비슷한 성공 코드를 꺼내 고친다.
  - 반론 (arXiv 2606.15017): 같은 토큰 예산이면 메모리 없는 기본 에이전트가 비슷하거나 더 나았다. → 같은 예산의 기본 방법을 기준 방법으로 꼭 넣는다.
  - ExpWeaver (arXiv 2605.07164): 매 스텝 주입보다 필요할 때만 꺼내 쓰는 게 낫다.
- [제안] 세 층 메모리
  1. 성공 계획 라이브러리: 같거나 비슷한 작업이면 Astra 호출을 건너뛴다. 느린 Astra를 쓰는 우리 구조에서 특히 효과가 크다.
  2. 실패 교훈 은행: 짧은 구조화된 교훈. 계획할 때와 복구할 때 상위 k개를 꺼낸다.
  3. ACE 방식 정리: 중복 병합, delta 수정으로 반복 실패를 규칙 하나로 합친다.
  - 성공과 실패의 라벨은 LLM 자기 판정보다 센서와 술어 검증을 쓴다.
