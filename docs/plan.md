## 1. 두 모델에 대해 확인된 사실 (설계 제약, v3 원문 확인)

### Jev (TypeSafe AI, Jev 1.13)
- 입력: 텍스트/JSON만. 영어가 가장 정확하다.
- 한도: 요청 64k 토큰, state + 가장 긴 질문 32k 토큰. **질문 개수 상한은 없다**(토큰 한도만). 속도 제한 1,200 요청/분, 250k 토큰/초(예고 없이 바뀔 수 있음).
- 출력: Choice(보기 ≤255, 보기별 확률 + confidence), Score(2~10단계), Noul(예/아니오 확률). confidence는 확률에서 계산한 값이다.
- 지연: 업체 수치(미국 서부 측정). OpenRouter 전 지역 P50 0.37초. 한국 측정값 없음 → 첫 실험에서 잰다.
- **공식 약점(jaggedness, 2026-09-17 검토) 중 설계에 직접 걸리는 것**
  - 수치 정밀도·비교·산술, 날짜 비교에 약하다 → 기하·시간 계산은 코드에서.
  - 관련 없는 내용이 늘면 정확도 하락 → 입력은 짧게.
  - **#2(c) Score 기댓값으로 두 단계 사이 값을 보간하지 말라**(임계값 판정에는 써도 된다) → M3의 "확률 가중 평균으로 크기 결정"을 고친다.
  - **#8 질문 사이 확률 항등식이 성립하지 않는다**(같은 질문의 긍정/부정 Noul 합 1.19 사례, Noul과 Choice 불일치) → M4 겹침 비교는 같은 문구·같은 보기·같은 유형 질문끼리만.
- 보정: 곡선·RLCD 논문 여전히 미공개 → 우리 데이터로 먼저 측정(질문 유형별).
- 새 위험 신호: 보기 이름 극성 효과(0/1 → no/yes로 바꾸면 AUC 0.81 → 0.58, 2609.26758, LOW) → M3 절제 변수.
- 기타 정정: 창업자 Diogo Almeida. 대기자 명단 폐지 2026-09-20 21:30 UTC.

### GPT-6 Astra (OpenAI)
- 입력: 텍스트 + 이미지(요청당 최대 1,500장, 32px 패치 × 1.2로 토큰 계산). 비디오 없음. `detail` 기본값 `auto` = `original` → 반드시 명시.
- effort: low / medium / high / xhigh / max. **`none`이 없다.**
- **logprob를 쓸 수 없다**: 공식 가이드상 effort가 `none`이 아니면 logprobs 파라미터를 빼야 한다. → "logprob 기반 선택기" 기준 방법은 GPT-6 Sol/Luna(`none` 지원)나 TypeSafe `system-one-adapter`(말로 적은 확률)로 바꾼다.
- 첫 토큰까지 시간(Artificial Analysis, 2026-09-24 읽음): low 3.0 / medium 5.9 / high 73 / xhigh 198 / max 352초. **날마다 바뀐다**(v2 때 high 45초). → effort 비교는 같은 날 벽시계로 직접 잰다.
- Fast mode: 2배 가격, Astra 속도 배수 미공개, SLA 없음.
- 로봇 결과는 모두 제3자·미심사. 정밀 삽입 2/20.
- **effort에 대한 반대 증거**: AGP(2609.12541, 실물 조립 1과제 5회)에서 effort low/medium/high 모두 5/5 성공, 시간도 비슷. Show-Harness에서도 사고량을 늘려도 성공률은 그대로이고 시간만 늘었다.

## 2. 모듈별 장착 후보 (v3)

> 모듈 설계 원칙 [사용자]: 파이프라인이 아니라, 모듈마다 어디의 어떤 연구가 최고였고 무엇을 가져와 어떻게 접목할지. 로봇 분야일 필요 없음.

### M1. 상태 표현: 이미지 → Jev 입력
- [사용자] AI 전 분야에서 가장 효율적인 방법. 변환 방법은 사용자가 정한다.
- [제안] **원칙: 문법보다 내용.** 입력 길이만으로 13.9~85% 하락(2510.05381, EMNLP 2025 Findings, 인용 163). JSON↔XML 차이 ±3%p(FloorplanQA, ICML 2026). 3D 장면 그래프도 관련 부분만 가져오면 0.33 → 0.77(2510.16643, MIT).
- [제안] 후보 순위 (확정 아님)
  1. ID 기반 객체 목록 + 코드가 계산한 범주 관계 + 참/거짓 술어, 작업 관련 객체만
  2. 작업 지향 장면 부분 그래프(MomaGraph식 공간 + 기능 + 상태)
  3. Astra가 쓴 설명(계획 시점에만)
- [제안] 인식 앞단 후보는 v2 유지(SAM 3/3.1, FoundationPose/Any6D, YOLOE).
- v3 정정
  - BALROG(ICLR 2025, **기간 밖 기초 문헌**): 이미지 추가 효과는 **모델 의존**(GPT-4o·Llama 3.2 하락, Claude 3.5·Gemini 1.5 상승). "텍스트 > 이미지" 일반 근거로 쓰지 않는다.
  - SiT-Bench(ACL 2026 Findings): 이미지와 비교하지 않았다. 좌표 텍스트만으로 공간 추론 평가, 전역 일관성 격차.
  - Robust TAMP(2608.28075): 관계형 상태를 명시하면 VLM이 LLM보다 나은 점이 없었다(8B·32B, LOW).
- [결정 필요] 변환 방법과 인식 앞단.

### M2. Astra → Jev 전달
- [사용자] M1과 같은 문제.
- [제안] Astra 출력 스키마
  - 객체 ID 참조(텍스트판 Set-of-Mark: Astra에는 이미지 위 번호, Jev에는 같은 번호를 텍스트 키로)
  - 완료 조건 술어 + 예상 소요 시간 + 연결할 스킬
  - **Code-as-Monitor식 제약 요소를 코드로** 정의 → 코드가 매 프레임 평가해 Jev에는 술어로(CaM, CVPR 2025, 기간 밖이라 개념 차용, 방해 조건 +28.7%p)
  - 필요하면 Gemini Robotics-ER식 0~1000 정규화 점 JSON
  - Jev에는 작업 관련 부분 그래프만(선택은 계획 때 1번, 이후 코드가 유지)

### M3. 행동 표현 (촘촘한 객관식)
- [사용자] 촘촘하게 가도 된다.
- [제안] **읽기 규칙 (v3 수정)**
  - 방향처럼 순서 없는 보기: 최빈값, 확률은 게이트로만.
  - 크기처럼 순서 있는 보기: **Choice로 이름 붙은 구간을 고른다(최빈 구간)**. Jev 공식 #2(c)가 Score 기댓값 보간을 금지하므로 "확률 가중 평균으로 크기 결정"은 기본안에서 뺀다.
  - LLM 판정 분야에서는 분포 평균이 최빈값보다 나았다(2503.03064, 48조건 중 42, **기간 밖**). "평활 → 봉우리 검사 → 한 봉우리면 주 구간 안 평균"은 비교 실험 조건으로만 둔다(Jev 공식 권장과 충돌하므로 측정 후 결정).
- [제안] 해상도: 차원당 ≤255 보기 1회 호출을 기본. 근거 VLA-0(NVIDIA, 인용 53): 해상도 250 대 1000 차이 1.5점(미세조정 모델). 2단계 줌, 병렬 두 척도 질문은 비교 변수.
- [제안] 단위: 저주파 제어점 객관식 유지. 근거가 BEAST(NeurIPS 2025, binning 대비 토큰 4~8배 적음)로 올라감. M5와 표현 공유.
- [제안] PIVOT의 텍스트판: 코드가 후보 행동과 **예상 결과 술어**를 만들어 보기로 주고, Jev 확률로 분포를 다시 맞춘다.
- [제안] 보정 순서(첫 실험): 측정(ECE, Brier, AUROC, 질문 유형별) → 유형별 온도 조정 → 보기 위치·이름 편향 점검(PriDe, 극성 효과) → KnowNo식 conformal 보기 집합이 여러 개면 Astra 호출.
- 선행 연구: Show-Harness(스텝마다 이산 행동 선택). 차별점은 Jev 확률, M4, M6.

### M4. 연속 동작 1단계: 계단식 겹침 호출 + 자기 검증 ★
- [사용자] 1초에 여러 번 계단식으로 겹쳐 호출, 겹친 구간이 제대로 반영됐는지 스스로 확인하고 업데이트. 가장 중요. RTC 참고.
- [제안] **"제대로 반영됐는지"를 두 가지로 나눈다 (v3 핵심)**
  - (a) **호출 사이 합의**: LocalAgreement(동시통역 표준, 기간 밖 기초 문헌) — 연속 호출이 같은 미래 스텝에서 일치하는 앞부분만 확정. 순서형 보기는 ±1단계면 일치로(Spec-VLA, EMNLP 2025, 완화 수용). 비교는 같은 문구·같은 보기·같은 유형 질문끼리만(Jev #8).
  - (b) **실제 반영 확인**: 확정해 실행한 스텝의 예상 상태와 측정 상태를 코드로 비교 → 범주(맞음 / 조금 모자람 / 어긋남)로 다음 Jev 입력에 넣는다. **(a)만으로는 부족하다**: 같은 모델은 같은 오답을 반복한다(자기 일관 오류, EMNLP 2025).
- [제안] 갱신 규칙 (Speculative Actions, ICLR 2026의 추측 → 검증 → 확정/수리 틀)
  - 합의 + 실제 반영 맞음 → 확정 유지
  - 불합의 + 새 호출 확신 낮음 → 이전 선택 유지(히스테리시스)
  - 불합의 + 새 호출 확신 높음, 또는 실제 반영 어긋남 → 미확정 구간 교체, 필요하면 수리 동작
  - 불일치 크기 → M7/M8 이상 신호
- [제안] 스케줄러: SmolVLA식 큐 임계값(HIGH) + TypeGo식 bounded queue(크기 3) + 조건부 분기 스텝(실행 시점에 코드가 조건 재평가) + 상태 변화가 P90을 연속 2회 넘으면 조기 호출(2609.22587의 규칙만).
- [제안] 병렬 질문은 추가 지연이 거의 없으므로, 겹침 검증 질문을 같은 요청에 함께 넣는다.
- v3 정정
  - VLASH: 원문은 미세조정 증강이 필요하고 "추론 때 미래 상태만 넣는 것은 부족하다"고 했다 → **발상만 빌린다**(효과 미보장). 첫 제출 2025-11-30.
  - A2C2: **ICLR 2026 거절**(OpenReview), 학습형 32M 보정 헤드, 4.7ms(RTX 5080 노트북). LIBERO는 RTC와 비교하지 않았다. → 비학습 기하 보정층의 발상만.
  - Slow Brain Fast Planner: LOW-MED(인용 0, 보행로 주행). 융합층은 학습 없음 확인.
  - 위험: LocalAgreement는 확정 지연을 약 2배로 늘린다. Jev 확률 가중 합의(CISC/DeepConf)는 보정 측정 후에만.
- 컨트리뷰션 문구: "Jev 확률 기반 계단식 겹침 호출 + 외부 기준(측정 상태)으로 겹침 반영을 확인하는 갱신". 선점 없음(v3/01).

### M5. 연속 동작 2단계: 스무딩
- [사용자] 두 단계. 2단계는 스무딩.
- [제안] LiPo식 후처리(겹침 선형 블렌딩 + jerk 최소화, IJCAS 23(11) 2025, 공 던지기 조건당 10회 80→90%) + B-스플라인 제어점(M3 공유). 기준 방법: temporal ensembling, 지수 평활.

### M8. Astra 호출 시점과 다중 프레임
- [사용자] 최소한 실패 판정 때 호출, 연속 프레임, 세 방식(주기 / 정한 순간 / "이때쯤 나왔어야 하는데") 비교, 처음 계획만 정지.
- [제안] **호출 구조**: 트리거 → 문지기(부를지, effort, 입력 토큰 예산) → 호출. 복구 직후 cooldown/commit 창(BRACE, ICML 2026: 재계획 진동 억제).
- [제안] **시간 초과는 코드가 계산**: M2 예상 소요 시간에서 다음 확인 시각을 정한다(self-triggered 개념, 기간 밖 기초 문헌). LLM 자기 판단으로 두지 않는다 — "필요할 때만 계획하라" 프롬프트가 작동하지 않았다(Learning When to Plan), Jev는 시간 비교에 약하다. Sentinel(CoRL 2024)이 경과 시간을 프롬프트에 넣은 선례가 있으나 효과는 측정되지 않았다.
- [제안] 정한 순간의 기본값: 스킬 전이 직전.
- [제안] **다중 프레임 기본값**: 개별 이미지 6~10장. 구성 = 하위 작업 시작 1 + 마지막 정상 1 + 움직임 키프레임 3~5(KITE, ICRA 2026: 균일 선택으로 바꾸면 실패 감지 0.84 → 0.69) + 감지 순간·현재 각 1. 감지 순간·현재는 `high`, 나머지 `low`. 각 이미지에 시각·스킬·단계 텍스트 꼬리표, 센서 술어 동반. 시점별 카메라는 나눠 넣는다. 격자 한 장은 비교 조건(격자 대 개별은 일관된 승자 없음: MIMIC, Grid2Matrix). 비용은 low 10장 ≈ high 격자 1장 ≈ 3,000 토큰.
- [제안] **effort (v3 수정)**: v2의 "복구·주기 호출은 low"를 기본안에서 뺀다. 이유: (1) 사용자가 다른 작업(2026-09-23)에서 "추론 강도를 낮추는 건 옳지 않다, 옳은 추론이 더 빨리 성공한다"고 했다. (2) AGP·Show-Harness에서 effort 차이가 성공률에 거의 영향이 없었다. → effort는 실험 축으로만 두고, 속도는 호출 수·결정 수를 줄여서 얻는다. [결정 필요]
- 실험 설계: **호출 수를 맞춘 비교**(CheckVLA 관행), 주기 간격은 검증 세트로 선택, 적시 재현율(오경보율 고정), 호출 지연 p95, 마감 초과율, 정지 시간. 조건에 "Astra 없음", "이미지 없는 Astra(텍스트 상태만)" 포함.
- 위험: 자주 부르면 나빠질 수 있다(Learning When to Plan, VLingNav, 2609.22587). 대부분의 비교가 학습된 게이트로 이겼다.

### M9. 실패 복구
- [사용자] VLA에서 가장 좋은 실패 복구 방법. 1년 반 이내.
- 사실: 복구 기법끼리 같은 벤치마크에서 직접 비교한 결과는 여전히 없다.
- [제안] 복구 사다리: 스킬 내부 재시도 → Jev 재선택 → 리셋 스킬 → Astra 재계획. 실패를 층으로 나눠 아래에서 먼저 처리하고, 못 고친 것만 구조화된 사건 문맥(종류, 단계, 관련 행동, 증거, 완료 행동 이력)으로 Astra에.
- [제안] 되돌리기를 둘로 나눈다(WebRollback, EACL 2026, 로봇 미적용): (a) 계획 체크포인트 복귀 `rollback_to=<id>`, (b) 리셋 스킬 호출. 이미 성립한 술어는 보존(코드 검사).
- FLARE(CVPR 2026) 정정: retry는 VLA 자체의 강건성 학습이고, 온라인 MLLM은 OOD 실패 때만 학습된 reset 어댑터로 바꾼다. 88/96%는 RoboMimic 두 작업 50개 영상 오프라인 분류. reset 추가 이득 +2~4%p. → **ID(자세 오류)/OOD(환경 파괴) 구분과 조율 규칙만** 가져온다.
- FailSafe: IROS 2026(arXiv 주석, 단일 출처), 미세조정 LLaVA-OV-7B, 22.6%는 "최대". 실패 자동 생성은 평가용 실패 주입에 쓴다.
- AHA: arXiv 2410.00371(2024-10, 기간 밖), 미세조정 VLM. 실패 설명 형식만.

### M10. 경험 축적
- [사용자] API 모델 기반 경험 축적을 제대로.
- [제안] **골격 (v3 수정)**
  1. Evo-Memory의 **ExpRAG**(Google DeepMind, 인용 130): (입력, 출력, 피드백) 저장 + top-k 검색. ALFWorld Claude 3.7에서 AWM 0.49 / ExpRAG 0.74 / ReMem 0.92. → Astra 쪽 기본 골격이자 강한 기준 방법.
  2. ReasoningBank 형식 교훈(ICLR 2026). **라벨은 센서 술어**로.
  3. ACE 정리(ICLR 2026)는 오프라인에서만, 항목 퇴출·개수 상한 추가.
  4. Dynamic Cheatsheet(EACL 2026)는 비교 기준.
- [제안] **Jev 메모리 규칙 (새로)**: 원시 경험·교훈 목록을 Jev에 넣지 않는다. Astra가 계획할 때 교훈을 typed 규칙으로 컴파일하고, 코드가 (스킬, 결정 지점, 술어)가 정확히 맞는 0~2개만 붙인다. 근거: MemCompiler(MSR·칭화 AIR, MED) — 통째 주입이 작은 실행기를 18~62% 떨어뜨림. Jev 확률 차이가 작을 때만 힌트를 붙여 다시 묻기(ExpWeaver 개념, MED-LOW). **둘 다 로봇 미적용, 선행 사례 못 찾음 → 컨트리뷰션 후보.**
- [제안] 라벨 규칙: 센서 술어로 확정한 경험만 Jev 규칙 재료. Astra 판정은 "미검증" 태그로 Astra 참고용만. 근거: 2606.15017에서 ReasoningBank의 LLM 판정 "성공"의 30~60%가 실제 실패. (반대: ReasoningBank는 판정 정확도 영향이 작다고 주장.)
- **반대 증거**: 2606.15017(EMNLP 2026, ServiceNow 외) — 웹, 예산 맞춤 비교에서 메모리 없는 기본 방법(44.78%)이 AWM(39.34), ASI(41.02), ReasoningBank(39.33)보다 높았다. 단 작업끼리 독립인 조건. 로봇에서 같은 물체·스킬 반복은 메모리에 유리할 수 있다(추론).
- v3 정정: ViReSkill LOW로 강등(인용 2, 스타 0). FCGraft(ICML 2026)는 KV cache 필요 → API 불가. MemAct는 RL 학습 필요.
- 평가: 메모리 on/off, 예산 맞춘 기본 방법, 라벨 방식, Jev 힌트 방식 ablation. **3회 이상 평균 ± 표준편차.**
- [결정 필요] Astra 메모리를 top-k 기본 주입 / 필요할 때 조회 / 둘 다 비교. Jev 재질의를 M4와 합칠지.
