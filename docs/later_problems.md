# 나중에 해결해야 하는 문제들

L8S 양산·본 35B 학습 뒤에 남는 문제만 적는다. 양산 전에 하기로 한 일(날개 뗀 상자 C, 새 물체 폐루프 평가 세트 ≥30편, 세운 막대 고리 꽂기 V 등)은 여기 넣지 않는다. 해결하면 줄을 지우고, 결과 문서 링크를 남긴다.
새 데이터나 새 기능은 기존 규칙대로 채택한다. 사전등록한 8B 비교에서 모든 세트가 비열등일 때만 쓴다.

| # | 문제 | 지금 상태 | 해결 방향 | 주의 |
|---|---|---|---|---|
| 1 | **실패 인지·재시도** | 학습 데이터가 성공 편 위주라 회복 장면이 없다. 매 호출 현재 이미지를 보는 암묵적 재시도만 있다 | 시뮬에서 환경이 실패를 주입한다(밀기·그리퍼에서 빼기). 회복 구간만 학습하고 비중은 ≤5% | 실패 구간을 정답으로 넣으면 역효과다. 전환 순간의 모호한 프레임은 버린다 (user-log 187) |
| 2 | **장애물 회피** | 코드가 위에서 접근하고 높이를 유지해 옮기는 것만 한다. 시범2에서 접근 중 충돌 2편 | 실행 단계에서 깊이 점구름과 충돌 고려 경로 계획기(cuRobo 등)를 쓴다. 재학습 불필요 | 모델 쪽 경유점 의도는 새 어휘가 필요해 후순위 |
| 3 | **옆에서 잡기 방향(front_h)** | 어휘가 없다 | 냉장고 문 선반 넣기(B), 누운 막대에 고리 꽂기(H)와 함께 추가 | 준비물: l8x_articulated_tasks.md |
| 4 | **관절 과제 전반**(서랍 열기·문 닫기 등 동작, 미리 연 서랍 넣기 A·낮은 상자 넣기 C 포함) | A: 방 배경에 들어가는 서랍장이 Dresser_318_1 1종뿐이고 fix2가 0/5. C: 관문 6→3→4/10, 키 큰 상자에서 집는 순간 넘어짐. 둘 다 이번 판에서 뺐다(09-29). 새 동작 어휘 없음 | 도달 범위에 맞는 관절 자산을 늘리고 어휘를 확장 | |
| 5 | **AgiBot 같은 물체 여러 개인 행** | 이름·마스크 재검증 통과 41%. 같은 물체가 여러 개인 정상 행도 잃었다 | 개체를 구분하는 grounding(위치 표현 추가 등)으로 되살린다 | 정확도가 우선이다 (user-log 165) |
| 6 | **DROID 손목 카메라 변환** | 3인칭만 있어 폐기(수율 1.7%) | 손목캠 변환기를 새로 만들고 8B 비교 | user-log 185 |
| 7 | **렌더 불가 노드** | 78dc(노드 전체)와 x3 GPU0에서 Vulkan DEVICE_LOST | 드라이버·노드를 점검하거나 렌더 가능 노드를 요청 | 렌더 가능 여부는 시드 2개 시험으로 먼저 확인 |
| 8 | **HF 토큰 교체** | 내려받기가 끝날 때까지 보류 | 내려받기가 끝나면 교체 | |
| 9 | **실제 로봇에서 모은 데이터** | 실측은 공개 RB2 약 4,000행(학습)과 held-out 1,506행(평가 G)뿐이다. 우리 로봇 실측 데이터는 없다 | 우리 로봇 머리캠+깊이캠으로 수집한다. 점·의도 라벨은 같은 변환 경로를 쓰고, 포스트 트레인과 실측 평가에 쓴다 | 캘리브레이션을 기록하고, 이름·마스크 검증을 같게 적용 |

| 11 | **왼팔·머리 링크 관성 자리표시값(1e-6)** | 변경 27에서 오른팔만 ffw_sg2 사양 관성으로 교정. 왼팔·머리는 움직이지 않아 그대로 | 양팔 과제·목 무작위 확대 전에 USD 자체를 사양 관성으로 교정 | 교정 전후 데이터 섞임 주의 |
| 12 | **실패 편 활용** | 실패 편은 빌드에서 빠지고 원인 통계만 남는다 | 실패 원인별 데이터셋을 보존해 회복 데이터(#1)와 판정기 검증에 재사용한다 | 학습 정답으로 직접 쓰지 않는다 |
| 14 | **손가락 링크 관성 1e-6(제조사 MJCF 값)** | 바구니 과제 약 2.6%에서 접촉에 눌려 mimic 제약이 무너지고 손가락 2.2·joint7 0.61 rad 튐. 빈손에서는 정상. 해당 편은 빌드에서 뺌 | 질량·크기로 계산한 그럴듯한 관성으로 올리거나 바구니 잡기·놓기 높이 조정. 사전등록 변경 필요 | 양산 도중에는 바꾸지 않음(데이터 일관성) |
| 13 | **공개 점 데이터 : 우리가 만든 데이터(시뮬) 최적 비율 탐색** | 본 35B는 min(0.75, 반복 2.0× 상한) 규칙(user-log 197). 공개 행 절대량 늘리기(AgiBot 다중 개체 되살리기, DROID 손목캠 등)도 이 항목에서 함께 본다. OPR2 ±10%p(0.49·0.59·0.69, 8B 시드 0) 진행 중 | 비율 스윕(OPR2 결과 포함)과 반복 상한 영향을 함께 본다 | 반복 상한이 1.5×를 넘는 것은 새 조건 |

## 실패한 것 (기록)
다시 시도하기 전에 읽는다. 자세한 근거는 results와 user-log에 있다.
- H·H+C′(하이브리드) → D에 밀려 중단 (user-log 159, final35.md)
- 이미지 격자 오버레이 → 쓰지 않음, 원 표시로 대체
- 3인칭 데이터(RH20T·DROID), 어안 카메라, PixMo → 정확도 위험으로 제외 (user-log 165, 169)
- 첫 번째 b4 생성본: 과노출 93%, 이름 중복 22%, 쟁반 47%로 전부 폐기 (l8s_audit_2026-09-29.md)
- L8S 1차 최종 검수 FAIL: 쥔 채로 넣기 성공, 첫 프레임 가림 27%, 원기둥 머그 (l8s_audit2_2026-09-29.md)
- 날개 연 상자 넣기 C 0/13(낮은 상자로 양산 전 재시도), 냉장고 선반 B 생성 불가 (#3)
- AgiBot TCP 플랜지 점 → 보정 불가라 물체 점으로 전환. v1→v2(다른 개체를 잡음)→v3
- 깊이→xyz 변환기 v2는 시뮬에서 v1보다 나쁨 (limits.md)
