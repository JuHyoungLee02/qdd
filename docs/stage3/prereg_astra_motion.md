## 4. 조건
### 4.1 S-sync (동기, 로봇이 답을 기다림)
- 호출 → 명령 실행(즉시 실행기) → 호출 … 편당 호출 자리 **최대 30**, 시뮬 60 s, 성공·stop·낙하에서 끝(끝나면 3 s 유예 동안 성공 확인). 요청에 최근 명령 6개와 결과(측정 TCP·패드 간격·잘림·막힘·못 미침·불확실 처리) 기록.
- **즉시 실행기**: edit = 명령 기준점(측정과 3 cm 넘게 벌어지면 측정 TCP)에서 delta만큼 8 cm/s 직선 이동(도달 8 mm, 또는 명령점에서 멈춤, 또는 거리/속도 + 2 s 초과) → 집기 동작(닫기 0.6 s, 열기 0.5 s). 닫기 폭 = 과제 대상 지름 − 14 mm(오라클과 같음). 회전은 목표 자세에 누적해 1.5 rad/s로 돈다. IK = `OraclePlanner._ik`(관절 한 걸음 0.04 rad/50 ms, 중력 보정). 안전 상자 x 0.25–0.65, y −0.50–0.10, TCP z 탁자 + 2.5–40 cm(자르면 기록).
### 4.2 S-stream (직렬 흐름, 로봇이 기다리지 않음) — F0 / F1
- 시뮬 시간을 벽시계에 맞춰(실시간) 돌리며 **한 번에 한 호출**: 답이 도착하면(또는 20 s 넘게 안 오면 포기하고 — 그 호출도 과금되어 도착 때 기록) 곧바로 최신 영상으로 다음 요청. 첫 요청부터 **90 s** 또는 **30호출**까지, 성공·stop·낙하에서 끝. 끝날 때 날아가는 답은 기다려 비용만 기록(적용 안 함).
- **F0(새로 묻기)**: 요청 = 지금 관측 + 과제만(이력 없음). 도착한 답의 (유효) 명령을 바로 적용.
- **F1(흐름 고정 diff)**: 요청에 **확정 흐름**(현재 확정 명령, 확정 task_progress, 최근 3 s 움직임·사건, 답 도착 때 예측 상태 — 예측 시간 = 현재 창)을 넣고 **keep**(확정 명령을 한 번 더) 또는 **revise**(새 명령: edit 또는 stop) + **evidence(필수)**로 답한다. revise는 **다음 답이 확인할 때만** 적용(같이 revise, 같은 집기 동작, 이동 방향 35° 안; 나중 답의 명령 적용) — spec §5 두 답 합의. 확인 못 받은 revise는 버린다. 불확실한 revise는 keep으로 본다. 직렬이라 한 번 바꾸는 데 답 두 개가 걸린다(미리 적음).
- **부드러운 실행기(spec §11, 흐름 조건 전부)**: edit의 delta를 **유효 창**(다음 답 예상 도착까지 = 최근 3개 답 나이의 중앙값, 처음 3 s, 1–8 s로 자름) 동안 선형 경사(일정 속도 = 배율 × delta / 창)로 넣고, **배율 = 합의 정도**(직전 적용 명령과 같으면 100 %, 아니면 50 %; F1의 확인된 revise는 100 %), 새 답이 없으면 0.5 s에 걸쳐 0으로 감쇠, **방향이 뒤집힌 답**(직전과 90° 넘게 다름)이면 속도를 0으로 되돌린 뒤 새 경사. 속도 변화는 가속 상한 0.32 m/s², 속도 상한 8 cm/s. 집기 동작이 있는 답은 이동을 빨리(|delta|/8 cm/s, 최소 0.5 s) 한 뒤 바로 집기(같은 집기를 다시 요청해도 미루지 않음; keep은 대기 중 집기를 지우지 않음).
- 5 cm 한도와 직렬 지연 때문에 VLA 없는 흐름 방식은 과제를 90 s 안에 끝내기 어려울 수 있다(참값 모델도 가짜 세계에서 F1은 들기까지만) — 흐름 방식의 주 목적은 지연·나이·일관성·비용 측정이다.
- **개루프 재생(무료)**: 기록된 답을 같은 도착 시각에 (a) 부드러운 실행기 (b) 즉시 실행기(각 답 = 8 cm/s 직선 이동, 이전 이동 대체)로 다시 넣어 같은 시드에서 궤적을 만들고 최대 TCP 속도·jerk(RMS·최대)를 비교한다(모델 호출 없음; 개루프라 성공률은 비교하지 않음). 부드러운 재생은 실시간 실행을 재현해야 한다(자체 점검).
### 4.3 기준(모델 없음, 무료)
- **oracle**(상한): `planner.run_episode` 그대로. **nomodel**(하한): 같은 즉시 실행기로 검출된(= 시뮬 참값, 이상적 검출기) 물체 중심으로만: 중심 위 10 cm → 중심 close → 탁자 + 20 cm → 놓을 곳 위 → 놓을 곳 윗면 + 반높이 + 1 cm open → 10 cm 위. **truth**(인터페이스 상한): 같은 명령 인터페이스를 참값으로 답하는 모델(`truth.py`: 다음 참값 점으로 ≤ 5 cm edit, 도달 때 집기, 놓은 뒤 stop) — 동기 S는 20편, 흐름은 스모크.
### 4.4 정지 영상 소시험: 잡기 상태 판정 (spec §12·§13)
- **스냅샷**(무료, 시뮬 참값으로 코드가 몰아서 만듦): 편 순서 앞 4편(0 mug_tray, 7 mug_marker, 14 bottle_tray, 1 mug_tray) × 3상태 = 12장. pre = 파지점에 벌린 손가락(쥐지 않음), grasped = 닫고 3 cm 들어올림(쥠), **miss** = 파지점을 로봇 쪽(−x)으로 9 cm 옮겨 닫고 3 cm 들어올림(머리 시점에서 손가락이 물체와 겹쳐 보이지만 쥐지 않음). 정답 = 시뮬 `holding(대상)` 실측(의도와 다르면 실측을 따른다).
- **질문**: "오른쪽 그리퍼가 지금 {대상}을 쥐고 있나?" → grasp_state(grasped / not_grasped / uncertain) + evidence_view + evidence + confidence. 고유 감각(패드 간격)은 주지 않는다(영상 능력만).
- **조건(Astra low)**: 시점 {머리만, 머리 + 오른손목, 셋 모두} × 덧그림 켬(각 1회) + **덧그림 절제** {셋 모두 · 덧그림 켬, 셋 모두 · 덧그림 없음(원본 영상)} 각 **2회 반복**(켬 1회는 위와 공유) → 스냅샷당 6호출, 72호출. **Astra high**: 셋 모두 · 덧그림 켬 1회(12호출) — low 대 high 비교를 같은 입력에서. Qwen도 low 조건 전부(무료).
- 지표: 오탐 "잡았다"율(정답 안 쥠인데 grasped), 놓친 잡기율(정답 쥠인데 grasped 아님), miss 상태의 오탐율, uncertain율, 반복 일치율(같은 입력 2회 답이 같음), 무효율, 비용.

## 7. 판정 규칙 (결과 전 고정)
1. **F1 채택 규칙(user-log 83)**: 같은 편들에서 F1의 뒤집힘율(편 합산) ≤ **0.5 × F0의 뒤집힘율** **그리고** F1 성공 편 수 ≥ F0 성공 편 수 → 요청 방식 = F1. 아니면 F0 유지. 편 수 2라 기술적 판정이며 다음 단계 기본값을 정하는 데만 쓴다. F1의 대가(한 번 바꾸는 데 걸린 시간, 호출당 토큰)는 함께 적는다.
2. **S 폐루프**: 판정 없음(기술). Astra low의 성공·파지 + 들기·실패 단계를 truth·nomodel·oracle과 나란히 적는다. Astra low 대 Qwen: 성공·파지 + 들기 차이의 **짝 부트스트랩 95 % 구간**(10,000회, 에피소드 군집, 시드 0) — E-Astra-necessity의 첫 자료(기술). Astra high는 소시험·(예산이 남으면) 동기 S 1편만.
3. **부드러운 반영**: 재생 jerk RMS 중앙값이 부드러운 쪽이 즉시보다 작으면 "급변을 줄임"으로 적는다(기술).
4. **정지 영상**: 머리만 대비 셋 모두의 miss 오탐율, 덧그림 켬/끔의 정답률·반복 일치율 차이를 기술한다(12장이라 판정 없음).
