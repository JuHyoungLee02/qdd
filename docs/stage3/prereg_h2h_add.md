# E-H2H-T 추가 판 — 기본을 줄이지 않고 공개 묶음을 더하면 (무료, 사전 등록)

- **상태: 등록**(학습 전 커밋). 결과는 `docs/stage3/results/h2h.md` '추가 판' 절에 쓴다. 12:53 결정 뒤의 재검증이다(통제자 지시).
- 이미 본 것(P16): 대체 판 결과(e31f1df) — t1t4 대 cp 9/9 SAME, 두 묶음 모두 기본 31 % 대체 시 L8-X OOD 여러 곳 WORSE. 그래서 이 판은 '희석'과 '묶음 자체의 효과'를 가른다.
- 팔:
  - `h2h_base` 재사용(b1 6,521행, 816걸음, 이미 평가됨).
  - `add_t1t4` = h2h_base 6,521행 전부 + 대체 판과 **같은** T1+T4 묶음 2,000행 = 8,521행.
  - `add_cp` = h2h_base 6,521행 전부 + 대체 판과 **같은** C′ 묶음 2,000행 = 8,521행.
  - 빌더 `tools/xemb/h2h_add.py`(대체 판 파일에서 기본 id가 아닌 행 = 묶음 2,000을 그대로 가져옴, 시드 0 섞기).
- **걸음 수: 행 수에 비례해 1,066걸음**(= ⌈8,521 × 2 / 16⌉, 기준 팔과 같은 약 2에폭). 이유: 기본 행 하나가 보이는 횟수를 기준 팔과 같게 두어야 '추가'의 효과만 잰다. 같은 816걸음이면 기본 노출이 23 % 줄어 다시 희석과 섞인다. 나머지 레시피는 L8 그대로(micro 8, accum 2, seed 0, 코사인 길이 = 1,066, 로더 작업자 3).
- 평가·판정: 대체 판과 같은 9세트(옛 DEV·OOD-H, L8-X dev_x·ood_h·ood_hl·ood_d·ood_s·ood_o·ood_t), `xemb.h2h_compare`(E-PT 5.2 규칙). 각 팔 대 h2h_base, 그리고 add_t1t4 대 add_cp.
- 결정에 쓰는 법: 추가 판에서 한 묶음이 기본보다 BETTER이고 다른 쪽이 아니면, 12:53 결정을 재검증 결과로 다시 올린다(user-log 143: 바로 버리지 않고 공정 비교 뒤에만). 둘 다 SAME/WORSE이면 '이 크기의 공개 묶음은 L8-X 학습에 더해도 이득 없음'으로 적는다.
- 한계: 추가 팔은 계산량이 기준보다 31 % 많다(걸음 1,066 대 816). 계산량 효과와 섞일 수 있음을 결과에 적는다.
