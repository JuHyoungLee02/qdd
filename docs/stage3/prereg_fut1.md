## 0. 사용자 원문과 범위

**사용자 원문 (10-01 KST)**
> "LLM을 다른 방식으로 학습시키는게 옳은 방식일 가능성이 높은데 그것까지도 검증해보면 좋음 미래예측 보정도 되면 좋으니까. 이것도 그냥 생각대로 짜지말고 비슷한 연구찾아서 1.5년내에 아이디어 따오기"

**범위 좁힘 (사용자 "그순간 등장하는 미래예측은 좀 어렵긴하겠고", 메인 경유 10-01)**
- 예측 대상은 **지금 보이는 장면과 진행 중인 명령으로 알 수 있는 것**뿐이다.
  - 도착 시점에 내릴 명령(점·높이 의도·그리퍼).
  - 도착 자세(실제로 멈출 TCP).
- 그 순간 새로 나타나는 일(새 물체 등장, 밀림·미끄러짐 같은 예측 못 한 외란)은 예측 대상이 아니다.
  - 학습·평가 행에서 뺀다(§3 창 조건).
  - 운영에서는 지금처럼 **JCR 이상 신호 + 상위 재호출**로 처리한다. 겹침 실행의 오래됨 검사(E-DEP1 §2: 물체 2 cm 이동·쥠 변화 시 버리고 다시 묻기)도 그대로 둔다.

**기존 계획과의 관계 (겹치지 않게, P2 구체화)**
- PLAN_coupling P2와 NOW.md §5에는 이미 두 줄이 있다.
  - "도착 전 다음 명령 학습(도착 예상 표시는 입력)"
  - "실제 도착 자기예측은 보조 과제"
- 무엇을 어떻게 넣을지는 정해져 있지 않았다. E-FUT1은 이 두 줄을 **구체 레시피 후보 4개**로 만들고, P1-5 'A1(최적 체크포인트에서 짧게 이어 학습, 확인용)' 규모로 짝 비교해 고른다.
- 채택된 레시피는 P2(다음 본 학습, 기본 모델부터 섞기)의 '미리 내기 행'과 '도착 자기예측 보조 행'의 정의가 된다.
- 지금 쓰는 상위(본 35B)는 바꾸지 않는다(§1-0e). E-FUT1 결과물은 판단 근거이고, 배치(E-DEP1)에 쓸지는 폐루프(§6) 뒤 사용자가 정한다.

**왜 필요한가 (E-DEP1 1단계 결과)**
- 본 35B ep1: 도착 0.5 s 전 장면까지는 안전하다(SAFE). 1 s부터 흔들리고(GRAY), 2 s에서 의도 정확도가 −10 %p다.
- f35_d는 0 s에서만 SAFE다.
- 점(xy)은 ±1 mm로 안정적이다. 흔들리는 것은 **의도(단계·그리퍼)** 이며, 뒤집힘은 0.5 s 6 %, 1 s 10 %, 2 s 23 %다.
- 그래서 겹침 폭을 1~2 s로 넓히려면, 상위가 도중 장면에서도 '도착했을 때의 의도'를 내도록 배워야 하는지 검증한다.

## 2. 팔 (같은 데이터 양, 같은 걸음 수, 같은 순서, 같은 시작점)

모든 팔은 **같은 기준점**(본 35B 판정 큐의 최적 체크포인트 병합본)에서 새 LoRA(r16, α32, lr 1e-4, 본 레시피)를 1에폭 학습한다.
- 행 8,000 = 재생 4,000 + d1 4,000. 재생은 본 35B 학습 행에서 고정 시드로 뽑은 같은 4,000행이다.
- global batch 24(micro 4 × accum 6, GPU 1장) → 333걸음. 행 순서는 모든 팔이 같다.
- d1 4,000행은 **같은 호출 지점 4,000개**이고, 정답(도착 시점 참값 명령)도 같다. 다른 것은 입력(장면 시점·상태 표시)과 F4의 보조 행뿐이다.

| 팔 | 무엇 | 입력 (Δ > 0 행) | 출력 형식 | 런타임 변경 |
|---|---|---|---|---|
| **F0** 기준 = 본 35B 방식 | 같은 지점을 **정지 장면(Δ 0)으로만** | — | 그대로 | 없음 |
| **F1** 도착 전 다음 명령 (L2) | 같은 지점, Δ ∈ {0, 0.5, 1, 1.5, 2} s 중 하나(가능한 것 중 균등) | 영상·TCP 줄·원·손목 카메라 = **지금**(t−Δ). 진행 중 명령은 역사 칸에 '도착했다고 본' 임시 줄(E-DEP1 런타임과 같음) | 그대로 | 없음(E-DEP1 2단계 러너가 지금 보내는 입력) |
| **F2** 도착 예상 표시 = 상태 굴리기 (L1) | F1과 같은 지점·Δ | 영상 = 지금. **TCP 줄·원·손목 카메라 자세 = 진행 중 명령의 목적지**(도착 예상). 역사 칸은 F1과 같음 | 그대로 | 요청 만들 때 TCP 자리에 목적지를 넣음(어댑터·러너 코드, 상위 형식 불변) |
| **F3** F2 + 남은 시간 (L3) | F2와 같음 | F2 + NOW에 한 줄: "The previous command is still executing: the arm reaches this TCP in about Δ s (the images show the scene now). Answer for the moment it arrives." | 그대로 | **입력에 한 줄 추가**(형식 변경 → 어댑터가 예상 남은 시간을 채움) |
| **F4** F2 + 도착 자기예측 보조 (L4–L6) | d1 몫 중 3,000 = F2 제어 행, 1,000 = 보조 행 | 보조 행: 지금 머리 영상(원 = 지금 TCP) + 진행 중 명령 문장 → **실제로 멈출 TCP의 점(0–1000)과 z**(시뮬 참값: 호출 시점 TCP) | 제어 행 그대로. 보조 행은 학습 전용 | F2와 같음 |

- **Zb**(학습 없음, 기준점 그대로)도 같은 평가를 한다(cur·roll·rt 입력). 그러면 'd1 정지 장면에 익숙해진 효과(F0 − Zb)'와 '학습 없이 상태만 굴린 효과(Zb roll − Zb cur)'를 나눠 볼 수 있다.
- **Z15**(본 35B ep1.5, E-DEP1 2단계 상위)는 1단계 탐색이다. 판정에는 쓰지 않는다.
- 정지 장면(Δ 0) 행은 모든 팔에서 원래 기록된 요청 그대로다(E-DEP1 1단계 재구성 검사 통과 행만).

**어댑터 영향**
- F1: 없음.
- F2·F4: 어댑터가 요청을 만들 때 TCP·원·손목 자세를 진행 중 명령의 목적지로 바꾼다. 상위 출력 형식과 JCR 명령 변환은 그대로다.
- F3: 추가로 예상 남은 시간(= E-DEP1 러너 `_t_left`)을 한 줄로 넣는다.
- 모든 팔에서 JCR 쪽 인터페이스는 바뀌지 않는다.

## 3. 데이터 (CPU, `tools/fut1/fut_rows.py`)

**원천**
- JCR d1(2,000편, SoloWorld mug_tray standard·dr)이다. 머리·손목 원본 프레임 약 0.2 s 간격, 20 Hz 특권 틱, 호출 기록(요청·참값 답·카메라·깊이), 실행 명령(cmds)이 있다.
- 이동 도중 장면이 기록돼 있어 렌더가 필요 없다.

**호출 지점**
- 참값 명령이 붙은 실제 호출이다. 기록 요청 재구성 검사(E-DEP1 1단계와 같은 규칙)를 통과해야 쓴다.

**Δ > 0 행의 창 조건** (예측 가능한 것만, §0)
1. 진행 중 명령이 **그리퍼 유지 이동**(point·edit)이다. 미리 낸 명령(pre)이나 도중 교체(swap)가 아니다. E-DEP1 변경 1(겹침은 유지 이동 중에만)과 같다.
2. [t−Δ, t_call] 안에 스크립트 외란(밀기 등)이 없다. 들고 있는 물체 말고는 10 mm 넘게 움직인 물체가 없고, 쥠 상태도 바뀌지 않는다.
3. t−Δ가 진행 중 명령 발행 뒤 0.3 s 이상이다.

**역사 칸**
- 진행 중 명령 줄을 E-DEP1 러너의 임시 줄('-> reached the target (error 0 mm); TCP now (목적지), pad gap 지금')로 바꾼다. 목적지 = 그 명령의 실행 목적지(cmds `goal_cmd`)다.
- 어댑터의 '; JCR: …' 꼬리는 뺀다(E-DEP1과 같음).

**정답**
- 호출 시점 시뮬 참값 명령이다(d1 `reply.txt`, 참값 계획자 = 특권 상태 함수).
- 평가 문장(assessment·reason)은 L8S 라벨과 같은 틀(`teach_l8.labels`)로 만든다. 근거 문장의 TCP·패드 간격은 요청에 보이는 값이다.
- 런타임 검증기(`pt_schema.validate`)를 통과하지 못한 라벨은 뺀다.

**분할**
- 보류 = E-DEP1 1단계 61편 + sha256('fut1|편') % 10 == 0.
- 평가 = 보류 편에서 해시 순 500 지점 × Δ {0, 0.5, 1, 2, 3}이다. 입력 변형 cur·roll·rt 세 파일은 같은 지점·Δ다.
- 학습 = 나머지 편에서 고정 시드로 4,000 지점을 뽑는다.

**스모크 (10-01 05:15, 12편)**
- 재구성 실패 0, 라벨 무효 0이었다.
- 학습 d1 몫의 Δ > 0 비율은 40 %였다.
- 원 위치는 육안으로 확인했다. Δ 2 cur = 지금 집게, roll = 도착 위치.

**L8S·L9로 넓히기 (P2 준비, 이번 판 밖)**
- L8S는 연속 프레임이 없다. 결정 시점 영상만 있고, 약 4 Hz `frames/`가 9,133편 중 1,389편에만 있다(E-VB1 조사 9f21dd3).
  - 이 1,389편으로 L8S 도중 장면 평가 세트를 만드는 것이 다음 단계다(렌더 없음).
  - 나머지는 기록된 관절 궤적을 5 Hz로 다시 렌더해야 한다. 채택 레시피가 나온 뒤, 렌더 카드 규칙(L9 우선) 안에서 계획한다.
- L9에는 편마다 ≥ 5 Hz 머리·손목 원본 프레임과 명령 발행·도착 시각 기록을 요청한다(P0-10).

## 5. 판정 (`tools/fut1/fut_summary.py`, 결과 전에 고정)
