## 0. 먼저 사실 하나: '단계별 상한'이 아니다
- `stage_cap_calls` = **편 전체 호출 30회 상한**(`run_closed_l8s --stop-calls 30`, `pt_episode.run`: `i > stop_calls`).
  이름의 'stage'는 실험 예산 단계라는 뜻이다. `approach/`·`place/`는 끊긴 시점의 `fail_stage`(Monitor: 잡은 적 없음 → approach, 들었음 → place).
  동작 상한 120 s(`stage_cap_motion`)는 거의 안 걸린다(3편). 상한에 걸린 편의 sim 시간 중앙값 39 s.

## 2. 상한을 늘리면 성공률은? (재실행 없는 추정)
- 방법 1(생존 곡선 외삽): 호출 21–30의 호출당 성공 위험을 30 이후에도 일정하다고 본다.
  - f35d none(216): 31.9 % → **상한 45: ≈32.6 %(+1.4편)**, **상한 60: ≈33.2 %(+2.7편)**.
  - OOD-O58(58): 50.0 % → 45: ≈52 %, 60: ≈55 %(편수 +1.4/+2.8, 표본 1편에서 나온 추정이라 불확실). L8S 보류: 21–30 호출 성공 0 → +0.
  - f35d 세 조건 전체(647): 28.9 % → 45: ≈30.4 %, 60: ≈31.8 %.
- 방법 2(궤적 상한): 정체도 오표적도 아닌 14편이 전부 성공해도 69 → 83/216 = **38.4 %**(상한). 엄격한 수렴 6편만이면 34.7 %.
- 결론: **상한은 주원인이 아니다**. 상한 실패의 58 %는 3번째 호출쯤부터 같은 자리 반복, 61 %는 목표 물체를 잘못 가리킴. 상한을 두 배로 해도 기대 +1–3 %p, 최대 +6.5 %p.

## 3. 고칠 것 (순위)
1. **정체 감지 + 루프 깨기(코드, 재학습 없음)** — 효과 범위 A+C(58 %·39 %), ep0.5의 2주기 루프 포함.
   (a) LoopGuard의 비교 기준을 클립 전 목표 대신 **실제 실행 목표(clip 후)·정착 TCP**로 바꾸고, (b) 연속 동일뿐 아니라
   **2주기(above↔lift) 반복**도 세고, (c) '명령 k=3회 연속 결과 불변(TCP 이동 <10 mm)'이면 같은 명령을 재실행하지 않고
   기록 문장에 "같은 명령, 변화 없음 — 다른 점/의도를 고르시오"를 넣거나(상위 입력 형식 불변, §1-0e 어댑터 문장 칸) 편을 조기 종료해 호출을 아낀다.
   도달 불가(클립·15–30 mm 앞 정지 반복)는 "BLOCKED/도달 한계"로 명확히 알린다.
2. **상위 판단 데이터(다음 본 학습)** — B·D(61 %·28 %). 시뮬 참값으로 라벨한 (i) 닮은꼴·어지럼 속 **정답 물체 가리키기** 어려운 음성,
   (ii) **클립/BLOCKED 뒤 다시 가리키기** 복구 행, (iii) '이미 above 자리 → grasp', '쟁반 위에 들고 있음 → place+open' 진행 판단 행.
   ep0.5가 접근 오표적(중앙 7.8 mm)은 줄였지만 놓기 판단(2주기)이 새로 문제 — 체크포인트 비교 때 따로 볼 것.
3. **상한 올리기는 1·2 뒤, 별도 사전 등록으로만** — 예: 30 → 45(+조기 종료 규칙과 함께). 단독으론 +1–3 %p 기대라 우선순위 낮음.
   도달 허용치 8 mm는 손대지 않는다(≤15 mm 근접 미도달 3.5 %·반복 16건). JCR 근거리 보정은 15–30 mm 앞 정지(접촉·도달 한계)에 의미가 있으나 도달 불가 목표는 못 고친다.
