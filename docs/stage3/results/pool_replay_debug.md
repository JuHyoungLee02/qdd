라벨러 롤아웃 하나를 그대로 재현하면 저장된 행 값과 **소수 여섯째 자리까지 같다**(예 ep2027 k26 33.322995, k17 18.216363; ep2052 k25 2.354491, k12 2.102155). 한 스냅샷 안에서 질문(= 롤아웃)마다 값이 다른 경우(1,200 스냅샷 중 62)도 롤아웃마다 이력이 달라 다른 궤적을 탔기 때문이다.

**고정 선행 실행으로는 못 맞춘다(E3).** 라벨러 롤아웃 하나(prefix → k까지 재실행 → 10 s 분기)로 이력을 "오염"시킨 뒤 네 가지 정규화를 해 보고 재실행이 녹화와 비트 동일한 비율(나쁜 시드 10개 × 오염 2가지 = 20회씩):

| 정규화 | 비트 동일 |
|---|---|
| K0 prefix(지금 라벨러) | 6/20 |
| K1 물체 전부 멀리 옮겨 쌍 끊기 → prefix | 7/20 |
| K2 prefix → DEV 0 P0 완주 → prefix(= warmup) | 11/20 |
| K3 prefix → 앞 풀 시드 완주 → prefix(= 생성기의 이력) | 13/20 |

정상 편 2040·2062는 네 방식 모두 8/8. 오염 24가지(정상 시드 포함) 중 22가지는 네 방식 중 하나 이상에서 비트 동일로 돌아왔다. 어떤 고정 절차도 항상 맞지는 않지만, **맞을 때까지 이력을 바꿔 다시 돌리면 대부분 맞는다** → 수정 방향(5절).

**장면을 다시 만들면 이력 의존이 사라진다(E6).** 오염 → `env.env.sim.reset(soft=False)`(타임라인 stop/play = PhysX 장면 재생성, 0.16 s) → prefix → 재실행. 시드 5개(2052·2037·2095·2027·2073) × 오염 3가지: **같은 시드의 세 번이 모두 서로 비트 동일**. 장면 재생성 없이 한 대조군은 28–34 mm 달랐다. 다만 새 장면의 궤적은 녹화(생성 중간의 장면)와 또 다른 궤적이라 녹화 대비 0.37·0.61·0.47·10.7·39.4 mm였다 → **지금 풀을 맞추는 데는 못 쓰고**, 풀·라벨을 다시 만들 때 "매 편 앞 장면 재생성"으로 가면 이력 문제 자체가 없어진다(6절).

**결론.** 이력은 PhysX 장면 내부에 남는다(자세 쓰기 리셋·prefix로는 안 지워지고 장면 재생성으로 지워짐). 결과가 이산적이라 연속량(접촉 캐시 값)보다 **순서 상태**(접촉 쌍·아일랜드·솔버 배치 순서가 생성·소멸 이력에 따라 달라짐)일 가능성이 크다. PhysX 문서도 결정성을 "새로 만든 장면에 같은 순서로 넣은 액터"에 대해서만 보장한다. 어느 자료구조인지는 Isaac/PhysX API로 볼 수 없어 확인하지 못했다(**가설**). pool.md 2절의 "첫 편 문제"(선행 실행이 이력을 다 지우지 못함)와 같은 현상이 prefix 뒤에도 일부 남아 있던 것이다 — pool.md가 확인한 6가지 이력은 모두 DEV 0 계열이라 이 경우를 못 잡았다.

## 6. 410 무효 행 처리 권고

1. **복원이 비트 동일이 아닌 행이 하나라도 있는 29편을 고친 라벨러로 다시 라벨한다.** 1 mm 초과 20편(2027·2037·2046·2047·2050·2051·2052·2053·2055·2062·2068·2070·2073·2074·2087·2095·2103·2108·2109·2110, 410행)에 더해, 1 mm 이하지만 0이 아닌 행만 있는 9편(2002·2009·2010·2024·2028·2045·2048·2049·2054, 157행, 최대 0.80 mm)도 포함한다. 근거: 2052·2073에서 1 mm 기준을 통과한(0.00003–0.62 mm) 행의 best 집합이 17개 바뀌었다(5절). 1 mm는 복원 위치 기준일 뿐 라벨 동일성을 보장하지 않는다.
   - 방법: `cli_label label`을 이 시드들로 **별도 폴더**(예 `labels_relabel/`; 풀 파일은 입력으로 읽기만)에 돌리고, 전 행 `replay_maxabs == 0`을 확인한 뒤 원래 행을 교체, `finalize --rule plan`·`poolsum`을 다시 돌린다. `cli_label.label_pool`은 `--pool` 아래 `labels/`에 쓰므로 풀 폴더를 가리키는 별도 폴더(심볼릭 링크 등)나 출력 경로 인자가 필요하다(`cli_label.py`는 이번에 안 건드림).
   - 비용: 시연 실측 편당 28–91분(원래 13–18분; 재시도 + 파드 부하) × 29 ≈ 15–40 프로세스-시간, 2 프로세스로 약 8–20시간. 줄이려면 같은 시드에서 직전에 맞았던 이력부터 시도하도록 순서를 바꿀 수 있다(미구현).
   - 재라벨 코드에는 dev의 `near` `≤ 5 cm` 변경이 섞인다. 재실행이 녹화와 비트 동일한지 전 행에서 확인하므로 그 영향은 복원 쪽에서는 걸러지고, 분기 롤아웃에서는 정확히 5 cm일 때만 차이가 난다.
2. 나머지 91편(전 행 `replay_maxabs = 0`)은 그대로 둔다. 대조 2040에서 비트 동일 복원이면 라벨이 57/57 재현됐다.
