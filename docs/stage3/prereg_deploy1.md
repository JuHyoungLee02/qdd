- 작성 2026-10-01 03시경 KST, JCR 테스트 팀. **이 문서 커밋 뒤에 각 단계를 시작한다.** 결과를 본 뒤 문턱·세트·팔을 바꾸면 '변경 n'으로 기록한다. 유료 호출 0. Astra·교사 정책은 쓰지 않는다.
- JCR1 체인(`prereg_jcr1.md`)과 병행한다. 상위는 불변이다(재학습·출력 형식 변경 없음, §1-0e).

## 0. 목적과 판단 기준 (사용자 10-01)

**목적**
- 로봇이 계속 연속적인 값을 내면서도, 상위 LLM의 정확한 공간 능력을 잃지 않는 배치를 찾아 적용한다.
- 방식은 **겹쳐서 계속 돌기**다. A 구간을 보고 계획·이동하고, 움직이는 동안 상위가 다시 개입해 다음을 생각한다. 겹치는 구간이 있어야 한다.
- '생각하는 동안 JCR은 작게만' 제약은 쓰지 않는다.

**판단 기준**
- 겉으로만 연속적이면 안 된다.
- 상위 명령이 오래된 채 JCR만 움직이는 **JCR 단독 구간을 최소화**해, 시스템 전체가 공간을 이해한 하나의 모델처럼 동작해야 한다.
- 동시에 **상위의 공간 정확도와 JCR 단독 성능이 떨어지면 안 된다**(비열등).

**가장 큰 위험**
- 상위는 도착 뒤 정지 장면으로 학습됐다. 움직이는 도중 장면에서는 점·의도 정확도가 떨어질 수 있다.
- 그래서 먼저 학습 없이 잰다(1단계). 그 결과로 '다음 본 학습에 도중 장면 행을 넣을지'의 근거를 낸다.

## 1. 1단계 — 도중 장면 정확도 곡선 (학습·렌더 없음)

**질문**
- 도착 Δ초 전의 도중 장면을 주면 상위의 점 오차·의도 정확도가 얼마나 떨어지는가?
- Δ ∈ {0, 0.5, 1, 2, 3} s다.

**세트**
- 기록된 폐루프 편(참값 명령)의 실제 명령 시점마다 요청을 만든다.
- **글자는 실제 호출과 같게**(역사·지시·호출 번호) 두고, **영상·손끝 줄은 t_call − Δ 시점**(팔이 아직 움직이는 중)의 것으로 바꾼다. 상위가 학습한 형식('도착했다고 보고 다음을 말하기')을 그대로 쓰고 장면만 바꾸는 것이다.
- 출처는 JCR d1(머리·손목 원본 0.2 s, 참값, 호출 기록)과 E-CJ1 OX(10 Hz 합성 프레임, 호출 기록)다.
- 선택 순서는 고정 시드다. 명령 시점당 Δ 5개이고, 목표는 400 명령 시점(Δ가 부족한 짧은 이동은 해당 Δ만 뺀다).

**모델**
- 본 35B 판정 큐의 최적 체크포인트(없으면 ep1)와 f35_d를 쓴다.
- 서빙과 채점은 main35 오프라인 평가와 같은 경로·같은 채점기를 쓴다(`teach_pt.metrics.score`, 라벨 = t_call의 참값 명령).

**지표 (Δ별, Δ = 0과 짝 비교, 부트스트랩 10,000회)**
- action_acc, approach_xy·carry_xy·grasp_z mm(중앙값·90분위), point_px.

**판정 (Δ별)**

| 판정 | 조건 |
|---|---|
| `SAFE@Δ` | action_acc 하락 ≤ 2 %p이고 approach_xy 중앙값 증가 ≤ 2 mm (95 % 구간 상한 기준) |
| `NEEDS_ROWS@Δ` | 하락 > 5 %p 또는 중앙값 증가 > 5 mm (하한 기준) |
| 그 밖 | `GRAY@Δ` |

- 결론 문장: '겹침 가능 최대 Δ*' = SAFE인 가장 큰 Δ.
- Δ* < 1 s이면 다음 본 학습에 도중 장면 행(Δ ∈ {0.5, 1, 2} s, 참값 라벨 = 도착 시점 명령)을 넣자고 제안한다.

**카드**
- 사용자 승인(10-01)으로 **x2 GPU0**을 쓴다. 옛 C1 서버는 사용자가 종료했다. JCR1 학습이 이 카드를 원하면(JCR 체인의 'd1 complete' 사건) 곧바로 비키고, 다음 빈 시간에 답 기록부터 이어서 돈다.
- 7a2a GPU2는 평가 큐 빈 시간에만 쓴다.

**모델 (구체화, 결과 전)**
- 본 35B는 병합본이 남아 있는 최신인 **ep1**(`/data/harvest/out/main35/merged_ep1`)을 쓴다. 판정 큐의 최적 체크포인트가 정해지면 그것으로 반복한다.
- f35_d는 `/data/harvest/out/final35/merged_d`다.

**세트 (구체화)**
- 1판은 JCR d1만 쓴다. E-CJ1 OX는 합성 프레임이라 뺀다.
- 명령 시점 요청은 기록된 pt 요청과 숫자 끝자리 반올림 차이까지 같아야 쓴다(재구성 검사).
- 도구: `tools/deploy/mm_rows.py` → `teach_pt.evaluate`(같은 채점) → `tools/deploy/mm_summary.py`, 체인은 `tools/deploy/mm_chain.sh`다.

## 2. 2단계 — 폐루프 배치 비교 (렌더 필요: 사용자 확인 뒤 x2 GPU1)

**팔 (같은 시드·세트)**

| 팔 | 방식 |
|---|---|
| S0 | 도착 뒤 묻기(기준) |
| S1 | 연속 파이프라인: 답이 오자마자 다음 호출 |
| S2(x) | 남은 이동 시간이 x × 예상 지연일 때 다음 호출. x ∈ {0.5, 1, 1.5}이며, x가 클수록 겹침이 크다 |
| +L | 지연 줄이기 조합: vLLM 접두 캐시 켬, 생각 끔. '명령 먼저 출력'은 상위 출력 형식 변경이라 제외(§1-0e) |

**오래된 명령 대책 (모든 겹침 팔 공통, `harvest/deploy/overlap.py`)**
- 절대 목적지를 쓴다.
- 목적지를 **대상 물체에 붙인다**: 요청 시점의 점 주변 영역을 답 도착 시점의 머리 깊이에서 다시 찾아 중심 이동만큼 옮긴다.
- 답이 도착하면 **오래됨을 검사**한다. 물체가 2 cm 넘게 움직였거나 쥠·그리퍼 상태가 바뀌었으면 버리고 바로 다시 묻는다.
- **RTC식 이어 붙이기**: 새 명령은 현재 명령 TCP·속도에서 이어 가고 멈추지 않는다.

**실행기**
- 먼저 스크립트 실행기(OX, 상위만 떼어 비교), 그다음 JCR1 통과 뒤 JCR이다.
- 상위는 1단계의 최적 체크포인트다.
- 지연은 시뮬 시간에 **측정한 호출 시간 그대로** 적용한다. 요청 시점 장면으로 호출하고, 그동안 시뮬은 멈추며, 답은 t_q + 지연에 적용된다.

**세트**
- SoloWorld mug_tray DEV 0–19 × standard·dr = 팔당 40편이다(E-CJ1과 같음).
- 교란 판: 같은 40편 + P1 밀기다.

**지표**

| 지표 | 정의 |
|---|---|
| 폐루프 성공 | 과제 자체 판정 |
| 판당 대기 시간 | 로봇이 상위 답을 기다리며 명령 없이 멈춘 시간 |
| 동작 연속성 | 편 가운데 멈춤 횟수·총 멈춤 시간(1 cm/s 미만 0.3 s 이상), 속도 튐 |
| **JCR 단독 구간** | 새 상위 답이 필요한데(다음 명령 대상 단계) 최신 답이 오래된 채 실행기만 움직인 시간. 편 대비 비율과 최대 길이. **최소화 목표** |
| 오래된 답 버림 비율 | |
| 편 안 상위 공간 정확도 | 호출마다 점 오차·의도 정확도를 참값과 비교하고, 도중 장면 호출과 정지 장면 호출을 나눠 본다 |
| 연결 손실 | min(PX, OV) − PV 정의(`coupling_program.md` §4)를 배치 방식별로 |

**채택 규칙** (S0 대비 짝 비교) — 아래를 모두 만족하는 팔 중 대기 시간이 가장 작은 것을 채택한다.
1. 성공 비열등: 95 % 하한 ≥ −5 %p.
2. **상위 공간 정확도 비열등**: 편 안 도중 장면 호출의 action_acc 하락 ≤ 2 %p, approach_xy 중앙값 증가 ≤ 2 mm.
3. **JCR 단독 성능 비열등**: JCR 팔에서만 본다. 같은 명령 조건의 OJ(JCR1) 대비 목적지 도달 오차 중앙값 증가 ≤ 2 mm, grip_fallback 증가 ≤ 2편.
4. 판당 대기 시간 ≥ 50 % 감소, 그리고 JCR 단독 구간 비율이 S0 이하.

- 아무 팔도 만족하지 못하면 S0를 유지하고, 1단계 결과와 함께 '도중 장면 행 학습'을 제안한다.

## 변경 1 (2026-10-01 04:50 KST, 2단계 시작 전; 1단계 결과 뒤의 구체화)

**배치** (사용자: "어디서 돌릴지 알아서 최적으로")

  - d1 속도가 361편/h의 85 % 밑으로 떨어지면 레인을 1개로 줄인다.
  - L9가 x2:1을 요청하거나 JCR이 x2:1을 반납하면 한 편 안에 비킨다.

**2단계 1판 범위**
- 팔은 S0, S1, S2x{0.5, 1.0, 1.5} × DEV 0–19 × standard·dr = 200편이다. 교란 판과 +L 조합은 2판으로 미룬다(접두 캐시는 모든 팔에 켜져 있음).
- 실행기는 스크립트(`TruthExec` 규칙 S, 가속 한도로 현재 명령 TCP·속도에서 이어 감) + 어댑터 이어가기다.
- 상위 인터페이스는 학습 형식 그대로(PtEpisode iface d-min)다. E-M35CL의 추가 장치(mem_points·fix_loop)는 빼고 모든 팔에 똑같이 적용한다.

**겹침 규칙**
- 겹침(미리 묻기)은 **그리퍼 유지 이동 중에만** 한다. 진행 중 명령은 학습 형식('-> reached the target (error 0 mm); TCP now (목적지)')으로 역사에 적는다.
- 쥐기·놓기는 결과(패드가 물체에 멈췄나)를 미리 적을 수 없어서, 모든 일정에서 도착·그리퍼 동작 뒤에 묻는다. 근거: 1단계에서 의도가 흔들린 것.

**오래됨 검사 구체화**
- 전제: 진행 중 이동이 reach로 끝났는지, 쥠 상태가 그대로인지.
- 물체 영역: 요청 시점 머리 깊이의 점 영역을 도착 시점 깊이에서 다시 찾는다. **쥐고 있을 때는 손끝 7 cm 안 점(들고 가는 물체)을 뺀다.** 스모크에서 이것 때문에 잘못 버린 경우가 5건 나왔다.

**지표 구체화**
- 'JCR 단독 구간'의 스크립트 판 대응은 **명령 없는 시간**(새 상위 명령 없이 기다리거나 어댑터 이어가기만 하는 시간)의 합과 시뮬 시간 대비 비율로 둔다.
- 편 안 공간 정확도는 xy 오차(목적지 − 참 물체) 중앙값을 도중·정지 호출로 나눠 비교한다. 호출별 의도 정확도는 참값 단계 라벨이 없어 2판에서 한다.

**채택 규칙 (스크립트 판)**
- 성공 95 % 하한 ≥ −5 %p (S0 대비 짝).
- 도중 xy 중앙값 − 정지 xy 중앙값 ≤ 2 mm.
- 명령 없는 시간 ≥ 50 % 감소, 그리고 그 비율이 S0 이하.
- JCR 단독 성능 비열등은 JCR 판에서 본다.

**스모크 (판정 제외, 시드 0 standard)**
- S0는 성공했다(12호출).
- S2x1.0은 호출 한도로 실패했다(30호출, 도중 22, 버림 6).
  - 상위가 쟁반 위에서 'lift'↔'carry'를 되풀이했다. 1단계에서 본 SoloWorld 의도 오판과 같다.
  - 버림 5건은 들고 가는 머그 때문이었고, 위 규칙으로 고쳤다.
