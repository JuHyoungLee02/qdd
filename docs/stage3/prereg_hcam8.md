## 1. 머리 카메라 무작위화 범위 (H1 학습 범위)

| 축 | 지금 L9 (H0) | H1 학습 범위 | 근거 |
|---|---|---|---|
| 카메라 높이 (작업면 위, 광학 중심) | 0.42–0.68 m (목·리프트 결과) | **0.35–0.80 m**: 목 자세 뒤 마운트를 세로로 dz ∈ U[−0.15, +0.15] m 옮기고, 결과가 범위 밖이면 다시 뽑기 | AI Worker 실로봇 머리 1.40 m·탁자 0.85 m → 0.55 m. Unitree G1 D435 머리 약 1.2 m·탁자 0.75 m → 약 0.45 m. Galaxea R1 Pro ZED 머리 약 1.3–1.5 m → 약 0.5–0.7 m. 조사 문서 권장 A "높이 ±15 cm" |

| 팬 | ±30° (목) | 그대로 | — |
| 해상도 | 672×376 | 그대로(렌더 산출물은 프로세스마다 하나). 자르기·크기 증강은 빌드 때 내부값을 함께 고칠 때만(이 실험에서는 하지 않음) | Do You Know(ICRA 2026): 자르기는 가상 카메라 |

- 편 단위 동전: **편의 50 %는 표준 기하(H0 방식), 50 %는 무작위 기하(H1 방식)**. 동전은 `sha256("l9-hcam:<seed>")`로 정한다(같은 시드는 언제나 같은 쪽). 두 쪽이 같은 양산 시간대·같은 정의 층에서 나오므로 장면·과제·동작 판(l9m-2)이 짝으로 맞는다.
- 대상 물체·목적지가 화면 안(가장자리 5 %)에 없으면 목 자세와 함께 기하도 다시 뽑는다(최대 5회, 그 뒤 표준 기하). 다시 뽑은 횟수와 최종 값을 meta에 남긴다.
- **기록**: 실제 렌더에 쓴 값을 편마다 두 곳에 남긴다.
  - `meta.json`의 `head_cam`: 방식(std/rand), 뽑은 값(dz·목표 피치·hfov), 실현값(작업면 위 높이·바닥 위 높이·피치·팬·fx·fy·cx·cy·W·H), 마운트(부모 링크, 위치, 쿼터니언), 다시 뽑은 횟수.
  - 호출마다 `calls/cXXX/cams.json`(지금과 같음: W·H·fx·fy·cx·cy·R·t). 데이터 생성용 프롬프트(prompt_v2.txt)의 머리 카메라 칸도 지금처럼 이 값으로 채워진다.
- 무작위화는 **데이터 생성 매개변수만** 바꾼다. 상위 출력 형식(점 0–1000·높이·그리퍼)은 그대로다.

## 2. `camera:` 줄 (빌드 때 넣는 입력 한 줄)
- 형식(한 줄, 단위 고정):
  `camera: head, 672x376 px, fx 367 fy 367 cx 336 cy 188, 0.49 m above the work surface, pitch 45 deg down, pan -2 deg; source: l9/ffw_sg2`
  - 값은 그 호출의 cams.json과 meta(작업면 높이)에서 코드가 만든다. 소수 자릿수: fx·fy·cx·cy 정수, 높이 0.01 m, 각도 1°.
  - `source:`는 `l8x/ffw_sg2`, `l9/ffw_sg2`, `l9/franka_mast`, 공개 행은 데이터셋 이름.
  - 카메라 값이 없는 공개 머리 행은 `camera: head, unknown`(우리 규칙: 좌표계 없는 공개 데이터는 camera unknown).
- 위치: 요청 글의 이미지 설명 바로 앞, 모든 행 공통. 런타임에서는 camera_info와 로봇 관절로 같은 줄을 자동으로 만든다(다음 본 학습 P2에서 적용, 지금 35B는 그대로).

## 3. 팔 (같은 행 수·같은 걸음, 8B D 줄기 레시피 = E-VIEW8 A0와 같음)
- 공통 바탕: E-VIEW8 A0 학습 파일(L8-X b2 D d-min 78,745행 + 공개 머리 37,490행 = 116,235행), 같은 G 제외 규칙.
- L9 몫: 양산에서 **같은 정의·팔(좌·우) 층으로 짝을 맞춘** 성공 편 2,000편씩(표준 기하 쪽 2,000 / 무작위 기하 쪽 2,000). 편 → 행은 L8S와 같은 빌드(`teach_l8d/build.py` → `teach_pt/min_format` d-min). 정의·팔 층마다 두 쪽 편 수를 같게 자른다(많은 쪽에서 시드 순으로 앞에서부터).

| 팔 | L9 편 | `camera:` 줄 | 비고 |
|---|---|---|---|
| H0 | 표준 기하 2,000편 | 없음 | 지금 방식 |
| H1 | 무작위 기하 2,000편 | **모든 행에** 있음 | 권장 A |
| H2 | H1과 같은 2,000편 | 없음 | 줄 효과 분리 |

- 걸음 = round(1,632 × 전체 행 / 78,745)(E-VIEW8 공식). 세 팔의 전체 행 수 차이가 1 % 넘으면, 많은 쪽을 시드 순으로 잘라 맞춘다(답 보기 전).
- 레시피: Qwen3-VL-8B LoRA r16 α32, lr 1e-4 코사인, 미세 배치 8 × 누적 2, 마지막 체크포인트로 평가. **시드 0–3**(`--seed`만 다름) → 12회 학습.
- 빌드 명세(파일 경로·sha256·행 수·G 제외 수)는 학습 전에 이 문서 변경 기록에 적는다.

## 5. 판정 (결과 전 고정)
- 지표: 상태별 접근 3D 오차(mm). 세트별 **중앙값**과 **20 mm 초과 실패율**. 짝 = (시드, 상태). 네 시드를 합쳐 짝 부트스트랩 10,000회(난수 시드 0).
- **A/A 여유 먼저**: H0 시드 쌍(0 대 1, 2 대 3)으로 세트마다 같은 통계의 차를 구해 95 % 구간 폭의 절반을 `aa_med`(mm)·`aa_fail`(%p)로 적는다. H1 비교를 보기 전에 계산해 기록한다.
- **이득(H1 대 H0, (ii) 전체 600편)**: (중앙값 H1 ≤ 0.90 × 중앙값 H0) **그리고** (실패율 차 95 % 상한 < 0). (ii-a)·(ii-b)는 따로도 보고한다.
- **비열등((i) 세트마다, (iii))**: 중앙값 차 95 % 상한 ≤ max(+1 mm, aa_med), 실패율 차 95 % 상한 ≤ max(+2 %p, aa_fail). (iii)은 픽셀 중앙값 차 상한 ≤ max(+3 px, A/A 폭).
- **결과**: ADOPT = 이득 + 비열등 전부. SAME = 비열등이지만 이득 없음(채택 안 함). REJECT = 비열등 하나라도 어김.
- **줄의 몫(H1 대 H2)**: 같은 규칙으로 (ii) 이득·(i)(iii) 비열등을 본다. H1이 ADOPT이고 H1 대 H2도 이득이면 `camera:` 줄과 무작위화를 함께 채택한다. H1 대 H2가 이득이 아니고 H2 대 H0가 ADOPT 조건을 만족하면 무작위화만 채택한다(줄 없이).
- **버리기 전 재검토(1회)**: SAME·REJECT이면 시드 6개로 늘리고, 범위를 좁혀(높이 0.40–0.70 m, 피치 35–58°, 화각 70–90°) H1을 다시 한 번 돌린다. 등록 변경으로 적는다.
- 8B 결과이므로 채택돼도 다음 본 학습(35B)에서 다시 확인한다고 적는다.

## 6. 데이터 생성·실행
- **양산 쪽**: L9 생성기에 로봇 프로필 층(`harvest/l9/robot9.py`)과 머리 카메라 무작위화(`harvest/l9/hcam9.py`)를 넣은 새 코드 사본(`/data/harvest/code_l9r_<커밋>`)으로 먼저 시범 관문을 돈다(G1 수율 기준 = 정의별 10편 ≥ 50 %이고 표준 쪽 대비 무작위 쪽 수율 차 ≥ −5 %p, 관절 걸음 ≤ 0.04 rad, 프레임 직접 검수). 통과 뒤 **L9 주인과 맞춰** 양산 교체(편 사이 정지, 새 편부터). 무작위 쪽 편은 meta `head_cam.mode`로 거를 수 있어, REJECT이면 본 빌드에서 빼고 양산은 표준으로 돌린다(지운 것은 없음).

## 변경 기록

- **변경 1 (2026-10-01 23시대 KST, 데이터 생성·학습 전)**: `camera:` 줄의 높이는 '작업면 위'가 아니라 **'바닥 위'(로봇 좌표 z = 0)**로 한다.
  - 이유: d-min 요청은 탁자 높이를 일부러 주지 않는다("The table height is not given", E-STRIP8). 작업면 위 높이를 적으면 탁자 높이가 새어 나가고, 런타임의 로봇은 작업면 높이를 모른다(camera_info + 관절로 아는 것은 바닥·기저 기준 높이뿐).
  - 형식: `camera: head, 672x376 px, fx 367 fy 367 cx 336 cy 188, 1.34 m above the floor, pitch 45 deg down, pan -2 deg; source: l9/ffw_sg2` (`harvest/l9/hcam9.line`).
  - 위치: d-min 요청의 `CAMERAS (directions are unit vectors in the robot frame)` 머리줄 바로 다음, `- Image 1:` 줄 앞.
  - 무작위화 범위(작업면 위 0.35–0.80 m 등)는 데이터 생성 기준이라 그대로 둔다.
