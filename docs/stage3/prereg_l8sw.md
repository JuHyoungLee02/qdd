# E-L8SW — L8S 양 25 · 50 · 100 % (8B, 시드 0, 무료, 사전 등록)

- 작성: OPR2 에이전트, 2026-09-30 KST (UTC 시각은 커밋 시각). 근거는 user-log 202(통제자 경유)다. **데이터 빌드·학습 전에** 커밋한다. 결과는 `docs/stage3/results/l8sw.md`에 적는다.
- **질문**: L8S를 더 넣을수록 좋아지는가? 새 물체(OOD-O58), G, 사실적 장면(L8S 보류분)에서 기울기를 보고, 본 학습의 L8S 비중을 정하는 데 쓴다.
- 유료 0원이다. 코드 고정 사본은 `/data/harvest/code_l8sw_<이 커밋>`, 산출물은 `/data/harvest/out/l8sw/`, 로그는 `/data/harvest/logs/l8sw/`에 둔다.
- E-OPR3(prereg_opr3.md)은 첫 체크포인트(100걸음)에서 멈춰 둔다. E-L8SW가 끝나면 같은 감시 체인이 그 상태에서 이어 간다.

## 1. 데이터
- **L8S 100 % 기준 편 = E-C35 층화 추출 1,000편**이다(`tools/final35/c35_prep.py strat 1000`, 과제 종류 층 + 고리 3 %, 층 안에서는 가구별로 돌아가며 sha256("c35s|<시드>") 순).
  - 매니페스트는 `/data/harvest/out/c35/man/{main,ring}_{train,val}.json`(01:18 KST 9/30 생성)을 **그대로 복사해 고정**한다(`/data/harvest/out/l8sw/man/`).
  - 1,000편을 고른 이유: 지금 모든 층을 채울 수 있는 최대치에 가깝다. 1,500편은 ov_into 250/318이라 모자란다. 이 판은 E-C35 학습 편과 같은 편이다.
- **보류분**: E-C35 검증 분할과 같다(sha256("c35|<시드>") % 100 < 3, `*_val.json`). 학습 편은 `*_train.json`이다.
- **부분집합(층화 유지, 포개짐)**: 층(과제 종류, 고리)마다 매니페스트 순서(= 층화 추출 순서)의 앞 round(f × 층 편 수)편을 쓴다. f = 0.25 / 0.5 / 1.0이다. 25 % ⊂ 50 % ⊂ 100 %.
- **학습 행**: 100 % 학습 편을 `tools/teach_l8d/build.py <root> … train pt --manifest`(main·ring 따로) → `convert_min.py d-min`으로 한 번 만든다(E-C35와 같은 경로). 25·50 %는 그 d-min 행을 편으로 걸러 만든다. 행 id의 `<과제>_s<시드>_c`로 편을 찾는다(걸러진 편 수를 기록한다).
- **공개 점**: 채택 풀 = `/data/harvest/out/poolv/train_adopted.jsonl`의 공개 행(`aux_kind` = `open_*`)을 id별 한 번씩 쓴다. 풀 32,365행, **반복 없음**이다. 모든 판에서 같다.
- **넣지 않는 것**: 옛 L8-X(b1–b3, b2 D 기본), L8S-drawer(b3d; 이 비교는 L8S 양만 바꾼다), AgiBot·RB2 추가분(채택 풀에 든 것 말고는 없음).
- 판 파일 = L8S d-min 행 + 공개 32,365행을 시드 [8, f×100]으로 섞은 것이다. `xemb.gsplit check`를 통과해야 한다. 실제 편 수·행 수·L8S 몫은 빌드 기록(`train.counts.json`)과 결과에 적는다.

## 2. 학습
- Qwen3-VL-8B-Instruct LoRA r16 α32, lr 1e-4 코사인 warmup 20, bf16, 비전 동결, 미세 배치 8 × 누적 2, 시드 0으로 E-OPRATIO8·E-OPR2와 같다. `--save-every 100`(재개용)을 쓴다.
- **걸음 = 에폭 기준 규칙**: 모든 판이 같은 에폭 몫을 돈다. round(1,632 × 행 수 / 78,745)이고, 이는 0.332 에폭(행 수 / 16 × 0.332)이다. E-OPRATIO8 이후 8B 비교의 공통 규칙이다. 따라서 L8S가 많은 판일수록 걸음(계산량)도 많다. 결과를 읽을 때 이 점을 적는다.

## 3. 평가
- L8-X 7세트(`dist8/data_x/x_*_d-min_clean.jsonl`), **새 물체 58편**(`/data/harvest/out/c35/data/x_ood_o58_d-min_clean.jsonl`, 448상태), **L8S 보류분**(`x_val_l8s_d-min_clean`: E-C35와 같은 방식, `build_min.py` d-min clean), G(`opratio/g_eval.jsonl` 1,577행)를 쓴다. vLLM 한 장으로 돌린다.

## 4. 판정 (결과 전 고정)
- 규칙은 ni_judge(user-log 186)다. 시드가 하나라 **A/A 여유는 기존 8B 시드 쌍(E-OPRATIO8 p0·p75의 시드 0/1)에서 빌려 쓴다**.
  - L8-X 7세트: `ni_judge.py aa`를 이 두 쌍으로 돌린다.
  - 새 세트는 그 쌍으로 평가된 적이 없어 가까운 세트의 여유를 빌린다. OOD-O58 ← OOD-O, L8S 보류 ← dev_x.
  - G는 E-POOLV8 방식이고 같은 두 쌍을 쓴다.
- 비교: 100 대 25, 100 대 50, 50 대 25(각 X 대 Y, X = 큰 판).
- 세트별 '나아짐' 기준:
  - L8 계열 세트: 실패율 차 상한 < 0이거나, 중앙값 차 상한 < −여유.
  - G: 전체 적중 차 하한 > 0. G 하위 세트도 같은 식으로 보고한다.
- 결론 규칙:
  - **'더 넣을수록 좋다'**: 100이 25보다 핵심 세트(OOD-O58, G 전체, L8S 보류) 가운데 하나 이상에서 나아지고, 모든 세트에서 비열등.
  - **'포화'**: 50이 25보다 나아지고, 100 대 50에서 핵심 세트가 나아지지 않음.
  - **'효과 없음'**: 핵심 세트에서 나아진 것이 없음.
  - **'해로움'**: 100이 25보다 어느 세트에서 나쁨.
  - 세트별 중앙값·실패율·G 적중을 판별로 표에 싣는다(기울기).
- 시드가 하나라 결과는 방향 신호로 적는다. 본 학습 L8S 비중은 통제·사용자가 정한다.

- 끝 표지는 `/data/harvest/logs/l8sw/l8sw.log`의 `L8SW_DONE`, `/data/harvest/logs/opr2/opr3.log`의 `STAGE3_DONE`이다.
