  - (정정, 00 §16) 첫 세션 초안의 "기존 방법들을 기본으로 사용"은 Claude의 풀어 쓰기였고 사용자 문장이 아니다.

  - 계획 시점(정지 허용): Astra가 **세션 계약**(단계 원장, 스킬 + stop 술어, 결정 지점 질문, critic 규칙, 금지 술어)을 쓴다. M10 규칙을 받는다.
  - 실행(비정지): 카메라 → 인식 → M1 변환(방법은 사용자 결정) → 텍스트 상태 → **Jev 약 3Hz 계단식 겹침 호출**(M3·M4·M6) → bounded 큐 → (a) 호출 사이 합의 + (b) 측정 상태 확인 → 확정 → 스킬/제어기 100Hz+ + M5 스무딩.

### 핵심 기여 두 개 [제안]
- **계층은 새로움이 아니다(v3.1, 정본 §24, D12)**: JEV-Star(2609.27331, 2026-09-23)가 "combining fast JEV action selection with persistent GPT-6 planning"을 StarCraft II에서 먼저 했다(GPT-6 Astra medium effort, 게임은 요청 중에도 진행, "A failed or delayed planning request leaves the previous valid plan available.", 계획기는 60 게임초 주기 + 사건 호출, JEV 요청은 초당 1회 제한). **반드시 인용**하고 "빠른 typed 선택 + 느린 Astra 비동기 계획"을 새로움으로 쓰지 않는다. 우리 차이는 "로봇 실행 중 **실패 판정이 불러내는** Astra 호출 + 겹침 호출 합의와 실행 뒤 확인(M4 (a)+(b))"으로만 쓴다. 이 구조는 원래 아래 기여 목록에 없으므로 기여 두 개는 그대로 선다(D12 결론). 사용자 원칙("실패할 때마다 Astra 개입")은 그대로.
1. **M4 확정 규칙**: 겹쳐 부른 Jev 호출들을 **같은 미래 결정 스텝에 대한 표**로 보고, (a) 호출 사이 typed 합의와 (b) 이미 실행한 스텝의 코드 예상 상태(M5 `ref(t)` + M3 `expected_after`) 대 측정 상태가 **둘 다** 맞을 때만 확정하고, 어긋나면 그 전제에 기댄 표를 무효화(전제 epoch)한다. 확정/유지/교체/수리를 이 규칙 하나가 고른다.
   - 선행으로 **인정하는 것**: 비정지와 겹쳐 보내기 자체. Slow Brain, Fast Planner(2606.20458)는 블랙박스 VLM에 고정 주기(기본 1 Hz)로 여러 요청을 띄우고(in-flight 상한은 원문에 없음), **요청 시각 기준 가장 새 응답 하나**를 빠른 플래너 점수와 감쇠 융합한다(로봇 무정지). 응답 사이 일관성 검사·다수결과 실행 뒤 확인은 없다(D9 원문 정독). Jev-as-Policy 등 Jev 데모는 요청 하나 + 직전 행동 유지로 비정지다(코드 확인). jev-realtime-sdk README는 "at most one decision is in flight at a time"로 겹침 호출을 설계상 금지한다(D7).

## 1. 사용자 의도 (줄이지 않은 원문 뜻)

`user-log.md`의 발언을 뜻 그대로 옮겼다(음성 입력이라 원문 오타는 user-log가 이미 정리함). 설계가 반드시 지켜야 할 줄은 **굵게**.

### 1.1 대주제와 계층 (user-log 3·4·5·6)
- 요즘 GPT Astra(GPT-6 Astra)로 로봇을 명령 제어하는 프로젝트가 많다.
- **물체를 보고 스킬을 생성해서 잡는 방법들이 많지만 실패할 때가 있다. 실패할 때마다 Astra가 개입해서 진행하는 방식을 원한다.**
  - (00 §16) 이 문장은 문제 설정이다. "기존 방법들을 기본으로 사용"은 user-log에 없다(첫 세션 초안의 풀어 쓰기). M6에서 생성형 (b)를 먼저 구현한다는 판단은 이 원문 뜻에 대한 **Claude의 해석**이다.
- 논문으로 제출할 계획이다. 컨트리뷰션은 아직 없고 점차 잡아간다.
- 사용자가 명령을 내리면 Astra가 명령을 잘게 쪼개 어떻게 실행할지 미리 계획한다. 계획에 맞는 스킬들을 불러와서 Astra가 진행한다.
- **진행 확인: 프레임별로 확인해서 Astra의 계획대로 되고 있는지 판별한다.**
- Astra의 문제는 API라서 시간이 너무 오래 걸린다는 것이다. Jev(TypeSafe AI, 새로 나옴)는 객관식 문제를 엄청 잘 푼다.
- Astra로 조정하는 방식이 VLA보다 생각보다 성능이 잘 나오지만, 결국 이미지를 보고 엔드포인트로 움직이는 방식에 그친다. Jev를 쓰면 엔드포인트를 어디로 얼마만큼 움직일지에 대한 순간적인 판단이 몇십 배 빠르다.
- **예전 VLA에서 상위에 큰 LLM, 하위에 작은 VLM을 둔 것처럼, 상위에 Astra, 하위에 Jev를 둔다.**

### 1.2 모듈별 방향 지시 (user-log 10·11)
- 큰 틀 사이사이를 효율적으로 연결하는 부분, 즉 컨트리뷰션 거리가 부족하니 논의할 거리를 정리한다.
- (1) 이미지→텍스트: **Jev는 이미지를 못 본다. LLM/VLM/VLA 논문뿐 아니라 텍스트와 이미지를 제대로 변환하는 다른 분야 연구에서 가장 효율적인 방법을 찾는다.** (CLAUDE.md 제약 절·plan 63행: 바꾸는 방법은 아직 정해지지 않았으므로 **사용자가 정하기 전에는 임의로 정하지 않는다**. 이 줄은 user-log에는 아직 없다.)
- (2) Astra→Jev 전달: 1번과 거의 같은 문제다. Astra는 이미지를 보고 명령하지만 Jev는 아니니, 효율적으로 전달하는 방법을 더 생각한다.
- (3) 행동: **촘촘하게 가도 된다. Jev 방식이면 충분히 가능하고 할 만하다고 본다.**
- RTC 적용:
  - **1초에 Jev를 한 번이 아니라 3번 정도 계단식으로 겹쳐 쓴다.**
  - **겹치는 부분의 움직임이 제대로 반영됐는지 스스로 감지하고 업데이트하는 시스템이 자동으로 있어야 한다. 이게 굉장히 중요하다.**
  - Jev가 빠르다지만 로봇 동작에서는 빠르지 않으니, 연속 동작처럼 내뱉게 하는 법을 RTC에서 많이 참고한다.
- **두 단계: 먼저 RTC와 유사한 방법, 다음으로 액션 스무딩이나 VLA에서 쓰는 부드럽게 하는 방법으로 아주 작은 움직임을 처리한다.**
- 스킬:
  - **기존 스킬도 Jev와 엄청 연관될수록 좋다.**
  - 1년 이내에 나온 GitHub 스타 상위 5개 중에서, **LLM이 스킬을 불러오고 끝이 아니라 잘게 엮어 놓은 논문**을 참고해 파이프라인을 대충 짜 본다.
- (5) 진행 판별:
  - VLA에서 "계획대로"를 무엇으로 정의했는지 많이 참고한다. VLA는 로봇을 학술적으로 조종하는 개념 공부를 많이 해 놓았다.
  - **하지만 VLA의 엄청난 단점은 다른 환경에 가면 일반화가 안 된다는 것이다. LLM은 일반화가 된다. 이걸 엄청 부각하고 항상 기억한다.**
- (6) Astra 호출:
  - **적어도 실패 판정이 났을 때는 Astra를 부른다. 그 순간 한 장이 아니라 연속 프레임을 준다. 예: 이미지 하나에 사진 10개.**
  - **호출 방식은 비교 평가한다: Hz 단위 주기 / 정해 둔 필요한 순간마다 / "이때쯤 결과가 나왔어야 하는데 안 나오네"라는 자체 판단.**
  - VLA에서 실패했을 때 어떻게 되돌아갈지 정하는 프레임워크를 참고한다.
- (7) 복구: **VLA에서 가장 좋은 실패 복구 방법을 찾는다. 논문은 무조건 1년 반 이내.**
- 정지: **Astra가 처음 생각할 때는 멈추는 게 맞지만, 그 이후는 웬만하면 멈추지 않는다. 실패로 생각해야 하는 경우만 어쩔 수 없다.**
- (9) 경험 축적: **경험 축적이 제대로 되어야 한다.** API로 불러오는 모델의 경험 축적을 어떻게 하는지, 어떻게 해야 효율적인지 논문을 찾는다. 1년 반 이내.
- (10) 평가 비교 대상: **Astra만 / Jev만 / VLA / 룰베이스(스킬 다발) / LLM+스킬을 연결한 기존 논문 / Astra를 쓰는 기존 논문.**
- (11) **안전은 크게 다루지 않는다.**
- 완벽한 계획을 제대로 짜고 모두 기억한다. 계획 초안을 Overleaf에 올린다. 사용자가 말한 내용이 사용자가 의도해서 적은 글로 보여야 한다.

### 1.3 조사·설계 원칙 (user-log 12~15, 20)
- 초안 조사는 약 3시간 동안 엄청 꼼꼼하게 한다. 틀린 건 없는지, 정말 최고 성능인지, 저자 블로그까지 뒤진다.
- **"마차를 이어서는 기차를 만들 수 없다." 처음이 틀어지면 아무리 고쳐도 좋은 게 안 나온다.**
- **끊임없이 스스로를 의심하되, 과한 의심으로 할루시네이션을 일으키지 않는다.**
- 초안 작성 버전도 MD로 다 기록한다(이때는 이렇게 했었다). 같은 실수를 반복하지 않기 위해서다.
- 상세 설계는 초안이 끝나면 간다. 최소 6시간, 최대 24시간. **파이프라인을 짜기보다 각 부분에 어떤 모듈을 장착하면 좋을지에 집중한다. 파이프라인은 생각은 하되 깊게는 하지 않는다.** 꼭 MD로 기억해 둔다. 시간은 정확히 맞출 필요는 없지만 ±1~2시간 안이어야 한다.
- **모듈 설계는 파이프라인 설계가 아니다. 각 부분마다 어디의 어떤 연구가 그 부분에서 최고였는지, 무엇을 가져올 수 있는지, 우리 것에 어떻게 접목할지를 최대한 모으는 과정이다. 모듈 단위로만 최고이면 된다. 로봇이나 VLA 분야일 필요가 없다. LLM, VLM 자체의 방법 중 아직 로봇에 적용되지 않은 것도 찾는다.**
- **신뢰도 낮은 논문과 깃 저장소는 최대한 쓰지 않는다. 쓰느니만 못하다.** 신뢰도가 무조건 있어야 하고, 스타도 어느 정도 있어야 하고, 논문도 좋아요(반응)를 많이 받은 것이어야 한다.
- **정답이 로봇 분야에서만 나온다고 생각하지 않는다.** LLM/VLM 분야의 방법이 로봇에 오기까지 시간이 걸리니, LLM, VLM, 로봇, VLA 전방위로 보고 최고의 모듈을 만드는 데 집중한다.
- **자료는 무조건 1년 반 이내. 단, 아주 큰 주제를 포괄하는 기초적인 것은 1년 반이 아니어도 된다.** 어쨌든 매우 꼼꼼한 조사가 필요하다. (LLM+스킬 결합 논문은 1년 이내, GitHub 스타 상위 기준.)
- 이제부터 사용자 허락 없이 자동으로 계속 진행한다(결정이 필요한 항목은 [결정 필요]로 기록하고 멈추지 않는다).

### 1.4 다른 작업에서 온 사용자 발언 (이 프로젝트 user-log에는 없음)
- 사용자가 **다른 작업**(2026-09-23)에서 한 말: "추론 강도를 낮추는 건 옳지 않다. 옳은 추론을 하면 더 빨리 성공한다." (출처: Claude 메모리, CLAUDE.md 모델 제약 절 85행. 이 프로젝트 user-log에는 없다.)
- 그래서 이 프로젝트의 **[사용자] 원칙이 아니다.** 모든 문서는 "**잠정 기본 high(다른 작업 발언 근거) — 이 프로젝트 적용은 [결정 필요] D5**"로 적는다(00 §16). 결정 전까지 설계는 이 잠정 기본을 쓴다: effort 기본 high, 실험 축은 low~max 전부 후보, low·medium은 측정 조건일 뿐 기본값 후보가 아니다. 속도는 effort가 아니라 호출 수·결정 수로 줄이고, 비용을 줄여야 하면 표본을 줄인다.

### 1.5 작업 방식 (user-log 1·2·7·9·16~24, 설계 내용과 무관하지만 지킨다)
- 저장소 이름 qdd → harvest 변경은 사용자가 직접 한다. 저장소의 논문 PDF는 모두 지운다.
- **모든 작업(글 작성, 코드 수정 포함)은 `dev`에서 시작하고 `dev`에만 푸시한다. `main`은 절대 건드리지 않는다.** 사용자가 확인한 뒤 직접 `main`에 반영한다. 푸시해 달라고 하면 `dev`에 자동으로 푸시한다.
- 대화 중 주의사항·제약은 반드시 MD 파일로 남기고, 자율로 맡겼을 때 계속 참고하고 어기지 않는다.
- Overleaf(`paper/main.tex`): 한국어, **논문이 아니라 마인드맵 초안**, 부분 부분만 채운다, "이 부분에선 이렇게 생각했다 / 이 방향으로 가려고 한다", 예쁠 필요 없다. 그때그때 최신 생각으로 갱신한다. **사용자가 의도하고 말한 것은 빨간색, 나머지는 검정색.** 빨간 줄은 요약하거나 줄이지 않는다. 양식은 **CVPR이 준비해 둔 공식 Overleaf 양식을 그대로** 쓴다(ICRA라고 했다가 CVPR로 정정).
- 모든 명령과 정보가 Git에 있어서, 저장소만 알려주면 새 세션이 100% 바로 이어서 진행할 수 있어야 한다.
- 사용자에게 하는 답은 한국어로 한다.

## 2. 모듈별 설계

각 모듈: 역할/입출력 → 설계(1순위·대안) → 빌려 온 연구(분야, 학회, 기간, **원문** 대 **[접목]**) → 핵심 파라미터(§3.10 설정 표) → 비교 실험 id → 반대 증거 → [결정 필요].

### M1. 이미지 → Jev 입력 (상태 표현)
- **[사용자]** (user-log 11 (1)) Jev는 이미지를 못 본다. LLM/VLM/VLA 논문뿐 아니라 텍스트와 이미지를 제대로 변환하는 다른 분야 연구에서 가장 효율적인 방법을 찾는다.
- **[사용자 — CLAUDE.md '연구 주제에서 확인된 제약'(첫 세션부터), user-log에는 원문 없음]** **변환 방법은 사용자가 정한다** → 이 모듈은 최종안을 고르지 않는다. 임시 기본값도 두지 않는다(00 §11.3).
- **역할/입출력**: 카메라(+깊이) → 인식 앞단 → **M1 직렬화기(코드)** → (1) Jev `state` 텍스트(관련 부분 전체 + 변화 절 + 시각 `t_state`), (2) 모든 술어의 참/거짓 표(M4(b)·M7·M9가 읽음), (3) Astra용 번호 표시(Set-of-Mark) 이미지. 불변 규칙: Jev에 숫자 계산을 시키지 않는다(범주·참거짓), 관련 없는 내용 넣지 않는다, 영어, 평평한 상태, 버전 고정.
- **모든 모듈이 의존하는 것 = 술어 등록부(M1 §4.0)**: 하나뿐인 술어 사전. 등급 T1(코드 기하·고유 감각, 결정적: `on`, `inside`, `above`, 방향 6종, `near`(≤5 cm 들어감/6 cm 나감), `in_contact`, `touch`, `holding`, `gripper_open`, `lifted`(`h_lift` 3 cm), `upright`/`tilt_ok`(`tilt_max` 30°), `contact_under`) / T2(코드지만 임계 민감: `aligned_*`, `at_pregrasp`, `reachable`(코드 IK), `clear`, `top_clear`, `path_clear`, `graspable`, `fits_in`, `contact_stable`, `collision_risk`, `next_entry_ok`) / T3(VLM·Astra 필요: `open`, `lid_on`, `empty`, `material`, 기능 간선). 값은 true/false/unknown. 수치 인자는 이름에 넣지 않는다(문턱은 설정 표 — `h_lift`·`tilt_max`는 정본 §7). 새 술어는 오프라인 경로로만. (ViPlan에서 VLM의 reachable·nextto가 90% 미만이지만 우리 `reachable`은 코드 IK라 T2다.)
- **후보(근거 수 순위일 뿐, 결정 아님)**:
  - **A. ID 술어 표 + 변화 절**: `objects`(관련 ID만) / `robot` / `facts` / `changes`(최근 3 s, 최대 8개) / `stage`. 추정 150~350 토큰(관련 물체 3~6개).
  - **B. 작업 부분 그래프**: 부품 노드·기능 간선 추가, 계약 `relevant_ids`에서 1홉. 토큰 A의 1.2~1.5배(추정).
  - **C. A + 영역 캡션 `attrs` + Astra 서술 `astra_note`**(Astra 호출 때만, 기준 시각 붙임).
  - 대조 조건(E3에만): A-full, N-num(숫자 좌표), D-only(변화 절만), V-free(코드 술어 없이 VLM 자유 서술 — 다른 모듈 전제를 깨므로 오프라인 비교만), A-QPR(줄 순서만 질문 앵커 PageRank).
- **공통 층**: 인식 앞단 SAM 3.1 → 깊이(Fast-FoundationStereo 또는 센서) → 3D 중심·크기 → 필요한 물체만 FoundationPose(기간 밖). 술어 계산기(코드, 히스테리시스 띠). 지연 목표 A/B 합계 p50 ≤ 70 ms / p95 ≤ 120 ms(3Hz 주기 333 ms의 1/3, 측정 전 목표값). p95를 넘기면 직전 상태 + `t_state`를 그대로 보낸다.

- **[사용자]** M1과 거의 같은 문제로 본다. Astra는 이미지를 보고 명령하지만 Jev는 이미지를 못 보므로, Astra가 본 것과 원하는 것을 Jev에게 효율적으로 전달하는 방법을 더 생각한다.

### M3. 행동 표현
- **[사용자]** 촘촘하게 가도 된다. Jev 방식이면 충분히 가능하고 할 만하다. (계층 발언: Jev는 "엔드포인트를 어디로 얼마만큼"의 순간 판단이 몇십 배 빠르다.)
- **역할/입출력**: Jev의 typed 선택을 로봇이 실행할 목표·설정값으로 바꾸는 약속. Jev는 숫자를 만들지 않는다. 입력 = M1 상태, M2 계약, 코드가 만든 후보와 후보별 **예상 결과 술어**. 출력 = M4로 `DecisionStep`(`ds_id`, `t_state`, `variant`, `questions[{question_id, dp_id, options, chosen, p_chosen, p_second}]`, `perm_id`, `target`(코드), `expected_after`, `commit_window`(M4가 채움), `escalate`), M4·M7로 `expected_after`, M5로 목표 자세(코드).
- **공통 뼈대**: 한 `JevCall` = 결정 질문 H개 + 감시 질문(§3.1). 보기 = 짧은 영어 식별자 + 예상 결과 술어. 순서형 보기도 **최빈 보기만**(확률 가중·Score 보간 금지). 모든 질문에 `NONE_ESCALATE` — 최빈이면 그 스텝은 보류 = **정지가 아니라 직전 확정 행동 유지 + 감속**. 한 질문 보기는 서로 뚜렷한 것 ≤ 약 17개.
- **`expected_after`는 등록부 술어 이름만 쓴다**(D5 1-13). 예: `after: above(gripper,o3.handle)=yes, collision_risk(A3)=no, reachable(o3)=yes, near(gripper,o3)=yes` / `after: aligned_x(gripper,target)=yes, in_contact(gripper,target)=no`. ### M4. 연속 동작 1단계: 계단식 겹침 호출 + 자기 확인·갱신 ★
- **[사용자]** 1초에 Jev를 한 번이 아니라 3번 정도 계단식으로 겹쳐 쓴다. **겹치는 부분의 움직임이 제대로 반영됐는지 스스로 감지하고 업데이트하는 시스템이 자동으로 있어야 한다. 이게 굉장히 중요하다.** Jev가 빠르다지만 로봇 동작에서는 빠르지 않으니, 연속 동작처럼 내뱉게 하는 법을 RTC에서 많이 참고한다.
- **역할/입출력**: 입력 = M3 `DecisionStep`, 측정 상태(매 제어 주기), Jev 지연 기록, **M5 `ref(t)`**. 출력 = 확정 스텝 열(스킬로), 가확정 열(M5가 미리 봄), 스텝별 `commit_window`(= `d_p95`), 스텝별 (b) 범주 → 다음 Jev 입력 한 줄(`last_step: LAG`), **M7로 신호만**, 조기 호출 요청. 하지 않는 것: Jev에 예상 상태·수치 묻기, 확률 가중 평균, **FAIL 판정·정지·M9 호출**.
- **설계(1순위)**: 표 원장 + 전제 epoch.
  - 자료 구조: `Vote{ds_id, question_id, choice, p_chosen, call_id, sent_at, recv_at, t_state, premise_epoch}`, `Slot{zone ∈ FROZEN/MID/FRESH, status ∈ OPEN/TENTATIVE/CONTESTED/COMMITTED/EXECUTING/VERIFIED/FAILED, incumbent, challenger, defer_left, votes, expected_after, outcome}`, `Ledger{slots, epoch, d_hat, flip_score}`.
  - **(a) 합의 [잠정 기본, [결정 필요] D4 승인 전]**: 전제가 살아 있는 표끼리 LocalAgreement-2(최근 두 표 같음) 또는 표 ≥3이고 최빈 비율 ≥ γ(0.67)이면 확정. 스텝 열 **앞에서부터만** 확정, 확정은 불변. 순서형 보기는 τ칸 이내면 일치(접촉 근처 τ=0). 도전 선택은 FLy식 **유예 창 W**를 통과해야 교체(경계 직후 W=2·γ=1.0, 멀수록 W=1·γ=0.67). (b)≠OK면 유예 없이 교체. 확률 게이트 θ는 E1 뒤에만. 표 폐기 나이 STALE_MAX 1.5 s(정본 §7).
  - **(b) 결과 확인**: 스텝 실행 뒤 (1) `ref(t)` 대비 연속 잔차와 (2) `expected_after` 술어 성립을 **따로** 계산, 성공 실행으로 split conformal 보정한 경계 + 짧은 창(w=5 제어 주기) + 느린 표류는 CUSUM → **OK / LAG / DEVIATE / CONTRADICT**.
  - 고리: DEVIATE·CONTRADICT → epoch +1, 이전 epoch 미확정 표 폐기(Raft term처럼), 조기 호출, 범주를 다음 Jev 입력에. LAG → 선택 유지, 뒤 스텝 시각만 미룸. CONTRADICT → 직전 확정 행동 유지 + 감속(정지 아님).
  - **M7로 가는 신호**: CONTRADICT → 모순 술어가 **T1일 때만 하드 채널(H4)**, T2·`unknown`이면 `C_m4` / DEVIATE(3스텝 연속) → `C_m4` / `flip_score` → `C_flip`. `C_m4`·`C_flip`은 둘 다 M4 출처라 **E-M7 전 기본은 동시 발동을 1표로 센다**(D4 C-11, M7 §4.2 채택, E-M7 D4f로 확정). **[잠정 기본] `flip_score` = 같은 스텝에 쌓인 표 분포와 직전 창 표 분포 사이 거리(총변동 거리 등)**, 임계 FLIP_TH = 성공 실행 flip_score의 1−α 분위(근거 Sentinel/STAC CoRL 2024 절제 그림 5, 기간 밖 → [결정 필요] D4 승인 전 잠정. 불허 시 "한 답 대 한 답" 뒤집힘 비율로, E0.5가 두 식을 같이 잰다). flip 급증 중에는 새 확정 중단.
  - 확정 못 한 스텝이 고정 구간에 들어가면 가확정을 그대로 실행(비정지), "unconfirmed-executed"로 기록하고 (b) 문턱을 한 단계 엄격하게.

### M5. 연속 동작 2단계: 스무딩
- **[사용자]** 연속 동작은 두 단계. 먼저 RTC와 유사한 방법(M4), 다음으로 **액션 스무딩이나 VLA에서 쓰는 부드럽게 하는 방법으로 아주 작은 움직임을 처리한다.** (00 §16: 정본 §1·§9 C3의 스무딩 문구도 이 원문대로 읽는다.)
- **역할/입출력**: M4 확정 이산 결정 열 → 제어기가 따라갈 매끄러운 설정값(100Hz+). 전부 코드. **`ref(t)` 공개**(M4(b)·M7이 읽음). 블렌딩 가중치는 시간 기반(확률 기반 아님). 교체·확정 규칙은 M4에만. M5는 스스로 정지하지 않는다.
- **설계(1순위, 3층)**:
  - **L1 결정 층**: 규칙은 M4 한 곳(첫 판의 "연속 2표"는 M4 W=2로 흡수). M5 책임은 시간 정렬(`t_state` 기준으로 목표 재정렬)뿐. 확정 길이 = `d_p95`(읽기만). 보수적 분위수 근거(v3.2): WAM "지연 과소 추정 = 되돌릴 수 없는 위치 점프, 과대 = 경미".
  - **L2 기준 궤적 층(기본 유지)**: 같은 보기면 겹침 구간 [t0, t0+T_b]에서 **RTC 식 5 시간판** 가중으로 이어 붙임: w = 1 (t < t0 + T_f), w = c(e^c − 1)/(e − 1), c = (t0 + T_b − t)/(T_b − T_f) (t0 + T_f ≤ t < t0 + T_b), 그 뒤 0. T_b 0.3 s, T_f 0([가정]) — 정본 §7·§25. (v3.2) 옛 exp(−(t−t0)/τ_b), τ_b 0.1 s는 T_b 끝에 e^−3 ≈ 0.050이 남아 약 5% 계단(우리 계산) → τ_b 삭제. 비교 조건 **S4-epoch**(기본 아님): M4 `premise_epoch` 교체 직후·M4 (b) 불일치 WARN 중에는 같은 보기라도 블렌딩 안 함. **다른 보기면 평균하지 않는다.** **[잠정 기본, [결정 필요] D4] 모드 전환 관성화(규칙 2b)**: 전환 순간 Δx·Δv를 한 번 계산하고 5차 다항식 오프셋으로 T_i(0.3 s, 정본 §7) 안에 0으로 감쇠, **오프셋은 `ref(t)`에 포함**, **near/contact에서는 끔**, 자동 트리거(|Δx| < ε_x이고 |Δv| < ε_v면 L3만). 접촉 구간은 블렌딩 끔, 최소 저크 5차 단일 구간. `NONE_ESCALATE`·보류 = 직전 확정 목표 유지 + 속도 상한 낮춤. 관성화 불허 시 = 모드 전환을 L3만으로(S4−i).
  - **L3 실행 층**: **잠정 기본 Ruckig**(RSS 2021, 기간 밖 기초 문헌, [결정 필요] D4 승인 전. 1순위는 관절 공간([가정], v3.2: FluxVLA 원문은 관절 분리만 평가, 직교 공간은 원문 평가 없음). 불허 시 대체 = 관절 MPC(FluxVLA, 기간 안, 조건 S5) 또는 최소 저크 5차 다항식). 초기 한계 자유 이동 v 0.25 m/s·a 1.0 m/s²·j 10 m/s³ / 접촉 v 0.05·a 0.3·j 3. 궤적 모양: G/H는 최소 저크 5차, D는 확정 스텝 목표의 3차 B-스플라인 재적합.
- **대안**: L1 + L3만(L2 없음) — 비교 조건 S3로만. (v3.2, 정본 §25) WAM은 이 대안의 지지 근거에서 뺐다(사후 블렌딩은 끼우기 40 → 37.5뿐, 컨베이어 20 → 40, 전자레인지 44 → 80, 저자 결론 "workable floor" — 혼재). Ruckig도 액션 스무딩 범주라 사용자 문장 안에 든다(00 §16). L2를 기본으로 둔 이유는 사용자가 VLA 방법을 함께 들었고 RTC가 가장 강한 근거이기 때문이다. 기본값 변경은 [결정 필요](00 §9 C3).

### M6. 스킬과 Jev 결합
- **[사용자]** 기존 스킬도 Jev와 엄청 연관될수록 좋다. LLM이 스킬을 불러오고 끝이 아니라 잘게 엮는다. 1년 이내 GitHub 스타 상위 5개 논문을 참고해 파이프라인을 대충 짜 본다. (문제 설정, user-log 3 원문: "물체를 보고 스킬을 생성해서 잡는 방법들이 많지만 실패할 때가 있다. 실패할 때마다 Astra가 개입해서 진행하는 방식을 원한다.")
- **"잘게 엮기"의 뜻 [제안]**: 스킬 **안의 단계 경계와 결정 지점마다** Jev가 typed 선택을 하고, 스킬은 그 선택을 인자로 받아 짧게 실행한 뒤 결과 술어를 돌려준다. "스킬 하나 부르고 끝날 때까지"(거침)와 "스텝마다 증분 이동"(Show-Harness, 스킬 없음)의 사이.
- **스타 상위(v3/06, 2026-09-23 측정)**: PhyAgentOS 2,481 / Zetta 1,252 / Harness VLA 962 / CaP-X 819(ICML 2026) / ROSClaw 625(저장소 연결 추정) 또는 Show-Harness 451 → 5위 [결정 필요 D8b].
- **1순위: 스킬 계약(HarvestSkill) + 단계 FSM + 단계별 결정 지점**
  - 형식: Agent Skills 폴더(`SKILL.md`, 점진 공개) + `contract.json`(MCP inputSchema/outputSchema 모양). 입력은 **enum(보기 ID)만**, 코드 표가 수치로 바꿈. 필드: `entry`, `exit`, `invariants`(phase별), `phases`, `decision_points`(**스킬 고정 id = 정본**), `stop`, `budget`, `default_on_timeout = hold_last_committed_slow`(정지 아님), `reentry`, `lookahead_req`(E-M6-2가 3%p 이상 기여할 때만 필수), `annotations`, **[잠정 기본, [결정 필요] D4] `effect`**(phase마다 `{kind: reversible, compensate: <스킬 id>}` 또는 `{kind: irreversible}`, 정본이며 `irreversible_phases`는 파생. 예: grasp·lift는 가역(보상 스킬 있음), release는 비가역. 사가·SagaLLM에 기대므로 불허 시 기간 안 근거는 Atomix(무학회)만 남음. `effect`는 표지이고 코드 안전 술어가 최종, 물리 보상은 원상 복구가 아니므로 보상 뒤 재개 phase의 `entry`를 반드시 다시 확인), `outputSchema`(`result` + `exit_predicates`).

### M7. 진행 판별 ("계획대로인가"와 실패 판정)
- **[사용자]** 프레임별로 확인해서 Astra의 계획대로 되고 있는지 판별한다. VLA에서 "계획대로"를 무엇으로 정의했는지 많이 참고한다(VLA는 로봇을 학술적으로 조종하는 개념 공부를 많이 해 놓았다). **하지만 VLA는 다른 환경에 가면 일반화가 안 되고 LLM은 된다 — 이걸 엄청 부각하고 항상 기억한다.**
- **역할/입출력**: **실패 판정은 코드 critic 한 곳에서만.** 입력(매 critic 틱 10Hz, Jev 채널은 약 3Hz): S1 단계 원장(`exit_k`, `entry_k`, `invariants_k`, `T_exp_k`(= M2 계약 단계 k의 `T_exp_s`), `forbidden`, 등급 붙은 등록부 술어) / S2 진행 대리값 `g(t)`(코드 기하) / S3 경과 시간 / S4 M4 신호 / S5 Jev 진행 범주 / S6 스킬 오류 코드 / S7 `expected_after`·`ref(t)` / S8 M2 가정 술어·`contract_patch_rejected` 사건 / 고유 감각. 출력 `{OK, WARN, FAIL}` + 사건 문맥. FAIL → M8(문지기 우회)과 M9가 동시에 시작. **FAIL 없이 M9가 시작되거나 로봇이 완전 정지하는 경로는 없다.**
- **"계획대로"의 정의 [제안]**: 불변(`invariants_k` 모두 참) AND 순서(완료 술어가 원장 순서대로 참이 되어 왔고 되돌아가지 않음) AND 분포 안(경과 시간이 conformal 마감 `D_k` 안, 정체 규칙에 안 걸림).
- **1순위: 2층 critic**
  - **하드 층(즉시 FAIL, 투표 없음) H1~H6**: H1 T1 불변 위반 연속 2틱(0.2 s) / H2 스킬 오류 코드(IK 실패, 충돌 정지, 타임아웃) / H3 다음 스킬 시작 시 T1 `entry_k` 거짓 / H4 M4 CONTRADICT(모순 술어 T1) / H5 M2 `forbidden` `enforce: fail`(T1만) / **H6 단계 경과 > 2 × `D_k`**(D5 1-3 해소, 00 §11.2). 술어를 쓰는 H1·H3·H4·H5는 **T1 술어만**, H2·H6은 술어가 아니라 결정적 코드 신호(오류 코드, 시계). H6을 하드 층에 두는 이유: 경과 시간은 시계로 재는 결정적 양이고, `D_k` 보정의 임계 민감도는 2배 여유로 흡수하며, 규칙을 지우면 한 채널만 계속 뜰 때 FAIL이 영영 안 나서 "실패할 때마다 Astra"가 막힌다. `D_k`가 대체값(1.5×`T_exp_k`)일 때도 같다.
  - **소프트 층(서로 다른 채널 2개 이상 동시 → FAIL, 1개 → WARN, 예외 없음)**: `C_stag`(Δg < ε_k가 N=10틱 연속 또는 최고 g를 δ=5% 넘게 M=20틱 못 갱신, FaRe식) / `C_dead`(경과 > `D_k`, α_ep = 0.1, 표본 n < 20이면 1.5 × `T_exp_k`) / `C_jev`(최빈 `failure` 2번 연속) / `C_m4`(DEVIATE 3스텝 연속, 또는 CONTRADICT의 모순 술어가 T2) / `C_flip` / `C_assume`(가정 0.5 s 연속 거짓(`unknown`은 거짓으로 세지 않음) **또는 M2 `contract_patch_rejected` 사건**(00 §15), 동시에 M8 재호출 신호) / `C_pred`(T2 위반 0.5 s 연속, T2 `entry` 거짓, `unknown` 1.0 s 초과 — 정본 §11.2 채택). 옛 "`C_dead` > 2 × `D_k`면 단독 FAIL" 예외는 H6으로 옮겨 소프트 층에는 예외가 없다.
  - **(v3, 정본 §21) `C_stag`와 Critic in the Loop**: 원문 정체 규칙(진행값 최고점 엄격 미갱신, N_stag = 180 @ ~20 Hz ≈ 9 s — "~9 s"는 우리 계산)은 우리 (b)("최고 g를 M틱 못 갱신")와 같은 모양이고 우리 문턱이 약 4.5배 짧다. **복구·재계획 뒤 `C_stag` 최고점·카운터 초기화**(원문 따름, 채택). 원문은 정체 단독으로 선점·리셋·상위 호출(동기)이고, 우리는 `C_stag` 단독이면 WARN, M8 T_stag가 그 WARN으로 Astra를 비동기로 부른다("정체 단독 FAIL·리셋"은 다름).
  - **같은 출처 채널 계수**: E-M7 전 기본값은 `C_m4`·`C_flip`(둘 다 M4 출처) 동시 발동을 **1표**로 센다(D4 C-11). E-M7 D4f 결과(동시 발동 비율)로 확정.
  - 허용 게이트: 잡기·놓기 전환 중 소프트 판정 보류, 최대 1.0 s. 복구 뒤 cooldown 2 s(소프트 FAIL 금지, 하드는 유지). Astra·Jev의 "잘 되고 있다"는 OK 근거로 쓰지 않는다. WARN만으로는 복구를 시작하지 않는다(M8 호출 모드와 문지기의 입력).
  - `PROGRESS_OPTIONS` = `valid_progress` / `allowed_change` / `failure` / `recovering` + `NONE_ESCALATE`(M6 `dp.grasp_result`와 한 목록). 이정표 질문도 코드 술어로 못 쓰는 이정표만, 호출당 감시 질문 1개로, 보기는 이 목록(옛 네 보기 체크리스트형 {완료, 진행 중, 시작 안 됨, 되돌아감}은 E-M7 대안 조건으로만).
  - **[잠정] 원장 편차 구분(새 채널 아님)**: 프로세스 마이닝 정렬 적합성으로 "건너뜀"(모델만 이동 → 뒤 단계 `entry` 검사: T1이면 H3, T2면 `C_pred`)과 "계획 밖 사건"(로그만 이동 → T1이면 H1, 아니면 `C_pred`)을 기록, **마지막 일치 위치**를 매 틱 M9에 넘김. `C_order` 채널은 E-M7 D4o 결과로만.
  - 계약 버전 교체: M4 `premise_epoch` +1, M7은 다음 틱부터 새 계약의 `exit_k`/`entry_k`/`invariants_k`로 바꾸고, 교체 직후 첫 틱의 H3은 새 `entry_k`로 검사. `C_stag`·`C_dead` 단계 시계는 단계 id가 같으면 이어서 셈.

### M8. Astra 호출 시점과 다중 프레임
- **[사용자]** 적어도 실패 판정이 났을 때는 Astra를 부른다. 그 순간 한 장이 아니라 연속 프레임을 준다(예: 이미지 하나에 사진 10개). 호출 방식은 비교 평가한다: Hz 단위 주기 / 정해 둔 필요한 순간마다 / "이때쯤 결과가 나왔어야 하는데 안 나오네"라는 자체 판단. VLA에서 실패했을 때 어떻게 되돌아갈지 정하는 프레임워크를 참고(→ M9). Astra가 처음 생각할 때는 멈추는 게 맞지만, 그 이후는 웬만하면 멈추지 않는다(실패로 생각해야 하는 경우만 어쩔 수 없다).
- [다른 작업 발언, CLAUDE.md 경유 — 이 프로젝트 적용은 [결정 필요] D5] Astra effort를 낮추는 것을 기본안으로 쓰지 않는다. 속도는 호출 수·결정 수로 줄인다.
- **역할/입출력**: 트리거 → 문지기 → 호출. 입력 = M7 상태·사건 문맥, 원장 `T_exp_k`, 경과 시간, 프레임 버퍼(최근 약 10 s, 카메라별), 진행 중 요청 수, 최근 호출 시각. 출력 = Astra 요청(목적, 이미지 묶음, 텍스트 문맥, effort, 최대 출력 토큰). **호출 때문에 로봇이 멈추는 것은 초기 계획(T0)뿐이다. 그 밖의 호출은 모두 비동기이고, 그 밖의 정지는 M9 L3 안전 대기 하나뿐이다. 새 계획 적용도 정지를 만들지 않는다**(00 §4·§16).
- **트리거**: T0 초기 계획(정지 허용, 문지기 없음) / **T_fail**(M7 FAIL, **항상 호출**, 문지기는 묶음만 결정) / T1 주기(P는 호출 수 맞춤으로) / T2 정해 둔 순간(기본: 되돌릴 수 없는 전이 직전) / **T3a** 코드 마감(경과 > `D_k` → WARN(`C_dead`) → 호출) / **T3b** 모델 판단(Jev Noul "should this step have been completed by now?"를 `JevCall` 감시 질문으로, 경과는 코드가 범주로 줌, 최빈 "예" 2번 연속이면 호출; 변형 T3b-A는 Astra) / T_stag 정체 시간 초과. T3a(예상 시간 마감, 계획 쪽)와 T_stag(진행이 멈춘 시간, 관측 쪽)를 구분한다. 사용자 문장은 T3b에 문자 그대로 가깝고 T3a는 우리 해석 → 둘 다 조건.
- **문지기(BRACE 접목)**: 비실패 진행 중 요청 1개(실패 호출은 예외로 새로 보냄), 복구 뒤 cooldown 2 s, **commit 창 = M2 R3 하나를 따른다**(결정 스텝 경계에서 적용, 진행 중 phase의 M6 `effect`가 `irreversible`이면 그 phase가 끝난 뒤. 첫 판의 "잡기 닫힘~들어올림 시작" 구간은 M6 `effect`에서 가역(grasp·lift 모두 보상 스킬 있음)이라 따로 두지 않고, 그리퍼가 닫히는 순간은 grasp/release 전환 보류 1.0 s가 보호한다. 기다리는 동안에도 직전 확정 행동 유지 + 감속이며 정지가 아니다), **effort는 문지기가 낮추지 않는다**(잠정 기본 high(다른 작업 발언 근거) — 이 프로젝트 적용은 [결정 필요] D5. low·medium은 측정 조건일 뿐 기본값 후보가 아니고, 실험 축은 low~max 전부 후보), 입력 예산 이미지 약 3,000~3,600 + 텍스트 ≤ 2,000 토큰. 지연 예산(2026-09-23 Artificial Analysis 기준 첫 토큰): low 3.0 / medium 5.9 / high 73 / xhigh 198 / max 352초(우리가 잰 값 아님) — 날마다 바뀌므로 같은 날 잰다.

### M9. 실패 복구
- **[사용자]** VLA에서 가장 좋은 실패 복구 방법을 찾는다. 논문은 무조건 1년 반 이내. VLA에서 실패했을 때 어떻게 되돌아갈지 정하는 프레임워크를 참고. 실패할 때마다 Astra가 개입. Astra가 처음 생각할 때는 멈추는 게 맞지만, 그 이후는 웬만하면 멈추지 않는다(실패로 생각해야 하는 경우만 어쩔 수 없다).
- **사실**: 2026-09 기준 로봇 복구 기법끼리 같은 벤치마크 직접 비교는 없다 → "최고"는 수치로 못 정한다.
- **역할/입출력**: **M7 FAIL로만 시작**(M4 CONTRADICT도 M7을 거쳐 FAIL이 된 뒤에만). 입력 = 사건 문맥, 원장·체크포인트, 현재 술어 표, 스킬 라이브러리, 이전 시도. 출력 = 계속 / 스킬 재시도(변경) / 체크포인트 k 재개 / 리셋 스킬 / 안전 대기 + Astra 도착 후 새 계획. 결정자: 언제 = M7, 어디로 후보 = 코드, 아래 층 선택 = Jev, 최종 = Astra.
- **1순위: 비동기 Astra + 아래 층 사다리(시간표)**
  - t0 FAIL: 새 단계 전이·되돌릴 수 없는 동작(놓기, 삽입 시작) **잠금**, 진행 중 동작은 허용 게이트(최대 1.0 s).
  - t0 + ≤0.1 s: M8 T_fail(격자 프레임 + 사건 문맥). 로봇은 계속 움직임.
  - t0 + ≤0.2 s: 코드가 ID/OOD 판정(ID = 사건이 계약 `expected_failures`에 있고 가정 술어 모두 참), 재개 가능 체크포인트 목록.
  - L1(ID이고 실행 어긋남일 때): 같은 스킬을 파라미터 바꿔 1회 재시도(직전 파라미터 제외). OOD면 건너뜀. 원문 사례(정본 §22, Harness/RPent): 빈 집기 → 재위치·re-stage, full prompt 금지, 한 레버만 변경.
  - **(v3, 정본 §22) 3분류 대응**: Harness 부록 A의 매 프리미티브 뒤 {progress, recoverable failure, unrecoverable failure} ↔ M7 정상 / WARN·FAIL / 복구 불가(L3).
  - **L2: Jev Choice = `dp.critic_accept`**(M6 고정 결정 지점 id). 보기 = 코드가 만든 **M9 복구 제안 목록** {`continue_lower_layer`, `resume_ckpt_<k>`(재개 가능 체크포인트마다), `reset_skill`, `safe_wait`} + `NONE_ESCALATE`. `continue_lower_layer`는 "아래 층(L1) 복구 결과를 인정하고 진행"이며 코드가 FAIL을 낸 채널이 해소됐다고 확인한 경우에만 목록에 넣는다. FAIL을 뒤집는 "거절하고 계속" 보기는 없다. E1 전엔 최빈만(최빈이 `safe_wait`·`NONE_ESCALATE`면 안전 대기), E1 뒤 후보 게이트 0.6.
  - **L3 안전 대기**(L2가 끝났는데 Astra 미도착): 쥐고 있으면 쥔 채 사전 자세, 아니면 관찰 자세. 00 §4가 정지를 허용하는 두 곳(T0, M9 L3) 중 하나. 사용자 예외 인정은 [결정 필요 D13](이 문서는 인정한다고 가정).
  - **Astra 도착**(effort에 따라 수 초~수십 초): `continue`(아래 층 결과 인정) / `rollback_to=k` / `reset_skill` / `new_plan`이 우선. `continue`가 아니면 **M2 R3 시점**(결정 스텝 경계, 진행 중 phase가 M6 `effect` 비가역이면 그 phase 끝)에 적용. **정지 없음** — 적용을 기다리는 동안 직전 확정 행동 유지 + 감속. 완전 정지는 L3 안전 대기 안에서만 허용되고 그 자체가 [결정 필요 D13]에 묶인다(00 §16). 아래 층이 이미 복구를 끝냈어도 Astra에 결과를 알리는 짧은 확인 호출은 하지 않는다.
  - 복구 완료 → cooldown 2 s, 센서 술어로 성공 확인된 시도만 M10 후보.
  - 한도: L1 1회, 같은 체크포인트 재개 2회. 넘으면 Astra를 기다린다(L3).
  - **체크포인트**: 생성 = 단계 `exit` 참이 된 순간(술어 벡터·시각·물체 위치 추정과 측정 시각·프레임 색인). 재개 가능 = **지금 측정한** 술어에서 k+1 `entry` 모두 참 AND 1..k 결과 술어 모두 참. 선택 = 가장 늦은 k(없으면 리셋 스킬 → 다시 계산 → 그래도 없으면 Astra `new_plan` 대기). 검사는 M7이 넘긴 **마지막 일치 위치**부터 거꾸로. 세밀 체크포인트(접근·잡기·들기)는 거친→세밀로. **[잠정 기본, [결정 필요] D4] "사전조건이 참인 가장 늦은 지점부터 재개"의 기간 밖 근거 = PLANEX 삼각표·BT 백체이닝**(불허 시 근거는 FaRe·BacktrackAgent만 남고 규칙은 그대로).
  - **[잠정 기본, [결정 필요] D4] 사가식 되돌림**: k까지 가역 단계의 보상 스킬을 **역순**으로 실행, 비가역 경계(M6 `effect`)를 넘어 되돌리지 않음(그 앞 k는 후보에서 뺌), 보상 뒤 재개 조건을 다시 측정한 술어로 확인.
  - 남길 것(RIR 로봇판) = 목표, 검증된 환경 지식(측정 시각 포함), 완료 이정표, Astra 실패 분석, 실패한 (스킬, 파라미터) 목록. 버릴 것 = 현재 상태 서술(재개 뒤 인식으로 다시 읽음). Jev에는 교훈 목록을 넣지 않는다.

## 3. 모듈 사이 규칙 (정본 `00-interfaces.md` §1~§25 요약, 뒤 절이 앞 절을 덮음)

### 3.1 한 번의 Jev 호출 `JevCall` (§2)
- 한 호출 = **결정 질문 H개**(미래 결정 스텝 k..k+H−1) + **감시 질문**(M7 진행 범주 1개, 필요 시 M8 T3b 1개; 감시 질문을 호출 N번에 한 번만 싣는 안도 있음).
- **H는 1과 3을 비교**(E-M4). H=1이면 M4 (a)의 여러 표는 "같은 스텝을 시각을 당겨 여러 번 묻기"로 얻는다. H=3이면 D-줌 세밀 질문은 첫 스텝에만.
- 입력 길이 상한은 설정 표(정본 §7, E0 뒤 확정). E0 지연은 실제 `JevCall` 크기로 잰다.
- API 형식(E §1.2): 질문 키 `ds<번호>.<질문>` / `mon.progress` / `mon.t3b`, 스텝별 전제(바뀐 술어만)는 구조화 `instructions`의 필드, 보기 설명에 `expected_after`, 모든 질문(진행 감시 질문 포함)에 `NONE_ESCALATE`. `model = "jev-1.13.0"` 고정(별칭 금지), 영어, SDK 재시도 끔.
- `DecisionStep.questions[]`에는 M6 결정 지점 id `dp_id`가 붙는다(스킬 밖 자유 이동 질문·`Q_target`은 null).

### 3.2 예상 상태는 한 곳 (§3)
- **M4 (b)의 연속 예상 상태 = M5가 공개하는 계획 궤적 `ref(t)`**(Ruckig 출력, 관성화 오프셋 포함). 추종 지연으로 인한 가짜 LAG를 막는다.
- M3가 보기마다 붙이는 예상 결과 술어 **`expected_after`**는 M4와 M7 모두에 간다. M6 `predict_after`는 이 함수 하나로 합친다. `expected_after`는 등록부 술어 이름만 쓴다(`above`, `collision_risk`, `reachable`, `near`, `in_contact` 등).
- M4 (b)는 (1) `ref(t)` 대비 연속 잔차와 (2) `expected_after` 일치를 **따로** 계산한다.

### 3.3 실패 판정과 정지 (§4, §11.2, §13, §15, §16)
- **M4는 신호만**: CONTRADICT → 모순 술어가 **T1일 때만** M7 하드 채널 H4, T2·`unknown`이면 `C_m4`(§13이 §4보다 우선) / DEVIATE → `C_m4` / `flip_score` → `C_flip`.
- **FAIL은 M7만 낸다.** AND 결합(소프트 채널 2개 이상 FAIL, 1개 WARN)은 M7에만. **소프트 층에는 예외가 없다.**
- M7 채널 전체: 하드 **H1·H2(스킬 오류 코드)·H3·H4·H5·H6(단계 경과 > 2×`D_k`)** — 술어를 쓰는 H1·H3·H4·H5는 T1만, H2·H6은 결정적 코드 신호 / 소프트 `C_stag`·`C_dead`·`C_jev`·`C_m4`·`C_flip`·`C_assume`·`C_pred`. 옛 "`C_dead` 단독 FAIL" 예외는 H6으로 옮겼다(D5 1-3).
- `C_m4`·`C_flip`(같은 출처 M4) 동시 발동은 E-M7 전 기본 1표.
- M2 가정 술어 거짓 → `C_assume` + 동시에 M8 재호출 신호. 실행 중 거부된 계약 patch(`contract_patch_rejected`)도 새 채널 없이 **`C_assume`로 확정**(00 §15, 사건 즉시 발동).
- **정지가 허용되는 곳은 두 군데뿐: T0(첫 계획)과 M9 안전 대기(L3).** M4 hold, M5 `NONE_ESCALATE` 감속, M6 `default_on_timeout`, M2 교체 대기, **Astra 새 계획 적용(M8·M9)**은 모두 **정지가 아니라 "직전 확정 행동 유지 + 감속"**이다. M9의 "Astra 재계획이면 정지"는 L3 안에서만 허용되고 그 자체가 [결정 필요] D13에 묶인다(§16). 완전 정지는 M7 FAIL을 거친다.
- M6 `dp.critic_accept`는 **M7 FAIL 뒤 M9 복구 제안 중 하나를 고르는 Choice일 뿐**이다. WARN으로는 발동하지 않고, M7 FAIL을 뒤집지 못한다. M3 `Q_accept`, M9 L2, E1 `QC-accept`가 모두 이 한 질문이다.

### 3.4 확정·교체 규칙은 M4 한 곳, 적용 시점은 M2 R3 한 곳 (§5, §14-3, D5 2-1)
- 고정 구간 길이 = 실측 Jev p95 지연 `d_p95`. M5 확정 길이와 M3 `commit_window`는 읽기만.
- 보기 교체는 M4의 유예 창 W와 합의 규칙만. M5 L1의 "연속 2표"는 W=2 설정으로 흡수.
- [잠정] 비가역 보기(M6 `effect`)는 W+1.
- 새 계약·Astra 새 계획의 적용 시점은 **M2 R3** 하나를 따른다: 결정 스텝 경계, 진행 중 phase의 M6 `effect`가 `irreversible`이면 그 phase가 끝난 뒤. M8 commit 창과 M9 적용 시점이 이것을 쓴다. 잡기 닫힘~들어올림은 M6 `effect`에서 가역이라 별도 창을 두지 않고, 그리퍼가 닫히는 순간은 1.0 s 전환 보류가 보호한다.

### 3.5 확률 게이트 (§6, §16)
- **E1(보정 측정) 전에는 모든 모듈에서 확률 게이트를 모두 끄고 최빈 선택만 쓴다.** 확률은 기록만 한다. 후보 값(M5 0.8, M7 0.8, M8 0.7, M9 0.6, M4 θ {0.8, 0.9})은 설정 표에만 둔다. (plan §1의 옛 문구 "게이트로만 쓴다"는 틀린 문구였고 고쳐졌다.)
- 확률을 **양**으로 쓰는 설계(가중 평균·가중 합의)는 E1 판정 2를 통과해야 켠다. 확률 비교는 같은 문구·같은 보기·같은 유형 질문끼리만(Jev #8). Score 기댓값으로 단계 사이를 보간하지 않는다(Jev #2(c)).
- M8 T3b 게이트는 E1 뒤 conformal risk control(보정 표본 단계당 500 이상)로 정한다. 실패 트리거는 게이트와 무관하게 항상 호출.

### 3.6 술어 등록부 (§11.1·§11.3)

- M1 후보 이름은 "후보 A / B / C".

### 3.7 결정 지점 id와 이름 (§11.1)

### 3.8 실험 순서 (§13이 §8을 덮음, §17 보강)
E0 지연(실제 `JevCall` 크기) → **E0.5 표 재생(오프라인, E0와 같은 날 가장 먼저, 정본 §17)** → E1 보정 → **E2a**(룰 대 Jev C1, M4 없이, 결과 기반 라벨, Astra 켠 대응 쌍 포함) → E-M4(C0~C6, C3'·C3''·C5-A3·C-FIX 포함, H=1·3) → E-M4-gen → E-M4-lat(정본 §17) → E-M3-2 → E-M5-1 → E-M8a → E-M9 → E-M6·E-M10. 오프라인 E1·E3·E-M3-1·E-M7·E-M8b는 병행. 환경: E0~E3와 모듈 실험 = 단일 팔 자작 장면, 본 평가 = RoboDojo(양팔). 둘을 섞지 않는다. 본 평가 S1 직후 **S1.5**(EVAL H4 + random 스냅샷 룰 대 Jev)를 당긴다. 옛 이름 "E2"는 E2a로 바뀌었다. 조건부: E-link(사용자가 [결정 필요] D29에서 2안을 고를 때만), E-real 최소판([결정 필요] D30 허락 시).

### 3.9 그 밖의 공통 규칙
- 겹침은 끄지 않는다(§9 C1). E0에서 지연이 결정 간격보다 짧으면 겹침의 목적을 "지연 숨기기"에서 "같은 스텝에 여러 표 받기(자기 확인)"로 옮긴다.
- M5 L2(같은 보기끼리 RTC식 감쇠 블렌딩)가 기본(§9 C3). 스무딩 원칙 문구는 user-log 원문대로 "먼저 RTC와 유사한 방법, 다음으로 액션 스무딩이나 VLA에서 쓰는 부드럽게 하는 방법으로 아주 작은 움직임을 처리한다"로 읽는다(§16, D11 정정).
- M8 effort 실험 축은 low / medium / high / xhigh / max 전부 후보, 빼면 이유를 적는다(§9 C5). Astra effort는 **잠정 기본 high(다른 작업 발언 근거) — 이 프로젝트 적용은 [결정 필요] D5**(§16. §13의 옛 "사용자 원칙" 표기는 D11에서 그 자리를 고침). RoboDojo 원문 medium은 재현 조건으로만.
- **잠정 기본**(기간 밖 문헌이 정한 기본값, 사용자 승인([결정 필요] D4) 전까지, §13·§16): LocalAgreement(M4), Sentinel식 `C_flip`(M4·M7), Ruckig(M5), 관성화(M5), 사가 보상(M6 `effect`·M9 되돌림), DFA 형식 검증(M2), PLANEX/BT식 재개(M9).

- 사용자 의도 정정(§16): 대주제 문장은 user-log 3 원문(§0·§1.1). M6 "(b) 먼저"는 Claude의 해석. (b)·(a') 대칭 + 최종 [결정 필요]는 그대로.
