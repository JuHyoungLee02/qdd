## 0. 사용자 의도와 결론 한 줄

- [사용자] 행동 표현은 촘촘하게 가도 된다. Jev 방식이면 충분히 가능하다.
- [제안] 결론: **"촘촘함"을 크기 숫자의 해상도가 아니라 (1) 결정 빈도, (2) 목표 지정의 해상도(어느 물체의 어느 부분·어느 영역), (3) 접촉 근처에서만 켜는 미세 조정 질문**에 둔다. 한 질문의 보기는 서로 뚜렷이 다른 것 ≤ 약 17개로 두고, 촘촘한 크기는 **거친→세밀 두 질문(줌)** 으로 만든다. 차원당 255개 한 질문은 비교 조건으로 남긴다.
- 사용자 원안(촘촘한 객관식, D안)과 목표 지정형(G안)을 **둘 다** 설계하고, 둘을 잇는 혼합안(H안)을 1순위 후보로 제안한다. [결정 필요: 기본안 — plan §5 목록 6번]
- 세 안 모두 M4에 같은 모양의 "결정 스텝 열"(§4.4)을 넘긴다. M4는 어느 안이 되든 그대로 동작한다.

## 1. 역할과 입출력

| 항목 | 내용 |
|---|---|
| 역할 | Jev의 typed 선택(Choice/Noul)을 로봇이 실행할 수 있는 **목표·설정값**으로 바꾸는 약속. "Jev가 무엇을 고르고, 코드가 무엇을 계산하는가"의 경계를 정한다. |
| 입력 | M1 텍스트 상태(객체 ID·부분·범주 관계·술어), M2 세션 계약(단계·스킬·stop 술어·금지 술어), 현재 로봇 상태, 코드가 만든 후보 목록과 후보별 **예상 결과 술어** |
| Jev에 나가는 것 | 결정 질문 묶음(한 요청 안 여러 질문). 보기는 ID + 짧은 이름 + 예상 결과 술어. 모든 질문에 `NONE_ESCALATE`(해당 없음/올림) 보기 |
| Jev에서 오는 것 | 질문별 선택 보기 + 보기별 확률(보정 전에는 **게이트로만**) |
| 출력 | M4로: 결정 스텝 기록(§4.4). M5로: 목표 자세 또는 제어점 열(연속 값은 **코드**가 만든다) |
| 제약(§1 plan) | Jev 텍스트만·수치 약함·#2(c) Score 기댓값 보간 금지·#8 질문 사이 확률 항등식 불성립·보정 전 확률은 게이트만 → **Jev는 숫자를 만들지 않는다. 순서형 보기도 최빈(argmax) 보기만 쓴다.** |

구조 속 위치: Astra(느린 상위, 계약) → **Jev(M3 질문에 답)** → 코드(기하·경로) → 기존 스킬/제어기(M6) → M5 스무딩. 코드 critic(M7)은 M3가 만든 "예상 결과 술어"를 M4(b) 확인에 그대로 재사용한다.

## 4. 설계안

### 4.1 세 안의 공통 뼈대
- 한 번의 Jev 요청 = **한 결정 스텝의 질문 묶음**(질문 개수 상한 없음, 공식). 질문마다 `question_id`(문구·보기 목록의 해시)를 붙인다. 같은 `question_id`끼리만 M4 합의·확률 비교를 한다(plan §1 #8 규칙).
- 보기 이름: 짧은 영어 식별자 + 예상 결과 술어(영어, 공식 "영어가 가장 정확"). 숫자는 이름 속 대략 값(`≈2cm`)까지만, 계산은 코드.
- 순서형 보기(크기·거리)도 **최빈 보기만** 쓴다. 확률 가중 평균·Score 기댓값 보간은 쓰지 않는다(#2(c)). v3/04의 "봉우리 검사 후 평균" 제안은 **E1 전까지 끈다**.
- 모든 질문에 `NONE_ESCALATE`. 이것이 최빈이면 그 결정 스텝은 "보류"로 M4에 넘긴다.

### 4.2 D안 — 사용자 원안: 촘촘한 객관식 [사용자 방향 그대로]
- 결정 빈도: M4 스텝(예: 1초 3회)마다.
- 질문(한 요청 안):
  1. `Q_dir`: 이동 방향 26개(3축 ±와 대각 조합) + `hold` + `NONE_ESCALATE`.
  2. `Q_mag_coarse`: 로그 간격 5구간(tiny/small/medium/large/xlarge).
  3. `Q_mag_fine`(D-줌): 선택된 거친 구간 안을 5~9등분. **같은 요청에서 병렬로 묻는 방법**은 거친 구간이 정해지기 전이라 불가 → 두 방식을 둔다. (a) 직전 결정 스텝의 거친 구간을 기준으로 세밀 질문을 미리 만든다(한 스텝 늦음), (b) 거친 질문의 게이트가 통과하지 못했을 때만 다음 스텝에서 세밀 질문. 유효 해상도 = 5 × 9 = 45단계.
  4. `Q_rot`, `Q_grip`: 회전 방향 보기, 그리퍼 {open, close, keep}.
- 비교 조건 D255: 차원당 한 질문 255 등간격 보기(plan 원안 그대로).
- 순서 없는 보기 → 최빈, 크기 → 최빈 구간(plan 원안과 같음).
- 제어점: Jev가 고른 스텝 열 k개를 코드가 B-스플라인 제어점으로 맞춘다(BEAST의 표현을 코드 내부에서만).

### 4.3 G안 — 목표 지정형
- Jev가 고르는 것: `Q_target`(목표 객체 ID·부분·이름 있는 영역), `Q_approach`(이름 붙은 접근 원형 3~6개), `Q_phase`(현재 단계 계속/다음 단계로 전이/보류), `Q_accept`(critic 제안 수락 Noul).
- 코드가 하는 것: 목표 자세 계산(부분 → 파지 자세, 영역 → 점), 경로(원형에 맞춘 경로 + 충돌 검사), 보폭(거리 범주), 속도 한계는 M5.
- 결정 빈도: 결정 지점마다(목표 바뀜·단계 전이·critic 제안). 사이 시간에는 M4가 **같은 질문을 계속 겹쳐 물어 확인**한다(대상이 바뀌지 않았는지).

### 4.4 H안 — 혼합: 목표 지정 + 접촉 근처 미세 조정 [제안, 1순위 후보]
- 먼 구간(`dist_cat ∈ {far, mid}`): G안.
- 접촉 근처(`dist_cat ∈ {near, contact}` 또는 스킬이 "정렬/삽입/놓기" 단계): **미세 조정 질문**을 추가로 켠다.
  - `Q_fine_dir`: {+x,−x,+y,−y,+z,−z, rot+, rot−, hold, done, NONE_ESCALATE}. 각 보기에 예상 결과 술어(예: `after: aligned_x=yes, contact=none`).
  - 크기: 코드가 {1cm, 2cm} 중 거리 범주로 고른다(Show-Harness 원문 값에서 출발, 튜닝 대상). 세밀 크기 질문은 τ_zoom 게이트로만 켠다(UI-Zoomer 발상).
- 이것이 [사용자] "촘촘하게"를 살리는 방식이다: 먼 구간에서는 목표 해상도(부분·영역)로, 접촉 근처에서는 결정 빈도 + 미세 조정으로 촘촘하다. 크기 숫자 해상도만 거칠다.

### 4.5 M4로 넘기는 결정 스텝 기록 (세 안 공통)
```
DecisionStep {
  ds_id            # 미래 결정 스텝 번호 (M4 표의 열)
  t_state          # Jev 입력 상태의 시각·프레임 번호 (시간 정렬, WAM 교훈)
  call_id, sent_at, recv_at
  variant          # D | D255 | G | H
  questions: [ {question_id, options[], chosen, p_chosen, p_second} ]   # p는 게이트·기록용
  target           # 코드가 계산한 목표 자세/제어점 (Jev가 만든 숫자 아님)
  expected_after   # 선택 보기의 예상 결과 술어 (M4(b)·M7이 측정 술어와 비교)
  commit_window    # 이 스텝이 확정되어야 하는 시각
  escalate         # NONE_ESCALATE가 최빈이었나
}
```
- D안: 결정 스텝 열이 촘촘하다(초당 3개, 스텝마다 5~6 질문). M4의 (a) 합의는 `Q_dir`·`Q_mag_coarse`에 건다. `Q_mag_fine`은 인접 보기 한 칸 차이를 일치로 볼지(Spec-VLA식 완화)를 M4 실험 변수로.
- G/H안: 결정 스텝 열이 짧다. M4 대상은 "결정 지점 열"(plan M4의 v4 의존 문단과 같음). 겹친 호출은 같은 `Q_target`·`Q_phase`를 반복해 묻는 확인이 된다. H안 접촉 근처에서는 D안과 같은 촘촘한 열이 다시 생긴다.
- `expected_after`는 세 안 모두 코드가 만든다 → M4(b) "코드 예상 상태 대 측정 상태"가 어느 안에서도 같은 코드로 돈다.

## 5. 비교 실험 (판정 기준은 실행 전에 적은 것)

### E-M3-1 보기 수·형식 오프라인 시험 (E1과 함께, 로봇 없이)
- 데이터: E2 과제에서 모은 텍스트 상태 300개 이상, 정답 라벨 = 코드 오라클(목표까지 최적 방향·구간, 올바른 목표 ID).
- 조건: 크기 질문 N ∈ {5(로그), 9, 17, 33, 65, 129, 255(등간격)}; 목표 질문 후보 수 ∈ {관련 객체만, 관련 + 무관 5, + 무관 20}; 보기 이름 형식 2종(이름 대 이름+예상 결과 술어); 보기 순서 3개 순열(편향 측정용, 본 운영은 고정).
- 지표: 정확도, 우연 보정 정확도(2604.14634의 NA), ±1구간 정확도, 앞쪽 보기 편향(정답 위치별 정확도 기울기), 지연 p50/p95, 토큰.
- **판정 기준(사전)**: (1) 크기 질문의 기본 N = "±1구간 정확도 ≥ 95% 이면서 NA가 N=5 값의 90% 이상"인 가장 큰 N. (2) 예상 결과 술어가 붙은 형식이 목표 선택 정확도를 **5%p 이상** 올리면 기본 형식으로. (3) 위치 기울기가 |slope| > 0.02(임계값은 우리가 정함. 참고: 2604.14634 Table 2 Full 환경의 slope 범위 약 −0.06 ~ +0.03)면 보기 순서를 무작위가 아니라 **"코드 오라클 비의존 고정 순서(ID 정렬)"** 로 두고 결과에 편향을 보고.

### E-M3-2 행동 표현 비교 (E2 마차 시험의 M3 부분)
- 공통: 같은 텍스트 상태, 같은 스킬·제어기·M5, M4 켬(C5) 고정, 단일 pick-and-place + 섭동(물체 2cm 이동, 방해물 추가, 잡기 실패 유도). 3시드 × 과제당 20회 이상.
- 조건: R 룰(같은 술어 위 규칙) / D255 / D-줌 / G / H / H−pred(H에서 예상 결과 술어 뺌) / SH(Show-Harness식: 방향 + 고정 2/4cm).
- 지표: 성공률, 최종 정렬 오차(mm), 완료 시간, Jev 호출·결정 수, `NONE_ESCALATE` 비율, M5 jerk.
- **판정 기준(사전)**:
  1. H 또는 G가 D255보다 성공률 ≥ 10%p 높고 95% 부트스트랩 구간이 0을 넘지 않으면 → 기본안을 H(또는 G)로 사용자에게 제안.
  2. D-줌이 H와 ±5%p 안이면 → 사용자 원안(D-줌)을 기본으로 둔다(사용자 의도 우선).
  3. 어떤 Jev 조건도 R보다 성공률이 높지 않으면(차이 < 5%p) → plan §5 "마차" 규칙대로 방향 재검토를 보고.
  4. H−pred가 H보다 5%p 이상 낮으면 → 예상 결과 술어를 필수로.

## 6. 반대 증거와 위험

- **G/H안에 대한 반대**: SPF의 100%는 **이미지를 보는 VLM**의 점 지정이다. Jev는 목표를 ID로만 고를 수 있고, 목표 자체가 M1 인식 품질에 묶인다. M1이 부분(손잡이)을 못 나누면 G안의 해상도는 떨어진다.
- **D안에 대한 반대**: SPF 7%(연속 수치 글쓰기), GUI-Cursor(학습 없는 반복 이동 이득 작음), Show-Harness(거친 보기로 결과), 2604.14634(비슷한 보기 많으면 하락). 단 모두 Jev가 아니다. Jev는 보기별 확률을 주는 분류형 모델이라 다를 수 있다 — **E-M3-1이 이 차이를 직접 잰다.**
- **보기 수 근거가 약하다**: #4·#5는 arXiv만, 과제 하나(한국어 맞춤법, 도구 선택). 방향만 참고하고 수치는 우리 실험으로.
- **예상 결과 술어의 위험**: 술어 계산이 틀리면(인식 오차) Jev는 틀린 설명을 믿고 고른다. M4(b)가 실행 뒤 이 불일치를 잡는 것이 안전망.
- **Show-Harness 1cm 개선(60→82%)** 은 끼우기·쌓기의 소수 과제 결과(시행 수 원문 확인 못 함).
- H안의 모드 전환(먼 → 근접) 경계에서 결정 모양이 바뀌면 M4 합의 표가 끊긴다 → 전환 자체를 `Q_phase` 결정으로 두어 M4가 합의하게 한다.
- RIA는 세계 모델이 학습형이고 주행이다. 우리 "코드 굴리기"는 짧은 기하 계산이라 같은 효과를 보장하지 않는다.
