## 0. 사용자 의도와 결론 한 줄

- [사용자] (user-log 11 (3) 행동) 촘촘하게 가도 된다. Jev 방식이면 충분히 가능하고 할 만하다고 본다.
- [제안] 결론: **"촘촘함"을 크기 숫자의 해상도가 아니라 (1) 결정 빈도, (2) 목표 지정의 해상도(어느 물체의 어느 부분·어느 영역), (3) 접촉 근처에서만 켜는 미세 조정 질문**에 둔다. 한 질문의 보기는 서로 뚜렷이 다른 것 ≤ 약 17개로 두고(D안 방향 질문도 두 질문으로 나눠 이 상한을 지킨다, §4.2), 촘촘한 크기는 **거친→세밀 두 질문(줌)** 으로 만든다. 차원당 255개 한 질문은 비교 조건으로 남긴다.
- 촘촘한 원안(촘촘한 객관식, D안·D-줌 — 사용자 '촘촘하게 가도 된다'를 Claude가 구현한 안)과 목표 지정형(G안)을 **둘 다** 설계하고, 둘을 잇는 혼합안(H안)을 1순위 후보로 제안한다. [결정 필요: 기본안 — plan §5 목록 6번]
- **(우리 해석, 00 §19, D8)**: RoboDawn(2609.22966, §2 #18)에서 성능을 가장 크게 움직인 것은 **공간 근거**(격자 제거 47.0 → 32.4%, −14.6%p)와 **결정 횟수**(명령 예산 60 → 240에서 +16%p)였고, 저자 스스로 "이산 의미 명령이 미세 보정에 너무 거칠다"를 한계로 적었다. 이는 [사용자] "촘촘하게"를 크기 숫자의 해상도가 아니라 **결정 빈도와 공간 근거(목표 지정 해상도)**로 구현하는 위 결론과, **접촉 근처에서만 미세 조정 질문을 켜는 H안**(§4.4)을 지지한다. 단 RoboDawn은 VLM이 수치를 직접 쓰고 하네스 주석 카메라를 보는 정지형이라 Jev 조건과 다르다 → 지지 근거일 뿐 수치를 옮기지 않는다.
- 세 안 모두 M4에 같은 모양의 "결정 스텝 열"(§4.4)을 넘긴다. M4는 어느 안이 되든 그대로 동작한다.

## 1. 역할과 입출력

| 항목 | 내용 |
|---|---|
| 역할 | Jev의 typed 선택(Choice/Noul)을 로봇이 실행할 수 있는 **목표·설정값**으로 바꾸는 약속. "Jev가 무엇을 고르고, 코드가 무엇을 계산하는가"의 경계를 정한다. |
| 입력 | M1 텍스트 상태(객체 ID·부분·범주 관계·술어), M2 세션 계약(단계·스킬·stop 술어·금지 술어), 현재 로봇 상태, 코드가 만든 후보 목록과 후보별 **예상 결과 술어** |
| Jev에 나가는 것 | 결정 질문 묶음. 한 번의 Jev 호출(`JevCall`, 00-interfaces §2)에 결정 질문 H개(미래 결정 스텝 k..k+H−1) + 감시 질문(M7 진행 범주 1개, 필요 시 M8 T3b 1개)이 함께 실린다. H는 1과 3을 비교한다(E-M4). 보기는 ID + 짧은 이름 + 예상 결과 술어. 모든 질문에 `NONE_ESCALATE`(해당 없음/올림) 보기 |
| Jev에서 오는 것 | 질문별 선택 보기 + 보기별 확률. **E1(보정 측정) 전에는 확률 게이트를 모두 끄고 최빈 선택만 쓴다**(00-interfaces §6). 확률은 기록용 |
| 출력 | M4로: 결정 스텝 기록(§4.5). **M4와 M7 모두로: 선택 보기의 `expected_after` 술어**(00-interfaces §3). M5로: 목표 자세 또는 제어점 열(연속 값은 **코드**가 만든다) |
| 제약(§1 plan) | Jev 텍스트만·수치 약함·#2(c) Score 기댓값 보간 금지·#8 질문 사이 확률 항등식 불성립·보정 전 확률은 게이트만 → **Jev는 숫자를 만들지 않는다. 순서형 보기도 최빈(argmax) 보기만 쓴다.** |

구조 속 위치: Astra(느린 상위, 계약) → **Jev(M3 질문에 답)** → 코드(기하·경로) → 기존 스킬/제어기(M6) → M5 스무딩. M3가 만든 "예상 결과 술어"(`expected_after`)는 M4(b)의 술어 일치 판정과 M7 critic 입력에 함께 전달된다. M4(b)의 **연속 잔차 기준(예상 상태)은 M3가 아니라 M5가 공개하는 계획 궤적 `ref(t)`**다(00-interfaces §3). M3는 연속 예상 상태를 만들지 않는다.

## 4. 설계안

### 4.1 세 안의 공통 뼈대
- 한 번의 Jev 요청 = `JevCall`(00-interfaces §2): **결정 질문 H개(미래 결정 스텝 k..k+H−1) + 감시 질문**(M7 진행 범주 1개, 필요 시 M8 T3b 1개. 호출 N번에 한 번만 싣는 안은 M4 설정). **H는 1과 3을 비교한다(E-M4).** 이 문서의 원안 "한 요청 = 한 결정 스텝"은 **H=1 조건**이다. H=1일 때 같은 스텝에 여러 표가 필요하면 M4가 "같은 스텝을 호출 시각을 앞당겨 여러 번 묻기"로 얻는다. 질문 개수 상한은 공식에 없지만, 입력이 길면 정확도가 떨어지므로(plan §1) 입력 길이 상한을 설정 표에 둔다. 질문마다 `question_id`(문구·보기 목록의 해시)를 붙인다. 같은 `question_id`끼리만 M4 합의·확률 비교를 한다(plan §1 #8 규칙).
- 보기 이름: 짧은 영어 식별자 + 예상 결과 술어(영어, 공식 "영어가 가장 정확"). 숫자는 이름 속 대략 값(`≈2cm`)까지만, 계산은 코드.
- 순서형 보기(크기·거리)도 **최빈 보기만** 쓴다. 확률 가중 평균·Score 기댓값 보간은 쓰지 않는다(#2(c)). v3/04의 "봉우리 검사 후 평균" 제안은 **E1 전까지 끈다**.
- 모든 질문에 `NONE_ESCALATE`. 이것이 최빈이면 그 결정 스텝은 "보류"로 M4에 넘긴다. 보류는 **정지가 아니다**: 로봇은 직전 확정 행동을 유지하며 감속한다(00-interfaces §4, M5 L2 규칙 4). 완전 정지는 M7 FAIL을 거칠 때만.

### 4.2 D안 — 촘촘한 원안: 촘촘한 객관식 (D-줌 — 사용자 '촘촘하게 가도 된다'를 Claude가 구현한 안)
- 결정 빈도: M4 스텝(예: 1초 3회)마다.
- 질문(한 요청 안):
  1. 이동 방향(26방향 = 3축 각각 {−, 0, +}의 조합에서 (0,0,0) 제외)을 **두 질문으로 나눠 묻는다**(D4 C-6 해소, 2026-09-23):
     - `Q_dir_xy`: 수평면 방향 8개(+x, −x, +y, −y와 대각 4개) + `none_xy` + `NONE_ESCALATE` = 10개.
     - `Q_dir_z`: {up, down, `none_z`, `NONE_ESCALATE`} = 4개.
     - 두 답의 조합 9 × 3 = 27 중 (`none_xy`, `none_z`) = `hold`, 나머지 26개 = 원안의 26방향. 둘 중 하나라도 `NONE_ESCALATE`가 최빈이면 그 스텝은 보류.
     - 왜 나누나: 첫 판은 한 질문에 26방향 + `hold` + `NONE_ESCALATE` = **28개**여서 §0의 "한 질문 보기 ≤ 약 17개"와 어긋났다(E §1.2도 28). 보기를 17개 이하로 **줄이는 안**(예: 6축 + 회전만)은 대각 방향을 없애 [사용자] "촘촘하게"의 해상도를 깎는다. **나누는 안**은 26방향을 그대로 살리면서 질문마다 ≤ 17을 지킨다. 수평/수직으로 가른 이유: 탁상 과제에서 z(들기·내리기)는 xy 이동과 의미가 다른 결정이고(접근 높이, 충돌 회피), 보기 이름이 서로 뚜렷이 다르게 유지된다.
     - 비용과 위험 [우리 추론]: 두 질문이 한 `JevCall`에 같이 실려 호출 수는 늘지 않지만 질문 수가 1개 늘어 입력이 길어진다. 두 답을 따로 고르므로 "대각"이 두 질문의 결합으로만 나온다 — Jev가 한쪽만 바꾸면 의도와 다른 대각이 나올 수 있다. M4 (a) 합의는 두 질문 각각에 건다(`question_id`가 다름). 한 질문 28개 원안은 **E-M3-1 비교 조건 `D-dir28`**로 남겨, 나눈 방식의 방향 정확도가 28개 한 질문보다 5%p 이상 낮으면 [결정 필요]로 되돌림 여부를 올린다.
  2. `Q_mag_coarse`: 로그 간격 5구간(tiny/small/medium/large/xlarge).
  3. `Q_mag_fine`(D-줌): 선택된 거친 구간 안을 5~9등분. **같은 요청에서 병렬로 묻는 방법**은 거친 구간이 정해지기 전이라 불가 → 두 방식을 둔다. (a) 직전 결정 스텝의 거친 구간을 기준으로 세밀 질문을 미리 만든다(한 스텝 늦음). **H≥2일 때 이 방식은 두 번째 이후 스텝에서 성립하지 않으므로, 세밀 질문은 `JevCall`의 첫 스텝(ds_k)에만 둔다**(D1 B1). (b) 거친 질문의 게이트가 통과하지 못했을 때만 다음 스텝에서 세밀 질문 — 확률 게이트이므로 **E1 전에는 끈다**(E1 전 D-줌은 (a)만). 유효 해상도 = 5 × 9 = 45단계.
  4. `Q_rot`, `Q_grip`: 회전 방향 보기, 그리퍼 {open, close, keep}.
- 비교 조건 D255: 차원당 한 질문 255 등간격 보기(plan 원안 그대로).
- 순서 없는 보기 → 최빈, 크기 → 최빈 구간(plan 원안과 같음).
- 제어점: Jev가 고른 스텝 열 k개를 코드가 B-스플라인 제어점으로 맞춘다(BEAST의 표현을 코드 내부에서만).

### 4.3 G안 — 목표 지정형
- Jev가 고르는 것: `Q_target`(목표 객체 ID·부분·이름 있는 영역), `Q_approach`(이름 붙은 접근 원형 3~6개), `Q_phase`(현재 단계 계속/다음 단계로 전이/보류), `Q_accept`(= M6 `dp.critic_accept`: M7 FAIL 뒤 **M9 복구 제안 중 하나를 고르는 Choice** + `NONE_ESCALATE`. 예/아니오로 묻지 않는다 — "아니오 = 거절하고 계속"이 생겨 FAIL을 뒤집기 때문, 00 §11.2 B10).
- 코드가 하는 것: 목표 자세 계산(부분 → 파지 자세, 영역 → 점), 경로(원형에 맞춘 경로 + 충돌 검사), 보폭(거리 범주), 속도 한계는 M5.
- 결정 빈도: 결정 지점마다(목표 바뀜·단계 전이·M7 FAIL 뒤 M9 복구 제안). 사이 시간에는 M4가 **같은 질문을 계속 겹쳐 물어 확인**한다(대상이 바뀌지 않았는지).

### 4.4 H안 — 혼합: 목표 지정 + 접촉 근처 미세 조정 [제안, 1순위 후보]
- `near/contact` 정의는 설정 표(00-interfaces §7)를 따른다: near = 목표까지 ≤ 5 cm, contact = 접촉 술어 참. M5·M7도 같은 정의를 쓴다. far/mid 경계는 M3 초기값(튜닝 대상).
- 먼 구간(`dist_cat ∈ {far, mid}`): G안.
- 접촉 근처(`dist_cat ∈ {near, contact}` 또는 스킬이 "정렬/삽입/놓기" 단계): **미세 조정 질문**을 추가로 켠다.
  - `Q_fine_dir`: {+x,−x,+y,−y,+z,−z, rot+, rot−, hold, done, NONE_ESCALATE}. 각 보기에 예상 결과 술어(예: `after: aligned_x(gripper,target)=yes, in_contact(gripper,target)=no`).
  - 크기: 코드가 {1cm, 2cm} 중 거리 범주로 고른다(Show-Harness 원문 값에서 출발, 튜닝 대상). 세밀 크기 질문은 τ_zoom 게이트로 켠다(UI-Zoomer 발상) — **E1 전에는 게이트를 끄고 세밀 크기 질문을 싣지 않는다**(코드가 정한 크기만 사용).
- 이것이 [사용자] "촘촘하게"를 살리는 방식이다: 먼 구간에서는 목표 해상도(부분·영역)로, 접촉 근처에서는 결정 빈도 + 미세 조정으로 촘촘하다. 크기 숫자 해상도만 거칠다.

### 4.5 M4로 넘기는 결정 스텝 기록 (세 안 공통)
```
DecisionStep {
  ds_id            # 미래 결정 스텝 번호 (M4 표의 열)
  t_state          # Jev 입력 상태의 시각·프레임 번호 (시간 정렬, WAM 교훈)
  call_id, sent_at, recv_at
  variant          # D | D255 | G | H
  questions: [ {question_id, dp_id, options[], chosen, p_chosen, p_second} ]   # p는 기록용 (E1 전 게이트 끔). dp_id = M6 고정 결정 지점 id(아래 대응표), 없으면 null
  perm_id          # 보기 순서 순열 번호. 기본 0(고정 순서). E-M4 C3''에서만 0..2 (§4.6). question_id는 순서와 무관하게 같다
  target           # 코드가 계산한 목표 자세/제어점 (Jev가 만든 숫자 아님)
  expected_after   # 선택 보기의 예상 결과 술어 → M4(b) 술어 일치 판정과 M7 입력 둘 다로
  commit_window    # 고정 구간 경계 시각. M4가 d_p95(E0 실측 Jev p95 지연)로 채운다. M3는 읽기만
  escalate         # NONE_ESCALATE가 최빈이었나
}
```
- D안: 결정 스텝 열이 촘촘하다(초당 3개, 스텝마다 5~6 질문). M4의 (a) 합의는 `Q_dir_xy`·`Q_dir_z`·`Q_mag_coarse`에 건다. `Q_mag_fine`은 인접 보기 한 칸 차이를 일치로 볼지(Spec-VLA식 완화)를 M4 실험 변수로.
- G/H안: 결정 스텝 열이 짧다. M4 대상은 "결정 지점 열"(plan M4의 v4 의존 문단과 같음). 겹친 호출은 같은 `Q_target`·`Q_phase`를 반복해 묻는 확인이 된다. H안 접촉 근처에서는 D안과 같은 촘촘한 열이 다시 생긴다.
- **질문 ↔ M6 결정 지점 id 대응**(00 §11.1: M10 규칙 키와 M2 계약은 M6 id만 쓴다): `Q_approach → dp.approach_dir`, `Q_phase → dp.next_skill`, `Q_accept → dp.critic_accept`, `Q_fine_dir → dp.align_commit`(접촉 근처 `adjust_*` 보기와 같은 자리). `Q_target`은 스킬 인자(`target_id`)라 `dp_id`가 붙지 않는다(null). D안 질문(`Q_dir_*`, `Q_mag_*`, `Q_rot`, `Q_grip`)은 스킬 밖 자유 이동 구간(M6 §3 Show-Harness 행)이라 `dp_id` = null.
- `expected_after`는 세 안 모두 코드가 만든다(M6 `predict_after`는 이 술어를 만드는 함수 하나로 합친다) → M4(b)의 "술어 일치" 판정과 M7 입력이 어느 안에서도 같은 코드로 돈다. M4(b)의 **연속 잔차**는 M5 `ref(t)` 기준이다(00-interfaces §3).

### 4.6 보기 순서 돌리기 — E-M4 조건 C3'' (기본값 아님, 00-interfaces §14-1·§15)

원문
- RecSys 2026 Short(#16, 기간 안): Table 1에서 무작위 순서 3회 + Borda 집계가 PPI를 0.4775→0.2992(Llama-3B, MovieLens), GPI를 0.1149→0.0827로 낮춘다. 저자 결론은 노출을 평평하게 해도 안정된 선호가 "반드시 복원되지는 않는다(does not necessarily restore)"이다. 채점은 logprob 기반 결정적 순위라, 결정적인 typed 모델(Jev)과 조건이 비슷하다.
- NAACL 2024(#17, 기간 밖): 순서 섞기 여러 번 + 중심 순위 집계가 목록 순위 정확도를 올린다(초록 최대치).

우리 접목안 [제안, 메인 세션 잠정 결정(00-interfaces §14-1)]
- **적용 범위**: 같은 `question_id`, 같은 문구, 같은 보기 집합. 바꾸는 것은 **보기 제시 순서뿐**이다. 순열 3개(예: 원순서, 한 칸 순환, 두 칸 순환)를 호출마다 돌리고 `perm_id`를 `DecisionStep`에 적는다. `NONE_ESCALATE`는 항상 마지막 자리에 둔다([제안]: 보류 보기의 위치 효과를 따로 섞지 않기 위해).
- **집계**: 표는 보기 id로 원장에 쌓인다. M4 (a)의 합의(LA2·γ·유예 창)와 C3'(Adaptive-Consistency식 정지)는 그대로 돈다. Borda나 확률 순위 집계는 쓰지 않는다. 확률 순위를 쓰는 판은 E1 뒤 후보다.
- **Jev #8과의 관계**: #8은 "다른 질문끼리 확률 항등식이 성립하지 않으니 확률을 비교하지 말라"이다. C3''는 확률을 비교하지 않고 **최빈 선택(보기 id)만 센다**. 그래서 충돌하지 않는 것으로 본다(00 §14-1). 엄밀히 순서가 다르면 같은 입력은 아니다. 그래서 순서 효과가 합의를 깨는지를 C3''가 직접 잰다.
- **기본값이 아니다**: 본 운영 기본은 순서 고정(§3 Massive-option 행)이다. C3''가 E-M4에서 이기면 기본 전환을 메인 세션에 올린다(M4 §5 판정 9).
- **위험**: (1) M4 `flip_score`(표 분포 거리)가 순서 효과로 부풀 수 있다 → C3''에서는 FLIP_TH를 같은 조건의 성공 실행으로 따로 보정한다. (2) RecSys 결과대로 흔들림은 줄어도 남는다. (3) 원문은 생성형 LLM의 목록 순위이고, Jev(typed 분류 모델)에 같은 위치 편향이 있는지는 모른다 → E-M3-1 순열 시험을 먼저 한다.

## 5. 비교 실험 (판정 기준은 실행 전에 적은 것)

### E-M3-1 보기 수·형식 오프라인 시험 (E1과 함께, 로봇 없이)
- 데이터: E1과 같은 스냅샷 풀(E §1.5 POOL)의 텍스트 상태 300개 이상, 정답 라벨 = 코드 오라클(목표까지 최적 방향·구간, 올바른 목표 ID). 이 라벨은 스크립트 플래너를 흉내 낸 정도를 재므로 지표 이름을 **"플래너 일치율"**로 보고한다(D4 F5). 룰 대 Jev 비교에는 쓰지 않는다 — 그 비교는 결과 기반 라벨(스냅샷에서 보기마다 짧게 굴려 과제 진행·성공으로 채점, E §4 E2a)로 한다.
- 조건: 방향 질문 {두 질문 분할(`Q_dir_xy` + `Q_dir_z`, 기본), `D-dir28`(한 질문 28개), **`D-axis-multi`**(00 §19, RoboDawn식: 6축 한 명령 + 한 JevCall에 명령 여러 개, 최대 4. 명령마다 축 보기 {+x,−x,+y,−y,+z,−z, `NONE_ESCALATE`} + 로그 크기 5구간, 정답 방향은 명령 합의 벡터로 채점)}; 회전 질문 {기본 `Q_rot`, **`D-rot15p`**(00 §19: 15° 단위 보기 + 이름 붙은 자세 프리셋 7개 [가정: 프리셋 목록은 RoboDojo 판을 코드 저장소에서 확인 뒤 정함])}; 크기 질문 N ∈ {5(로그), 9, 17, 33, 65, 129, 255(등간격)}; 목표 질문 후보 수 ∈ {관련 객체만, 관련 + 무관 5, + 무관 20}; 보기 이름 형식 2종(이름 대 이름+예상 결과 술어); 보기 순서 3개 순열(편향 측정용, 본 운영은 고정).
- 지표: 정확도, 우연 보정 정확도(2604.14634의 NA), ±1구간 정확도, 앞쪽 보기 편향(정답 위치별 정확도 기울기), 지연 p50/p95, 토큰. 순열 지표(00-interfaces §14-1): **순열 사이 1위 뒤집힘률**(같은 상태, 순서만 다른 3개 순열에서 최빈 보기가 다른 비율)과 RecSys식 PPI(보기 쌍의 선호가 순열 사이에 뒤집히는 비율, 확률 없이 1위 기준으로 계산).
- **판정 기준(사전)**: (1) 크기 질문의 기본 N = "±1구간 정확도 ≥ 95% 이면서 NA가 N=5 값의 90% 이상"인 가장 큰 N. (2) 예상 결과 술어가 붙은 형식이 목표 선택 정확도를 **5%p 이상** 올리면 기본 형식으로. (3) 위치 기울기가 |slope| > 0.02(임계값은 우리가 정함. 참고: 2604.14634 Table 2 Full 환경의 Slope100 범위 약 −0.07 ~ +0.03)면 보기 순서를 무작위가 아니라 **"코드 오라클 비의존 고정 순서(ID 정렬)"** 로 두고 결과에 편향을 보고.
- 추가 판정(사전, [제안]): (4) 순열 사이 1위 뒤집힘률이 5% 이상이면 E-M4 C3''를 필수 조건으로 돌리고, 5% 미만이면 C3''는 선택 조건으로 둔다(예산이 모자라면 뺀다). 어느 쪽이든 기본은 순서 고정이며 C3'' 결과로만 바꾼다.
- 추가 판정(사전, [제안], 00 §19): (5) `D-axis-multi`의 방향 정확도가 두 질문 분할보다 5%p 이상 높으면 E-M3-2 조건에 넣는다. 아니면 기록만. (6) `D-rot15p`의 회전 정확도(±1 보기 허용)가 기본 `Q_rot`보다 5%p 이상 높으면 E-M3-2 D-줌·H 조건의 회전 질문을 `D-rot15p`로 바꾸는 안을 [결정 필요]로 올린다.

### E-M3-2 행동 표현 비교 (E2a 뒤, M4 = E-M4 승자)
- 순서(00-interfaces §8·§13·§17, SUMMARY §3.8): E0 지연(실제 `JevCall` 크기) → E0.5 표 재생(오프라인, E0와 같은 날 가장 먼저) → E1 보정 → E2a 마차(룰 대 Jev C1, M4 없이) → E-M4(C0~C6, C5·C5-A3·C-FIX 포함, H=1·3, M3 = D-줌과 H 두 안) → E-M4-gen → E-M4-lat → **E-M3-2** → E-M5-1. E-M3-1은 E1과 함께 오프라인으로. 환경은 초기 실험과 같은 단일 팔 자작 장면(00 §13).
- 공통: 같은 텍스트 상태, 같은 스킬·제어기·M5, M4는 **E-M4 승자 조건**으로 고정(H도 E-M4 결과를 따름), 단일 pick-and-place + 섭동(물체 2cm 이동, 방해물 추가, 잡기 실패 유도). 3시드 × 과제당 20회 이상.
- 조건: R 룰(같은 술어 위 규칙) / D255 / D-줌 / G / H / H−pred(H에서 예상 결과 술어 뺌) / SH(**Show-Harness 원문판**, 00 §20: 원문 행동 단위 목록 그대로, 2/4 cm(설정 기준)·MV_UP 4 cm, `WRIST: NO`일 때만 청크 ≤ 3, 최근 행동 기록 3~5, 폭 5 mm 빈 집기 되돌림, 에피소드 50 스텝 상한, **정지형(블로킹) 루프** — 결정마다 로봇이 응답을 기다림. 크기·청크 전환 신호 = 결정 모델이 매 응답에 고르는 `WRIST: YES/NO`[가정: Jev면 보기 2개 질문 하나로]) / SH-wall(벽시계 트랙의 **"기다림 없음" 변형**: 응답 동안 로봇이 직전 행동을 이어감. 원문판과 섞지 않고 따로 표시한다).
- 지표: 성공률, 최종 정렬 오차(mm), 완료 시간, Jev 호출·결정 수, `NONE_ESCALATE` 비율, M5 jerk.
- **판정 기준(사전)**:
  1. H 또는 G가 D255보다 성공률 ≥ 10%p 높고 95% 부트스트랩 구간이 0을 넘지 않으면 → 기본안을 H(또는 G)로 사용자에게 제안.
  2. D-줌이 H와 ±5%p 안이면 → D-줌을 기본으로 둔다(사용자 '촘촘하게' 방향에 가장 가까운 안, 잠정).
  3. 모든 Jev 조건에서 R 대비 성공률 차이의 **95% 상한 < +5%p**일 때만 plan §5 "마차" 규칙대로 방향 재검토를 보고한다. 구간이 +5%p를 걸치면 "결론 유보"(00 §13, D4 F3).
  4. H−pred가 H보다 5%p 이상 낮으면 → 예상 결과 술어를 필수로.
  5. 위 1·2 어느 것도 걸리지 않으면(예: H가 D-줌보다 5~10%p 높고 D255와의 차이는 10%p 미만) 결과만 [결정 필요]로 보고하고, 기본은 D-줌(촘촘한 원안)으로 둔다(D4 C-8).

## 6. 반대 증거와 위험

- **G/H안에 대한 반대**: SPF의 100%는 **이미지를 보는 VLM**의 점 지정이다. Jev는 목표를 ID로만 고를 수 있고, 목표 자체가 M1 인식 품질에 묶인다. M1이 부분(손잡이)을 못 나누면 G안의 해상도는 떨어진다.
- **D안에 대한 반대**: SPF 7%(연속 수치 글쓰기), GUI-Cursor(학습 없는 반복 이동 이득 작음), Show-Harness(거친 보기로 결과), 2604.14634(난도 범위가 넓은 방해 보기가 많으면 하락). 단 모두 Jev가 아니다. Jev는 보기별 확률을 주는 분류형 모델이라 다를 수 있다 — **E-M3-1이 이 차이를 직접 잰다.**
- **보기 수 근거가 약하다**: #4·#5는 arXiv만, 과제 하나(한국어 맞춤법, 도구 선택). 방향만 참고하고 수치는 우리 실험으로.
- **예상 결과 술어의 위험**: 술어 계산이 틀리면(인식 오차) Jev는 틀린 설명을 믿고 고른다. M4(b)가 실행 뒤 이 불일치를 잡는 것이 안전망.
- **Show-Harness 1cm 개선(ZS 60→82%, FT 40→65%, 본문 §5.3.1)** 은 블록 쌓기·페그 삽입 2과제 결과(과제당 10회로 보임, 조건당 약 20회). 그림·프로젝트 페이지 값은 60→80%, π0.5 15→60으로 본문(π0.5 18→62)과 다르다(D9) → 인용 시 둘 다 적는다.
- H안의 모드 전환(먼 → 근접) 경계에서 결정 모양이 바뀌면 M4 합의 표가 끊긴다 → 전환 자체를 `Q_phase` 결정으로 두어 M4가 합의하게 한다.
- **RoboDawn(#18)의 근거 한계**(00 §19): 같은 인식 비교가 아니다(하네스 주석 카메라·cm 상태·탁자 높이·명령당 계획기 실행). 자유 수치 명령이라 Jev 보기 조건과 다르다. 절제·예산 수치는 설계 방향의 지지로만 쓰고 기본값 근거로 쓰지 않는다.
- RIA는 세계 모델이 학습형이고 주행이다. 우리 "코드 굴리기"는 짧은 기하 계산이라 같은 효과를 보장하지 않는다.
- **보기 순서 돌리기(C3'')의 근거 한계**: 기간 안 근거는 RecSys 2026 **Short** 한 편(MED)이고 모델 3B~7B, 추천 과제다. "줄어들지만 없어지지 않는다"가 원문 결론이다. NAACL 2024는 기간 밖이다. 순서를 돌리면 M4 합의의 "같은 입력" 전제가 약해지고 `flip_score`가 부풀 수 있다(§4.6).
