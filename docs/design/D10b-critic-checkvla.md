## 1. Critic in the Loop: A Tri-System VLA Framework (2603.05185)
### 원문 사실
- **구조(§3.1~§3.2)**: System 2 "Brain" = 대형 VLM이 아니라 **π0.5(openpi)를 자기회귀 하위 과제 텍스트 출력으로 고친 것**(PaliGemma 백본 공유, §4.1). 프롬프트 "Task: ℓ; Info: m; Current Subtask:", 출력 하위 과제 문장 g_t. m = "g_prev completed" / "accident happened"(§3.2) / "stagnation timeout"(Algorithm 1). System 1 "Cerebellum" = π0.5 flow-matching 행동 전문가, 청크 a_{t:t+H}(**H 값 원문에 없음**). System 3 "Critic" = Florence-2-base(약 0.2B), VQA 프롬프트 "Evaluate the progress for task: g_t.", 출력 진행 bin 문자열 또는 이상 토큰 `<aci>`, 시각 타워 동결·언어·투영층만 미세조정, AdamW lr 1×10⁻⁶ 선형 감쇠, warmup 0, 50 epoch, GPU당 배치 64(§4.1), "real-time, non-blocking evaluation at 20 Hz".
- **진행값(§3.3)**: V_t = max(−1.0, (t − L)/L_max^{g_t}), L = 하위 과제 실행 길이, L_max^g = 학습 말뭉치에서 하위 과제 g 길이의 **90번째 백분위**. 범위 [−1, 0], **B = 101 bin** 문자열로 학습. = "normalized expected time-to-completion".
- **이상 감지(§3.3)**: 실패 궤적의 "critical temporal window(예: 마지막 20 프레임)"에서 bin 대신 `<aci>`를 정답으로 넣어 같은 CE 손실. 별도 분류기 없음(값 하락만으로는 떨림 때문에 불신). Fallen 시나리오용 넘어진 컵 복구 시연 100개 추가 수집(§4.1).
- **스케줄링(Algorithm 1, §3.4)**: "Frequencies: Control ∼20 Hz, Max Stagnation N_stag = 180". 루프: 관측 → Critic(V_t, y_t) {System 3 Async} → t_stag ← (V_t > V_max) ? 0 : t_stag + 1 → V_max ← max(V_max, V_t) → 선점 순서 ① y_t == `<aci>` → m = "accident happened" ② V_t > τ_succ → m = g_t + " completed" ③ t_stag ≥ N_stag → **Reset Robot State**; m = "stagnation timeout" → m ≠ None이면 A ← ∅, V_max ← −∞, t_stag ← 0, g_t ← Brain(O_t, ℓ, m) {System 2 Sync} → A가 비면 A ← Cerebellum(O_t, s_t, g_t) {System 1 Sync} → a_t ← A.pop() 실행.
  - 정체 정의(§3.4 3항): "The system tracks the frames elapsed (t_stag) since V_t last updated its historical maximum (V_max), exceeding the stagnation limit triggers both a policy preemption and a physical robot state reset."
  - **"~9 s"는 원문 표기가 아니다** — 180 프레임 / ~20 Hz ≈ 9 s는 우리 계산. 갱신 조건은 엄격한 증가(V_t > V_max), bin 폭 0.01 → 최고점 갱신 = L_max^g의 1% 이상 "남은 시간" 감소(우리 계산).
  - 완료 문턱 τ_succ 과제별, 예 "τ_succ ≈ −0.041". 이상은 `<aci>` 한 번에 즉시 발동(연속 횟수·창 없음).
  - 선점 뒤: 사건을 m에 넣고 낡은 행동 버퍼 비움(A ← ∅, "emergency synchronization"), Brain "out-of-turn" 호출 → Cerebellum 새 궤적.
  - 세 주기: Actuation & Observation ∼20 Hz(Critic이 새 프레임을 버퍼 실행과 병렬로 비동기 처리) / System One Sync(버퍼가 비었을 때만) / System Two Sync(평소 휴면, Critic 인터럽트로만). 그림 3의 "Async 20Hz 20Hz 20Hz 10Hz 2Hz"는 어느 줄인지 추출 텍스트로 대응 불가.
- **동기/비동기**: Critic만 비동기. **Brain(S2)·Cerebellum(S1)은 Sync** — 선점 때 버퍼를 비운 뒤 Brain → Cerebellum을 차례로 부르고 그 뒤에야 A.pop() → **Brain이 생각하는 동안 실행할 행동이 없다**(알고리즘 구조에서 읽음, 본문이 "멈춘다"고 명시하지는 않음). 정체 선점은 로봇 상태를 물리적으로 되돌린다. "asynchronous architecture"는 Critic 분리를 뜻함.
- **"무한 재시도 루프를 끊는 사람식 규칙"**: 정체 시간 초과 + 로봇 상태 리셋 + Brain에 "stagnation timeout" 전달 하나뿐. 재시도 상한·같은 하위 과제 반복 금지·쿨다운 없음. "Reset Robot State" 구체 동작 미정의(§4.3 Q3 "Retracting the arm breaks the visual-kinematic trap"). 루프 탈출 설명(§4.3 Q2~Q3): 오른팔이 왼쪽 컵 근처에서 "repeatedly attempts unfeasible reaches … trapped in a kinematic loop" → 정체 → 팔 물림 → 왼팔로 hand-over 또는 재계획.
- **모델·지연**: Brain = π0.5 확장, Critic = Florence-2-base 0.2B, 주석만 Qwen3-VL 32B(§3.5). **Brain 호출 지연·Critic 실측 지연·에피소드당 Brain 호출 수 모두 미보고.**
- **실험(§4.1~§4.2, Table 1, 실물만)**: Cobot Magic ALOHA 양팔(팔당 7 DoF), RealSense D435 3대. 과제당 원격조작 200개(Arrange the Tableware에 복구 100개 추가, 컵은 모든 시연에서 오른쪽·오른팔 — 의도적 편향). 과제: Arrange the Tableware 4 시나리오(Ordered / Scattered / Left cup(OOD) / Fallen), Tidy up the Desk(봉투 열기 → 병1 → 병2 → 휴지, 순차 성공률). 기준선 Single-System π0.5, Dual-System π0.5(**행동 청크마다 사용자 프롬프트로 하위 과제 재생성**, Critic·기억 없음).

  - §4.2 정성: Dual-System은 청크마다 하위 과제 생성 → 지연 크고, 상태 추적 없이 하위 과제 사이 **진동**, 연체(비닐봉투)에서 멈춤(그림 6 "execution stagnation").
- **절제(§4.3 Table 2) — 트리거 절제 아님**: OOD 왼컵에서 프롬프트 형식·출처·왼팔 데이터만 변경. ### 우리 해석
- M7: 정체 규칙 형태는 우리 C_stag (b)("최고점 미갱신 지속")와 같다. 값 차이: 원문 갱신 폭 1 bin(1%) + 180 프레임(~9 s, 우리 계산) 대 우리 초기값 진행 범위 5% + M = 20 틱(2 s) → 우리 문턱이 약 4.5배 짧다. → E-M7에 **D1-CiL**(b만, δ = 진행 대리값 최소 해상도 [가정], M = 9 s) + M ∈ {2, 4.5, 9} s 스윕.
- 원문 정체는 단독 발동(AND 없음) → 곧바로 선점·리셋·상위 호출. 우리 M7은 C_stag 단독이면 WARN, M8 T_stag가 그 WARN으로 Astra 호출 → "정체 단독으로 상위 모델 호출"은 원문과 같고, "정체 단독 FAIL·리셋"은 다름. M7 §3에 명시.
- 진행값 정규화(성공 롤아웃 90번째 백분위)는 우리 C_dead의 `D_k`와 같은 정보원이지만 원문은 마감 트리거로 쓰지 않음 → T3a(마감)는 원문에 없는 우리 트리거.
- 완료 판정(진행값 > τ_succ) 때마다 상위 모델 호출 = 우리 T2 "정해 둔 순간"의 하위 과제 경계판. 사건 종류를 상위 모델 입력에 명시(m) = 우리 M8 사건 문맥의 원문 근거.
- 선점 뒤 V_max·t_stag 초기화 → 우리 복구·재계획 뒤 C_stag 최고점 초기화를 명시([제안]: 원문 따름).
- M8: 정체 트리거의 효과 근거는 정성뿐(Left cup 1과제, 트리거 절제 없음) → 신뢰도·근거 수준 표기. Dual-System(청크마다 재계획)의 진동 = "매번 부르면 나빠진다"의 반대 증거(단 Critic·기억도 빠진 조건).

## 2. CheckVLA: Execution-Time Verification with Action-Conditioned World Model (2607.26789)
### 원문 사실
- **문제 설정(식 1)**: 청크 경계에서 c_t = VLM(L, o_t; ρ_t)로 H개 행동 확정, 청크 실행 중 정책은 새 시각 입력 없음, 감시기만 받음. 트리거 t*, 추론 몫 d_lat 제어 스텝, 실제 배치 d_eff(일찍 끝나면 기다리고 넘치면 d_eff > d_lat, 지난 위치 버림). h < d_eff 되돌릴 수 없음.
- **행동 조건 세계 모델(식 2~5)**: 동결 감시 인코더 φ = **V-JEPA 2-AC**, z = φ(o). Ψ가 아직 유효한 확정 행동 ā와 명목 고유감각 롤아웃 ŝ = f(s, ā)를 조건으로 다음 k 스텝 **특징만** 예측(k ≪ H, 픽셀 없음), 관측마다 재기준점, 재작성 뒤 대체된 행동 조건 예측 무효화. Ψ 학습: teacher forcing(Huber) 뒤 자기 롤아웃(부록 D), block-causal. 불일치 d_t = cosine(pooled·정규화 특징), 기간별 성공 통계로 표준화 d̃_t = (d_t − μ_d^(ℓ)) / max(σ_d^(ℓ), ε). 단일 스텝 불일치는 약한 증거 → **시간 인과 위험 헤드 R**(창 w의 (d̃_τ, ℓ(τ)/k, h_τ/H, Δ_sw,τ) + 에피소드 기억 요약) → r_t ∈ [0, 1]. R은 명목 성공·개루프 자연 실패·시작 시각 주석 물리 섭동으로 학습(성공·무해 편차 음성). [τ_on, τ_on+Δ] softmax 풀링 위험 BCE, 시작 전 벌점, 실패 뒤 마스크. 명목 타이밍 감시기 p95 16.4 ms < 제어 주기 100 ms → 보통 span ℓ = 1.
- **보정 트리거(식 6~7, 부록 D)**: 명목 성공 shadow 궤적에 시각별 (μ_r,t, σ_r,t), 보정 궤적 점수 κ^(i) = sup_t (r_t^(i) − μ_r,t)/σ̃_r,t, q̂_α = ⌈(n+1)(1−α)⌉번째(n 초과면 +∞), δ_t = μ_r,t + q̂_α σ̃_r,t. 보장(식 7): 교환 가능한 새 명목 성공 궤적에 대해 Pr(∃t: r_t > δ_t | nominal success) ≤ α — **첫 개입에 대한 보장뿐**(재현율, 수리 뒤 안전, 반복 개입, 분포 이동 보장 없음, 원문 명시). t* = 첫 교차, 재작성 중·배치 뒤 s_min 스텝 억제.
- **수리(식 8~10)**: t*에서 **실행은 계속**, 같은 VLA가 후보 생성. 초과량 e = ((r − μ)/σ̃ − q̂_α)_+, w_0(e) = w_min + (1 − w_min)exp(−βe), W_{h,m} = w_0(e)·exp(−λ_m(h − d_lat)), v = (1−W)⊙v_θ + W⊙v_ref, h < d_lat 고정("empirical projection, not exact conditional sampling"). 초과량→보존 사상은 검증 선택, conformal 보장 없음.
- **에피소드 기억(부록 E)**: 사건 기반 키프레임 뱅크(관절 변위 평균의 지연 확인 극소 + 유사·근접 거부), 정책은 gated cross-attention으로 전체, 위험 헤드는 요약 (t − t_last, m_t, F̄_last)만. 에피소드 끝에만 비움.
- **전체 설정(Table S20)**: H = 50(사전), 흐름 적분 10 스텝(Δu = 0.1), d_lat = 3 제어 스텝(사전) / span 상한 k = 8(검증), 거리 cosine(검증), ε = 10⁻³(사전), 창 w = 32(검증), α = 0.05(사전), s_min = 8(검증) / w_min = 0.0, β = 1.38, λ_mobility/λ_manip 재계획 0.60/0.90, 정규 전이 0.10/0.15(검증) / 뱅크 K = 8, 키프레임당 토큰 16, 멈춤 창/확인 지연 5/3, 최소 쓰기 간격/유사도 문턱 10/0.95, 게이트 편향 −4 / Ψ 폭/깊이/헤드 960/7/12, R 384/4/6, 추가 파라미터 88.4M / Ψ AdamW lr 3×10⁻⁴, 배치 32, 60k TF + 20k 자기 롤아웃, R lr 1×10⁻⁴, 배치 64, 20k, R 시작 창 Δ = 20, 감독 혼합 명목:자연:섭동 = 2:1:1(1,800/900/900), 적합/보정 에피소드(시드당) 200/400 / 재경보 창 K_audit = 20 / **기준선: 주기 재계획 간격 39 제어 스텝(검증)**, 정책 쪽 탐지기 표본 Q = 8, RTC/REMAC 비동기 지평 25(검증) / A100 80GB bf16, PyTorch 2.3.1, CUDA 12.1, RoboCasa365(robosuite 1.4.1, MuJoCo 3.1.4), 시드 1/2/3. 정책 = π0.5 flow-matching, 이동·조작 전문가 분리.

### 우리 해석
- **M7 지표 정정(중요)**: M7 §5의 "적시 재현율(CheckVLA 방식: 실패 시작 뒤 τ초 안 탐지, τ=2초)"은 원문 정의가 아니다. 원문 = τ_on ≤ t* 그리고 t* + d_lat < τ_irrev. → E-M7에 두 지표: (a) "고정 창 재현율(우리, τ = 2 s)", (b) 원문판(τ_irrev는 기록 궤적 스냅샷에서 M9 수리 규칙으로 분기해 결정, d_lat = **실측 Astra 지연**). (b)에서 Astra high 첫 토큰 약 73 s면 적시 창이 사실상 닫힌다 → "Astra가 늦게 올 때 아래 층이 버텨야 한다"(M9)의 정량 근거.
- 오경보는 **에피소드 FWER**로 보고(스텝 단위는 진단만). M7 판정의 "오경보율 5%와 10%"를 에피소드 FWER로 명시.
- functional conformal(sup 점수): 우리 `D_k`의 단계별 분위수 + 본페로니보다 덜 보수적 → E-M7 **D11 functional CP 조건** 후보(n = 400/시드 원문, n = 100이면 FWER 5.4%).
- 고정 문턱은 FWER 7.1%(목표 5%) → 우리 C_stag·C_flip 고정 값도 넘을 위험, 실측 FWER 병기.
- 무해 편차 음성(카메라 흔들림·짧은 가림·배경 변화·자가 교정 이동) 없으면 무해 첫 개입 14.8% → E-M7 데이터에 무해 편차 롤아웃 추가.
- 트리거 억제 s_min = 8 스텝(0.8 s) = 우리 복구 뒤 cooldown 2 s와 같은 역할의 원문 근거. 단계별 보고(Table S16식)를 E-M7에.
- **M8**: 호출 수 맞춤을 원문대로 — (i) 평균 호출 수 맞춤, (ii) 검증(개발) 분할에서만 간격 선택, (iii) 주기 기준선에도 같은 감시기 shadow, (iv) 호출 수·벽시계 배수 병기. 맞춤 정밀도 원문 약 1%(10.1 대 10.2) 대 우리 ±10% 병기.
- 시점 몫 분리: 주기 → 검증 트리거로 시점만 바꾸고 수리 규칙은 같게 → E-M8a에서 A2(주기) 대 A1-cal을 같은 M9 규칙으로 비교.
- "경계까지 기다림": d_lat = 10에서 모든 청크 내 수리보다 높았다(우리 읽기). Astra 지연은 몇 자릿수 길다 → **A1-wait**(실패 트리거를 다음 주기 호출까지 미룸)로 "실패 즉시 호출"(사용자 원칙)의 이득을 직접 잰다(원칙 불변, 이득 없으면 결과로 보고).

### M8 평가 기여 차별화 문장(초안)
1. "CheckVLA는 같은 VLA를 0.29 s(p50) 지연으로 다시 불러 실행 중 청크 뒷부분만 고치고, 지연은 1 s(10 제어 스텝)까지만 쟀다. 그 끝점에서는 청크 안 수리 규칙 모두(23.4~31.4%)가 다음 경계까지 기다리는 기준선(34.0%)보다 낮았다(Table S6). 저자도 동적 지연 인지 스케줄링을 향후 과제로 남겼다. 우리는 수 초에서 수십 초 걸리는 API 모델(Astra)을 부르는 층에서 트리거 방식을 비교하며, 그동안 아래 층이 로봇을 멈추지 않고 움직인다."
2. "Critic in the Loop는 완료·이상·정체(학습된 진행값 최고점이 180 프레임, 약 20 Hz에서 약 9 s 동안 갱신되지 않음) 때만 상위 모델을 부르지만, 그 호출은 행동 버퍼를 비운 뒤의 동기 호출이고 정체 때는 로봇을 물리적으로 되돌린다(Algorithm 1). 트리거별 절제, 호출 수, 지연은 보고하지 않았다. 우리는 같은 호출 수에서 트리거 방식을 따로 비교하고, 호출이 로봇을 멈추게 하지 않는다."
3. "CheckVLA는 호출 수를 맞춘 주기 재계획과 비교해 시점의 몫(+3.9%p)을 분리했지만 호출 모델과 추론량은 하나였다. 우리는 호출 수를 맞춘 뒤 추론 강도(low~max)를 두 번째 축으로 둔다."
4. "기존 트리거는 관측 쪽 신호다(정체, 행동 조건 예측 불일치). 우리는 계획 쪽 마감(T3a: 성공 롤아웃 conformal 마감 `D_k`)과 모델 자체 판단(T3b)을 같은 호출 수에서 비교해, 사용자가 말한 '이때쯤 나왔어야 하는데'가 관측 쪽 정체와 다른 정보인지 확인한다."
- 주의: "멈추지 않는다" 자체는 CheckVLA에도 있다(트리거 뒤에도 청크 계속 실행). 차별점은 "느린 **별도** API 모델 + 수 초 이상 지연 + effort 축".
