## 1. 사용자 지시 대비 결과 (모듈별)

사용자가 정한 모듈 설계의 뜻([사용자], user-log 20): "각 부분마다 어디의 어떤 연구가 그 부분에서 최고였는지, 무엇을 가져올 수 있는지, 우리 것에 어떻게 접목할지를 최대한 모으는 과정이다. 모듈 단위로만 최고이면 된다. 로봇이나 VLA 분야일 필요가 없다. LLM, VLM 자체의 방법 중 아직 로봇에 적용되지 않은 것도 찾는다."

### M1. 이미지 → Jev 입력
- [사용자] "Jev는 이미지를 못 본다. LLM/VLM/VLA 논문뿐 아니라 텍스트와 이미지를 제대로 변환하는 다른 분야 연구에서 가장 효율적인 방법을 찾는다." (user-log 11)
  - "변환 방법은 사용자가 정한다"는 **user-log에 없다**. CLAUDE.md 첫 세션 제약에서 온 줄이다(D11 I-5). 그래서 이 모듈은 최종안을 고르지 않고 후보 A / B / C 순위만 냈다.
- 가져온 것: 게임 에이전트 lmgame-Bench(기호 상태 표로 Sokoban 상자 1.0~1.3 → 5.3~6.0개, 텍스트 전용 모델도 상위권), ViPlan(VLM 술어 신뢰도), 웹 에이전트 Read More·FocusAgent·ACON(무엇을 넣을지). lmgame·ViPlan은 D13에서 **원문 정독**.
- 접목: 모든 모듈이 쓰는 **술어 등록부 하나**(T1 코드 기하 / T2 임계 민감 / T3 VLM 필요). 파생 술어는 코드로 계산한다.
- 아직 가정: lmgame 상태는 오라클이다(인식 잡음 조건 필요). 지연 목표 p50 ≤ 70 ms / p95 ≤ 120 ms는 측정 전 값이다. 비교는 E3.

### M2. Astra → Jev 전달 (세션 계약)
- [사용자] "(2) Astra→Jev 전달: 1번과 거의 같은 문제다. Astra는 이미지를 보고 명령하지만 Jev는 아니니, 효율적으로 전달하는 방법을 더 생각한다." (user-log 11)
- 가져온 것: AgentSpec(ICSE 2026, 규칙 = 트리거 + 술어 + 집행), Magentic-One 원장(기간 밖, 기초 문헌), Agentproof(DFA 감시, LOW), AgileThinker(실시간 계획 참조). AgentSpec·AgileThinker·COPE는 D13 **원문 정독**.
- 접목: 세션 계약 v1(목표 중심 + 가정 술어 + 버전). Jev는 계약 전체가 아니라 **현재 단계 조각**만 본다.
- 아직 가정: **COPE는 v1의 근거에서 빠졌다**(D13). 큰 계획기 → 작은 실행기 이득(Llama-3B 42.8 → 53.0)은 절차형 계획에서 나왔다. v1은 이제 "설계 선택"이고 E-M2-1의 B-COPE 조건으로 확인한다. `rationale`을 Jev에서 빼는 기본값(D20)의 근거도 그만큼 약해졌다. DFA는 잠정 기본(D4).

### M3. 행동 표현
- [사용자] "(3) 행동: 촘촘하게 가도 된다. Jev 방식이면 충분히 가능하고 할 만하다고 본다." (user-log 11)
- 가져온 것: SPF(CoRL 2025), GUI-Cursor(ICML 2026), Show-Harness(D9 정독), RoboDawn(D8 정독), 보기 수 연구 2604.14634(메인 원문 확인, LOW-MED).
- 접목: 세 안. D-줌(= 사용자 "촘촘하게"를 **Claude가 구현한 안**, 방향 xy 10 + z 4, 크기 로그 간격 5구간 + 세밀 5~9) / G(목표 지정형) / H(혼합, [제안] 1순위 후보). Jev는 숫자를 만들지 않고 코드가 만든 보기를 고른다.
- 아직 가정: 반대 증거가 있다. 학습 없는 모델은 잘게 여러 번보다 목표를 한 번에 가리킬 때 훨씬 잘했다(SPF 7% / 40% / 87~100%). 다만 Jev가 아닌 모델의 결과다. 크기 cm 값은 가정이다. 보기 이름 편향(Type-Safe)은 D32. 결정은 E-M3-2.

### M4. 계단식 겹침 호출 + 자기 확인 ★
- [사용자] "1초에 Jev를 한 번이 아니라 3번 정도 계단식으로 겹쳐 쓴다." "겹치는 부분의 움직임이 제대로 반영됐는지 스스로 감지하고 업데이트하는 시스템이 자동으로 있어야 한다. 이게 굉장히 중요하다." (user-log 11)
- 가져온 것(분야가 넓다): 동시통역 LocalAgreement·RALCP(기간 밖, 기초 문헌), LLM 추측 디코딩 FLy(ICLR 2026, 메인 원문 확인), VLA RTC(NeurIPS 2025), 로봇 실패 예측 FIPER(NeurIPS 2025). 가장 가까운 선행 A3·Slow Brain은 D8·D9에서 **본문·부록 정독**.
- 접목: 표 원장 + 전제 epoch. (a) 호출 사이 typed 합의와 (b) 실행 뒤 코드 예상 상태(M5 `ref(t)` + M3 `expected_after`) 대 측정 상태가 둘 다 맞을 때만 확정. 어긋나면 그 전제에 기댄 표를 버린다.
- 아직 가정: (a)의 실익이 구조적으로 작을 위험(D6 R2: 온도 ≈ 0, 0.33초 사이 변화 작음) → E0.5가 먼저 잰다. 선행 없음 판단은 확신 MED.

### M5. 스무딩
- [사용자] "두 단계: 먼저 RTC와 유사한 방법, 다음으로 액션 스무딩이나 VLA에서 쓰는 부드럽게 하는 방법으로 아주 작은 움직임을 처리한다." (user-log 11)
- 가져온 것: RTC(식 5 모양, D13에서 **코드까지 확인**), Ruckig(RSS 2021, 기간 밖, FluxVLA Table 11 1.17 ms 원문 확인), 게임 애니메이션의 관성화(기간 밖, 업계 발표), SEAM·WAM(LOW-MED, D13 정독).
- 접목: 3층. L1 시간 정렬 / L2 같은 보기끼리만 RTC 식 5 가중으로 이어 붙임(다른 보기는 평균하지 않음) / L3 Ruckig. 관성화는 접촉 근처에서 끈다.
- 아직 가정: T_f 0([가정]), 관절 공간 1순위([가정]), 블렌딩이 이산 선택기에 그대로 옮겨진다는 증거 없음. Ruckig·관성화는 잠정 기본(D4).

### M6. 스킬과 Jev 결합
- [사용자] "기존 스킬도 Jev와 엄청 연관될수록 좋다." "1년 이내에 나온 GitHub 스타 상위 5개 중에서, LLM이 스킬을 불러오고 끝이 아니라 잘게 엮어 놓은 논문을 참고해 파이프라인을 대충 짜 본다." (user-log 11)
- 가져온 것: 스타 상위(2026-09-23 측정) PhyAgentOS 2,481 / Zetta 1,252 / Harness VLA 962 / CaP-X 819(ICML 2026) / 5위 ROSClaw 625 또는 Show-Harness 451(D8b). Harness VLA·CaP-X는 D10a에서 **코드까지 정독**. 그 밖에 GPSFSM(IROS 2026), Agent Skills·MCP 표준, DB 트랜잭션의 사가(기간 밖).
- 접목: 스킬 계약 + 단계 FSM + **단계별 결정 지점**(스킬에 고정된 `dp.*` id). "잘게 엮기"의 뜻은 [제안]: 스킬 안의 단계 경계·결정 지점마다 Jev가 고른다. 생성 스킬의 typed hole 검사는 원문 미평가 접목이다.
- 아직 가정: "(b) 생성 스킬 먼저"는 user-log 3에 대한 **Claude의 해석**이다(D8). 반대 증거: SkillsBench에서 스스로 만든 스킬이 스킬 없음보다 −8.1~−11.5pp(조건 다름).

### M7. 진행 판별
- [사용자] "VLA에서 "계획대로"를 무엇으로 정의했는지 많이 참고한다." "하지만 VLA의 엄청난 단점은 다른 환경에 가면 일반화가 안 된다는 것이다. LLM은 일반화가 된다. 이걸 엄청 부각하고 항상 기억한다." (user-log 11)
- 가져온 것: FIPER·SAFE(NeurIPS 2025), FaRe(MED-LOW), LLM 웹 PRM Web-Shepherd(NeurIPS 2025 Spotlight), 프로세스 마이닝 정렬(기간 밖). CheckVLA·Critic in the Loop는 D10b **본문·부록 정독**, GPT-as-Policy gate는 D9.
- 접목: FAIL은 코드 critic 한 곳에서만. 하드 층 H1~H6(즉시 FAIL) + 소프트 7채널(서로 다른 채널 2개 이상이면 FAIL, AND).
- 아직 가정: 진행 대리값을 코드 기하로 바꿨는데 효과가 같다는 근거가 없다. conformal은 새 환경에서 교환 가능성이 깨질 수 있다. H6의 "2배"는 설계 여유값이다.

### M8. Astra 호출 시점과 다중 프레임
- [사용자] "적어도 실패 판정이 났을 때는 Astra를 부른다. 그 순간 한 장이 아니라 연속 프레임을 준다. 예: 이미지 하나에 사진 10개." "호출 방식은 비교 평가한다: Hz 단위 주기 / 정해 둔 필요한 순간마다 / "이때쯤 결과가 나왔어야 하는데 안 나오네"라는 자체 판단." (user-log 11)

- 접목: 트리거 T0 / T_fail(항상 호출) / T1 주기 / T2 정한 순간 / T3a 코드 마감 / T3b 모델 판단 / T_stag. 기본 다중 프레임 = 사용자 예시(한 장에 10프레임 격자).
- 아직 가정: T3b는 늦을 것이라는 사전 가설(BAGEN). 반대 증거 CheckVLA Table S6(아래 §2). effort 기본 high는 **사용자 원칙이 아니라 잠정 기본**(D5).

### M9. 실패 복구
- [사용자] "(7) 복구: VLA에서 가장 좋은 실패 복구 방법을 찾는다. 논문은 무조건 1년 반 이내." (user-log 11)
- 사실: 2026-09 기준 로봇 복구 기법끼리 같은 벤치마크 직접 비교는 없다 → **"최고"는 수치로 못 정했다.**
- 가져온 것: FaRe·RIR(언제/어디로/무엇을 남길지, 둘 다 MED-LOW·심사 전, 메인이 초록 재확인), FLARE(CVPR 2026, ID/OOD), Show-Harness 빈 집기 되돌림(D9), Harness VLA·CaP-X 복구 방식(D10a), PLANEX·BT 백체이닝(기간 밖).
- 접목: 실패 순간 Astra를 **비동기로** 부르고, 기다리는 동안 아래 층(L1 재시도 → L2 Jev가 복구 제안 중 선택 → L3 안전 대기)이 움직인다. 재개는 "사전조건이 참인 가장 늦은 체크포인트".
- 아직 가정: 복구 이득은 작고 조건부(FaRe 시뮬 +1.7%p). "반성 유지"에 반대 증거: CaP-X H.4 68.29 → 65.43.

### M10. 경험 축적
- [사용자] "경험 축적이 제대로 되어야 한다." "API로 불러오는 모델의 경험 축적을 어떻게 하는지, 어떻게 해야 효율적인지 논문을 찾는다. 1년 반 이내." (user-log 11)

## 3. 검증 과정에서 바로잡은 것 (주요 12건)

원 문서: 각 D 문서와 draft-log. 앞 6건은 인용·정의 오류, 뒤 6건은 사용자 의도 표기와 우리 작업 실수다.

1. **CheckVLA "적시 재현율" 정의(D10b)**: 우리가 "적시 재현율(CheckVLA 방식, τ = 2 s)"이라 부른 것은 원문 정의가 아니었다. 원문은 τ_on ≤ t* 그리고 t* + d_lat < τ_irrev. → 판정 기준은 **"고정 창 재현율(τ = 2 s)"**(우리 정의)로 이름을 바꾸고, 원문판은 병기 보고만(정본 §21·§23).

## 6. 다음 단계 제안 [제안]

user-log에는 모듈 설계 다음 단계에 대한 지시가 아직 없다. 아래는 Claude 제안이다.
1. **사용자 결정 받기**: §5.1 묶음, 특히 D29(논문 틀)와 D5·D14(effort·정지). CVPR 2027 제출까지 약 7주라 E0~E2a·EVAL S0~S4를 모두 돌리기 빠듯하다(SUMMARY D29).
2. **단계 3 = 첫 실험**: E0와 E0.5를 같은 날 먼저(E0.5 가장 먼저), 이어 E1 → E2a. 병행으로 EVAL S0(루프 동기 여부)·S1(H200 Isaac Sim 스모크). 판정 기준은 이미 사전 등록되어 있다.
3. **E0.5 결과로 M4 주장 폭 조정**: flip ≈ 0이면 C1을 "(b) 되먹임 + 전제 epoch"로 미리 좁힌다.
4. **남은 정리**: user-log에 없는 두 줄(effort 발언, M1 "변환 방법은 사용자가 정한다")을 사용자에게 확인. Overleaf에 §17~§25 반영 여부 점검(SUMMARY §6.3은 확인하지 않았다고 적음).
5. **선점 감시 계속**: 이 분야는 주 단위로 새 논문이 나온다(D7·D12 교훈).
