## 3. 가져올 것과 접목 방법

| 출처 | 원문에 있는 것 | 우리 접목안 [제안] |
|---|---|---|
| FaRe | 세계를 되돌리지 않고 **현재 물리 상태와 맞는 과거 기준점**을 찾음 | 체크포인트 = 원장 단계 경계. "어디로" = **현재 측정 상태에서 단계 k의 `entry` 술어가 모두 참이고, k 이전 단계의 결과 술어가 여전히 참인 가장 늦은 k**. 행동 트리 reactive sequence의 재개 규칙과 같은 모양(**기간 밖, 기초 문헌** — 설계 모양의 비유로만 쓰고 근거로 인용하지 않는다. 같은 규칙의 기간 안 근거는 FaRe "현재 물리 상태와 맞는 과거 기준점") |
| FaRe 가설 비교 | 계속/앞부분 복원/리셋을 예측 진행으로 비교 후 확정 | 코드가 후보 목록 작성 → Jev Choice로 하나 선택(**E1 전에는 확률 게이트를 끄고 최빈 선택만**. 최빈이 `NONE_ESCALATE`이면 안전 대기. "최상위 확률 < 0.6이면 안전 대기" 게이트는 E1 뒤에 켤 후보 값, 00-interfaces §6) → Astra 응답이 최종 |
| RIR | 거친→세밀 재개점 선택, 남길 것·버릴 것 규칙 | 거친 = 단계 단위 체크포인트, 세밀 = 단계 안 스킬 하위 단계(접근/잡기/들기). 남길 것 = 목표, 검증된 환경 지식(물체 위치는 **측정 시각과 함께**), 시도 이정표, Astra 실패 분석. 버릴 것 = "현재 상태" 서술 전부 → 재개 뒤 센서로 다시 읽는다 |
| Safe to Resume? | 부수 효과가 복원을 무효로 만든다 | 체크포인트에 **술어 벡터만** 저장하고, 재개 가능 여부는 저장값이 아니라 **지금 측정한 술어**로 판단(부수 효과 — 떨어뜨린·밀린 물체 — 가 자동 반영) |
| FLARE | ID/OOD로 재시도와 리셋을 가름 | ID = 사건 종류가 세션 계약의 "예상 실패 목록"에 있고 계획 가정 술어(물체 존재, 경로 비어 있음 등)가 모두 참. OOD = 가정 술어 하나라도 거짓. ID면 아래 층이 복구까지 해도 됨, OOD면 아래 층은 안전 대기·리셋만 하고 재개는 Astra가 정함 |
| REACH | 실패 행동을 부정 조건으로 | Jev 재질의 때 직전 실패 보기를 "이미 실패함" 표시 또는 제외. 같은 스킬 같은 파라미터 재시도 금지 |
| CorrectVLA | 고칠 수 있는 건 실행 어긋남(약 22~23%)뿐 | 아래 층의 스킬 파라미터 변경 재시도는 **실행 어긋남 유형(ID)에만** 쓴다. 작업 오해·인식 실패는 Astra로 |
| AgileThinker, Slow Brain | 느린 쪽을 기다리지 않음 | Astra 응답 전 아래 층 진행, 도착 시 덮어쓰기 |
| WebRollback | 되돌리기를 명시 행동으로 | Astra 출력 스키마에 `rollback_to=<체크포인트 id>`, `reset_skill=<id>`, `new_plan=[...]`, `continue` 네 선택지를 분리 |
| VRL-Bench (LOW), 2606.15017 | 반성 메모리가 단순 재시도보다 나쁠 수 있음 | 기준 방법에 "메모리 없는 재시도" 필수 |
| 사가(기초) + SagaLLM + Atomix | 가역 효과는 역순(역방향 의존 순서)으로 보상, 비가역 효과는 커밋 게이트 전 방출 금지. 보상은 외부 효과가 모두 가역일 때만 돕는다. Atomix는 물리 행동을 비가역 게이트 대상으로 직접 꼽음 | [접목안, 00 §14-3 채택] M6 스킬 카드 단계의 `effect`(가역 + 보상 스킬 id / 비가역)를 읽어 재개 경로를 만든다: 현재 위치에서 재개 지점 k까지 **가역 단계의 보상 스킬을 역순 실행**(backward recovery). 경로에 비가역 단계가 있으면 **그 경계를 넘어 되돌리지 않고** 경계 뒤 체크포인트만 후보로 둔다(경계 앞은 forward recovery = 재시도·리셋·Astra `new_plan`). 보상 뒤 재개 가능 조건은 다시 측정한 술어로 확인 |
| M7 원장 정렬(00 §14-2) | 정렬 적합성 검사의 마지막 동기 이동 위치(기간 밖 기초 문헌 + 2511.10876, M7 §2) | [접목안] 재개 지점 검사의 시작점 = M7이 매 틱 갱신해 넘기는 **마지막 일치 위치**. M9는 그 위치부터 거꾸로 "재개 가능 조건"을 보고, 원장 정렬을 따로 다시 하지 않는다 |

근거 상향 메모(00-interfaces §12, D3 §2.1): "`entry`가 참인 가장 늦은 지점부터 재개" 규칙의 근거는 PLANEX 삼각표(Fikes·Hart·Nilsson 1972, **기간 밖, 기초 문헌**) + BT 백체이닝(ICRA 2019, 기간 밖) + BacktrackAgent(EMNLP 2025, 기간 안)로 올라갔다. 기간 밖 두 건의 사용은 [결정 필요] 4(사용자 승인) 전까지 잠정이다. 불허하면 근거는 FaRe(2026-09, MED-LOW)·BacktrackAgent만 남고 규칙 자체는 바뀌지 않는다.

### 4.2 체크포인트 정의
- **생성**: 원장 단계 k의 완료 술어 `exit`(단계 k)가 참이 된 순간. 저장 = (단계 id, 그 순간의 술어 벡터, 시각, 물체 위치 추정과 측정 시각, 프레임 색인).
- **재개 가능 조건**: 지금 측정한 술어에서 단계 k+1의 `entry` 모두 참 **그리고** 단계 1..k의 결과 술어가 모두 참.
- **선택**: 재개 가능한 것 중 가장 늦은 k(진행 보존, RIR의 "진행 보존" 축). 없으면 리셋 스킬 → 다시 계산 → 그래도 없으면 Astra `new_plan`을 기다린다.
- **시작점(00 §14-2)**: 검사는 M7이 넘긴 마지막 일치 위치 m에서 시작해 m, m−1, … 순으로 "재개 가능 조건"을 본다. 결과는 "가장 늦은 k" 규칙과 같고, 계산을 M7과 공유한다.
- **되돌림 경로(사가, 00 §14-3)**: 현재 단계에서 고른 k까지 되돌아가야 하면 사이 단계들의 보상 스킬(M6 `effect`의 보상 스킬 id)을 **역순으로** 실행한다. 사이에 `effect`가 비가역인 단계(예: 놓기, 끼우기 완료)가 있으면 그 경계 앞의 k는 후보에서 뺀다(비가역 경계를 넘어 되돌리지 않는다). 경계 뒤에 재개 가능한 k가 없으면 기존 규칙대로 리셋 스킬 → 다시 계산 → Astra `new_plan`.
- **보상 뒤 재확인**: 로봇 보상 스킬은 원상 복구를 보장하지 않는다(물체 자세 변화). 보상 뒤 재개 가능 조건을 **다시 측정한 술어로** 확인한다(Safe to Resume? 행과 같은 원칙).
- **세밀 단계**(RIR 거친→세밀): 단계 안에서 접근·잡기·들기 경계에도 작은 체크포인트를 둔다. 먼저 단계 단위로 고르고, 그 단계 안에서 세밀 체크포인트를 고른다.

### 4.3 무엇을 남기나 (RIR 규칙의 로봇판)
- 남김: 목표, 검증된 환경 지식(측정 시각 포함), 완료 이정표, 이번 실패의 Astra 분석, 실패한 (스킬, 파라미터) 목록.
- 버림: "지금 물체가 어디 있다" 같은 현재 상태 서술. 재개 직후 인식으로 새로 읽는다.
- Jev에는 교훈 목록을 넣지 않는다(plan M10: 정확히 맞는 규칙 0~2개만).

## 5. 비교 실험 E-M9 (사전 등록)
- 순서: Jev p95(E0)와 확률 게이트 방침(E1)에 기대므로 E0·E1 뒤에 돌린다. 자리는 00-interfaces §8·§13 순서대로 E0 → E0.5 → E1 → E2a → E-M4 → E-M3-2 → E-M5-1 → E-M8a → **E-M9** → E-M6·E-M10이다(M3·M4·M5가 고정된 뒤에 실패 흐름을 잰다). 환경은 초기 실험(E0~E3)과 같은 단일 팔 자작 장면을 쓰고 RoboDojo 본 평가와 섞지 않는다(00 §13). 확률 게이트 변형(L2 0.6)은 E1 뒤에만.
- 과제: 단일 pick-and-place + 2~3단계 과제, 실패 주입 ID(미끄러짐, 잡기 빗나감, 운반 중 작은 위치 교란) / OOD(물체 제거·교체, 경로에 새 장애물, 처음 보는 물체). 시뮬(주 벤치마크는 plan §3 [결정 필요]).
- 조건
  - P 1순위(§4.1)
  - B1 멈추고 기다리기(C1, stop-and-wait)
  - B2 메모리 없는 재시도(같은 스킬 같은 파라미터, 한도 3회)
  - B3 완전 리셋(처음 단계부터)
  - B4 Astra 맨 마지막(C2)
  - B5 아래 층만(Astra 없음)
  - B6 Astra만(아래 층 없음, C3)
  - 절제: P−체크포인트(항상 리셋), P−남김 규칙(실패 분석·실패 목록 없이), P−ID/OOD(항상 L1부터), P−부정 조건(직전 실패 보기 허용), P−사가(보상 역순 실행 없이 고른 체크포인트에서 바로 재개 시도, 비가역 경계 검사 유지)
- 지표: 복구 성공률(FAIL 뒤 τ=30초 안에 다음 단계 완료), 전체 성공률, 복구 시간, **정지 시간**, 같은 실패 반복률, Astra 호출 수·비용, 되돌림 횟수(RIR 지표).
- **판정 기준(실행 전 고정)**
  1. P가 B1 대비 복구 성공률 −3%p 이내(비열등) **그리고** 정지 시간 50% 이하면 사용자 원칙("웬만하면 멈추지 않는다")이 비용 없이 지켜진다고 보고 채택.
  2. P가 B2보다 +5%p 이상이 아니면 "메모리·체크포인트의 가치 없음"으로 보고하고 기본을 B2+Astra로 단순화 검토.
  3. B1이 정밀 과제 부분집합에서 P보다 +5%p 이상이면 정밀 구간 정지 허용을 [결정 필요]로 올린다.
  4. 절제 각각이 P보다 3%p 이상 떨어질 때만 그 부품의 기여를 주장한다.
  5. 시드 3개 이상, 부트스트랩 95% 구간.

## 6. 반대 증거와 위험
1. **복구 이득은 작고 조건부**: FaRe 시뮬 +1.7%p, 트리거 없으면 기준보다 나쁨(차이 0.5%p, 유의성 미확인). LIBERO-RECOVER에서 복구 데이터 학습은 표준 성공률을 깎았다.
2. **RIR은 환경 복원을 전제**한다. 로봇 근거가 아니다. 가져오는 것은 재개점 선택 순서와 남김 규칙뿐이다.
3. **반성 메모리가 재시도보다 나쁠 수 있다**(VRL-Bench LOW, 2606.15017).
4. **물리 부수 효과**: 체크포인트 복귀가 "재개 가능"이라고 판정해도 술어로 표현 안 된 변화(물체 자세 미세 변화, 쏟아짐)는 놓친다(Safe to Resume?의 로봇판, 우리 추론).
5. **아래 층과 Astra의 충돌**: 아래 층이 체크포인트 k로 이미 돌아갔는데 Astra가 k′를 지시하면 두 번 움직인다. commit 창과 "아래 층 결과를 Astra 입력에 포함하지 못하는 시차"가 남는다.
6. **체크포인트 정의가 M1에 달려 있다**: 술어가 없으면 재개 가능 판정이 불가능하다.
7. 핵심 근거(FaRe·RIR)가 모두 MED-LOW, 심사 전이다. "세 결정 분해"는 설계 정리 도구로 쓰고 성능 근거로 인용하지 않는다(v3/17 B8).
8. **사가 근거는 소프트웨어 효과에서 나왔다**: DB 사가·SagaLLM·Atomix의 보상은 소프트웨어 상태다. 로봇 보상 스킬(내려놓기·후퇴)은 물체 자세를 바꿀 수 있어 정확한 역연산이 아니다 → 보상 뒤 재측정 필수. SagaLLM은 기간 8일 밖, Atomix는 무학회.

- 열린 질문: "예상 실패 목록"(ID 판정 기준)을 Astra가 초기 계획 때 쓰게 할지, M10 경험에서 채울지.
- 열린 질문: 양팔 과제에서 한 팔 실패 시 다른 팔 진행을 계속할지.
