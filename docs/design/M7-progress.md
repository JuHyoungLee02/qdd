[사용자] (user-log 11 (5)) "VLA에서 '계획대로'를 무엇으로 정의했는지 많이 참고한다. VLA는 로봇을 학술적으로 조종하는 개념 공부를 많이 해 놓았다." "하지만 VLA의 엄청난 단점은 다른 환경에 가면 일반화가 안 된다는 것이다. LLM은 일반화가 된다. 이걸 엄청 부각하고 항상 기억한다."
[사용자] (user-log 5) "프레임별로 확인해서 Astra의 계획대로 되고 있는지 판별한다."

[제안] (plan v4.3 M7 그대로, 00-interfaces §4로 확정) **실패 판정은 한 곳, 코드 critic에서만 한다.** Jev·Astra·M4는 critic의 입력 채널이지 별도 판정자가 아니다. **M4는 신호만 낸다**(CONTRADICT → 하드 채널 H4(모순된 술어가 T1일 때, 아니면 `C_m4`), DEVIATE → 소프트 채널 `C_m4`, `flip_score` → 소프트 채널 `C_flip`). M2 가정 술어 거짓 → 소프트 채널 `C_assume`. AND 결합(소프트 채널 2개 이상이면 FAIL, 1개면 WARN)은 M7에만 둔다. critic이 FAIL을 내면 M8(Astra 호출)과 M9(아래 층 복구)가 동시에 시작된다. **FAIL 없이 M9가 시작되거나 로봇이 완전 정지하는 경로는 없다**(정지는 T0과 M9 L3뿐).

## 4. 설계안

### 4.1 "계획대로"의 정의 [제안]
VLA 쪽 정의(π*0.6: 남은 시간 / π0.7: 조건 + 실수 구간 / R²VLM: 단계 완료 상태 / SAFE·FIPER: 성공 롤아웃 분포 안)를 합쳐 세 조건의 AND로 정의한다.
1. **불변**: 현재 단계의 불변 술어 `invariants_k`가 모두 참(예: 운반 중 파지 유지).
2. **순서**: 완료 술어가 원장 순서대로 참이 되어 왔다(이미 참이 된 이전 단계의 결과 술어가 거짓으로 돌아가지 않음).
3. **분포 안**: 단계 경과 시간이 conformal 마감 `D_k` 안이고, 진행 대리값이 정체 규칙에 걸리지 않음.

### 4.2 1순위: 2층 critic 규칙 (파라미터는 개발 시드로 조정하고 적응 예산 열에 적는다)

**술어 등급 규칙(00-interfaces §11.2, D2 B4)**: 하드 층은 H1·H2(스킬 오류 코드)·H3·H4·H5·H6(마감 2배 초과)이다. 술어를 쓰는 H1·H3·H4·H5는 M1 등록부의 **T1 술어만** 쓴다. H2·H6은 술어가 아니라 결정적 코드 신호(오류 코드, 시계)다. T2 술어의 같은 위반은 소프트 채널 `C_pred`로, `unknown`(가려짐·`id_uncertain`·T3 미측정)은 **위반으로 세지 않고** 1.0초 넘게 이어질 때만 `C_pred`로 간다. T3 술어는 하드 층에 쓰지 않는다.

**하드 층 (즉시 FAIL, 투표 없음)**
- H1 **T1** 불변 술어(`invariants_k`) 위반이 연속 2틱(0.2초, 센서 잡음 거르기).
- H2 스킬 오류 코드(IK 실패, 충돌 정지, 타임아웃).
- H3 다음 스킬 시작 시점에 **T1** `entry_k` 중 하나라도 거짓(CommitFlow식 전이 직전 확인). 예: M6 `entry`의 `gripper_open`·`not holding(any)`는 T1이라 H3, `reachable(target)`은 T2라 `C_pred`.
- **H4 M4 CONTRADICT**(M4 (b)가 예상 결과 술어와 모순되는 측정을 확정): 모순된 `expected_after` 술어가 **T1**이면 즉시 FAIL(00-interfaces §4). T2이면 `C_m4`로 셈. M4는 이 신호만 보내고 직전 확정 행동을 감속하며 이어간다. 정지·복구는 이 FAIL 뒤 M9가 맡는다.
- H5 M2 `forbidden`의 `enforce: fail` 술어가 참(M2 검사기가 T1만 허용, M2 §4.1 2c).
- **H6 마감 2배 초과**: 단계 경과 > `2 × D_k`(D5 1-3 해소, 00 §11.2). 첫 판은 이것을 소프트 층의 "`C_dead` 단독 FAIL 예외"로 두었다. 그러면 00 §4의 "소프트 채널 2개 이상이면 FAIL, 1개면 WARN"에 예외가 생긴다. 하드 층으로 옮기는 이유: (1) 경과 시간은 시계로 재는 결정적 양이라 술어 추출 잡음이 없다(00 §11.2가 하드 층에 요구하는 "결정적" 성질, T1과 같은 등급). (2) `D_k` 보정의 임계 민감도는 2배 여유로 흡수한다. (3) 규칙을 지우면 한 채널만 계속 뜨는 경우 FAIL이 영영 안 나서 "실패할 때마다 Astra"(사용자 원칙)가 막힌다. `D_k`가 대체값(1.5×`T_exp_k`)일 때도 같은 규칙을 쓴다.

- **공유 보기 목록 `PROGRESS_OPTIONS`**(00-interfaces §11.2, D2 B11): `valid_progress`(유효 진행) / `allowed_change`(허용 변화) / `failure`(실패) / `recovering`(복구 중) + M3 공통 `NONE_ESCALATE`. M7 S5 감시 질문과 M6 `dp.grasp_result`가 이 한 목록을 쓴다(파지 세부 — 빈 집기·미끄러짐 — 는 보기가 아니라 `failure`의 `expected_after` 술어로 구분).
- **계약 버전 교체**: M2 계약 버전이 바뀌면 M4 `premise_epoch`가 +1 된다(00-interfaces §11.2). M7은 새 계약의 `exit_k`/`entry_k`/`invariants_k`로 다음 틱부터 바꾸고, 교체 직후 첫 틱의 H3은 새 `entry_k`로 검사한다. `C_stag`·`C_dead`의 단계 시계는 단계 id가 같으면 이어서 센다.
- **허용 게이트**(FaRe): 그리퍼 폭 변화율 > θ_g **그리고** 팔 속도 > θ_v 인 동안(잡기·놓기 전환 중)에는 소프트 판정을 보류한다. 보류 최대 **1.0초**(설정 표 "grasp/release 전환 보류", M9도 같은 값).
- **near/contact 정의**(설정 표, M3·M5와 공유): near = 목표까지 ≤ 5 cm, contact = 접촉 술어 참. M7은 이 정의로 단계 유형(접근/접촉)을 나눠 진행 대리값 `g(t)`와 정체 규칙의 `ε_k`를 고른다. 초기값: near/contact 구간에서는 `ε_k`를 먼 구간보다 작게(정밀 동작이 느린 것을 정체로 오인하지 않게), 값은 개발 시드로 조정.
- **S7 `expected_after`의 쓰임**: 스텝 끝 술어 불일치 자체의 범주 판정은 M4가 한다(중복 판정 방지). M7은 이 술어를 (1) 사건 문맥(어떤 예상이 깨졌나)에 넣어 M8·M9로 넘기고, (2) §4.1 "순서" 조건 검사에서 Jev가 결정한 스텝의 예상 결과로 쓴다.
- **원장 편차 구분(00 §14-2, 새 채널 아님)** [제안]: §4.1 "순서" 조건을 계산할 때 원장과 관측 술어 전이를 정렬해 편차를 둘로 나눠 원장·사건 문맥에 적는다. 발동은 기존 채널 규칙을 그대로 쓴다.
  - "건너뜀"(프로세스 마이닝의 모델만 이동) = 단계 k의 `exit_k`가 확인되지 않았는데 뒤 단계의 사건이 먼저 옴. 따로 발동하지 않고 뒤 단계 `entry` 검사로 간다(**T1**이면 H3, T2면 `C_pred`).
  - "계획 밖 사건"(로그만 이동) = 원장·`expected_after`에 없는 술어 전이(예: 운반 중 `holding`이 거짓이 됨). T1 불변 위반이면 H1, 그 밖은 `C_pred`(00 §11.2 등급 규칙 그대로).
  - **마지막 일치 위치** = 원장 순서대로 `exit`이 확인된 가장 늦은 단계(마지막 동기 이동). M7이 매 틱 갱신해 M9에 넘기고, M9는 이것을 재개 지점 검사의 시작점으로 쓴다(M9 §4.2). 한 계산을 두 모듈이 공유하고 M9가 다시 정렬하지 않는다.
  - `C_order`를 별도 소프트 채널로 둘지는 E-M7 조건 D4o 결과로만 정한다(00 §14-2).
- **판정**: 소프트 채널 2개 이상 동시 발동 → FAIL(FIPER의 AND 발상을 채널 투표로 옮긴 우리 안). 1개만 → WARN. 소프트 층에는 예외가 없다(옛 "`C_dead` 2×`D_k` 단독 FAIL"은 하드 채널 H6으로 옮겼다).
- **같은 출처 채널 계수**: E-M7 전 기본값은 `C_m4`·`C_flip`(둘 다 M4 출처) 동시 발동을 **1표**로 센다(D4 C-11, M4 §4.2). E-M7 D4f 결과(동시 발동 비율, §6-8)로 확정한다.
- **복구 직후 cooldown**: 2초 동안 소프트 FAIL 금지(하드는 유지). M8 문지기의 cooldown과 같은 값.
- **WARN의 용도**: M8 호출 모드 (3)과 문지기의 입력. WARN만으로는 복구를 시작하지 않는다.

### 4.3 대안
- A1 **OR 규칙**: 소프트 채널 하나라도 발동하면 FAIL. 적시 재현율은 오르고 오경보가 늘어난다. FIPER 부록 C.4.1의 방향(시간 변동 임계값 = TPR↑, 오경보↑)과 같다. E-M7에서 AND와 같은 오경보율로 맞춰 비교.
- A2 **CUSUM 채널**: C_stag 대신 `g`의 증가율에 CUSUM(기간 밖 기초 문헌, 2608.02464가 LLM 궤적에 사용, LOW). 파라미터가 적다.
- A3 **학습형 진행 모델 옆 센서**: Robo-Dopamine GRM 8B(CVPR 2026). "API 모델만" 틀과 맞는지 [결정 필요](plan §5-9와 같음).
- A4 **Astra GVL 주기 확인**(기간 밖 기초 문헌): M8 주기 호출 조건에서만. FAIL 채널로만 쓰고 OK 근거로는 안 쓴다.
- A5 **조건부 conformal test martingale**(2602.13848, 무학회 LOW-MED, 이론만): `C_dead`·`C_flip`의 임계값을 성공 실행 고정 기준 집합 대비 베팅 마팅게일(1/α를 넘으면 발동)로 바꾼다. 원문 주장 = anytime-valid 1종 오류, 기준 집합 오염 없음, 탐지 지연 한계(초록). 로봇·LLM 에이전트 적용 사례는 없다 → 대안 조건으로만(E-M7 D10).

## 5. 비교 실험 E-M7 (사전 등록)

- **데이터**: 개발 시드 성공 롤아웃(보정용) + 평가 시드 롤아웃에 실패 주입(물체 미끄러짐, 운반 중 위치 교란, 방해물 삽입, 잡기 빗나감; FailSafe식 생성) + 주입 없는 롤아웃. 정답 라벨 = 주입 시각과 센서 술어로 확인한 실제 실패(LLM 판정 라벨 금지, plan M10 원칙). **오프라인 재생**으로 모든 조건을 같은 궤적에서 비교한다(로봇 재실행 비용 없음). 정상 궤적 중 "첫 교정되지 않은 치명 오류" 이전 구간은 정상으로 라벨(2609.02057의 라벨 규칙, LOW지만 라벨 정의로는 타당).
- **순서**: E-M7은 기록 궤적 재생이라 주 실험 순서(00-interfaces §13: E0 → E0.5 → E1 → E2a → E-M4 → E-M3-2 → E-M5-1)와 **오프라인으로 병행**한다. C_jev의 확률 게이트 변형은 E1 뒤에만 넣는다.
- **조건**: D0 하드 층만(H4·H5 포함, T1만) / D0x 하드 층에 T2까지 넣음(등급 규칙의 오경보 효과 확인용 대조) / D1 +C_stag / D2 +C_dead / D3 +C_jev(최빈) / D4 +C_m4 / D4f +C_flip / D4a +C_assume / D4p +C_pred / D5 전부 AND(1순위) / D6 전부 OR(A1) / D7 Jev 범주 단독 / D8 Astra 주기 GVL 단독 / D9 D5 + CUSUM 대체(A2) / **D4o** D5 + `C_order`를 별도 소프트 채널로(원장 "건너뜀·계획 밖 사건" 편차 수가 문턱을 넘으면 발동, 00 §14-2: 채널 추가는 이 결과로 판단) / **D10** D5에서 `C_dead`·`C_flip` 임계를 조건부 CTM으로(A5) / (E1 뒤) D3p C_jev 확률 게이트 0.8.
- **지표**: 오경보율 5%와 10%에서의 적시 재현율(CheckVLA 방식: 실패 시작 뒤 τ초 안 탐지, τ=2초), 탐지 지연 중앙값, 성공 롤아웃 오경보율, 새 환경(standard→random)에서 재보정에 필요한 성공 롤아웃 수.
- **기록 추가(D6 R3, 00 §17)**: E-M7 재생과 E-M4(·E-M4-lat) 폐루프 기록에 에피소드 단위로 (i) **epoch 교체 빈도**(초당, M7 DEVIATE·CONTRADICT·FAIL 등 교체 원인별 칸), (ii) **미확정 실행 비율**(가확정으로 실행된 결정 스텝 / 결정 스텝), (iii) **번복률**(가확정 뒤 바뀐 스텝 / 가확정 스텝)과 에피소드 결과(성공/실패, 실패면 주입 종류)를 남긴다. 보고는 평균이 아니라 **성공/실패 분리 ECDF**(조건별, E-M4-lat는 지연 점별). 형식은 M4 §5.1 (3)과 한 벌이다. 재생(E-M7)에서는 M4가 궤적을 바꾸지 못하므로 (i)은 "그 조건의 채널이 DEVIATE를 냈다면 epoch가 바뀌었을 횟수"로 계산한다.
- **판정 기준(실행 전 고정)**
  1. D5가 D0보다 오경보 5%에서 적시 재현율 +10%p 이상이면 1순위 채택. 아니면 D0 + 가장 좋은 단일 채널.
  2. C_jev는 D5에서 뺐을 때 적시 재현율이 3%p 이상 떨어질 때만 남긴다. 아니면 빼고 기록(Jev의 가치가 여기엔 없다는 결과도 보고). C_flip·C_assume·C_pred도 같은 규칙(C_flip은 Rewind-IL이 잠정 근거라 빼도 설계가 서야 한다).
  2b. D0x가 D0보다 성공 롤아웃 오경보율이 높고(2%p 이상) 적시 재현율 이득이 3%p 미만이면 "하드 층은 T1만" 규칙을 확정 근거로 기록.
  3. D6(OR)이 같은 오경보율에서 D5보다 5%p 이상 높으면 OR로 바꾼다.
  4. D7·D8(모델 단독)이 D5보다 낮으면 "실패 판정은 코드 한 곳" 원칙 유지. 높으면 [결정 필요]로 올린다.
  5. 시드 3개 이상, 부트스트랩 95% 신뢰구간이 0을 포함하면 "차이 없음"으로 적는다.
  6. [제안] D4o가 D5보다 오경보 5%에서 적시 재현율 +3%p 이상이고 성공 롤아웃 오경보율 증가가 1%p 이하일 때만 `C_order` 채널 추가를 메인 세션에 올린다. 아니면 원장 편차 구분은 사건 문맥·M9 공유용으로만 둔다.
  7. [제안] D10이 D5와 같은 오경보율에서 탐지 지연 중앙값을 0.5초 이상 줄이거나 새 환경 재보정에 필요한 성공 롤아웃 수를 줄이면 A5를 [결정 필요]로 올린다. 아니면 conformal 분위수 유지.
  8. [제안, D6] 성공 롤아웃에서 epoch 교체 빈도가 초당 1회 상한에 닿는 시간 비율 중앙값이 5%를 넘는 조건은 (적시 재현율과 무관하게) "오경보가 epoch를 흔든다"로 표시하고, 1순위 후보면 conformal 임계 재보정(ACI, A5·D10과 같은 묶음)을 먼저 본다. 실패 롤아웃의 분포는 M4 §5.1 판정 16과 함께 해석한다.

## 6. 반대 증거와 위험
1. **진행 대리값이 약할 수 있다.** FaRe의 이득은 8B 학습 진행 모델 위에서 나왔다. 코드 기하 `g(t)`가 같은 역할을 할지 모른다. 천 접기처럼 기하로 진행을 못 쓰는 과제는 C_stag가 비고 C_jev에 기댄다.
2. **FaRe 트리거 절제 차이는 0.5%p**(91.0 대 91.5), 반복 수·분산 미확인(v3/17 B8). "매 스텝 판정이 해롭다"를 강한 근거로 쓰지 않는다.
3. **conformal 보장은 교환 가능성 가정** 아래에서만 성립한다. 새 환경(random)에서는 개발 시드 분포가 달라 보장이 깨진다. SAFE 저자도 온라인 conformal을 미래 과제로 적었다(부록 F.2 제목). → 새 환경에서 재보정에 필요한 성공 롤아웃 수를 지표로 둔다.
4. **SAFE·FIPER는 정책 내부 특징(또는 행동 분포)이 있어야 한다.** 우리 스킬 + Jev 구조에는 행동 청크 엔트로피가 없다. 가져오는 것은 **보정 방식과 AND 구조**뿐이다.
5. **AND 규칙은 느리다.** 채널 둘이 겹칠 때까지 기다리므로 탐지 지연이 늘 수 있다. 정밀 삽입처럼 짧은 창에서 실패가 끝나는 과제는 하드 층에 기대야 한다.
6. **Jev 확률 보정 전**(E1 전)에는 임계값 0.8이 뜻 없는 숫자일 수 있다 → E1 전에는 확률 게이트를 끄고 최빈 선택만 쓴다(00-interfaces §6). 최빈 "실패"만으로는 오경보가 늘 수 있으나 AND 결합(다른 채널과 동시)이 이를 줄인다.
7. **"LLM은 일반화된다" 주장과의 관계**: critic은 코드라서 새 환경에서 무너지는 쪽은 인식 앞단과 임계값이다. 새 환경에서 critic의 오경보가 늘면 그것은 LLM이 아닌 부분의 한계로 따로 보고해야 한다(plan §3 "같은 인식 위 룰 대 LLM").
8. **M4 신호의 중복 계수**: `C_m4`(DEVIATE)와 `C_flip`은 같은 사건에서 함께 뜰 수 있다(둘 다 M4 출처). 서로 독립이 아니면 AND가 사실상 한 채널처럼 동작한다 → E-M7에서 두 채널의 동시 발동 비율을 재고, 높으면 둘을 한 채널로 묶는 안을 [결정 필요]로.
9. **등급 규칙의 비용**: 하드 층을 T1로 제한하면 `reachable`·`aligned_*` 같은 T2 위반은 다른 채널과 겹칠 때까지 FAIL이 늦어진다. D0x 대조로 오경보 감소와 지연 증가를 함께 잰다.
10. **원장 편차 구분의 잡음**: 술어 전이 추출 잡음이 크면 "계획 밖 사건" 오경보가 늘어난다(D4 §13). 기간 안 근거는 철도 소프트웨어 사례 1건의 최대치 수치(2511.10876)이고 로봇 근거가 아니다. 등급 규칙(하드는 T1만)과 `unknown` 비계수 규칙이 이 잡음을 거른다고 가정한다(미검증, E-M7 D4o에서 성공 롤아웃 오경보율로 확인).

## 7. 열린 질문, [결정 필요]
- [결정 필요, 사용자] M1 변환 방법. 이 문서는 등록부 인터페이스에만 의존하므로 결정이 채널 구조를 바꾸지 않는다. 단 T1 술어가 적은 후보면 하드 층이 약해진다.
- 열린 질문: `C_assume`과 `C_pred`는 같은 술어(예: `path_clear`)에서 함께 뜰 수 있다. §6-8과 같은 방식으로 동시 발동 비율을 E-M7에서 잰다.
- [결정 필요] 학습형 진행 모델(Robo-Dopamine GRM 8B)을 옆 센서로 허용할지(A3).
- (정리됨, 00 §14-2) `C_order` 새 채널은 두지 않는다. 원장 편차 구분 + M9와 마지막 일치 위치 공유로 대신하고, 채널 추가는 E-M7 D4o 결과로 판단한다(D4 §14-2의 [결정 필요: 메인 세션] 해소).
- [결정 필요] 판정을 AND(1순위)로 둘지 OR로 둘지 — E-M7 결과 전까지 AND를 기본으로 둔다.
- 열린 질문: 단계당 α를 본페로니로 나누면 단계가 많은 과제에서 마감이 너무 느슨해진다. 단계 유형별로 α를 달리할지.
- [결정 필요] 정밀 접촉 구간의 짧은 정지와 M9 안전 대기(L3)를 사용자 예외로 인정할지(00-interfaces §4). M7은 두 경우 모두 FAIL을 거치게 한다.
- 열린 질문: Astra가 원장에 적는 `T_exp_k`의 정확도. 처음 보는 과제에서는 conformal 표본이 없어 `1.5 × T_exp_k`에 기대야 한다(§4.2).

## 8. 확인 못 한 것
- FIPER·SAFE의 표 수치(정확도, 탐지 시간)는 이번에 옮기지 않았다. FIPER의 창 크기 값(부록 C.3)도 옮기지 않았다. FIPER 부록 인용 위치는 D1 검증으로 C.4.1(TNR/TPR 문장)·C.4.2(최고 TWA, 탐지 쪽 문장)로 고쳤다.
- 모든 신규 항목의 인용 수·스타(API 금지).
- LLM 에이전트 정체 감지의 학회 채택 논문(검색 1회로 못 찾음, 부재 주장 아님).
- 2608.02464의 코드·데이터 실재 여부.
- Web-Shepherd Table 1의 조건별 수치(체크리스트 유무 차이 크기).
- 정렬 기반 적합성 검사 기초 문헌(Adriansyah 외 2011) 원문은 읽지 않았다(D4 검증 §4). 2511.10876·2602.13848은 D4 검증이 초록과 학회 페이지(DOI)로 확인한 범위만 옮겼다.
