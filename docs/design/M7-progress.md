## 4. 설계안

### 4.1 "계획대로"의 정의 [제안]
VLA 쪽 정의(π*0.6: 남은 시간 / π0.7: 조건 + 실수 구간 / R²VLM: 단계 완료 상태 / SAFE·FIPER: 성공 롤아웃 분포 안)를 합쳐 세 조건의 AND로 정의한다.
1. **불변**: 현재 단계의 불변 술어 `inv_k`가 모두 참(예: 운반 중 파지 유지).
2. **순서**: 완료 술어가 원장 순서대로 참이 되어 왔다(이미 참이 된 이전 단계의 결과 술어가 거짓으로 돌아가지 않음).
3. **분포 안**: 단계 경과 시간이 conformal 마감 `D_k` 안이고, 진행 대리값이 정체 규칙에 걸리지 않음.

### 4.2 1순위: 2층 critic 규칙 (파라미터는 개발 시드로 조정하고 적응 예산 열에 적는다)

**하드 층 (즉시 FAIL, 투표 없음)**
- H1 불변 술어 위반이 연속 2틱(0.2초, 센서 잡음 거르기).
- H2 스킬 오류 코드(IK 실패, 충돌 정지, 타임아웃).
- H3 다음 스킬 시작 시점에 `pre_k` 중 하나라도 거짓(CommitFlow식 전이 직전 확인).

**소프트 층 (채널 투표)**
| 채널 | 발동 조건(초기값) | 근거 |
|---|---|---|
| C_stag 정체 | (a) `Δg < ε_k`가 N=10틱(1초) 연속 **또는** (b) 최고 `g`를 δ=진행 범위의 5% 넘게 갱신 못 한 채 M=20틱(2초) | FaRe (값은 우리 초기값) |
| C_dead 마감 | 단계 경과 > `D_k` (conformal, α_ep=0.1) | SAFE functional CP |
| C_jev Jev 범주 | S5 "실패" 확률 ≥ 0.8이 Jev 호출 2번 연속 (게이트로만, E1 보정 전) | Robo-Dopamine 2.0 범주, plan 확률 규칙 |
| C_m4 M4 불일치 | (b) 예상 대 측정이 "큼" 범주로 확정 3번 연속 | plan M4(b) |

- **허용 게이트**(FaRe): 그리퍼 폭 변화율 > θ_g **그리고** 팔 속도 > θ_v 인 동안(잡기·놓기 전환 중)에는 소프트 판정을 보류한다. 보류 최대 1초.
- **판정**: 소프트 채널 2개 이상 동시 발동 → FAIL(FIPER의 AND 발상을 채널 투표로 옮긴 우리 안). 1개만 → WARN.
- **예외**: C_dead가 `2 × D_k`를 넘으면 단독으로 FAIL(끝없는 WARN 방지).
- **복구 직후 cooldown**: 2초 동안 소프트 FAIL 금지(하드는 유지). M8 문지기의 cooldown과 같은 값.
- **WARN의 용도**: M8 호출 모드 (3)과 문지기의 입력. WARN만으로는 복구를 시작하지 않는다.

### 4.3 대안
- A1 **OR 규칙**: 소프트 채널 하나라도 발동하면 FAIL. 적시 재현율은 오르고 오경보가 늘어난다. FIPER 부록 C.4의 방향(시간 변동 임계값 = TPR↑, 오경보↑)과 같다. E-M7에서 AND와 같은 오경보율로 맞춰 비교.
- A2 **CUSUM 채널**: C_stag 대신 `g`의 증가율에 CUSUM(기간 밖 기초 문헌, 2608.02464가 LLM 궤적에 사용, LOW). 파라미터가 적다.
- A3 **학습형 진행 모델 옆 센서**: Robo-Dopamine GRM 8B(CVPR 2026). "API 모델만" 틀과 맞는지 [결정 필요](plan §5-9와 같음).
- A4 **Astra GVL 주기 확인**(기간 밖 기초 문헌): M8 주기 호출 조건에서만. FAIL 채널로만 쓰고 OK 근거로는 안 쓴다.

## 5. 비교 실험 E-M7 (사전 등록)

- **데이터**: 개발 시드 성공 롤아웃(보정용) + 평가 시드 롤아웃에 실패 주입(물체 미끄러짐, 운반 중 위치 교란, 방해물 삽입, 잡기 빗나감; FailSafe식 생성) + 주입 없는 롤아웃. 정답 라벨 = 주입 시각과 센서 술어로 확인한 실제 실패(LLM 판정 라벨 금지, plan M10 원칙). **오프라인 재생**으로 모든 조건을 같은 궤적에서 비교한다(로봇 재실행 비용 없음). 정상 궤적 중 "첫 교정되지 않은 치명 오류" 이전 구간은 정상으로 라벨(2609.02057의 라벨 규칙, LOW지만 라벨 정의로는 타당).
- **조건**: D0 하드 층만 / D1 +C_stag / D2 +C_dead / D3 +C_jev / D4 +C_m4 / D5 전부 AND(1순위) / D6 전부 OR(A1) / D7 Jev 범주 단독 / D8 Astra 주기 GVL 단독 / D9 D5 + CUSUM 대체(A2).
- **지표**: 오경보율 5%와 10%에서의 적시 재현율(CheckVLA 방식: 실패 시작 뒤 τ초 안 탐지, τ=2초), 탐지 지연 중앙값, 성공 롤아웃 오경보율, 새 환경(standard→random)에서 재보정에 필요한 성공 롤아웃 수.
- **판정 기준(실행 전 고정)**
  1. D5가 D0보다 오경보 5%에서 적시 재현율 +10%p 이상이면 1순위 채택. 아니면 D0 + 가장 좋은 단일 채널.
  2. C_jev는 D5에서 뺐을 때 적시 재현율이 3%p 이상 떨어질 때만 남긴다. 아니면 빼고 기록(Jev의 가치가 여기엔 없다는 결과도 보고).
  3. D6(OR)이 같은 오경보율에서 D5보다 5%p 이상 높으면 OR로 바꾼다.
  4. D7·D8(모델 단독)이 D5보다 낮으면 "실패 판정은 코드 한 곳" 원칙 유지. 높으면 [결정 필요]로 올린다.
  5. 시드 3개 이상, 부트스트랩 95% 신뢰구간이 0을 포함하면 "차이 없음"으로 적는다.

## 6. 반대 증거와 위험
1. **진행 대리값이 약할 수 있다.** FaRe의 이득은 8B 학습 진행 모델 위에서 나왔다. 코드 기하 `g(t)`가 같은 역할을 할지 모른다. 천 접기처럼 기하로 진행을 못 쓰는 과제는 C_stag가 비고 C_jev에 기댄다.
2. **FaRe 트리거 절제 차이는 0.5%p**(91.0 대 91.5), 반복 수·분산 미확인(v3/17 B8). "매 스텝 판정이 해롭다"를 강한 근거로 쓰지 않는다.
3. **conformal 보장은 교환 가능성 가정** 아래에서만 성립한다. 새 환경(random)에서는 개발 시드 분포가 달라 보장이 깨진다. SAFE 저자도 온라인 conformal을 미래 과제로 적었다(부록 F.2 제목). → 새 환경에서 재보정에 필요한 성공 롤아웃 수를 지표로 둔다.
4. **SAFE·FIPER는 정책 내부 특징(또는 행동 분포)이 있어야 한다.** 우리 스킬 + Jev 구조에는 행동 청크 엔트로피가 없다. 가져오는 것은 **보정 방식과 AND 구조**뿐이다.
5. **AND 규칙은 느리다.** 채널 둘이 겹칠 때까지 기다리므로 탐지 지연이 늘 수 있다. 정밀 삽입처럼 짧은 창에서 실패가 끝나는 과제는 하드 층에 기대야 한다.
6. **Jev 확률 보정 전**(E1 전)에는 C_jev 임계값 0.8이 뜻 없는 숫자일 수 있다.
7. **"LLM은 일반화된다" 주장과의 관계**: critic은 코드라서 새 환경에서 무너지는 쪽은 인식 앞단과 임계값이다. 새 환경에서 critic의 오경보가 늘면 그것은 LLM이 아닌 부분의 한계로 따로 보고해야 한다(plan §3 "같은 인식 위 룰 대 LLM").
