## 1. 공통 규칙 (네 실험 모두)

### 1.1 모델·언어·버전
- `model = "jev-1.13.0"`(버전 ID 고정, 별칭 `jev-latest` 금지 — 공식 models.md: 별칭은 새 릴리스에 따라 움직인다). 응답의 `model` 필드를 매 호출 기록하고, `jev-1.13.0`이 아닌 응답이 1건이라도 나오면 그 세션을 분리 보고한다.

- Python SDK를 쓰면 **재시도를 끈다**(`RetryPolicy(max_retries=0)`). SDK 기본값은 재시도 2회·백오프 0.5 s·타임아웃 30 s라서(공식 retries 문서) 429·5xx를 지연 속에 숨긴다. 재시도가 필요한 폐루프(E2a)는 재시도 층을 우리 코드에 두고 재시도 횟수를 따로 기록한다.

### 1.2 `JevCall` 형식 (00-interfaces §2를 API 요청으로 옮긴 것) [제안]
- 한 호출 = 결정 질문 H개(미래 결정 스텝 k..k+H−1) + 감시 질문(M7 진행 범주 Choice 1개 + 필요 시 M8 T3b Noul 1개).
- 질문 키(`questions` 맵의 키)는 추론에 쓰이지 않는다(공식 api.md). 키 규칙: `ds<번호>.<질문>` / `mon.progress` / `mon.t3b`.
- 스텝별 전제(M4 §4.1 "그 전 스텝들이 코드 예상대로 끝났다고 가정한 상태", 바뀐 술어만)는 **구조화된 `instructions` 객체의 한 필드**로 넣는다(공식 api.md가 허용하는 "질문 필드 + 데이터 필드" 형식). state는 모든 질문이 공유한다.
- 보기 설명(`criteria` 값)에 M3 `expected_after` 술어를 붙인다(E-M3-1이 효과를 재기 전까지는 붙인 형식을 기본으로 둔다).
- `NONE_ESCALATE` 보기는 모든 결정 질문에 둔다(M3 §4.1).

H=1, D-줌 예(값·문구는 예시, 실제 템플릿은 E1 결과로 고정):
```json
{
  "model": "jev-1.13.0",
  "state": "t_state: f1287 (t=42.90s)  contract: c7  stage: S2 \"place mug o3 on tray o5\"\nrobot: gripper=closed_holding(o3) wrist_force=light arm=moving\nobjects:\n  o3 mug red | held_by_gripper | upright\n  o5 tray blue | on(table) | clear=yes\nfacts: above(o3,o5)=no near(o3,o5)=yes aligned_xy(o3,o5)=no ...\nstage S2: exit=on(o3,o5)=no invariants=holding(o3)=yes elapsed=normal\nchanges (last 3s): -0.4s aligned_x(o3,o5): no->yes",
  "questions": {
    "ds412.dir": {
      "type": "choice",
      "instructions": {
        "assumed_before_step": "step ds411 finished as planned: aligned_x(o3,o5)=yes",
        "question": "Which direction should the gripper move during step ds412 to make progress toward the `exit` of stage S2 without violating `forbidden`?"
      },
      "criteria": {
        "plus_y": "Move toward +y (robot left). expected_after: aligned_xy(o3,o5)=yes, in_contact(o3,o5)=no",
        "minus_z": "Move down. expected_after: in_contact(o3,o5)=yes",
        "hold": "Keep the current position. expected_after: no change",
        "NONE_ESCALATE": "None of the options fits the situation."
      }
    },
    "ds412.mag_coarse": { "type": "choice", "instructions": "...", "criteria": { "tiny": "about 0.5 cm", "small": "about 1 cm", "medium": "about 2 cm", "large": "about 4 cm", "xlarge": "about 8 cm", "NONE_ESCALATE": "..." } },
    "ds412.mag_fine":   { "type": "choice", "instructions": "...", "criteria": { "...": "9 sub-bins inside the previous step's coarse bin (M3 §4.2 (a))" } },
    "ds412.grip":       { "type": "choice", "instructions": "...", "criteria": { "open": "...", "close": "...", "keep": "...", "NONE_ESCALATE": "..." } },
    "mon.progress":     { "type": "choice", "instructions": "Considering the change since the last step, how is stage S2 going?", "criteria": { "valid_progress": "...", "allowed_change": "...", "failure": "...", "recovering": "...", "NONE_ESCALATE": "Cannot tell from the state." } },
    "mon.t3b":          { "type": "noul", "instructions": "Given elapsed = `normal` of expected for step 'place', should this step have been completed by now?" }
  }
}
```
- 방향은 M3 §4.2 개정(D4 C-6)대로 **두 질문으로 나눈다**: `ds412.dir_xy`(수평 8방향 + `none_xy` + `NONE_ESCALATE` = 10개), `ds412.dir_z`({up, down, `none_z`, `NONE_ESCALATE`} = 4개). 위 예의 `ds412.dir`은 모양만 보인 것이다. 한 질문 28개(26방향 + `hold` + `NONE_ESCALATE`)는 E1·E-M3-1의 비교 조건 `D-dir28`로만 쓴다. 크기 구간의 cm 값은 **[가정]**(M3는 "로그 간격 5구간"만 정했고 값은 튜닝 대상).
- H=3: `ds412`, `ds413`, `ds414` 각각 `dir`·`mag_coarse`·`grip` + 전제 필드, `mag_fine`은 첫 스텝(`ds412`)에만(M3 §4.2, D1 B1), 감시 질문은 한 벌.
- G/H안: `ds.target`, `ds.approach`, `ds.phase`, (접촉 근처) `ds.fine_dir` — M3 §4.3·4.4.

### 1.3 크기 등급 (E0이 실제 `usage.input_tokens`로 교정) [가정: 토큰 수는 추정]
| 등급 | 구성 | 입력 토큰 추정 |
|---|---|---|
| S1 | H=1, D-줌(위 예) | 1.0k~1.5k |
| S3 | H=3, D-줌 | 2.5k~4k |
| G1 | H=1, G/H안(목표·접근·단계 + 감시) | 0.6k~1k |
| X8 | 응력 시험(관련 없는 물체·술어를 채워 약 8k) | 약 8k |
- 공식 fan-out 문서: 질문들은 병렬 평가되므로 질문을 더해도 응답 시간 증가는 보통 작다. **이것을 E0이 우리 크기에서 직접 확인한다.**

### 1.4 환경과 상태 원천
- **첫 환경(00 §13으로 확정): 시뮬 단일 팔 탁상 pick-and-place.** E0~E3 전용이며 RoboDojo 본 평가와 섞지 않는다. 7자유도 팔 + 평행 그리퍼, 탁상 1개, 대상 물체 1(머그/블록), 놓을 곳 1(트레이), 방해물 0~2개. 과제 문장: "Put the red mug on the blue tray."
  - 엔진: RoboDojo-Sim과 같은 Isaac Sim 위 자작 장면(00 §13: 초기 실험은 자작 장면, 본 평가는 RoboDojo. 첫 판의 "벤치마크가 정해지면 그 안으로 옮긴다"는 쓰지 않는다). 요구 조건만 고정한다: (1) 참 자세 접근(오라클), (2) 시드로 초기 배치·섭동이 결정됨, (3) 섭동 주입 훅, (4) **벽시계 동기 실시간 실행**(시뮬 시간을 벽시계에 묶어 실제 Jev 지연이 그대로 작용).
  - 성공: `on(o3,o5) ∧ ¬holding(o3) ∧ upright(o3)`가 1 s 연속 참(T1 술어). 시간 제한 60 s. 물체가 탁상 밖으로 떨어지면 즉시 실패.
- **상태 원천**: E0.5·E1·E2a·E3a는 **오라클 상태**(시뮬 참 자세 → M1 술어 등록부 계산기 → 텍스트). 인식 앞단(SAM 3.1 + 깊이)은 이 단계에서 쓰지 않는다. 이유: 마차 시험은 **결정 층**을 재는 것이고, 인식 오류가 섞이면 결정 층 차이를 가린다. 인식 조건은 E3의 잡음 주입 하위 조건과 뒤 단계(E3-P, 환경 일반화 평가)에서 다룬다.
- M1 변환: 기본 후보 A(정본 §26)이며, E0~E2a는 **등록부 술어를 그대로 줄 표로 쓴 최소 직렬화**(M1 후보 A와 모양이 같다)를 **측정용 고정 형식**으로 쓴다. 이것은 M1 결정이 아니다. E3 결과로 기본 후보가 바뀌면 E2a 핵심 조건만 재실행한다(§4.9).

## 2. E0 — Jev 지연 (한국, 실제 `JevCall` 크기)

### 2.1 목적
M4의 고정 구간 길이 `d_p95`와 동시 in-flight 상한 `N_max`의 초기값을 정하고, **겹침의 주 목적이 "지연 숨기기"인지 "같은 스텝 여러 표(자기 확인)"인지**를 정한다. 겹침 자체는 끄지 않는다(00 §9 C1 [사용자]).

### 2.2 가설 (사전)
- H0-a: 한국발 S1 p50은 0.35~0.7 s, p95는 0.6~1.2 s이다 **[가정 근거]**: 업체 측정은 미국 서부(v3/01 블로그 단서), OpenRouter 전 지역 P50 0.37 s, 제3자 데모 p50 0.53/p95 0.81 s(LOW), 한국–미국 서부 왕복 약 0.13~0.16 s(측정 안 함, 일반 값).
- H0-b: S3 − S1의 p95 차이는 0.1 s 미만이다(공식: 질문 병렬 평가).
- H0-c: 동시 in-flight 4개까지 p95 증가는 25% 미만이다.
- H0-d: 시간대 사이 p95 최대/최소 비는 1.5 미만이다. 미국 업무 시간(PDT 09~18 = KST 01~10)에 느리다.

### 2.3 설정
- **측정 위치 2곳**: (주) 폐루프를 돌릴 기계(시뮬이 도는 클러스터 파드, **[가정] 한국 소재**), (보조) 로컬 PC(한국). 결과는 위치별로 따로 보고, 설계값은 주 위치 값.
- 연결: HTTP keep-alive(연결 재사용). 첫 요청(새 연결) 지연은 따로 기록(`cold`). 네트워크 분해용으로 세션 시작마다 `curl -w`의 `time_namelookup/time_connect/time_appconnect/time_starttransfer/time_total`을 20회 기록.
- 페이로드: §1.3의 S1, S3, G1, X8. 스냅샷 풀이 없으면 템플릿 생성기로 만든 현실적 상태를 쓰고, 풀이 생긴 뒤 **확인 세션 1회**를 실제 스냅샷으로 돌린다. 두 결과의 p95가 10% 넘게 다르면 실제 스냅샷 값을 쓴다.
- 부하 방식 2가지:
  1. **닫힌 루프 동시성 스윕**: in-flight 수 N ∈ {1, 2, 3, 4, 6, 8}을 유지(응답이 오면 즉시 다음 요청). 각 (크기, N)마다 300 요청.
  2. **열린 루프 주기 재생**(실제 스케줄러 모양): T_c ∈ {0.2, 0.33, 0.5} s마다 무조건 송신, in-flight가 N_cap(=6)에 닿으면 그 슬롯은 건너뜀(건너뜀 수 기록). 각 (크기 S1·S3, T_c)마다 60 s.
- 시간대: KST 02·06·10·14·18·22시 6슬롯 × 평일 3일 + 주말 1일 = 24 세션. 세션 하나 약 15~20분.
- 결정성(재시험 flip, M4 §5 전제 실험): 고정 페이로드 20개를 세션마다 1회씩 보내 24회 반복 → 같은 입력에서 최빈 보기가 바뀌는 비율, 확률 최대 변화 |Δp|.
- **Astra 첫 토큰(부수 측정, D4 W4)** [제안]: E0 첫 평일에 Astra effort별(low·high 필수, medium·xhigh·max는 여력 있으면, 정본 §26) 첫 토큰 지연을 실제 T_fail 입력(격자 1장 약 3,600 토큰 + 텍스트 약 2k)으로 20회씩 잰다. 결과는 M9 §7 [결정 필요](원칙 세 개(사용자 원칙 2 + 잠정 기본 1)의 충돌)에 "effort X면 실패당 대기 Y초" 표로 붙인다. 기본은 low다(정본 §26, D14 해소 — 옛 "medium은 측정만 하고 기본값 후보로 쓰지 않는다"는 폐기). 비용은 E0 표에 넣지 않은 Astra 약 $5~20 **[가정]**.
- 속도 제한: 공식 1,200 요청/분 = 20 요청/초. N=8에서 p50이 0.4 s면 초당 20회에 닿는다. 429는 **지연 표본에서 빼지 않고 "실패"로 따로 센다**(아래 지표).

### 2.4 조건 요약
크기 {S1, S3, G1, X8(동시성 1·4만)} × 부하 {닫힌 N=1..8, 열린 T_c 3값} × 시간대 24 세션 × 위치 {파드, PC(평일 1일만)}.

### 2.5 표본과 근거
- 세션당 약 (3 크기 × 6 N × 300) + (X8 2 × 300) + (2 × 3 × 60 s × ~3 rps) ≈ 7,000 요청, 24 세션 ≈ 17만 요청.
- p95 정밀도: 한 칸 n=300이면 p95 순위 285의 이항 표준편차 약 3.8 → 95% 구간 약 p92.5~p97.5 (칸별 참고용). **설계값은 시간대를 합친 n ≥ 7,200(300 × 24)에서 계산** → p95 순위 구간 약 p94.5~p95.5로 충분.
- 시간대 비교: 슬롯당 n = 300 × 4일 = 1,200 → 슬롯별 p95 95% 구간 폭 약 ±1.2 백분위.

### 2.6 지표
- 요청별 총 지연(t_done − t_send), 첫 바이트까지, 네트워크 분해(DNS·TCP·TLS·TTFB).
- 칸별 p50/p90/p95/p99, 실패율(429·529·5xx·타임아웃 2 s 초과). **p95 계산 시 실패와 2 s 초과는 +∞로 넣는다**(검열 자료; 실패가 5%를 넘으면 p95 자체가 ∞ → 그 칸은 "사용 불가").
- 크기 효과: p95(S3) − p95(S1), p95(X8) − p95(S1), 토큰당 기울기(선형 회귀).
- 동시성 효과: p95(N)/p95(1).
- 시간대 효과: 슬롯별 p95의 최대/최소 비, 요일 효과.
- 열린 루프: 실효 응답률(초당 답), 건너뜀 비율, **스텝당 표 수** — 지연 기록으로 M4 스케줄러를 오프라인 재생: 스텝 시작 전 `lead_max` ∈ {1.0, 1.5} s부터 `d_p95` 전까지 T_c 간격으로 같은 스텝을 묻는 H=1 방식(M4 §4.1)에서 고정 구간 경계 전에 도착한 답의 수.
- 결정성: 재시험 flip 비율, |Δp| 중앙값·최대.

### 2.7 판정 기준 (사전 등록)
운영점 L = **파드 위치, 선택 크기(S1과 S3 각각), N = N_max 후보에서의 전체 합산 p95**. T_c = 0.33 s(설정 표).
1. **`d_p95` 초기값** = L(크기별). 추가로 "최악 시간대 슬롯 p95"를 설정 표 비고에 적는다. 최악/전체 비가 1.3을 넘으면 E2a 이후 모든 폐루프 실험에서 **시간대를 기록하고 조건을 같은 시간 블록 안에 교차 배치**(블록 무작위화)한다.
2. **`N_max` 초기값** = ceil(L / T_c) + 1(M4 §4.3). 단 p95(N_max)/p95(1) > 1.25면 동시성 벌점이 있다는 뜻 → N_max를 벌점이 1.25 이하인 가장 큰 N으로 낮추고, 초당 호출 예산을 M4 C0~C6에서 같게 맞춘다.
3. **겹침의 목적** (00 §9 C1, M4 §5 전제 실험의 문턱을 그대로 씀):
   - (a) L < T_c/2(0.165 s): 지연 숨기기 목적 약함 → **주 목적 = 자기 확인(같은 스텝 여러 표)**. 겹침 유지. "겹침 끄는 안"은 [결정 필요]로 사용자에게 보고만.
   - (b) T_c/2 ≤ L ≤ T_c: 두 목적 모두. 주 목적은 자기 확인, 지연 숨기기는 보조.
   - (c) T_c < L ≤ 1.0 s: **겹침 없이는 3회/초 불가능** → 주 목적 = 지연 숨기기, 자기 확인은 스텝당 표 수가 허락하는 만큼.
   - (d) 1.0 s < L ≤ 2.0 s: (c)와 같되, 확정 행동이 1 s 이상 낡은 상태 위의 결정이 된다 → M3 D-줌(촘촘한 이동)에 불리하다는 경고를 E2a 해석에 붙이고 [결정 필요]로 보고(T_c 또는 D-줌 결정 빈도).
   - (e) L > 2.0 s 또는 운영점 실패율 > 2%: "Jev를 초당 3회 루프 안에"라는 전제가 흔들림 → E2a 전에 사용자와 방향 논의(E2a는 G/H 중심으로 축소 실행 제안).
4. **자기 확인이 실제로 가능한가**: 열린 루프 재생에서 T_c=0.33, lead_max=1.5 s일 때 스텝당 표 수 중앙값 ≥ 2이면 M4 (a)의 LA-2 확정이 성립 가능. < 2이면 (a)는 대부분 "미확정 실행"이 된다 → M4에 보고(E-M4의 "미확정 실행 스텝 비율" 감시 기준을 사전에 높게 잡음).
5. **H 선택에 지연이 영향 주나**: p95(S3) − p95(S1) ≤ 0.05 s면 E-M4의 H 비교에서 지연은 무시(정확도·토큰만). > T_c(0.33 s)면 H=3에 지연 벌점이 있다고 E-M4 판정 7 해석에 붙인다.
6. **결정성**: 재시험 flip = 0이고 |Δp| 최대 < 0.01이면 "Jev는 같은 입력에 결정적" → M4 (a) 합의의 불일치는 **상태 변화에서만** 온다고 해석(M4 §5 기록 그대로). flip > 0이면 그 비율을 M4 `flip_score` 기준선으로 쓴다. 상태 변화에서 오는 불일치가 실제로 있는지는 **E0.5(§2A)**가 잰다.
7. **위치 차이**: PC − 파드 p95 차이가 0.1 s를 넘으면 폐루프는 반드시 파드에서 돌린다(당연하지만 기록).

## 2A. E0.5 — 오프라인 표 재생 (M4 (a) 합의에 거를 불일치가 있나) [D4 W2, 00 §13]

### 2A.1 목적
M4 새로움의 절반((a) 합의)은 "시간차로 받은 Jev 표들 사이에 정보가 있는 불일치가 있다"에 기댄다. Jev가 같은 입력에 결정적이고 0.33 s 사이 상태 변화가 작으면 (a)는 자명하게 일치하고, 주장은 (b) 코드 잔차 감시로 줄어든다(D4 F2). 이것을 **폐루프 E-M4(수천 에피소드) 전에, 기록된 궤적을 재생해 싸게** 잰다. 겹침 자체는 결과와 무관하게 끄지 않는다(00 §9 C1 [사용자]).

### 2A.2 가설 (사전)
- H05-a: 성공 궤적에서 연속 스냅샷(0.33 s 간격) 사이 최빈 보기 불일치율(flip rate)은 5% 이상이다(모름, 방향만).
- H05-b: 합의 규칙(LA-2 / γ=0.67)이 newest-wins보다 결과 기반 정답률이 높다.
- H05-c: 섭동 직후 창의 불일치가 성공 궤적 창보다 크다(`C_flip` 조기 경고의 전제).

### 2A.3 설정
- 자료: 스냅샷 풀 POOL 에피소드(§1.5)에 **0.33 s 간격 연속 스냅샷 열**(시뮬 전체 상태 포함, 짧은 롤아웃 재시작용)을 함께 저장한다. 궤적은 오라클 스크립트 플래너가 몬다(재생이라 표가 궤적을 바꾸지 않는다).
- 재생 방식: 결정 스텝 ds마다 H=1 "같은 스텝을 시각을 당겨 2~3회 묻기"(M4 §4.1)를 흉내 낸다. 스텝 시작 시각 t_s에서 `d_p95`(E0 값) 앞의 최근 연속 스냅샷 3개(t_s − d_p95 − {0, 0.33, 0.66} s)의 텍스트 상태로 같은 질문(같은 `question_id`)을 묻는다. 각 표 = 그 시각 상태에서의 답.
- 재시험: 같은 스냅샷을 한 번 더 물어 재시험 flip(E0 판정 6과 같은 정의)을 같이 잰다.
- **같은 시각 반복 호출(D8, 00 §19, C5-A3 공정성)**: 결정 스텝마다 가장 최근 스냅샷 하나(t_s − d_p95)에 같은 질문을 **K=3번 동시에**(M4 §3 #16의 C5-A3 묶음 호출과 같은 모양) 묻는다. 같은 시각 뒤집힘 = K개 답 중 최빈과 다른 답이 하나라도 있는 스텝 비율. 재시험(1회)과 달리 C5-A3 묶음 크기 그대로 재서, C5-A3의 합의가 자명하게 일치하는지(= 같은 시각 표본 다양성이 없는지)를 E-M4 전에 안다.
- 표현: M3 D-줌(분할 방향 질문 `dir_xy`·`dir_z` + `mag_coarse`)과 H안(`target`·`phase`, 접촉 근처 `fine_dir`). 확률 게이트 끔(00 §6).
- 비교 규칙(같은 표 묶음에서 사후 계산): **newest**(C2 = Slow Brain VLM Stream, **요청(스냅샷) 시각 기준** 가장 새 유효 표, 00 §20) / **LA-2·γ=0.67**(C3의 합의 부분, 합의 안 되면 가확정 = 첫 표) / **C2''**(우리 변형, 이전 판의 C2' "감쇠 융합": 표 나이에 지수 감쇠 가중을 둔 최빈, 반감기 0.33 s 시작값) / **C2'**(Slow Brain Probability Fusion 원문 충실판, 00 §20, 정의 정본 M4 §5: p = (1−α)·softmax(S1) + α·softmax(Sim), α = λ/(λ+1)·exp(−Δt/τ), λ=3, τ=5 s, T_vlm=1, 5 s 타임아웃, Δt = 결정 시각 − 표의 요청 시각, **S1 = 빠른 층 코드 규칙 점수**(E2a 룰 점수 또는 스킬 기본값, Jev logprob 아님), Sim = 요청 시각 기준 가장 새 유효 표가 고른 보기의 코드 예상 결과 궤적과 현재 보기들의 예상 결과 궤적 사이 거리(진행분 잘라냄)/d_scale, d_scale은 우리 작업공간 척도 [가정]). C2'-S(Score Fusion, λ=1)도 같은 표 묶음에서 계산해 기록만 한다. [우리 해석] C2'는 여러 표의 합의가 아니라 가장 새 표 하나 + S1이라 (a)의 정보를 재지 않는다 → §2A.6 판정 1~3에는 쓰지 않고 판정 7로 값만 보고한다.
- 결과 기반 라벨(§4 E2a-off와 같은 라벨러): 스냅샷 상태를 복원해 보기마다 그 보기를 한 스텝 실행한 뒤 고정 후속 정책(오라클 플래너)으로 최대 10 s(시뮬 시간) 굴려, 성공·진행 점수가 최선인 보기 **집합**을 정답으로 둔다. 플래너와 다르지만 똑같이 좋은 보기는 정답이다(D4 F5).
- `C_flip` 두 계산식을 같이 계산: (i) 표 분포 거리(같은 스텝 표 분포 대 직전 창 분포의 총변동 거리, 00 §12) / (ii) 한 답 대 한 답 뒤집힘 비율(첫 판 식).
- **(i) 보기 이름 치환 대조(00 §24, D12)**: 같은 스냅샷·같은 질문 문구·같은 루브릭(보기 뜻 설명)에서 보기 이름만 바꾼 두 판을 묻는다 — 의미 있는 이름(지금 M3·M6 이름, 예: `descend`, `close_now`) 대 중립 식별자(뜻은 루브릭에만). 보기 순서와 보기 수는 같게 둔다. 치환 flip = 두 판의 최빈 보기(보기 뜻으로 맞춰 셈)가 다른 스텝 비율. 근거: Type-Safe Is Not Error-Free(2609.26758) — 0/1 → no/yes로 100개당 70.4개 답이 바뀌고 AUC .94 → .23, hosted 모델 .8146 → .5806에 test-retest 바닥의 24배 flip, type-error 0% 유지, 권고 "Use neutral option identifiers and carry the meaning in the rubric".
- **(ii) 같은 입력 반복 test-retest flip 바닥(00 §24)**: 같은 스냅샷·같은 판(이름 포함 완전히 같은 요청)을 반복해 묻고 최빈 보기가 바뀌는 비율을 잰다. 위 "재시험"(1회)을 바닥 추정에 쓸 만큼 늘린 것이다(반복 횟수는 [가정], E0 판정 6과 같은 정의). 치환 flip의 해석 기준선이다. 참고(해석용, [초록만]): 2609.03221 — 같은 조건 10회 반복에서 행동 8.7%가 바뀌고 5회 다수결이 그 흔들림의 39%만 없앤다.
- **(i) 확장판(정본 §27, D14)**: 위 두 판 대조를 다음 판으로 늘린다(같은 스냅샷, 같은 문구, 같은 설명). **A0** 지금 이름 / **A1** 중립 문자 / **A2** 무작위 5자 문자열 / **A3** 이름을 설명과 한 칸 어긋나게 돌린 판(이름과 설명 중 무엇을 따르는지 재는 진단용, Type-Safe의 rotated·swapped에 해당) / **A4** 이름은 A0 그대로, 순서만 한 칸 순환 / **(ii)** A0 반복(test-retest 바닥, 호출 2회 이상). **층**: 2지선다·Noul / k = 3~6 / k = 7~17로 나눠 따로 판정한다(Type-Safe가 층마다 반대 방향을 예측). 모든 판의 답은 `option_key`로 되돌려 센다(정본 §27 R5).

(정본 §27) (i) 확장판 층별 지표: A0 대비 flip(`option_key` 기준), 결과 기반 라벨 정답률(판별), A3 이름 추종률(답이 이름의 원래 뜻을 따른 비율), 첫 자리 선택률 대 정답이 첫 자리에 있는 비율(위치 추종).

### 2A.6 판정 기준 (사전 등록)
1. **M4 주장 좁힘**: 성공 궤적 flip rate < 5%(≈0)이고 LA-2·C2''(감쇠 가중 최빈, 이전 판 이름 "감쇠 융합") 둘 다 newest 대비 정답률 +2%p 미만이면, **E-M4 전에 M4 컨트리뷰션 문장을 (b)(코드 잔차 감시 + 전제 epoch 무효화) 중심으로 좁히고 (a)는 "안정화 장치"로 적는다**(M4 §5 판정 2를 앞당김). 겹침은 끄지 않는다.
2. **(a) 유지**: flip rate ≥ 5%이고 LA-2 또는 C2''(감쇠 가중 최빈)가 newest보다 +2%p 이상(하한 > 0) → (a) 주장 유지, E-M4 그대로.
3. **불일치는 있으나 잡음**: flip rate ≥ 5%인데 정답률 이득 < +2%p → (a)는 "흔들림 억제"로만 주장, 번복률 지표를 E-M4 주 지표에 올린다.
4. **조기 경고**: 섭동 창 flip이 성공 창의 2배 이상이고 AUROC ≥ 0.7이면 `C_flip`을 M7 소프트 채널로 유지. 두 계산식 중 AUROC가 0.03 이상 높은 쪽을 잠정 기본으로 보고([결정 필요] 4 승인 전), 차이가 0.03 미만이면 00 §12 식(표 분포 거리)을 유지.
5. 재시험 flip > 0이면 그 값을 flip rate 해석의 기준선으로 뺀 값도 함께 보고.
6. **C5-A3 공정성(D8, 00 §19)**: 같은 시각 반복 호출 뒤집힘이 1% 미만(≈ 0 [우리가 정한 임계])이면 C5-A3의 합의는 자명하게 일치한다 → M4 판정 17 결과에 "C5-A3는 같은 시각 표본 다양성이 낮아 A3(같은 관측 K=8 샘플)를 과소 재현했을 수 있다"를 붙이고, 같은 시각 뒤집힘과 시간차 flip rate를 나란히 보고한다. 1% 이상이면 단서 없이 판정 17을 그대로 쓴다. 어느 쪽이든 C5-A3 조건은 E-M4에서 빼지 않는다.
7. **C2' 원문 충실판 값(00 §20, D9)**: C2'(Probability Fusion)의 결과 기반 정답률은 판정 1~3에 쓰지 않는다. C2' − C2와 C2' − LA-2를 함께 보고하고, C2'가 LA-2보다 +2%p 이상(하한 > 0) 높으면 "E-M4 판정 1에서 C2'가 강한 기준일 것"을 결과에 미리 적는다(판정·조건은 바꾸지 않음). S1 단독 정답률도 함께 적는다(S1이 약하면 C2'가 C2-match로 줄어든다).
8. **보기 이름 규칙(00 §24, D12)**: (i) 치환 flip이 (ii) test-retest flip 바닥보다 크면(정본 §24 판정. "크다"의 통계 기준은 짝 부트스트랩 차의 95% 하한 > 0으로 둔다 — 우리가 정한 기준) M3/M6 보기 이름 규칙을 바꿀 근거로 보고한다. 바꿀지는 [결정 필요] D32(사용자)이고, 이 판정은 자료만 낸다. 두 판의 결과 기반 정답률 차도 함께 적는다. 바닥 이하이면 "이름 치환 효과를 test-retest 흔들림과 가를 수 없음"으로 보고한다. 어느 쪽이든 판정 1~7과 M4 설계는 바꾸지 않는다.
9. **보기 이름 규칙 확정(정본 §27, D14, 층별 판정)**: **중립 전환** = A1 정답률 ≥ A0 − 2pt(짝 부트스트랩 하한) 그리고 A3 이름 추종률이 (ii) 바닥보다 유의하게 큼 / **이름 유지** = A1 정답률이 A0보다 낮고 차의 95% 하한 > 0 / **순서**: A4 flip ≥ 5%면 C3''를 필수 조건으로 올린다(E-M3-1 판정 4와 같음). 판정 8(치환 flip > 바닥)은 유지하되 정답률 차 없이 "바꿀 근거"로 읽지 않는다. D32는 정본 §27로 해소됐고 이 판정은 R3(3지선다 이상 행동 보기 이름 방식)를 확정한다. R1·R2·R4·R5·R6은 결과와 무관하게 기본이다.
- 한계(결과 문장에 명시): 재생은 개루프다. 표가 궤적을 바꾸지 못하므로 "불일치에 정보가 있는가"만 재고, 폐루프 이득은 E-M4가 잰다.

### 2A.7 비용·시간
- Jev: 약 1.5만 요청 × 약 1~1.5k 토큰 ≈ 2,000만 토큰 ≈ **$1**. 표현·반복을 늘려도 **$1~5**. 같은 시각 반복 호출 K=3 추가분은 스텝당 요청 +3(첫 판 스텝당 4요청 = 3표 + 재시험 1에 더함, 약 1.75배) → 약 +$1 [우리 계산, 같은 단가 가정].

- (00 §24) (i) 보기 이름 치환 대조와 (ii) test-retest 바닥 추가분: 요청 수와 비용은 문서 추정 없음(표본 크기를 정한 뒤 적는다).
- (정본 §27) (i) 확장판 + (ii): 층마다 결정 스텝 300개 이상 × 판 5개 × 반복 2회 ≈ 층당 약 3천 요청, 세 층 합쳐 **약 9천 요청**, 기존 단가(1.5만 요청 ≈ $1)로 **약 $1 미만** [우리 계산]. 결과 라벨 롤아웃은 기존 라벨러를 그대로 쓰고 판 수만큼 늘지 않는다(보기별 라벨은 한 번).
- 벽시계 약 1일(풀·라벨러 준비 뒤).

### 2A.8 E0와 같은 날 실행 (D6 메타 사유 4, 00 §17)
- **왜**: flip ≈ 0이면 M4 주장을 E-M4 설계·구현(C5·CAL, 수천 에피소드) **전에 미리** "(b) 되먹임 + 전제 epoch 무효화"로 좁혀야 한다. 판정이 늦을수록 E-M4 조건 구성과 논문 틀([결정 필요] 18) 판단이 흔들린다.
- **어떻게**: 스냅샷 풀(연속 스냅샷 열 포함)과 롤아웃 라벨러를 0주에 끝낸다. E0 첫날 첫 세션(약 2시간, 시간대 1개)의 실측 p95를 **잠정 `d_p95`**로 두고 같은 날 E0.5 재생·라벨·판정을 돌린다(재생은 오프라인이라 E0 자동 세션과 요청 한도만 나눠 쓴다: E0.5 요청을 분당 400 이하로 제한 [가정]).
- **사전 등록 재실행 규칙**: E0 4일 결과의 최종 `d_p95`가 잠정값과 T_c(0.33 s) 넘게 다르면 최종값으로 재생을 한 번 더 하고 **그 결과로 판정**한다(첫 결과도 함께 보고). T_c 이하 차이면 첫 결과로 확정. 판정 기준(§2A.6)은 바꾸지 않는다.
- 비용·시간 [가정]: 첫 실행 약 $1~5 + 재실행 시 약 $1, 벽시계는 E0 첫날 안(라벨 롤아웃 GPU 수 시간 포함). 0주 준비가 늦으면 E0는 먼저 시작하고 E0.5는 준비 끝난 날 바로 돌린다(E1보다는 항상 먼저).

## 3. E1 — 보정 (질문 유형·보기 이름·보기 수·위치)

### 3.1 목적
00 §6에 따라 지금은 모든 확률 게이트가 꺼져 있다. E1은 **어느 질문군에서, 어떤 형식으로, 어느 임계값까지 확률 게이트를 켜도 되는지**를 정한다. 부수로 보기 이름 형식·보기 순서 규칙(E2a 템플릿 고정)을 정한다. E-M3-1(보기 수·형식 오프라인 시험)과 같은 자료·같은 호출로 돈다.

### 3.2 가설 (사전)
- H1-a: 공식은 "보정됨"이라 하지만 기준이 정답이 아니라 최상위 LLM 판단에 가깝다(plan §1). **시뮬 오라클 정답 기준 ECE는 0.05를 넘을 것**이고, 온도 조정 뒤 줄어든다.
- H1-b: 보기 수 K가 늘면 정확도·보정이 나빠진다(2604.14634 방향, Jev 아님).
- H1-c: 의미 있는 보기 이름 > 중립(A/B/C) > 무작위 문자열 순으로 정확도가 높다.
- H1-d: 위치 편향이 있다(앞쪽 보기 선호). 크기는 모름.
- H1-e: Noul 긍정/부정 문구의 확률 합은 1에서 벗어난다(공식 #8 예: 1.19).

### 3.3 설정
- 자료: 스냅샷 풀 1,200개(§1.5), 에피소드 단위로 적합 600 / 시험 600.
- 질문군(모두 설계 문서에서 실제로 쓰는 질문, 영어 고정 문구):

### 3.4 표본과 근거
- 본 운영 형식 칸: 질문군별 시험 600항목. ECE(15개 동일 질량 구간) 부트스트랩 표준오차 약 0.01~0.015 **[가정: 일반적 규모, 실제 구간은 부트스트랩으로 보고]**. AUROC는 오답 수가 좌우한다: 오답 ≥ 60이면 AUROC 표준오차 약 0.03. **시험 세트 오답이 30개 미만인 질문군은 "AUROC 판정 불가"로 두고 게이트를 켜지 않는다**(검증 못 한 게이트는 켜지 않는다). 경계 과표집(§1.5)이 오답 수를 확보하는 장치.
- 형식 요인 칸: 시험 세트 중 300항목 하위집합에서 이름 3 × K 4 × 위치 3 = 36변형(QC-dir·QC-target). 300 짝 항목이면 정확도 차이 약 5%p를 짝 비교로 가를 수 있다(불일치 10% 가정 시 약 310항목 필요, M1 E3와 같은 계산).

### 3.5 지표
- 정확도(최빈 보기), 우연 보정 정확도(NA, E-M3-1과 같음).
- 보정: **최상위 확률 ECE**(Choice·Score), **이진 ECE**(Noul p(yes)), 클래스별 ECE(K ≤ 6), Brier, NLL, 신뢰도 도표.
- 선택적 예측: 정오답 판별 AUROC(점수 = 최상위 확률, 그리고 응답의 `confidence` 필드 둘 다), AURC, 임계 θ별 (적용률, 적용 구간 정확도).
- 위치 편향: 정답 위치별 정확도 기울기, 오답이 고른 위치 분포(균등 대비 χ², 최대 위치 몫/균등 몫), 회전 사이 최빈 불변 비율.
- Noul 극성: p(긍정) + p(부정)의 1과의 차이 분포(보고만, #8 규칙상 설계에 쓰지 않음).
- Score: **최빈 수준의 정답 여부로만** 보정을 잰다. `score` 기댓값은 보정 대상이 아니다(#2(c) 보간 금지).

### 3.6 온도 적합
- 로짓 = log(p)(p는 1e-6에서 자름; 응답 확률이 소수 2자리로 반올림돼 오면 꼬리 해상도가 낮다 → **[가정] 반올림 여부 확인**, 반올림이면 0.0 확률 보기는 1e-3으로 두고 보고).
- 질문군별 단일 온도 T를 적합 세트 NLL 최소화로 적합. 비교: 히스토그램 구간화·등위 회귀. **기본은 온도**, 등위 회귀는 시험 ECE가 0.02 이상 더 낮을 때만.
- 원 확률 ECE ≤ 0.03이고 T ∈ [0.8, 1.25]면 보정 없이 원 확률 사용.

### 3.7 판정 기준 (사전 등록)
질문군 Q(본 운영 형식 고정, `question_id` 계열 단위)마다, 시험 세트에서:
1. **게이트 켬 조건(모두 만족)**: (i) 보정 뒤 ECE ≤ 0.05이고 부트스트랩 95% 상한 ≤ 0.08, (ii) AUROC ≥ 0.75(하한 ≥ 0.70), (iii) 후보 임계 θ(모듈 설정 표 후보값: M5 0.8, M7 0.8, M8 0.7, M9 0.6)에서 "보정 확률 ≥ θ" 구간의 실제 정확도 ≥ θ − 0.03(하한 ≥ θ − 0.08), (iv) 그 구간 적용률 ≥ 20%. 통과하면 그 질문군에 **보정 확률 기준 θ 게이트**를 허용(원 확률에 거는 것 아님).
2. **확률을 양으로 쓰는 설계**(가중 평균·가중 합의, M3 "봉우리 검사 후 평균", M5 AAC 확정 길이 게이트 등): 1번 + ECE ≤ 0.03 + K·이름 형식을 바꿔도 ECE 차이 ≤ 0.03일 때만. 아니면 계속 끈다.
3. **보기 이름 형식**: 의미 있는 이름이 기본. 중립 또는 무작위가 정확도에서 −2%p 이내이면서 AUROC가 0.03 이상 높으면 그 형식으로 바꾼다(이름이 답을 흘리는 효과를 줄이는 쪽). 무작위 이름 정확도가 의미 있는 이름보다 10%p 이상 낮으면 "Jev는 보기 이름을 크게 읽는다"로 기록 → M3 보기 이름 규칙을 엄격히(이름과 설명을 일치시키는 검사 추가).
4. **보기 수**: K별 정확도·ECE를 E-M3-1 판정 1과 함께 보고. K=28(`D-dir28`)에서 QC-dir의 ECE가 K=6보다 0.05 이상 나쁘면 한 질문 28개 형식은 게이트 영구 금지(최빈만)로 기록. 분할 형식(10 + 4)의 방향 정확도(두 답의 결합 기준)가 `D-dir28`보다 5%p 이상 낮으면 [결정 필요]로 되돌림 여부를 올린다(M3 §4.2).
5. **위치 편향**: |기울기| > 0.02(M3 E-M3-1과 같은 값) 또는 오답 위치 최대 몫 > 균등의 1.5배(χ² p < 0.01)면 보기 순서를 **오라클 비의존 고정 순서(ID 정렬)**로 두고 편향 크기를 결과에 적는다. 회전 사이 최빈 불변 비율 < 90%면 M4 합의에서 "같은 `question_id`"의 정의에 보기 순서까지 포함(순서가 다르면 다른 질문).
6. **Noul 대 Choice**: 같은 판단을 Noul과 2보기 Choice로 물었을 때 임계값을 옮기지 않는다(공식 #8). 각각 따로 보정한 값만 쓴다.
7. **재보정 조건**: 모델 버전, 질문 문구, 보기 목록, 상태 형식(M1 후보) 중 하나라도 바뀌면 해당 질문군은 게이트를 끄고 E1 축소판(시험 300항목)을 다시 돌린다.

### 3.8 결과별 설계 분기
- 통과한 질문군만 00 §6의 후보 게이트를 켠다(예: QN-t3b 통과 → M8 T3b "예 확률 ≥ 0.7" 변형 허용). 통과 못 한 질문군은 최빈 선택만 유지(현재 설계 그대로라 설계가 깨지지 않는다).
- 전부 실패: 확률은 기록용으로만 남고, M4 교체 게이트 θ·M5 확정 길이 게이트는 영구 끔. **설계 전체는 최빈 선택만으로 이미 서 있으므로 방향 변경은 아니다.**
- QC-progress·QN-pred 정확도 자체가 낮으면(< 80%, **[가정] 문턱**) E2a 전에 M7 진행 질문·M1 형식을 먼저 손본다(E-M4의 감시 질문 잡음이 결과를 흐리지 않도록).

### 3.9 비용·시간

### 3.10 위험
- **오라클 정답이 "사람이 볼 정답"과 다를 수 있다**: 문턱 근처 술어, 방향 26개의 최근접 선택은 경계에서 애매하다. `ambiguous` 항목은 본 ECE에서 빼고 따로 보고.

## 4. E2a — 마차 시험 (같은 텍스트 상태에서 룰 대 Jev C1, M4 없이)

> 개정(D4 F3·F4·F5·D-1, 00 §13): 첫 판 E2를 나눴다. **E2a** = 룰 대 Jev C1(세 표현), M4 없이 — 마차 판정은 여기서. 첫 판의 C5 조건(JD-C5·JG-C5·JH-C5)과 "M4 첫 신호" 판정은 **E-M4의 첫 칸으로 옮겼다**(M4 §5). 오프라인 비교는 결과 기반 라벨(E2a-off)로, Astra를 켠 대응 조건을 보조 쌍으로 더했다. 방향 재검토는 95% 상한 < +5%p일 때만 발동하고, 그 밖의 비유의는 "결론 유보"다.

### 4.1 목적
plan §0의 "가장 약한 고리": **Jev가 코드가 만든 술어 위에서 내리는 결정이 같은 술어를 쓰는 룰보다 나은가.** 낫지 않으면 M3·M4 이후 설계의 전제가 사라지므로 방향을 다시 본다(plan §5). M4 구현(C5, CAL 보정) 없이 돌 수 있어야 "먼저 싸게 재는 마차 시험"이 된다(D4 F4). 부수로 M3 세 안(D-줌/G/H)의 첫 신호를 얻는다(최종 판정은 E-M3-2).

### 4.2 가설 (사전)
- H2-a(주): 최선 Jev 조건의 성공률이 R0보다 5%p 이상 높다.
- H2-b: 그 우위는 **룰 작성자가 보지 못한 보류 섭동**(P3·P4)에서 더 크다(LLM 일반화 주장, plan §0 [사용자]).
- H2-b′(00 §18, D7): H2-b와 같은 우위가 **보류 모호함**(P5, §4.5)에서도 나타난다(판정 4는 P3+P4+P5 90쌍으로 본다).
- H2-c: R0 대 R-lag 차이(지연만의 비용)는 Jev 조건 사이 차이보다 작다.
- H2-e: 결과 기반 라벨로 채점한 오프라인 정답률에서도 최선 Jev ≥ 룰이다(플래너 일치율과 방향이 다를 수 있음).
- H2-f(보조): Astra 실패 호출을 룰·Jev 양쪽에 켜면 둘의 차이가 줄어든다(방향 모름, D4 D-1).
- (첫 판 H2-d "M4 켬 > 끔"은 E-M4로 옮김.)
- **알려진 반례 (00 §18, D7, 둘 다 커뮤니티 GitHub·LOW)**: RoboJEV(lykycy123, 2026-09-23)는 **같은 구조화 상태**에서 Jev 43/50 < 룰 48/50(과제 5 × 시드 10, 정지형)을, embodied-jev(FBddcz, 2026-09-22)는 스킬 모드에서 Astra 9/9 = 룰 9/9를 보고했다. 즉 H2-a("코드 술어 위 Jev > 룰")에는 이미 반대 관측이 있다. 두 관측은 모두 룰이 풀 수 있는 조건(구조화 상태, 정해진 과제)에서 나왔다. 그래서 E2a는 **룰이 못 푸는 조건 — 보류 섭동(P3·P4)과 보류 모호함(P5) — 을 반드시 포함**하고, H2-b를 그 조건에서 본다. 이 조건을 빼고 돌린 E2a는 마차 판정에 쓰지 않는다. 결과 문장에는 두 반례를 나란히 적고, 우리 결과가 반례와 같은 방향이면(판정 2·3) 그대로 보고한다.

### 4.3 설정

- Astra: 세션 계약(M2)은 **과제 템플릿당 1회 Astra가 작성하고 모든 조건·시드에서 같은 계약을 재사용**. **effort = high**(잠정 기본 high(다른 작업 발언 근거) — 이 프로젝트 적용은 [결정 필요] 5, 00 §16. low·medium은 쓰지 않는다). 주 조건에서는 **실행 중 Astra 개입(실패 시 호출)을 끈다.** 이는 [사용자] "실패할 때마다 Astra 개입" 원칙에서 **측정 목적상 벗어나는 것**이며 E2a 주 조건 한정이다. 이유: 결정 층만 분리해 재기 위해. 그래서 **Astra를 켠 대응 조건 쌍(R0+A / J*+A)**을 보조로 둔다(§4.4). 주 조건에서 M7은 신호를 기록만 하고 개입하지 않는다. 종료 = 성공 / 60 s 시간 초과 / 낙하.

### 4.6 표본과 근거
- TEST 150 시드 = 섭동 5종 × 30시드. 주 조건(R0, R-lag, Jev 3조건)이 같은 150개를 짝으로 돈다.
- 주 비교(최선 Jev − R0, 합산 성공률): 짝 McNemar로 차이 15%p를 검정력 0.8·α 0.05로 잡으려면 불일치 비율 25% 가정 시 약 85쌍 필요 → 150쌍이면 약 12%p까지. 차이 추정의 95% 구간 반폭 약 ±7~8%p. **그래서 "유의하지 않음"만으로는 "우위 없음"을 말할 수 없다**(D4 F3) — 방향 재검토는 상한으로만 판정한다(§4.8).
- 보류 섭동 부분집합(P3+P4, 60쌍): 20%p 차이 정도만 가를 수 있다 → **보조 판정**으로만 쓴다. Astra 켠 대응 쌍도 이 60쌍.
- **보류 모호함 블록 TEST-P5**(30시드, 00 §18): 주 조건(R0, R-lag, Jev 3조건) 모두 같은 30시드를 짝으로 반드시 돈다. 판정 4의 "보류" 부분집합은 P3+P4+P5 90쌍으로 본다(약 16~17%p까지 가름 [우리 계산: 60쌍 20%p에서 √(60/90) 비례]). P5 단독(30쌍)은 기술 통계와 함께 보고한다. Astra 켠 대응 쌍은 비용 때문에 P3·P4 60쌍 그대로다(P5 제외).
- 섭동별(30쌍)은 기술 통계만.
- **1회 사전 등록 연장**: 어느 Jev 조건이든 95% 구간이 +5%p를 걸치면(우위도 우위 없음도 보이지 않음) TEST2(시드 1150~1299, 150개)를 주 조건 모두에 추가하고 300쌍으로 한 번만 다시 판정. 그 외 연장 없음.
- 실행 순서: 시드 블록(10시드)마다 모든 조건을 무작위 순서로 돈다(시간대 효과 제거, E0 판정 1).

### 4.11 위험
- **룰이 약하게 만들어지면 마차 통과가 거짓 양성.** 대책: 시간 예산 동일, R0 두 벌 중 좋은 쪽, SKILL 참고치 보고, 룰 코드 공개.
- **알려진 반례가 이미 있다(00 §18, D7)**: RoboJEV(Jev 43/50 < 룰 48/50, 같은 구조화 상태, 정지형)·embodied-jev(Astra 9/9 = 룰 9/9). 둘 다 커뮤니티 LOW지만, 룰이 풀 수 있는 조건만 돌리면 우리도 같은 결과가 나올 가능성이 높다. 대책: 보류 섭동·보류 모호함(P3·P4·P5)을 빼지 않는다. 반대로 P5가 룰에 너무 불리하게 설계되면 거짓 양성이 된다 — 지시문 모음을 다른 사람이 만들고 룰의 파싱 실패 행동을 동결 전에 정하는 이유다.
- **오라클 상태라 Jev의 이점이 과소/과대평가될 수 있다.** 오라클 술어는 깨끗하므로 룰에 유리할 수 있다(룰은 잡음에 취약). 인식 조건 재시험 전까지 결론은 "오라클 상태에서"로 한정.
- **M4 없는 Jev(C1)는 사용자가 만들려는 시스템이 아니다.** E2a 결론은 "M4 없는 결정 층"으로 한정하고, 겹침(M4)을 켠 비교는 E-M4에서 한다.
- **결과 기반 라벨의 후속 정책 치우침**: 후속 정책이 오라클 플래너라 플래너가 잘 이어 가는 보기에 유리하다. 두 번째 후속 정책(R0)으로 100 스냅샷 하위집합을 다시 라벨해 라벨 일치율을 보고한다.
- 단일 pick-and-place는 룰이 쉽게 잘하는 과제다 → 천장 효과(R0 > 90%)면 판정 1은 사실상 불가능. **R0 DEV 성공률이 90%를 넘으면 TEST 전에 섭동 크기를 한 단계 키운다(P1 2 cm → 4 cm)** — 이 규칙 자체를 사전 등록.
- 주 조건에서 Astra 개입을 끈 것은 사용자 원칙에서 벗어난 측정 설정이다. 결과를 "Astra 없는 결정 층 비교"로 명시하고, 켠 대응 쌍을 함께 보고.
- 속도 제한 변동으로 429가 나면 해당 에피소드는 지연 오류로 남는다 → 429 발생 에피소드 비율을 조건별 보고, 5%를 넘는 조건은 재실행.

### 4.12 E-M4로 옮긴 것 (첫 판 E2에서)

## 5. E3 — M1 상태 표현 비교 (오프라인, 오라클 정답)

### 5.1 목적
M1 기본 후보 A(Claude 결정, 정본 §26, user-log 25)를 확인하고 B·C로 바꿀 근거가 있는지 본다. (옛 "사용자가 고를 근거 자료, 결정은 사용자(00 §11.3)"는 "변환 방법은 사용자가 정한다"(사용자가 한 말이 아님)에 기대던 것이라 폐기.) 판정 기준은 M1 §5를 그대로 가져오고, 이 문서는 실행 절차와 표본·비용을 채운다.

### 5.2 가설 (사전, M1 §5·§6에서)
- H3-a: 관련 부분만(A)이 전체(A-full)보다 정확도에서 2%p 넘게 떨어지지 않으면서 토큰을 50% 이상 줄인다(공식 jaggedness #5 방향).
- H3-b: 숫자 좌표(N-num)는 A보다 Q1·Q3에서 5%p 이상 낮다(공식 #2 방향).
- H3-c: 단순 pick-and-place에서 B ≈ A(M1 §4.2 추론).
- H3-d: 인식 잡음 주입 하락폭이 표현마다 다르다(모름).
- H3-e(00 §14, 방향 모름): 줄 순서만 바꾼 A-QPR이 A와 정답률이 같거나 높다. 원문 근거: TabGR(2601.08444, 무학회, LOW) **부록 Table 12** — QG-PPR을 빼고 행·열을 섞으면 WikiTQ 하락 5.8~7.1% 대 넣은 판 0.1~1.3%(TabFact에서는 1.0~1.5% 대 0.5~0.7%로 차이 작음). 원문은 행·열 격자 표 QA이고 우리 상태는 격자가 아니다(접목안).

### 5.3 설정
- **E3a(지금, pick-and-place)**: 스냅샷 풀(§1.5)에서 600 스냅샷(시험 분할과 같은 에피소드 쪽을 쓰되 E1 적합에 쓴 에피소드는 제외), 에피소드 ≥ 60개.

### 5.6 판정 기준 (사전 등록, M1 §5 판정 1~7을 그대로 인용)
1. 필터 효과: A가 A-full보다 평균 정답률 2%p 이상 낮지 않고 토큰 50% 이상 적으면 "관련 부분만" 유지. A-full이 3%p 이상 높으면 [결정 필요]. (00 §25 기록할 예상, 판정 기준은 그대로) 강한 모델은 기호 표 이득이 작을 수 있다(lmgame 2048 gemini −3.1).
2. 숫자 대조: N-num이 A보다 Q1·Q3에서 5%p 이상 낮으면 "Jev에 숫자 금지" 확정 근거로 기록.
3. diff 단독 금지: D-only가 A보다 Q2에서 10%p 이상 낮으면 규칙 유지. 3%p 미만이면 변화 절의 가치를 따로 본다(A 대 A−변화 절).
4. B 채택 조건(E3b에서): 관절 물체 하위집합 B − A ≥ 5%p, 단순 과제 −2%p 이내 → 과제 유형별 B 제안.
5. C 채택 조건(E3b에서): T3 필요 질문에서 C − A ≥ 5%p, 나머지 −2%p 이내 → C 제안. 나머지에서 떨어지면 C'(`attrs`만) 재시험.
6. 인식 민감도: 깨끗 → 잡음 하락폭이 표현 사이 5%p 이상 차이 → 하락폭이 작은 표현을 권고 1순위로(환경 일반화 주장과 직결).
7. 모든 비교는 부트스트랩 95% 구간, 겹치면 "차이 없음".
- 추가(이 문서) — **V-free 해석**: V-free가 A보다 높아도 다른 모듈 전제(코드 술어)를 깨므로 채택 판정에 쓰지 않고, M1 §7-2 [결정 필요]의 자료로만 보고.
- 추가(00 §14) — **A-QPR**: A-QPR이 A보다 평균 정답률 +2%p 이상이고 구간이 0을 넘으면 "줄 순서 규칙"을 M1 결정 자료에 넣는다. 근거가 LOW라 기본값으로 올리지 않는다. 변환 방법 기본은 A(Claude 결정, 정본 §26).

### 5.7 결과별 설계 분기
- 판정 1·2·3은 A 형식 세부 규칙(필터, 숫자 금지, 변화 절)을 확정 또는 수정 → E2a 측정용 형식에도 반영(바뀌면 §4.9 재실행 규칙).
- 판정 6에서 하락폭 차이가 크면 M1 결정 자료의 1순위 근거로 사용자에게 제시.
- 사용자가 후보를 정하면: 다른 모듈은 등록부 인터페이스에만 의존하므로 설계 변경 없음. E1 해당 질문군 재보정(E1 판정 7).

### 5.8 비용·시간
- Jev: 7 표현 × 600 × 3회 ≈ 12,600 요청 + 잡음 3조건 × 4표현 × 600 × 3회 ≈ 21,600 요청, 요청당 약 0.7~3k 토큰(A-full이 가장 큼) → 약 4,000~6,000만 토큰 ≈ **$2~3**(3회 반복이 1회로 줄면 1/3).
- A-QPR 추가분: 600 × 3회 ≈ 1,800 Jev 요청, 약 $0.3~0.5(A와 같은 크기).
- Astra(V-free 600 + C `astra_note` 600 = 1,200 요청): 입력 = 이미지 1장(640×480이면 32px 패치 20×15=300 × 1.2 ≈ 360 토큰, plan §1 공식) + 텍스트 약 1.5k ≈ 2k → 2.4M × $10 = $24. 출력(effort high, 추론 포함) 요청당 1k~5k **[가정]** → 1.2~6M × $50 = $60~300. **합계 약 $85~325.** 비용을 줄여야 하면 effort가 아니라 **표본을 줄인다**(V-free·C를 300 스냅샷으로, 구간이 넓어짐을 기록) — (정본 §26) 이 추정은 high 기준이다. 기본은 low이고 high는 비교 조건이라, low 조건분은 첫 10요청으로 따로 재추정한다.
- 시간: Jev 부분 수 시간. Astra high는 첫 토큰 약 73 s(plan §1, 날마다 변동) → 1,200 요청을 동시 20개로 약 1.5~2 시간. 분석 1일. 합계 1~2일.

### 5.9 위험
- 풀이 pick-and-place 하나뿐이라 B·C의 강점이 드러날 자리가 없다 → E3b 전에는 B·C에 대해 결론 내리지 않는다.
- C의 `attrs`를 메타데이터로 채우면 상한이다. 실제 캡셔너 오류는 E3-P에서.
- V-free는 Astra 결과이지 "VLM 일반" 결과가 아니다(plan §3 RoboDojo 교훈과 같은 한정).
- E1과 같은 풀을 쓰므로 형식 과적합 위험 → E1 적합 에피소드는 E3에서 뺀다(§5.3).
