## 0. 조사 방법과 한계
- WebSearch는 M7·M8·M9 합산 8회. 이번에 원문을 새로 읽은 M8 관련 문헌: BAGEN(2606.00198, 본문 §1 요약 목록·§3.4·표), BATS(2511.17006v2, 초록), T2SGrid(2603.06973, 초록·§1·§4 절제 표 6), OpenAI 이미지 입력 문서(developers.openai.com, WebFetch 요약). D1 검증(`D1-verification.md` A.1 #1·#2·#3·#18, A.2)이 원문과 공식 문서 원문으로 다시 대조한 결과를 이번 개정에 반영했다.
- 앞 보고서 원문 확인분(CheckVLA, BRACE, Learning When to Plan, RARRL, ASSCG, VLingNav, React When You Need To, AgileThinker, KITE, MIMIC, Grid2Matrix, LIBERO-RECOVER, 고전 event/self-triggered)은 `v3/05`·`v3/12`·`v3/13`의 확인 결과를 쓴다.

## 4. 설계안

### 4.1 트리거 (모두 비초기 호출은 비동기)
| id | 트리거 | 규칙 | 문지기 |
|---|---|---|---|
| T0 | 초기 계획 | 과제 시작. **로봇 정지 허용**(사용자) | 없음 |
| T_fail | M7 FAIL | 항상 호출. 연속 프레임 필수 | "부를지" 건너뜀, 묶음만 결정 |
| T1 | 주기(Hz) | P초마다(P는 §5에서 호출 수 맞춤으로 결정) | 적용 |
| T2 | 정해 둔 순간 | 세션 계약에 적힌 순간(기본: 되돌릴 수 없는 전이 직전 — 놓기 직전, 삽입 시작 직전; CommitFlow·OneTwoVLA의 하위 작업 경계) | 적용 |
| T3a | 자체 판단 — 코드 마감 | 단계 경과 > `D_k`(M7 conformal 마감, 표본 부족 시 1.5×`T_exp_k`) → M7 WARN(C_dead) → 호출 | 적용 |
| T3b | 자체 판단 — 모델 판단 | Jev에 Noul 한 문항 "Given elapsed = {범주} of expected for step '<이름>', should this step have been completed by now?"를 `JevCall`의 감시 질문으로 싣고(00-interfaces §2, 호출 N번에 한 번 싣는 안 포함), **최빈 답이 "예"인 것이 2번 연속**이면 호출. E1 전에는 확률 게이트를 끈다. "예 확률 ≥ 0.7" 게이트는 E1 뒤에 켤 후보 값(00-interfaces §6). 변형 T3b-A: 같은 질문을 Astra에 주기적으로(비용 큼) | 적용 |
| T_stag | 정체 시간 초과 | M7 C_stag 단독 WARN → 호출(Critic in the Loop식). T3와 구분해 기록 | 적용 |

- T3a와 T_stag의 차이: T3a는 **예상 시간 대비 마감**(계획 쪽 정보), T_stag는 **진행이 멈춘 시간**(관측 쪽 정보). plan v4.3의 구분을 유지한다.
- T3b의 사용자 표현 적합성: "이때쯤 결과가 나왔어야 하는데 안 나오네"라는 **자체 판단**은 모델이 내리는 것으로 읽는 게 문자 그대로다(v3/17 B5). 3a는 우리 해석이다. 둘 다 조건으로 둔다.
- **T3b 게이트 문턱 정하는 법(E1 뒤, 00 §14·§15)**: 후보 값 0.7을 그대로 쓰지 않고 RouteNLP식 conformal risk control로 정한다(§3 RouteNLP 행). 질문 유형당 보정 사건이 500개 미만이면(원문 n=100 위반 7.2%) "보장 없음"으로 표기한다. 새 환경에서는 분포 이동으로 보장이 깨지므로(원문 도메인 이동 위반 8.1%) 재보정 표본 수를 기록한다.

### 4.2 문지기 (BRACE 접목)
- 진행 중 요청 한도: 비실패 1개. 실패 호출은 진행 중인 비실패 요청이 있어도 새로 보낸다(이전 요청 결과는 도착하면 버리지 않고 사건 문맥에 붙인다).
- cooldown: 복구 완료 후 2초, 비실패 호출 금지(설정 표 "복구 뒤 cooldown", M7과 같은 값).
- commit 창: Astra 새 계획의 적용 시점은 **M2 R3 하나를 따른다**(D5 2-1). 결정 스텝 경계에서 적용하고, 진행 중 phase의 M6 `effect`가 `irreversible`이면 그 phase가 끝난 뒤 적용한다. 첫 판의 "잡기 닫힘~들어올림 시작"은 M6 `effect`에서 가역(grasp·lift 모두 보상 스킬 있음)이라 따로 두지 않는다. 그리퍼가 닫히는 순간은 grasp/release 전환 보류(1.0 s, 설정 표)가 보호한다. 기다리는 동안에도 직전 확정 행동 유지 + 감속이며 정지가 아니다.
- effort: 잠정 기본 high(다른 작업 발언 근거) — 이 프로젝트 적용은 [결정 필요] 5(00 §16). low·medium은 측정 조건일 뿐 기본값 후보가 아니다. 실험 축은 **low / medium / high / xhigh / max 전부를 후보**로 둔다(00-interfaces §9 C5, §5 E-M8a). 지연 예산(2026-09-23 AA 기준 첫 토큰): low 3.0 / medium 5.9 / high 73 / xhigh 198초, max는 미측정 — 날마다 바뀌므로 같은 날 잰다. 실패 호출은 이 시간 동안 M9 아래 층이 로봇을 움직인다.
- 입력 토큰 예산: 이미지 약 3,000~3,600 토큰 + 텍스트 문맥 ≤ 2,000 토큰(아래 표).

### 4.3 다중 프레임 묶음
**1순위 = 사용자 예시: 한 장에 10프레임 격자.** 근거: T2SGrid(CVPR 2026, 토큰 맞춤 절제 Table 6 Stage 1에서 3×3·4×3 격자 > 순차. 단 학습 설정일 가능성이 높고, 5×2는 시험하지 않았고, 효과의 큰 몫은 칸별 타임스탬프), MIMIC(비슷하거나 약간 오름). 위험: Grid2Matrix(세부 손실), 4×4는 T2SGrid에서도 하락.

구성 [제안]:
- 배치 5×2(카메라 1대) 또는 4×3(10칸 + 텍스트 칸 2). 칸마다 좌상단에 `t=-3.2s`, 단계 이름을 덧그린다(T2SGrid 타임스탬프, KITE 덧그림).
- 손목·외부 카메라는 **카메라별로 격자 한 장씩**(v3/05: 시점 축은 개별이 나았다는 Guardian 결과).
- **`detail`은 반드시 명시한다.** 공식 문서상 `auto`는 `original`과 같다. `low`로 격자를 보내면 한 칸이 약 100×77픽셀이 되어 쓸 수 없다(아래 표).
- 텍스트 문맥(M7 사건 문맥): 사건 종류, 단계 id, 발동 채널, 센서 술어 표, 완료 단계 목록, 최근 Jev 선택. 프롬프트 첫 줄은 ReflAct식 "지금 상태가 목표에 비해 어디인가"를 먼저 쓰게 한다.

**Astra 이미지 토큰 계산** (공식 규칙: 32px 패치, ×1.2, `high` 최대 2,500패치·65,535px, `low` 512×512 안, `original` 최대 30,000패치(초과 시 거부), `auto` = `original`. D1 A.2가 공식 문서의 축소 공식(shrink_factor + floor 보정)으로 다시 계산했고, 토큰은 **이미지마다 올림**)

|---|---|---|
| 개별 1장 high | 300패치 → 360 토큰 | 920패치 → 1,104 토큰 |

## 5. 비교 실험 (사전 등록)

### E-M8a 호출 모드 (온라인, 호출 수 맞춤)
- 조건: A0 초기 계획만 / A1 T_fail만 / A2 T_fail+T1 / A3 T_fail+T2 / A4 T_fail+T3a / A5 T_fail+T3b(Jev) / A5' T_fail+T3b-A(Astra) / A6 T_fail+T_stag / A7 전부 / **A8 정적 규칙**(A7과 같은 트리거, 문지기의 동적 "부를지" 판단 대신 트리거별 부름/안 부름을 개발 시드에서 미리 고정. T_fail은 여기서도 항상 호출).
- **A8의 근거 표기(00 §15)**: A8은 동적 문지기(BRACE 접목)의 가치를 재는 **절제 조건**이고 근거 논문을 두지 않는다. 00 §14 첫 판이 근거로 적은 2602.09902(ICLR 2026)는 공급자 비용 기준 2모델 라우팅 게임 결과라 이 비교의 근거가 아니다(§3).
- **호출 수 맞춤**: A3의 에피소드당 평균 비실패 호출 수를 기준으로 A2의 주기 P, A4의 α, A5의 연속 횟수(E1 뒤에는 확률 문턱도)를 개발 시드에서 조정해 ±10% 안으로 맞춘다(CheckVLA 관행). 맞추지 못한 조건은 호출 수를 함께 보고.
- effort 축: **{low, medium, high, xhigh, max} 전부를 후보**로 둔다(00-interfaces §9 C5, plan §1 "effort는 실험 축"). low는 **측정 조건일 뿐 기본안이 될 수 없다**(잠정 기본 high(다른 작업 발언 근거) — 이 프로젝트 적용은 [결정 필요] 5(00 §16)). 비용·지연 때문에 뺄 값이 생기면 그 이유(예: xhigh 첫 토큰 198초, max 미측정)를 결과와 함께 적는다. [다른 작업 발언, CLAUDE.md 85 — 이 프로젝트 적용은 [결정 필요] 5] ("옳은 추론이면 더 빨리 성공")을 따라 높은 쪽(xhigh·max)을 이유 없이 빼지 않는다.
- 섭동: 운반 중 물체 이동, 잡기 미끄러짐, 방해물 삽입(ID), 처음 보는 물체·배경(OOD).
- 지표: 성공률, 완료 시간, **정지 시간**, Astra 호출 수·비용·첫 토큰 p50/p95, 적시 재현율(실패 시작 뒤 τ=2초 안 호출), T3a·T3b의 발동 시각 차이.
- **판정 기준**
  1. 어떤 모드가 A1보다 성공률 +5%p 이상이고 부트스트랩 95% 구간이 0을 넘으면 "이득 있음".
  2. **T3b 대 T3a 사전 가설**(BAGEN 근거): T3b는 T3a보다 늦게 발동한다(발동 시각 중앙값 차 > 0). T3b가 T3a 대비 적시 재현율 −5%p 이내이면 "비열등", 사용자 표현에 가까운 T3b를 (3)의 대표로 쓴다. 아니면 T3a를 대표로 쓰고 T3b 결과도 보고한다.
  3. 정지 시간은 A0를 제외한 모든 조건에서 초기 계획(T0) 시간 + M9 L3 안전 대기 시간만 허용. 그 외 정지가 생기면 구현 결함으로 본다.
  4. [제안] A8(정적 규칙)이 A7(문지기)과 성공률 −2%p 이내이고 비실패 Astra 호출 비용이 같거나 적으면 문지기 단순화를 [결정 필요]로 올린다. A8이 5%p 이상 낮으면 문지기 유지 근거로 기록.
- 시드 3개 이상, 조건당 에피소드 수는 E0 뒤에 정한다(검정력 계산).
- 순서: T3b의 Jev 감시 질문은 `JevCall`에 실리므로 E0(실제 `JevCall` 크기)·E1 뒤에 돌린다. 확률 게이트 변형(T3b 0.7)은 E1 뒤에만. E-M8b는 기록된 실패 사건으로 **오프라인 병행**(00-interfaces §8).

### E-M8b 다중 프레임 묶음 (오프라인, 기록된 실패 사건 재생)
- 기록된 FAIL 사건 N개(정답 실패 원인·올바른 복구 선택 라벨 = 센서 술어 + 사람 확인)에 대해 Astra를 같은 텍스트로 부르고 이미지 묶음만 바꾼다.
- 조건: G-orig(사용자 기본, 5×2 original) / G-high / S-high(개별 10장, **G-orig과 토큰 같음**) / S-mix(2 high + 8 low) / G+현재 고해상 1장 / 변화 텍스트만 / 텍스트 상태만 / 균일 선택 대 키프레임 선택(격자 안에서).
- 지표: 실패 원인 정답률, 복구 선택 정답률(M9 보기 기준), 첫 토큰 시간, 입력 토큰.
- **판정 기준**: S-high가 G-orig보다 원인 정답률 +5%p 이상(토큰 같음, 구간이 0을 넘음)일 때만 기본값을 개별로 바꾸자고 [결정 필요]로 올린다. 그렇지 않으면 사용자 예시(격자) 유지. "텍스트 상태만"이 G-orig과 −3%p 이내면 이미지 가치가 작다고 보고한다.

## 6. 반대 증거와 위험
1. **자주 부르면 나빠질 수 있다**: Learning When to Plan, VLingNav, React When You Need To(v3/05). 비동기라도 새 계획이 진행 중 스킬을 흔들 수 있다 → commit 창.
2. **T3b는 늦을 가능성이 크다**: BAGEN에서 프런티어 모델도 실패 궤적의 마지막 20%에서야 경보. 다만 BAGEN은 "남은 예산 구간 추정"이고 우리 질문은 "끝났어야 하는가" 이진 판단이며 경과·예상을 명시 제공한다(BATS식). 옮겨 올 수 있는지는 모른다.
3. **대부분의 트리거 비교 승자는 학습 게이트**(ASSCG, RARRL, VLingNav, Learning When to Plan). 학습 없는 규칙 트리거가 이긴다는 보장이 없다.
4. **격자 근거의 절제 수치는 오픈 7B 모델(학습 설정일 가능성 높음), 시간 위치 찾기 과제**다(T2SGrid Table 6). 독점 모델에도 적용한 결과는 있다(Table 1의 GPT-4o → +T2SGrid 행, §4.2.1 "further gains", 수치 미추출). 그래도 Astra, 실패 진단 과제, 5×2 배치, 키프레임 칸에서 같은 방향인지는 모른다. Grid2Matrix는 독점 모델도 촘촘한 격자에서 무너진다고 했다.
5. **정지 원칙의 반대 증거**(v3/16): WAM 실물 정밀 끼우기에서 동기 실행 72.5점 > 비동기 40점. 사용자 원칙은 유지하고 정밀 구간 정지 허용을 [결정 필요]로 둔다(plan §5-10).
6. effort high의 첫 토큰 73초 동안 로봇이 할 일(M9 아래 층)이 모자랄 수 있다.
7. **비용 측면 반대 이론**(2602.09902, ICLR 2026): 공급자 비용 기준으로는 실패 뒤 상향(캐스케이드)이 대개 최적이 아니다. 가정(2모델, 사용자 이탈, i.i.d. 성공)이 달라 설계를 바꾸지 않는다. 사용자 원칙은 유지하고, E-M8a에서 Astra 호출 비용을 성공률과 함께 보고한다.
8. **RouteNLP 보장의 한계**: 주변(marginal) 보장이고 교환 가능성이 필요하며 분포 이동에서 깨진다(원문 명시, 도메인 이동 위반 8.1%). 새 환경 일반화가 핵심인 우리 과제에서는 약점이다. 보정 표본이 단계당 500개에 못 미치면 원문 조건 밖이다.
