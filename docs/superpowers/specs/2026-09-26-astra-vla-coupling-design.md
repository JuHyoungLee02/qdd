## 3. 시간 구조 (RTC식 상호 보완)

```
Astra 요청:  s0   s1   s2   s3   s4   ...        (1 s 간격, 동시 ≤ 3)
Astra 도착:            a0   a1   a2   a3 ...     (약 3 s 뒤, 약 1 s 간격)
Astra 확정:                 ▲(a0=a1 합의)  ▲ ...  (연속 2답 합의 = 히스테리시스)
VLA 표:     ▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶▶   (0.33 s)
실행:       현재 목표 T_i를 향해 보정 …… T_i 도달/확정 교체 → T_{i+1}
```

- **앞부분 고정 / 뒷부분 교체(RTC)**: 새 확정 목표열이 와도 (1) VLA가 지금 향하는 목표 T_i와 (2) M4가 이미 확정한 스텝은 바꾸지 않는다. 교체는 T_{i+1}부터.
- **도착 시점 예상 상태**: 요청 s_k에는 "지금 관측"과 함께 "확정된 VLA 청크·목표로 예측한 3 s 뒤 손끝 자세"를 넣는다. Astra는 답이 쓰일 때의 상태를 기준으로 답한다.
- **적응 간격**: 흐름이 안정(연속 N답 모두 '유지')이면 간격을 1 → 2 → 3 s로 늘리고, 사건(§5)이 나면 즉시 1 s로 되돌린다. 비용 한도(§8) 안에서 조정.

## 5. 두 층 M4 합의 규칙

- **Astra 층**: 목표열 수정은 **연속한 겹친 답 2개가 같은 수정**을 말할 때만 확정(히스테리시스). 한 답만 튀면 무시하고 기록.
- **VLA 층**: 기존 M4(겹친 표 합의, 2/3, W, τ, epoch 등 §72–§75) 그대로.
- **층 사이**:
  - 과제 수준(단계·대상)은 **Astra 확정이 우선**. Astra 확정이 오래되면(> 3 s 무답 또는 목표열 소진) VLA의 단계·대상 판단으로 흐름을 잇는다(대충이지만 멈추지 않음).
  - **불일치 사건**: VLA 단계·대상 ≠ Astra 확정 목표가 1 s 이상 지속 → 다음 Astra 요청에 사건 표시(간격 즉시 1 s).
  - **비가역 동작**(그리퍼 닫기·열기, 단계 S1→S2)은 **두 층이 일치할 때만** 확정(M4 "비가역 W+1" 원칙 확장).
  - **진전 없음**(현재 목표까지 거리가 T_stag 동안 줄지 않음) → 사건 표시 + J2(진단·복구) 요청.

## 6. VLA의 역할: 목표 기준 정밀 보정기 (학습 측면)

- 입력에 **현재 목표**를 넣는다(목표점의 로봇 기준 좌표 또는 이미지 표시 — 탐침 결과에 맞춤). VLA 조이스틱 결정은 "목표까지 남은 변위"에 대한 방향·크기가 된다(labels_v2와 같은 정의 — 이미 목표 기준).
- 학습 데이터:
  - 시뮬(R2): 오라클 계획기의 목표점을 그대로 쓴다.
  - 실물 공개 데이터(S-E2E): 시연의 **미래 손끝 자세를 목표로 되짚어 붙인다**(hindsight relabeling — 단계 경계·그리퍼 사건에서 목표를 끊는다).
- 기대 효과(가설): 과제와 무관한 "목표 대비 보정" 신호라 장면·과제에 묶인 지름길을 덜 배운다 → 새 환경에 덜 취약. 입증 전(E-H2 계열로 시험).
- 조이스틱 준수: 융합 경로에도 확정 결정 투영(모듈형 `skills.project` 규칙)을 넣고, 준수율(E-SR0)을 잰다.

## 11. Astra 조정을 부드럽게 반영 (개정 2026-09-25 16:38 UTC, user-log 83: "아스트라의 조정을 부드럽게 해결하는 방식이어야 … 반응성이 너무 느리고 … 이미지만 보고는 확실하지 않은 경우들이 많기 때문")

- **부드러운 적용**: Astra `edit`는 즉시 점프하지 않는다. VLA가 따라가는 손끝 기준(조이스틱 결정의 기준 방향)에 **편향(offset)으로 더해** 유효 창(다음 답 예상 도착까지, 약 1–3 s) 동안 선형으로 들어가고(GPT-as-Policy `edit`의 α=(i+1)/steps와 같은 방식), 새 답이 없으면 서서히 사라진다(감쇠).
- **확신에 따른 크기**: 반영 비율 = 합의 정도 — 한 답만 말하면 50 %, 연속 두 답이 같은 방향이면 100 %(히스테리시스와 같은 규칙). 방향이 뒤집힌 답이 오면 편향을 0으로 되돌리고 확정을 미룬다.
- **불확실하면 끼어들지 않는다**: Astra는 `assessment`에 확신(`confidence`: low/medium/high)과 근거를 낸다. `uncertain`이거나 low면 `continue`로 본다 — GPT-as-Policy 원칙 "Uncertainty alone … is not a takeover reason". 대신 **더 보기 요청**(손목 카메라를 대상 쪽으로 기울이기·잠시 속도 낮추기 같은 정보 수집 동작)을 낼 수 있게 한다 — 무엇을 허용할지는 구현 계획에서 목록으로 고정.
- **VLA가 빠르게 검증**: VLA는 0.33 s마다 새 이미지로 보정하므로, Astra 편향이 관측과 맞지 않으면(편향 방향으로 가는데 목표 쪽 오차가 커짐) 편향을 줄이고 사건으로 기록 → 다음 Astra 요청에 "편향이 관측과 어긋남" 표시.
- **튐 금지 안전장치**: 편향 변화율 상한(손끝 속도 상한 안), 비가역 동작은 두 층 일치에서만(§5), 모든 편향·감쇠는 로그에 남긴다. 설계 문서 M5(스무딩)의 규칙과 맞춘다.
- 탐침(E-Astra-motion)에서 `confidence` 분포와 '불확실 → continue' 비율, 편향 반영 뒤 궤적의 급변(jerk)을 함께 잰다.

## 12. Astra는 카메라 3대를 모두 본다 (개정 2026-09-25 16:40 UTC, user-log 83: "아스트라는 3개의 캠을 다봐야해 … 헤드캠에서 봤을때는 원시때문에 물체를 잡을 때, 잡았다고 오탐하지 않게 우론목에는 안보이는 그런게 있는거지")

- **시점별 신뢰 규칙**(프롬프트 + 코드 검증):
  - 머리 카메라 = 전체 배치·경로·대상 선택의 근거. 멀리서 보므로 **접촉·파지·놓임 판단의 단독 근거로 쓰지 않는다**(원근 때문에 손가락과 물체가 겹쳐 보여 '잡았다'고 오탐할 수 있음).
  - 손목 카메라 = 접촉·파지·놓임·정렬의 근거. **"잡았다/놓았다/닿았다" 주장은 해당 손목 시점의 근거가 있어야 유효**하다(`evidence`에 시점을 적게 하고 코드가 확인).
  - 시점끼리 어긋나면(머리는 잡힘, 손목은 빈 손) **손목 우선** + 고유감각(그리퍼 폭·힘, 정본 §61·§64 T1) 교차 확인. 둘 다 불확실하면 `uncertain` → 끼어들지 않음(§11).
- **비가역 동작 확정**(§5): 그리퍼 닫기·들기 시작·놓기는 두 층 일치에 더해 **손목 시점 근거 또는 T1 고유감각 근거**가 있어야 한다.
- **비용**: 이미지가 2장 → 3장이라 입력 토큰이 늘어난다(머리 672×376·손목 424×240 기준 추정 약 1.3–1.5배) — 탐침에서 실측하고 프롬프트 캐시·해상도로 조절.
- **탐침 검증**: 파지 직전·직후 스냅숏에서 {머리만, 머리+활성 손목, 세 대} 조건으로 Astra의 "잡았다" 판정 오탐·미탐을 잰다(스냅숏 정지 판정이라 호출 수가 적다).

- **VLA도 세 대를 볼지 (개정 2026-09-25 16:41 UTC, user-log 83: "VLA도 사진을 보는것도 좋을 것 같구")**: VLA 결정 입력을 머리 + 활성 손목(§57, 시각 토큰 356)에서 **머리 + 양 손목**(252 + 104 + 104 = 460, +29 %)으로 늘리는 안. 손목 시점이 파지·접촉 판단의 근거라는 §12 규칙과 같은 이유로 이득이 기대되지만, 결정 지연(p95 예산 약 0.3 s)이 늘 수 있다 → **E-CAM3(사전 등록)**: S-E2E(고친 데이터 `se2e_c1`, ROBOTIS 데이터가 양 손목을 담고 있는지 먼저 확인)에서 {2대, 3대} × 움직임 줄 포함, 같은 스케줄, 채택 규칙 = 전체 정확도 +0.02 이상 · 전환 층 −0.01 이상 · FULL p95 증가 ≤ 10 %(E-TC와 같은 틀). 움직임 줄 확인 실험이 GPU 2·3을 비운 뒤 돌린다.

## 15. 승인 뒤 재점검으로 고친 점 (개정 2026-09-25 17:13 UTC, user-log 85: "1,2,3 허용했지만 옳은 방향으로 바꿔도돼 확인해보고"; 정본 §84 보충 1)

- **비용 현실 점검**: low 1회 ≈ $0.02 ≈ 28원 → 1 Hz 조밀 호출은 로봇 1분당 약 1,700원, 한도 10만 원이면 **전 실험 합쳐 로봇 약 60분**밖에 안 된다. E-Couple(조건 2개 이상 × 여러 판)과 E-Astra-necessity를 1 Hz로 다 돌리면 한도를 넘는다. 그래서:
  - **기본 = 단계 적응 간격**: 접촉 근처(`core.near_contact` ≤ 5 cm)·파지·놓기 창과 사건(§5) 직후 3 s는 1 Hz 계단식, 그 밖(빈 공간 이동)은 3 s 간격. 추정 1분당 약 0.5–0.9천 원(접촉 창 비율 20–40 % 가정 — 탐침에서 실측으로 바꾼다).

  - **high는 흐름에 쓰지 않는다**(지연 45–73 s): high는 J1 과제 컴파일·J2 진단·오프라인(J6)과 low/high 비교 실험에서만.
  - 실험마다 **예산 상한과 판 수를 사전 등록에 먼저 적고**, 누적 비용 기록이 상한의 80 %에 닿으면 멈추고 보고.
