## 2. 장면 층: 받침면 그래프

- 한 장면 = 로봇 앞 1~3개 가구 + 받침면 노드 목록. 노드 종류: `top`(윗면), `cubby`(선반 칸: 입구 사각형·깊이·위 막힘), `seat`(식탁 자리: 접시 위치·수저 위치), `slot`(건조대·꽂이 구멍: 축·지름), `container`(통·바구니·상자 입구), `zone`(작업면 안 구역).
- 노드마다 도달 판정(좌·우 팔 IK로 위·앞 접근 가능 여부)을 미리 계산해, 과제는 도달 가능한 노드만 쓴다.
- 환경 계열 8종(각 ≥ 5 배치 규칙): 선반장 정면, 식탁, 거실 낮은 탁자, 주방(카운터·싱크·건조대·수저통), 현관·복도(우산꽂이·신발장), 사무실 책상(펜꽂이·서류함), 가게 진열대, 작업대·창고. 배치 규칙 예: 선반장 = {단 수 3~5, 칸 너비, 칸 속 기존 물건 채움률, 로봇과 거리}, 식탁 = {자리 수 2~6, 차림 정도, 의자 유무}.
- 가구: THOR 248조각 + 새 에셋(§5) + 파라메트릭 생성(선반장·식탁·건조대·꽂이는 치수 무작위 상자 조합으로도 만든다 — 모양 다양성의 바닥을 보장).
- 로봇 위치: L8S는 원점 고정. L9는 가구 앞 거리 0.15~0.45 m, 가구 정면 대비 로봇 방향 ±20°, 리프트 높이는 작업 면에 맞춰 뽑는다.

## 3. 과제 층: 기본 동작 조합

- 기본 동작: `pick`, `place_on(node, pose)`, `insert_into(cubby|container, front|top)`, `insert_upright(slot)`(우산·펜·수저·꽃), `stack_on(obj)`, `line_up(objs, axis, spacing)`, `sort_into(objs→containers, key=color|kind|size)`, `push(obj, dir)`, `rel_place(obj, ref, left|right|front|behind|between)`.
- 과제 정의 = 동작 순서 + 물체 역할 규칙 + 성공 술어. 성공 술어는 동작에서 자동 생성(예: `insert_upright` = 축 기울기 ≤ 15°·바닥이 꽂이 안·손 놓음 1 s).
- 과제 계열 9종 × 계열당 ≥ 8 정의 = ≥ 75 정의: 꽂기, 정리·줄 세우기, 쌓기, 분류, 넣기(칸·용기·건조대), 차리기, 치우기, 위치 관계, 높이 옮기기. 한 편의 물체 1~6개, 단계 1~6.
- 지시문: 과제 정의당 영어 문장 틀 ≥ 5개 + 물체 이름·색·위치 표현 변주. 상위 입력 형식(astra-solo / d-min)은 그대로.
- 1단계에서 뺌: 넘어진 물체 세우기·뒤집기(실행기가 위 접근 위주), 서랍·문 등 관절(본 35B에서도 뺌), 바닥 높이(도달 밖).

## 4. 팔·출력 형식·카메라 (왼팔)

- 팔 선택: 과제 정의가 대상·목표 노드의 도달 판정으로 팔을 고른다(둘 다 되면 무작위, 좌·우 비율 40~60 % 유지). 한 편 안에서는 한 팔(1단계).
- 실행기: `eef` 명령에 `arm: left|right`를 더한다. 쓰지 않는 팔은 스토우 자세 고정(지금 왼팔과 같은 방식). 왼팔 링크 관성 자리표시값(later_problems 11)을 먼저 고친다 — 오른팔 변경 27과 같은 방식, 시험으로 고정.
- 접근 방향: `top` 기본, 선반 칸·용기 옆 입구는 `front`(서랍 과제 b3d에서 쓴 앞 접근). 칸 안 충돌은 시범에서 먼저 확인(§6 관문).
- 상위 출력 D: 기존 점(0–1000)·높이 의도에 `hand: left|right` 한 필드. 라벨·런타임 파서·d-min 변환에 더하고, 필드가 없으면 right(L8S 행 호환).
- 영상 입력: 머리(원 표시) + **쓰는 팔의 손목** 한 장. 이름표는 기존 규칙대로 `right wrist camera` / `left wrist camera`. L8S 행은 그대로(머리 + 오른손목).
- 목: 모든 편에서 흔든다. 기본 45°(실로봇) 중심으로 tilt ±15°, pan ±30°(대상이 화면 밖이면 다시 뽑기, 최대 5회 뒤 기본값). 카메라 내부 파라미터는 실로봇 값 고정(실물과 맞추기) — 단 §9.3(E-HCAM8)의 무작위 기하 편은 예외로, 실제로 쓴 값을 meta·cams.json에 남긴다.

## 5. 다양화 층·에셋

- 공간 종류(주방·거실·사무실·가게·창고·현관·식당·욕실 앞 등)에 맞는 배경 방. 방 ≥ 190: iTHOR 38 + MolmoSpaces ProcTHOR 계열 방(라이선스 확인분) + 파라메트릭 방(벽·바닥·천장 재질 무작위).
- 조명 계열 ≥ 10: 낮 창가 햇빛, 흐린 날, 저녁 주황, 형광등 사무실, 매장 스포트, 어두운 방 + 스탠드, 역광, 색 조명, 강한 그림자, 약한 확산광. 계열마다 밝기·색온도·방향 분포를 따로 둔다. 자동 ISO(L8S)는 그대로.
- 재질 ≥ 650: Poly Haven + ambientCG(CC0). HDRI ≥ 140: Poly Haven(CC0).
- 물체 ≥ 6,000, 가구 ≥ 1,400: GSO 전량(검증 통과분), MolmoSpaces Objaverse 추가분, Objaverse(CC0·CC BY·CC BY-SA만, NC·ND 제외, 물체별 출처 기록). 과제에 필요한 범주(우산·우산꽂이·접시·그릇·컵·수저·펜·꽃·꽃병·신발·건조대 등)는 범주별 최소 수를 채운다. 모든 에셋은 L8S와 같은 안정성 관문(탁자 위 정착: 바닥 5 mm, 기울기 10°, 표류 2 cm)과 크기 재조정, 이름 붙이기를 통과해야 한다.
- 비현실 모드(편 단위, 기본 끔): 단색·과장된 색·무늬 텍스처·색 반전 조명 등 도메인 무작위화. 켠 편은 `unreal: true`. 학습에 섞는 것은 투두 비교(사실만 vs 사실 + 비현실 20 %)로 효과가 확인된 뒤.
- 물체 색은 지시문에 색 이름이 들어가는 물체는 바꾸지 않는다(L8S 규칙). 비현실 모드도 지시문에 쓰는 색은 지킨다.

## 6. 생산·관문·일정

- 카드: 렌더 카드 7a2a GPU0·1·3, x2 GPU1(4장). 렌더 안 되는 카드는 검증용(사용자 지시). 본 35B 학습(78dc)은 건드리지 않는다.
- 처리량 추정: L8S 약 100편/h/레인, 카드당 2레인 → 약 800편/h. L9는 물체·단계가 많아 편당 1.5~3배 느릴 것으로 보고 약 270~530편/h → 38,000편 성공에 수율 60 % 가정 약 5~10일. CPU 쿼터(7a2a 32코어, x2 12코어)가 병목이면 레인 수를 CPU에 맞춘다. 시범에서 실측해 다시 잡는다.
- 관문 순서: (G0) 단위 시험 → (G1) 과제 정의마다 시범 10편 수율 ≥ 50 % → (G2) 환경 계열마다 프레임 검수(무작위 20편, 머리·손목) → (G3) 대량 생산 중 300편마다 감사(수율·팔 튐·라벨 파서·겉보기) → (G4) 다양성 수치 보고(§0 표).
- (사용자 2026-09-30 추가: "모든 환경은 l9의 환경은 진짜 각기 다른 환경으로 보여졌으면 좋겠어.") 모든 편의 환경 조합 해시가 서로 다르다(생성기가 중복이면 다시 뽑고 기록). 관문 G2·G4에 '거의 같은 장면' 검사를 더한다: 머리 f0 SigLIP 임베딩으로 무작위 편 쌍과 최근접 이웃 코사인 유사도를 재고, 0.95를 넘는 쌍 비율이 L8S보다 낮아야 통과. 프레임 검수 때도 편들이 서로 다른 환경처럼 보이는지 직접 본다.
- 대량 생산은 과제·환경 계열을 층화해 뽑는다(한 계열이 몰리지 않게).

## 7. 검증

- 단위 시험: 받침면 그래프 도달 판정, 과제 정의 → 성공 술어, 팔 선택 비율, `hand` 필드 라벨·파서 왕복, L8S 행이 바뀌지 않음(기존 시험 전부 통과).
- 편 검증: 관문 G1~G3.
- 평가 분할: L9 환경 계열·과제 계열 일부를 **학습에서 뺀 보류 세트**로 떼어, 본 35B(L8S) 모델과 다음 판(L8S + L9) 모델의 처음 보는 환경 성능을 잰다.
- 투두(later_problems에 등록): 사실적 L9만 vs 사실적 + 비현실 20 %를 같은 조건으로 학습해 실제 효과 비교.

### 10.1 속이 빈 물체(컵·그릇·머그) 잡기 — 실측과 설계 (2026-10-02 00시대, 시험 전)

- 사용자 관찰(10-02 00시대): "컵이나 이런거를 잡을때는 컵의 옆면을 잡던지 이래야하는데 그냥 중심에다가 밀어넣어서 잡으려하니까 거긴아무것도 없으니 안되는 거라고 보면돼".
- **실측(L9 prod1 6,000편, `tools/l9r/hollow_grasp.py`, `/data/harvest/out/hcam8/hollow/l9_prod1.json`)**
  - 잡기 라벨(`descend_close`)은 **항상 물체 중심**을 향한다: 명령 TCP xy와 물체 중심 거리 중앙 0.4 mm(95 % 0.6 mm). TCP는 윗면 1.75 cm 아래, 집게를 다 벌린 채 내려와 '물체 폭 − 1.4 cm'까지 닫는다(`teach_l8/labels.plan`, L8S와 같은 규칙).
  - 즉 너비가 벌림(AI Worker 10.7 cm, Franka 8.0 cm)보다 충분히 작으면 손가락이 **바깥 벽 양쪽**에 오고 벽을 바깥에서 쥔다(정상). L9 양산의 속이 빈 대상은 컵 70·용기 42·유리잔 7편뿐이고, 너비 3.5–7.8 cm(중앙 5.4 cm)라 모두 이 경우다. 수율은 너비 6 cm 미만 0.79, 6–9 cm 0.66으로, 같은 너비의 속이 찬 물체(0.73, 0.59)와 비슷하다.
  - 너비가 벌림 이상인 그릇·머그는 지금 L9 대상에 **없다**(물체 관문·`fits_into`에서 빠짐). 이런 물체를 중심 규칙으로 잡으면 손가락이 안쪽으로 들어가 빈 곳을 쥔다 — 사용자 관찰과 같은 실패다.
  - 런타임(상위 점 → 깊이 해석기)에서는, 컵 입구 가운데를 가리키면 안쪽 벽이 테두리와 이어져 영역 윗면이 테두리, 중심이 테두리 고리 중심이 된다(`astra_solo/resolve.py`). 그래서 같은 중심 잡기가 된다. 머그·그릇처럼 넓은 물체에서는 같은 실패가 난다.
- **설계(시험 전, 가설)**
  1. 잡기 방식을 물체마다 고른다: `fits` = 잡는 너비 ≤ 벌림 − 2 cm면 지금의 중심 잡기(바깥 벽 양쪽). 아니면 속이 빈 물체(카탈로그 `inside` 또는 범주가 bowl·mug·cup·pot·basket·vase 계열)는 **테두리 잡기**: 한 손가락은 벽 안쪽, 한 손가락은 바깥쪽, 닫는 축은 벽에 수직(반지름 방향), TCP는 테두리 1.5–2 cm 아래.
  2. 테두리 점은 §10 antipodal 해석 샘플러로 메시에서 뽑는다: 벽 두께 < 벌림 − 1 cm인 테두리 점 → Isaac 들어 올림 시험 통과분 → 로봇에 가까운 쪽·손잡이 반대쪽을 선호하고 편마다 무작위로 고른다. 머그 손잡이는 별도 후보로 둔다(나중).
  3. 라벨·어댑터: 상위 출력 형식은 그대로 두고, 점을 **테두리 위**에 찍는다. 해석기는 영역이 '속이 빈 고리'(테두리 고리 안쪽이 테두리보다 2 cm 이상 낮음)이고 점이 테두리 위면, 그 점의 xy와 반지름 방향 yaw를 쓴다(중심 대신). 높이 의도 `grasp` 그대로.
  4. 옆에서 잡기(NOW §6 투두)와 같은 틀: 키 큰 컵·병은 앞 접근(손가락 수평)도 후보로 둔다.
  5. 시험(등록 뒤): 너비 ≥ 벌림인 그릇·머그를 대상으로 하는 L9 정의를 새로 만들어 시범 10편씩. 관문 수율 ≥ 50 %, 관절 걸음 ≤ 0.04 rad, 프레임 검수. 중심 규칙(대조) 대 테두리 규칙을 같은 시드로 비교한다. 런타임 해석기 변경은 오프라인(저장된 깊이·점)으로 먼저 잰다.

### 12.4 잡기 후보 — 생성 → 선별 → 캐시 → 편마다 무작위
1. **생성**(물체 × 집게, 물체 좌표계, 순수 `grasp9.py`):
   - 자체 antipodal 해석 샘플러: 메시 표면 점을 면적 비례로 뽑고, 법선 반대 방향 광선의 출구 점과 짝을 짓는다. 폭 0.5 cm ≤ w ≤ 최대 벌림 − 1 cm, 두 법선과 닫힘 축의 각이 마찰 원뿔(μ = 0.4, 21.8°) 안. 닫힘 축 둘레로 접근 벡터를 15° 간격으로 돌려 자세를 만들고, 아래에서 오는 접근(접근 벡터 z > +0.26)은 버린다.
   - 속이 빈 물체(컵·그릇·머그·바구니·화분 계열, 카탈로그 `inside`): 벽을 사이에 두는 테두리·벽 파지가 자연히 나온다(한 손가락 안·한 손가락 밖). 중심 잡기와 비교 대상으로 §10.1의 설계를 그대로 시험한다.
   - GraspGen-X(코드 Apache-2.0, 체크포인트 NVIDIA Open Model License; 사용자 10-02 02시 허용, 내부용·재배포 없음): 우리 집게 URDF로 후보를 더해 위 후보와 합친다. antipodal 경로가 돈 뒤 넣는다.
   - 점수: 마찰 원뿔 여유 × 접점 사이 중심과 질량 중심 거리 페널티 × 손가락 접촉 깊이(패드 가운데에 가까울수록).
2. **선별**: 집게–물체 충돌(집게 상자 모형 vs 메시 SDF) → Isaac 들어 올림 + 흔들기 시험(떠 있는 집게: 가상 6관절 + 집게 URDF, 지면에 물체; 닫기 → 10 cm 들기 → ±15° 두 축 흔들기 1.5 s → 물체가 집게 사이에 있고 상대 이동 < 1 cm). GraspGen·GraspVLA의 흔들기·낮은 마찰 재시험 관행을 따라 마찰 0.4에서 통과한 것만 남긴다.
3. **캐시**: `assets9/grasps/<gripper>/<object>.npz` = 후보 자세(4×4), 두 접점, 폭, 접근 벡터, 점수, 시험 결과. 물체 × 집게마다 통과 후보 ≥ 8개가 아니면 그 물체는 그 로봇의 대상에서 뺀다.
4. **편마다**: 물체의 실제 자세로 후보를 옮기고 → 지지면 충돌(손가락 끝이 면 아래로 가면 버림) → cuRobo 배치 IK(충돌 포함) 도달 → **결정적 규칙**으로 하나를 고른다(12.8). 다양성은 무작위 라벨이 아니라 장면 제약 설계(위가 막힘·키 큰 물체·납작한 물체·넓은 빈 물체·손잡이)와 지시문에 접근 방향을 적은 '방향 지시 행'(약 20 %)으로 만든다(조사 문서 §11.6 위험 1). 놓기 높이·놓기 자세는 편마다 뽑는다.

### 12.8 라벨 형식 v2 (메인 채택 10-02 02시대, `docs/research/grasp_point_learning_2026-10-02.md` §11.6–11.9가 정본; E-GP2 8B 검증 뒤 최종 확정)
- 프롬프트 입력: 지금 칸 + `camera:` 줄(E-HCAM8) + **`robot:` 줄**(robot9 프로필에서 자동, 예: `robot: ffw_sg2, arm right 7-DoF, parallel gripper max 10.7 cm`). 지시문에 접근 방향을 적은 행이 약 20 %.
- 상위 출력(잡기 호출) = 점(0–1000, **잡을 부위의 보이는 표면 점**: 두 접점 가운데의 머리 영상 투영, 가려지면 가까운 쪽 접점의 보이는 부분) + 높이 의도 + 그리퍼 의도(열기/닫기) + **`approach ∈ {top, oblique, front, side}`**(로봇 기저 기준; side의 좌·우는 기하가 정함) + **`rot ∈ 0..11`**(머리 영상에 투영한 닫힘 축 각, 15° 구간, 0–165°로 접음). **벌림 칸 없음**(사전 벌림 = 고른 후보의 접점 폭 + 여유 1.5–4 cm, 최대 벌림으로 자름). above는 접근 축을 따라 물러난 사전 자세.
- 접근 계열 정의: 접근 벡터 a와 아래 방향의 각 θ — top θ < 25°, oblique 25–65°, 그 밖(수평 근처)은 로봇 기저에서 물체로 향하는 수평 방향과의 각으로 front(< 45°) / side.
- 라벨 선택(결정적, `label_rule = deterministic_v1`): 0) 위·중심 잡기가 유효(시험 통과 + 도달)하면 그것. 1) 아니면 장면 제약이 정하는 계열. 2) 계열 안에서 로봇 쪽으로 보이는 부위 → 손잡이 반대 → 도달 여유 최대. 지시 행은 지시한 계열 안에서 같은 순서.
- 실행기(런타임 어댑터와 같은 경로): 기하 후보 중 같은 계열, 회전 ±1구간 안에서 보이는 접점 투영이 점에 가장 가까운 것(GraspMolmo식) → cuRobo IK·충돌·궤적. 도달 불가 대체 순서: 회전 ±1 → ±2구간 → 이웃 계열(각도 가까운 순) → 멈춤. 바꾼 사실은 다음 호출의 '직전 명령과 결과' 칸에 글로 넣는다(예: "side 도달 불가 → oblique, 회전 4→5로 잡음").
- meta(형식이 바뀌어도 빌드 단계에서 다시 만들 수 있게 원시값; 조사 문서 §11.9 목록 전부):
  - 잡기 자세 4×4(월드·물체), 두 접점(월드·물체), 벌림·사전 벌림 폭, 접근 벡터, 손목 회전 연속값, 접근 계열, 후보 출처(analytic / graspgenx / graspgen_ds)·점수·시험 결과, 놓기 높이·자세, 로봇·집게·카메라, cuRobo 버전, `motion_version = l9v2`, `grasp_label_version = v2`.
  - `label_rule`, `rule_step`, `approach_reason`(default / scene_constraint:<종류> / instructed), `instructed_approach`, `random_alt_idx`.
  - `point_px_visible`, `grasp_center_px`, `contact_px_head[2]`, `contact_visible[2]`, `point_depth_edge`.
  - `rot_bin_img`·`rot_deg_img`, `rot_bin_base`·`rot_deg_base`.
  - `open_bin3`(narrow/mid/wide), `open_cm_bin`(meta만).
  - `valid_set[]`(물체당 ≤ 64: 계열·회전 구간·보이는 접점 투영·시험 결과·자세), `ik_ok_by_family`, `fallback_trace`.
  - `robot_line`, `camera_line`, 집게 시간선(`open_cmd_t`, `close_cmd_t`, `contact_t`, `final_gap_m`, `slip`, `drop`), `label_origin`(l9v2 / v1_filled).
- 기존 L8S·L9 v1 행은 `approach=top`, `rot=실행된 값의 영상 각 구간`으로 채우고 `label_origin = v1_filled`.
- 빌드: `build9.py`가 형식 v2 행으로 변환한다. 평가는 '고른 잡기의 시뮬 성공률'과 '예측 점 ↔ 같은 계열 유효 후보의 보이는 접점 투영' 거리로 잰다.

### 12.9 관문 (로봇마다)
- 계열별 실행 성공(시뮬 참값 실행) ≥ 70 % — E-GP2 선행 관문.
- G1 수율: 정의별 시범 ≥ 10편, 성공 ∧ 관절 걸음 ≤ 0.04 rad, v1 같은 정의 수율 대비 −10 %p 이내(새 잡기는 더 어렵다는 가설로 v1의 5 %p보다 넓힘; 시범 뒤 다시 정함).
- 잡기 변주 지표: 접근 계열 분포(장면 제약·지시 행으로 top 외 계열 합 ≥ 30 %, 계열마다 ≥ 5 %), 잡을 곳 점 − 물체 중심 거리 분포, 회전 분포(12구간 중 ≥ 8구간 사용), 대체 발생률, 위·중심 편의 '물체 중심 점 대 v2 점' 거리 중앙값 ≤ 8 px(조사 §11.8 위험 6).
- G2 프레임 직접 검수: 계열·접근 방향마다 성공 2편, 머리·손목 f0·잡기 직전·들기·놓기. 비스듬·앞·옆 잡기가 실제로 보여야 통과.
- 설계 항목별 구현 표(항목 → 구현/부분/미구현, 코드 위치)를 관문 보고마다 붙인다(함정 P152).
- G4 v2 다양성(12.3).
