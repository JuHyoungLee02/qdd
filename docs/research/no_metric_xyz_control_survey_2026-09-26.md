# 로봇 좌표 x·y·z(m) 없이 조종하기 + 그래도 추정한다면 어떻게 — 문헌 조사 (2026-09-26)

작성: 무좌표 조종 조사 에이전트, 2026-09-26 14:5x–15:0x UTC(KST 09-27 00:0x). **조사와 설계 제안만 — 구현 0, 유료 호출 0, GPU 0.** user-log 118.

근거 발언(원문):
- "로봇 좌표로 x, y, z가 몇 m인지 없이 할방법을 관련 서적 다뒤져서 찾아봐보 ㅏ뎁스여도되고 이미지여도 되고 다괜찮아"
- (이어서, 통제자 경유) "로봇 좌표 x, y, z를 m 단위로 말하지 않고 조종하는 방법도 좋지만 어떻게 그걸 추정할 수 있는지에 대한 방법론도 괜ㅊ낳아"

출발점:
- 지금 상위 VLM(Astra 대체, 정본 §96·가설 H-L, §97 자동 맥락은 깊이를 가정)은 로봇 기준 절대 xyz를 답해야 한다.
- 영샷 모델은 바로 이 일에서 실패했다. gpt-5.2는 접근 xy 오차 편 중앙 104–207 mm, Qwen3-VL-8B는 0/5였다(`stage3/results/open_vlm_solo.md`).
- 같은 8B를 시뮬 참값으로 LoRA 학습하자 오프라인 DEV 2.6 mm, 폐루프 4/4가 됐다(E-TEACH-L8, user-log 117). 다만 **분포 안**(탁자 z 0.850 고정·같은 물체) 결과다.
- 병행 에이전트가 "점 찍고 행동"(E-PT: 픽셀 목표 + 높이 의도 → 코드가 깊이로 역투영)을 구현 중이다. 이 문서는 E-PT의 팔(arm) 추가와 대안을 제안한다. E-PT·E-TEACH-L8·xemb 파일은 건드리지 않았다.

## 0. 요약

**결론 한 줄.** 상위 VLM은 **m 단위 숫자를 말하지 말고 "영상 위에서 고르게"** 해야 한다(점 → 물체 ID → 상대 방향 순). m 값은 **코드가 깊이·카메라 자기 정보로 계산**한다. m 값을 VLM이 직접 내는 방식은 분포 안에서는 학습으로 된다(L8 2.6 mm). 그러나 문헌상 카메라·장면이 바뀌면 크게 무너진다. 그래서 우리 경우엔 **"피하기"가 주 경로이고 "학습해 추정하기"는 대조군·보조 출력**이다.

근거 세 가지:
- **같은 백본 절제**: SPF(CoRL 2025)에서 같은 Gemini 2.0 Flash로 영상 위 2D 점을 찍으면 100 %였다. 수치를 글로 내면 7 %, 후보 화살표 고르기(PIVOT식)는 40 %였다(UAV 시뮬, 표 2).
- **로봇 팔에서도 점 출력이 기본형**:
  - RoboRefer(NeurIPS 2025)는 출력이 정규화 2D 점이고, 깊이로 3D에 올린다.
  - A0(ICCV 2025)는 접촉점 + 2D 궤적 → 깊이 역투영 → 계획기 구조로, Franka 62.5 %·Kinova 53.75 %였다(Kinova에서 π0 20 %).
  - Embodied-R1(ICLR 2026)은 점 4종으로 실물 XArm 87.5 %였다.
  - SpaceTools(CVPR 2026)는 VLM이 도구(포인팅·깊이·투영)를 부르게 학습했고, 실물 집어 놓기 86 %였다.
- **직접 metric 출력의 한계**:
  - SpatialRGPT(기초)는 직선거리 ±25 % 안 성공이 41.2 %다.
  - VLM-3R(CVPR 2026)은 VSI-Bench 절대거리 MRA 49.4로, 대략 상대오차 25 % 안팎이다.
  - CA-MLLM(ICLR 2026 Oral)에서는 시험 영상 크기만 ×0.8 바꿔도 3D 검출 F1@0.25 m가 46.5 → 25.8로 떨어진다.
  - 탁자 위 cm 정밀도를 VLM 숫자로 일반화한 기간 안 근거는 **찾지 못했다**.

**우리에게 추천 순위(3절 상세)**

**E-PT에 더할 팔(4절)**:
- PT-ID(물체 ID)
- PT-KP(2점 + 관계 등급 → 코드 풀이)
- PT-REL(상대 방향)
- PT-SERVO(손목 서보 정렬)
- PT-VERIFY(역투영 결과를 다시 그려 확인)
- 대조군 PT-XYZ(지금 방식 = L8)와 PT-XYZ+tool(점 → 코드가 잰 xyz를 돌려줌 → VLM이 최종 xyz)

**가장 먼저 할 무료 시험(7절)**: 같은 L8 레시피·같은 편으로 **출력 형식만 바꾼 8B 두 개**(xyz 대 점)를 학습한다. DEV와 **OOD-H(탁자 높이 변경)**에서 접근 오차를 비교한다. 탁자 높이를 외운 xyz 출력은 OOD-H에서 깨지고 점 + 깊이는 버틸 것이라는 예측을 가장 싸게 가를 수 있다.

## 2. 추정 방법론 — VLM(또는 VLM + 도구)이 metric xyz를 잘 내게 하려면

이 절은 추가 요청("어떻게 그걸 추정할 수 있는지에 대한 방법론")에 답한다. 보고 수치의 **지표 정의**를 같이 적는다. 대부분이 cm 오차가 아니라 상대 지표다.

지표 정의:
- **MRA**(VSI-Bench): θ ∈ {0.50, 0.55, …, 0.95} 10개 문턱마다 상대오차 |ŷ − y|/y < 1 − θ이면 1점을 주고 평균을 낸다. MRA 100은 모든 문턱 통과(상대오차 5 % 미만)다. MRA 50은 대략 상대오차 25–30 %다(정의는 원문, 환산은 우리 해석).
- **±25 % 성공률**: SpatialRGPT-Bench 지표다.

### 2.4 카메라 인지 조건화 — CA-MLLM (2603.06704, ICLR 2026 Oral, 31★ — 별 적음, 구두 발표가 근거)

## 3. 우리에게 추천 — 상위 3

### 1위. 점 찍고 역투영 + 물체 군집 기하 (E-PT를 이렇게 강화)
- **무엇**: VLM은 머리 영상 [0,1000] 점을 낸다. 대상 1점과 놓을 곳 1점에 단계(접근·잡기·들기·놓기)와 높이 의도(윗면 위·잡기 높이·놓기 면 위)를 붙인다.
- **코드가 하는 일**:
  1. 점 주변 창의 유효 깊이 중앙값을 구한다.
  2. 역투영해 카메라 3D로 옮긴다.
  3. 머리 FK 자세로 로봇 좌표로 바꾼다.
  4. RANSAC 탁자 평면 위 높이 군집에서 그 점을 포함한 물체를 찾는다.
  5. **발자국 중심**(윗면·앞면 점 편향 제거)과 윗면 z를 구한다.
  6. 도출 규칙 D(`auto_context` 5절)로 잡기·놓기 z를 계산한다.
- **왜 1위인가**:
  - 기간 안 근거가 가장 많고 강하다(SPF 절제, RoboRefer, A0, Embodied-R1, SpaceTools, Gemini Robotics-ER 1.5).
  - Qwen3-VL의 기본 출력 형식이라 8B·35B가 이미 할 줄 안다.
  - 깊이·카메라·FK가 모두 자기 정보(모델 0개 추가)다.
  - 영샷 실패 지점(격자에서 깊이 방향 읽기)을 **코드로 없앤다**.
- **위험**:
  - 점이 가장자리·옆 물체에 걸리는 것 → 군집 단계에서 흡수된다.
  - 얇은 손잡이·결손 깊이.
  - 가림(A0 실패 양상).
  - 실물 스테레오 깊이 잡음(§37 추정 0.6 m 약 5 mm, 1.0 m 약 15 mm, 측정 전).

### 2위. 물체 ID 고르기 (표식 붙은 후보 중 선택)
- **무엇**:
  - 코드가 깊이 군집으로 후보 물체·놓을 면을 만들고, 머리 영상에 번호 표식을 그린다(Set-of-Mark식).
  - VLM은 `{object_id, place_id, phase}`만 낸다.
  - m 값은 전부 코드(1위와 같은 기하)가 계산한다.
- **왜**:
  - 출력이 이산이라 오류가 "틀린 물체" 하나로 분명하다. 무효율·정확도를 재기 쉽고 픽셀 정밀도 요구가 0이다.
  - 우리 과제(머그 → 쟁반, 방해물 0–6)는 **물체 선택이 곧 과제**라 표현이 과제와 맞다.
  - GraspMolmo(CoRL 2025)는 점 → 후보 매칭 방식이다. 실패 원인은 잘못된 부위 62 %·잘못된 물체 24 %·매칭 오류 5 %였다. 부위 선택이 없는 우리(위에서 곧게)에게는 가장 큰 실패원이 빠진다.
- **위험**:
  - 후보 생성 실패(맞닿은 물체·같은 높이 물체) → `auto_context` 4절의 SAM 3 조건부 도입 관문과 같은 판단.
  - 번호 착오(OWG 기초: "위치는 맞췄는데 ID 번호를 잘못 고름").
  - 표식이 물체를 가림.
- 1위와의 관계: **같은 코드 기하에 입력만 다르다**(점 대 ID). 그래서 짝 비교가 깨끗하다.

### 3위. 상대 방향 × 크기 등급 + 손목 영상 서보 (마지막 정렬)
- **무엇**:
  - 굵은 접근은 1·2위로 한다.
  - 대상 위 몇 cm 안에서는 VLM이 손목·머리 영상 기준 **방향(영상 8방향 + 위·아래) × 크기 등급(S/M/L, 예 1/3/8 cm — 값은 등록 때 고정)**을 낸다.
  - 또는 손목 영상 위 대상 점을 내고, 코드가 픽셀 오차로 서보한다(IBVS: 보정 오차에 둔감, 손목 D405 근거리 깊이).
- **왜**:
  - 우리 VLA가 이미 방향 + 크기 등급 조이스틱이라 **표현이 하위와 같다**(번역 층 0).
  - Steerable VLA Policies(RSS 2026)에서 단일 명령 방식 중 원자 동작("move left")이 가장 좋았다.
  - ECoT-Lite(CoRL 2025)·Gemini Robotics 1.5도 원자 동작을 중간 표현으로 쓴다.
  - 손목 서보는 머리 깊이·외부값 오차(실물)를 마지막에 흡수한다.
- **위험**:
  - VLM 호출이 1–3 s(SPF 종단)라 **VLM을 서보 고리 안에 넣으면 안 된다**. VLM은 점 하나를 주고, 서보는 코드가 추적 점으로 수십 Hz로 돈다.
  - 기간 안 VLM + IBVS 학회 확인 선례가 **없다** → 조합은 우리 설계다.
  - Steerable의 "좁은 데이터에서 조종 효과 약함"이 우리 VLA에도 해당될 수 있다(P101·E-MA2와 같은 걱정).

### 추천하지 않는 것
- **목표 영상 생성(7a)**: 느리고(CoT-VLA 7배), 병목이 하위 목표 품질이며(정답 영상 주면 +40 %), 우리 VLA가 목표 영상 조건이 아니다.
- **동작 화살표 반복 선택(PIVOT식)**: SPF 같은 백본에서 40 % 대 점 100 %다.
- **6D 키포인트 풀이(ReKep·OmniManip 원형)**: 회전 명령이 없어 과하다. 2점 + 관계 등급으로 줄인 판(PT-KP)만 제안한다.
- **열지도 출력(6)**: 새 헤드 비용 대비 점을 넘는 이득 근거가 없다.
- **잡기 생성기(GraspGen 등)**: 위에서 곧게 잡는 지금은 과하다. 물체 모양 다양화(user-log 116) 뒤 손잡이·비대칭 물체가 들어오면 다시 본다.

## 4. E-PT에 더할 팔(또는 대안) — 같은 스냅샷·같은 실행기·같은 지표

공통:
- 입력: 머리 RGB-D + 자동 자기 정보 블록(§97). 격자 없음.
- 실행기: 기존 astra-solo 실행기(절대 목표 이동).
- 지표:
  - 오프라인: 참값 대비 명령 목표 오차(접근 xy·잡기 z·놓기 z)
  - 무효율
  - 폐루프: 성공·첫 닫기 xy 오차
- 분포: DEV + **OOD-H(탁자 높이)·OOD-O(물체 범주)·OOD-D(방해물 배치)** — `diversity_plan` 세트, 준비되는 대로.

| 팔 | VLM 출력 | 코드 | 비교 목적 | 비고 |
|---|---|---|---|---|
| PT-XYZ (대조) | 로봇 기준 xyz(m) — 지금 astra-solo@v2 / L8 | 없음 | 기준선 | 이미 있음(L8) |
| PT-0 (E-PT 원안) | 픽셀 + 높이 의도 | 깊이 역투영 | 점 대 m 숫자 | 병행 에이전트 |
| **PT-0c** (1위 강화) | 같음 | + 평면 위 군집 → 발자국 중심·윗면 z + 규칙 D | 점이 윗면·가장자리에 찍혀도 되는가 | PT-0과 짝(코드만 다름) |
| **PT-ID** (2위) | `{object_id, place_id, phase}` | 깊이 군집 후보 + 번호 표식 그리기 + PT-0c 기하 | 픽셀 정밀도 요구 0 | 후보 생성 실패율을 따로 보고 |

| PT-VERIFY | (PT-0c 결과를 영상에 다시 그린 뒤) 확인/수정 점 | 재역투영 | 자기 교정 이득(RoboMonkey식) | 호출 +1 |
| PT-XYZ+tool | 먼저 점 → 코드가 잰 xyz·물체 치수를 글로 돌려줌 → VLM이 최종 xyz | 역투영·군집 | "추정 학습" 쪽 최선형(SpaceTools·TIGeR식 도구 호출) | 5절 조합 비교의 핵심 팔 |

## 5. "m 출력 피하기" 대 "m 추정 학습하기" — 우리 경우 비교

| 기준 | 피하기(PT-0c·PT-ID·PT-REL) | 학습해 추정(PT-XYZ, L8) | 근거 |
|---|---|---|---|
| 분포 안 정확도 | 깊이·군집 오차(시뮬 GT 깊이면 mm급, 관문 `auto_context` 4절 ≤ 10 mm) | **이미 2.6 mm**(L8) | user-log 117 |
| 탁자 높이·카메라 변경 | 깊이가 매번 새로 재므로 원리상 불변 | 학습 분포 상수 암기 위험(z 0.850 고정 데이터); 카메라 변경 붕괴(CA-MLLM 46.5 → 25.8) | CA-MLLM, 우리 데이터 구조 |
| 영샷·새 물체 | 포인팅은 기본 능력(Qwen [0,1000]) | 영샷 104–207 mm, 0/5 | open_vlm_solo |
| 필요한 데이터 | 점 라벨 = 시뮬 GT 투영(무료·무한) + 공개 포인팅(RefSpatial·Pixmo-Points·RoboPoint 계열) | 넓게 일반화하려면 수백만 QA로도 ±25 %대 | 2.7절 |
| 실물 이전 | 스테레오 깊이 품질·외부 보정에 의존(측정 전) | 시뮬 GT 좌표 → 실물은 카메라·깊이 차가 그대로 오차 | §37·§43 |
| 모델 수 | 0 추가(코드) | 0 추가 | — |
| 해석 가능성 | 점·ID를 영상에 그려 바로 눈으로 확인(user 규칙: 프레임으로 검증) | 숫자만 | feedback_verify_with_frames |

**판정**:
- 주 경로 = 피하기(PT-0c, 다음 PT-ID)다. 학습해 추정하기는 (a) 대조군 PT-XYZ, (b) PT-XYZ+tool(점 → 코드 측정값 → VLM 최종 xyz)로 둔다.
- (b)는 "VLM이 m를 말하되 스스로 재지 않는다"는 절충이다. 문헌의 도구 호출형(SpaceTools CVPR 2026)과 같은 모양이다.
- 두 방식을 한 번에 학습해도 된다. 예: 학생 답 JSON에 `point`(필수) + `xyz`(보조 출력)를 두면 같은 라벨에서 둘 다 나온다. 실행은 point 경로로 하고, xyz는 코드 측정값과의 차이를 **이상 감지 신호**로 쓴다.

## 7. 8B로 무료 시험 가능한 것 (설계만, 실행 안 함, 사전 등록 전)

GPU는 x2 파드 규칙을 따른다.

| 순서 | 시험 | 무엇을 가르나 | 비용 |
|---|---|---|---|
| F0 | **영샷 Qwen3-VL-8B 포인팅**: DEV 스냅샷에서 "point to the red mug" [0,1000] → PT-0c 코드 → 접근 xy 오차; 같은 8B의 영샷 xyz(0/5, 기존)와 비교 | 영샷에서도 점 경로가 격자 읽기보다 나은가(SPF 절제의 우리 판) | GPU 추론만 |
| F1 | 영샷 PT-ID 선택 정확도(번호 표식) | 물체 선택은 영샷으로 이미 되는가 | 같음 |
| **F2 (첫 학습 시험)** | L8 레시피·같은 편·같은 스텝으로 **출력 형식만 다른 LoRA 2개**(PT-XYZ 대 PT-0c 점) → DEV + **OOD-H**(탁자 높이 ±5–10 cm, 무료 생성) | "피하기 대 학습하기"의 핵심 예측: 분포 안은 비슷, OOD-H에서 xyz만 깨짐 | 약 1.4 GPU-h × 2 [L8 기준 추정] |
| F3 | F2에 PT-ID·PT-REL 팔 추가 | 2·3위의 비용·정확도 | 같은 규모 |
| F4 | PT-SERVO 시뮬: 외부값에 일부러 오차를 넣고 PT-0c 단독 대 + 서보 | 실물 보정 오차 흡수 | 코드 + GPU 렌더 |
| F5 | 학생 JSON에 `point` + `xyz` 둘 다 학습(5절), xyz–측정값 차이의 이상 감지 AUC | 두 출력의 절충 | F2 데이터 재사용 |

- F0·F1은 표본 수를 등록 때 고정한다(P103: 기준 팔이 바닥·천장이 아닌지 먼저). 영샷 8B가 격자 조건에서 0/5였으므로 F0은 "점 경로가 바닥을 벗어나는가"만 본다.
- 관문 초안(등록 때 고정): F2에서 OOD-H 접근 xy·잡기 z 오차 중앙이 PT-0c ≤ 10 mm이고 PT-XYZ보다 짝 비교로 작으면 "피하기 주 경로" 채택.

## 8. 계열별 메모(우리 계층 적합도 세부)

- **지연**: 모든 방식에서 VLM 호출은 단계 수준(편당 약 6호출, L8 p50 3.5 s)이다. 0.33 s 조이스틱 고리는 VLA·코드 몫이다.
  - 점·ID 방식은 호출 수를 늘리지 않는다.
  - 상대 방향(PT-REL)은 호출 수가 늘 수 있다 → 크기 등급 L로 굵게 가고 가까이서만 S.
- **고정 45° 머리 카메라**: 깊이 방향(로봇 x)이 영상 세로축과 섞인다. 영샷 격자 읽기가 x를 12–19 cm 틀린 이유다. 점 + 깊이는 이 축을 센서가 재므로 가장 이득이 크다.
- **회전 명령 없음**: 6D 풀이(ReKep·CoPa·OmniManip·GraspGen)의 장점이 대부분 사라진다.
- **깊이 결손**: 얇은 손잡이·반사면은 창 중앙값 → 군집 → 그래도 없으면 FK·평면으로 대체하고 표시한다(`auto_context` 3절 규칙과 같음). 실물은 Fast-FoundationStereo(CVPR 2026)가 1순위, MoGe-2는 교차 확인이다.
