## 0. 해석 (메인 에이전트의 읽기 — 사용자 확인 전)
1. 로봇이 **자기 자신에 대해** 알 수 있는 것(기구학·URDF → TCP 자세, 그리퍼 형상, 작업 범위, 카메라 내부·외부 파라미터)은 계속 줄 수 있다. 단 **사람이 손으로 쓴 숫자가 아니라 로봇에서 자동으로** 나와야 한다.
2. 추가로 **시각적 자기 인식**: 영상만으로 말단(엔드포인트)과 그것이 향하는·작용하는 방향을 찾는다 — 보정에 기대지 않고, 보정을 검증할 수 있게.
3. 그 밖의 모든 것은 인식·학습으로 자동화한다: 장면 기하(탁자 높이, 물체 위치·크기·모양, 놓을 면), 과제 절차(잡기·놓기 요령은 손으로 쓴 공식이 아니라 학습 또는 도출).
4. 모델을 이어붙여도 되지만 **모델 수 최소화가 목표**. 이상형 = 상위 학습형 VLM(Astra 대체, §96) + VLA(그대로) **2개**. 다른 인식 모델은 스스로 정당화해야 하고, 가능하면 학습으로 상위 VLM에 접어 넣는다.
5. (사용자 결정, 추가) **깊이를 쓴다고 가정한다** — 머리 RGB-D, 시뮬은 렌더 깊이.

- **깊이가 돕는 것**: 점 픽셀 + 깊이 → 3D 말단 점(카메라 좌표) → FK 3D와 **mm 단위 대조**. 뿌리·TCP 두 점을 역투영하면 **3D 접근 축**(FK z축과 각도 비교). 여러 자세에서 (FK 3D, 깊이 3D) 짝을 모으면 **머리 카메라 외부 파라미터 자가 보정·표류 감지**(점 정합, 코드). 얇은 손가락의 깊이는 결손이 잦으므로 점 주변 작은 창의 유효 깊이 중앙값을 쓰고, 결손이면 FK 깊이로 대체하고 표시한다.
- **시뮬 검증(FK 대조, 무료·GPU만)**: TRAIN 시드(DEV는 평가 전용)의 참값 모델 편 상태 스냅샷에서 머리 RGB-D + FK 정답. 지표: TCP 점 픽셀 오차, 3D 오차 mm(GT 깊이·잡음 깊이 두 판), 접근 축 각도 오차, 보임 판정 정확도, 열림/닫힘 정확도. 관문 초안(등록 때 고정): 보이는 상태에서 3D 오차 중앙 ≤ 10 mm, 축 오차 중앙 ≤ 10°, 보임 판정 ≥ 95 %. 가림(팔이 머그 뒤) 상태는 따로 보고.
- **상위 VLM에 접기**: 학생 답 JSON에 선택 블록 `self: {tcp_px, root_px, pad_px[2], visible, open}`을 더해 SFT(라벨 = 시뮬 FK 투영; 실물 추가학습 자리에서는 FK + 보정, Molmo2-ER + 거르개 v2는 교차 확인). 실행 때 코드가 VLM 점과 FK 투영을 비교해 차이가 문턱을 넘으면 '보정 의심'으로 기록·경고(행동은 FK 기준 유지). 별도 모델 0개.

## 4. 장면 자동화 (깊이 가정)
모두 **코드**(모델 아님) + 상위 VLM의 점. 입력 = 머리 RGB-D, 머리 카메라 FK 자세.
1. **탁자 평면·높이**: 작업 상자 앞쪽 ROI의 깊이 점 → RANSAC 평면(법선이 로봇 z와 10° 안) → 평면 식·탁자 z. 시뮬 대조 `TABLE_TOP_Z`(0.850): 관문 |Δz| ≤ 5 mm(GT 깊이), 잡음 깊이는 보고.
2. **물체 3D 위치·크기**: 상위 VLM이 이름 붙인 물체마다 점 하나(또는 상자) → 평면 위 높이 > 5 mm 점들의 연결 성분 중 그 점을 포함한 군집 → 중심 (x, y) = 발자국 중심(윗면 아님 — 격자 범례가 경고한 편향을 코드가 없앰), 높이 h = 평면 위 높이 상위 분위(98 %), 발자국 크기 = xy 최소 면적 사각형 또는 원 맞춤. 머리에서는 앞·윗면만 보이므로 깊이 방향 크기는 과소 추정 → 원기둥은 폭으로 지름, 상자는 윗면 모서리로. 손목 D405 깊이(근거리)로 접근 중 다듬기. 시뮬 관문 초안: 중심 xy ≤ 10 mm, h ≤ 5 mm, 폭 ≤ 10 mm.
3. **놓을 면 높이**: 놓을 곳 군집의 윗면 높이(쟁반 = 평면 + 1.5 cm) → 놓기 목표 z.
4. **분할 모델이 필요한가**: 맞닿은 물체·같은 높이 물체는 높이 군집으로 안 갈릴 수 있다. 그 비율이 관문(예 > 5 % 상태)을 넘을 때만 SAM 3(ICLR 2026, 11,771★)를 3번째 모델 후보로 올린다(5절).
- 결과 쓰는 방식: 학생 프롬프트에 **숫자로 넣는다**("red mug: cylinder, base centre (0.428, −0.382), top z 0.945, width 6.3 cm — 측정값") — 이 값은 손으로 쓴 것이 아니라 매 호출 인식 결과다. 격자 읽기(대리 모델 실패 지점)가 필요 없어진다. 다만 "VLM이 점을 잘 찍는가"가 새 병목이 된다 → 3절과 같은 무료 라벨(GT 물체 중심 투영)로 학습.

## 5. 절차 자동화
| 방식 | 내용 | 장점 | 약점 |
|---|---|---|---|
| D 도출 규칙 | 로봇 자기 정보(패드 길이·몸통 높이·열림 폭) + 인식(h, 평면, 놓을 면)만으로 일반 규칙: 잡기 전 높이 = 윗면 + 몸통 2.5 cm + 여유; 잡기 z = 윗면 − min(패드 반길이, h/2 − 여유); 놓기 z = 면 + (TCP − 물체 바닥 거리) + 1 cm | 물체별 손 튜닝 없음, 새 물체에 바로 | 규칙은 여전히 사람이 씀(물체 무관 기하일 뿐); 쥘 수 없는 폭(> 열림) 판단 등은 추가 |
| T 학습(E-TEACH) | 선생(참값 모델·Astra)의 편에서 학생이 요령을 배움; 학생 프롬프트에서 10–12행 삭제 | 사용자 요구("학습 또는 도출")에 가장 가깝고 모델 수 0 추가 | 선생 데이터 필요(참값은 무료) |
- **제안**: 학생 = T(요령 문장 없는 프롬프트로 SFT), 선생·실행기·참값 모델 = D(참값 모델 `truth.py`의 경유점을 GT가 아니라 4절 인식값 + D 규칙으로 계산하는 판을 둠). 즉 사람이 쓴 물체별 수치는 어디에도 남지 않고, 남는 규칙은 로봇 기하에서 도출된 것 하나다. E-TEACH-L 팔(L-T)의 참값 라벨이 곧 D 규칙의 시연이 된다.

## 7. 절제 사다리 — 자동화 전에 무엇이 중요한지 잰다 (한 번에 하나)
원칙: 무료(참값·오라클, 스냅샷)를 먼저, 유료는 작게. 사용자: "좀 아껴서 ... 제대로 된 결과 나오게".

| 단 | 무엇 | 방법 | 비용 |
|---|---|---|---|
| **A0 (첫 무료)** | 자동 원천이 손 값만큼 정확한가 | TRAIN 시드 초기 장면 + 참값 모델 편(무료)의 방문 상태 스냅샷을 **깊이 켜고** 렌더(GT·잡음 두 판) → 탁자 평면, 물체 군집 중심·높이·폭, 놓을 면, 자기 점(FK 투영 기준)·축 → GT와 대조; 관문 4·3절 | 0원, GPU(Isaac 렌더만) |
| A1 무료 | 자동 값으로 바꿔도 **실행이 되나** | '인식 참값' 팔: `truth.py`의 입력을 한 번에 하나씩 자동 값으로 교체(탁자 z → 물체 크기 → 물체 위치 → D 규칙) → DEV 대신 TRAIN 12편 폐루프, 참값 6/6 대비 성공·첫 닫기 xy 오차 | 0원, GPU |
| A2 유료 소액 | **모델이** 어떤 손 정보를 실제로 쓰나 | 저장된 Astra 호출(파일럿·전체 팔 앞 3편)의 요청을 그대로 두고 **한 항목만 빼거나 바꿔** 재질문(`harvest/astra_solo/reask.py` 방식, 동기라 상태 고정): ① 탁자 z 삭제 ② 물체 크기 삭제 ③ 그리퍼 수치 삭제 ④ 요령 삭제 ⑤ 격자 삭제 + 인식 숫자 추가 ⑥ 정의·조언 삭제. 지표 = 참값 대비 명령 목표 오차(접근 xy·잡기 z·놓기 z), 무효율 | 단계 1 ≤ 3,000원(약 55호출: 핵심 상태 9 × ①–⑥), 결과 보고 판단 뒤 단계 2 ≤ 5,000원 → **합 ≤ 8,000원** |
| A3 | 학생에서 다시 | E-TEACH-L 학생을 '자동 맥락' 프롬프트로 학습 — 손 정보 없는 판과 짝 | 0원, GPU |
- 자체 검사(user-log 87): A2는 첫 10호출 뒤 단가·무효율 확인, 80 %에서 멈춤, 빈 답 3연속 정지(P108); 모든 단은 결과 전에 관문·표본 고정, 영상·프레임 눈 확인.
- 해석 주의: A2는 Astra가 무엇에 기대는지를 보여 줄 뿐 학생이 무엇을 배울 수 있는지를 보여 주지 않는다(학생 판단은 A3). 대리 영샷(0/4)은 바닥이라 무료 로컬 모델 절제는 정보가 없다(P103과 같은 이유).
