# 관절형 스킬(서랍/문/손잡이/버튼/밀기) 확장 — 문헌조사 + 포맷/데이터 생성 설계

날짜: 2026-10-02
범위: Fly-by-Wire 상위 VLM 조종기(Qwen3.5-35B LoRA) 출력 포맷 v2 → v3 확장, Isaac Sim 데이터 생성 설계, 과제 목록, 공수/위험
비범위: LIBERO/RoboCasa/BEHAVIOR 자산·장면·과제 사용 금지(held-out 평가 유지), 모바일 베이스 작업 없음, 파드/GPU/구동 코드 미접촉

## 0. 요약

- 지금 포맷은 "집기/놓기"만 표현 가능. 서랍·문·손잡이·버튼·밀기를 표현하려면 **포인트 1개를 더(point2) + 스킬 태그(skill) 1개**만 추가하면 된다. 축/방향/거리/회전량은 point + point2 + 기존 15° 빈 재사용으로 코드가 유도한다 — 새 자유 필드를 늘리지 않는다.
- 최근 1.5년 문헌(MOKA, A3VLM, ManipVQA, RoboPoint, RoboBrain 2.0, UniAff, π0.5, GR00T N1/N1.5)은 모두 "포인트/박스 + 소수의 이산 태그"로 조작을 표현하고, 관절체는 **부품 포인트 + 운동축**으로 별도 인코딩한다. 우리 설계는 이 흐름과 합치한다(아래 1장, 근거표 §6).
- 라이선스: **PartNet-Mobility 원본은 비상업 연구용 전용(NC) — 사용 금지.** 파생 재배포(QueST-PartNetMobility-SAPIEN 등 CC-BY)도 원본 NC 조항이 승계될 위험이 있어 보류. **GAPartNet은 CC BY-NC 4.0 — 사용 금지.** 실사용 가능: **ArtVIP(Apache-2.0)**, **Infinigen-Sim/Infinigen-Articulated(BSD-3-Clause, 절차 생성)**. 주력은 자체 절차 생성(캐비닛/서랍/문)으로 라이선스 리스크를 원천 제거.
- ≥40개 과제(§4), 공수 추정 총 24~35일 핵심 구간(§5), 최대 위험은 절차 생성 관절 물리 안정성과 축 제약 계획 수렴(§5).

## 1. 문헌조사 — 최근 VLM/VLA가 포인트/타겟을 표현하는 방식

모든 출처는 1.5년 이내(2024-03~2025-07) 논문/기술보고서 또는 스타 수 확인된 GitHub다. 표 뒤에 설계 시사점을 정리한다.

| 방법 | 출처/날짜 | 스타·라이선스 | 표현 방식 |
|---|---|---|---|
| **MOKA** | arXiv 2403.03174, 2024-03 (Berkeley, RSS 2024) | 코드 공개, 연구용 | 이미지에 마킹(후보점/그리드)을 찍고 VQA로 "어느 마크가 집을 곳/놓을 곳/웨이포인트인가"를 묻는다. 관절체 축도 같은 마킹 방식으로 "회전축이 어느 변인가" 질문해 2D 포인트 2개(피벗점+진행 방향점)로 환원 |
| **A3VLM** | arXiv 2406.07549, 2024-06 (CoRL 2024), github.com/changhaonan/A3VLM | 공개 저장소(CoRL 공식) | 객체중심·"actionable" 표현: 부품 바운딩박스 + **관절축(방향 벡터+피벗점)** + 동작 범위를 로봇에 무관하게 출력, 이후 단순 프리미티브(push/pull/rotate)로 변환 |
| **ManipVQA** | arXiv 2403.11289, 2024-03 (IROS 2024) | 공개 저장소 | 도구 사용(비관절) affordance를 VQA 포맷으로. 관절체는 다루지 않음 — 우리 설계에서 "press/push" 쪽 참고, "pull/rotate" 축 표현은 A3VLM/UniAff 쪽이 더 적합 |
| **RoboPoint** | arXiv 2406.10721, 2024-06, github.com/wentaoyuan/RoboPoint | 공개 저장소 | 단일 2D 키포인트(또는 포인트 집합) 예측에 집중, 자유공간/타겟 지점 모두 "점"으로 통일. 우리 point/point2 설계의 직접 전례 |
| **RoboBrain 2.0** | arXiv 2507.02029, 2025-07 (FlagOpen) | 공개 저장소(RoboBrain 계열) | pointing + affordance + **trajectory forecasting**(점의 시퀀스)을 한 틀에서. "축 당김"을 시작점→끝점 2점 + 중간 보간으로 표현하는 것과 동형 |
| **UniAff** | arXiv 2409.20551, 2024-09 (ICRA 2025) | 공개, 연구용 | 관절체(900개/19종) + 도구(600개/12종)를 **부품 박스 + 6D 포즈 + 운동 타입(회전/병진) + 축**으로 통일 VQA. A3VLM 대비 미지 카테고리 +9.6%p — 우리가 "skill 태그 + 축 유도"로 가는 것과 같은 방향성의 정량적 근거 |
| **π0.5** | arXiv 2504.16054, 2025-04 (Physical Intelligence) | 기술보고서(가중치 비공개) | 서랍 정리·캐비닛 닫기 등을 "고수준 서브태스크 선택 + 저수준 연속 액션"으로 처리. 포인트/축 같은 명시적 기하 표현은 쓰지 않고 end-to-end 플로우 매칭 — 우리 설계(명시적 포인트+스킬 태그)와 대비되는 "암묵적" 노선으로 참고만 |
| **GR00T N1 / N1.5** | arXiv 2503.14734, 2025-03 (NVIDIA) | 공개 저장소(Isaac-GR00T) | 이중 시스템(VLM 플래너 + DiT 플로우 정책), 플래너 쪽 중간 표현은 논문에 세부 공개 적음 — 관절체 특화 포인트 스킴은 명시돼 있지 않음. 우리가 참고할 것은 "상위 선언 + 하위 연속 제어" 분리 구조 자체 |
| **ManipGPT / RoboSeek 계열 affordance segmentation** | arXiv 2412.10050 등, 2024-12 | 공개 | 포인트 대신 **분할 마스크**로 affordance 표현 — 우리 포맷(포인트 기반)과는 결이 다르지만 "넓은 접촉 영역"이 필요한 press/push에 마스크가 유리하다는 반례로 기록(채택 안 함, 포인트로 충분) |
| **cuRobo constrained planning** | arXiv 2310.17274 + 공식 문서(curobo.org), NVlabs/curobo(Apache-2.0, 다수 스타) | 공개 | 포즈 비용에 선형/각 축을 "잠그고" 나머지 축만 목표로 보내는 제약 계획을 기본 지원 — **서랍 당김/문 회전을 축 제약 코스트로 바로 구현 가능**, 신규 플래너 불필요 |

**시사점**:
1. 포인트 기반 표현(RoboPoint, MOKA)과 "부품-축" 표현(A3VLM, UniAff)이 수렴점이다. 우리는 이미 포인트 기반이므로 **A3VLM/UniAff의 "피벗점+축" 개념을 2번째 포인트로 압축**해 넣는 것이 최소 변경이다.
2. π0.5/GR00T는 명시적 기하 표현을 쓰지 않는 "암묵적" 노선이라 포맷 설계에는 직접 참고되지 않는다. 다만 둘 다 "고수준 선언 → 저수준 연속 제어" 분리는 우리 구조(VLM → 3D 타겟 → cuRobo)와 동일한 철학이라는 점만 근거로 채택.
3. cuRobo는 이미 축 제약 계획을 1급 기능으로 지원하므로, GT 플래너 구현 리스크는 "플래너 자체"가 아니라 "접촉/마찰 하에서의 수렴성·안정성"으로 좁혀진다(§3, §5 위험).

## 2. 출력 포맷 v2 → v3: 최소 확장안

### 2.1 기존 v2 (변경 없음)
- `point` (픽셀 0–1000) + `height`
- `approach` ∈ {top, oblique, front, side}
- `wrist_bin` (15° 양자화)
- `gripper_intent`
- `arm` ∈ {left, right} (1–2개)
- 양손 필드(추가 중): `role`, `hold`, `sync`

### 2.2 추가 필드 — 딱 2개

| 필드 | 타입 | 기본값 | 의미 |
|---|---|---|---|
| `skill` | enum {pick_place, pull, push, rotate, press} | `pick_place` (생략 시 기존 동작과 100% 호환) | 동작 종류 |
| `point2` | 픽셀 (0–1000), optional | 없음(pick_place/press는 미사용) | 스킬별로 "축 방향점" 또는 "목적지점" 역할 |

`point2`는 새 좌표 인코더를 만들지 않고 `point`와 동일한 0–1000 양자화를 재사용한다. 기존 토크나이저/헤드 변경 없음.

### 2.3 스킬별 의미 매핑 (코드에서 3D로 변환하는 규칙)

| skill | `point` | `point2` | 축/거리/회전량 유도 | 재사용 필드 |
|---|---|---|---|---|
| **pull**(서랍/당김문) | 손잡이 그립점 | 당기는 방향의 끝점(이미지상) | `point→point2` 벡터를 3D로 역투영 → 조인트 축에 투영(조인트는 장면에서 알 수 있으므로 코드가 가장 가까운 축에 스냅) → 당김량은 `wrist_bin`과 동일한 15°/또는 거리 빈 재사용(§2.4) | `gripper_intent`에 `hook_pull` 값 추가 |
| **push**(힌지문 밀기/슬라이딩 도어/물체 밀기) | 접촉점 | 목적지점(문이 도달할 지점, 또는 물체가 밀려갈 지점) | 동일하게 `point→point2` 벡터 = 이동 방향, 힌지문이면 코드가 조인트 축에 스냅해 각도로 변환, 자유물체면 그대로 평행이동 목표 | 기존 `approach` 그대로(접근 방향) |
| **rotate**(손잡이/다이얼) | 손잡이 중심점 | 회전 진행 방향 위의 한 점(원주상) | `point`=피벗, `point2`로 회전 방향(시계/반시계) 결정, 회전량은 거리 빈 재사용(§2.4: 작게/중간/크게/최대) | `wrist_bin`을 손목 사전정렬에 그대로 사용 |
| **press**(버튼/스위치) | 누를 지점 | 미사용 | 깊이는 기존 `height` 필드를 "누름 깊이"로 중의적 재사용(스킬이 press일 때만 의미 전환) | `gripper_intent`에 `flat_press` 값 추가 |

### 2.4 거리/회전량 — 새 필드 대신 기존 15° 빈 인프라 재사용
`wrist_bin`과 동일한 이산 양자화 메커니즘(모델 헤드·손실 동일)을 "진행량 빈"으로 복제해 쓴다:
- pull/push 거리: {quarter, half, full, max} 4빈 — 서랍 전장 대비 비율로 장면이 정규화해 해석.
- rotate 각도: {15°, 30°, 45°, 90°, 180°, continuous} — 다이얼류는 continuous(끝까지) 빈이 실용적으로 많이 쓰일 것으로 예상(가설, 미검증).

새 벡터·새 헤드·새 손실 함수 없음 — 기존 분류 헤드를 값 집합만 바꿔 복제.

### 2.5 양손 필드와의 호환성
`role`/`hold`/`sync`는 스킬 종류와 독립이다. 예: 서랍을 한 손이 캐비닛 몸체를 `hold`(고정)하고 다른 손이 `pull`하는 2단계 양손 협응도 기존 필드 조합(각 `arm`마다 다른 `skill`)으로 그대로 표현된다. 포맷 변경 불필요.

### 2.6 호환성 요약
- `skill` 생략 = v2 그대로 pick/place. 기존 체크포인트·라벨 영향 없음.
- 신규 enum 값(`hook_pull`, `flat_press`)은 기존 `gripper_intent` 분류 헤드에 클래스 2개 추가 — 파인튜닝만 필요, 아키텍처 불변.
- 코드(3D 변환기, cuRobo 타겟 생성기) 쪽 변경이 모델 포맷 변경보다 크다 — 의도된 설계(모델은 가볍게, 기하 처리는 결정적 코드로).

## 3. Isaac Sim 데이터 생성 파이프라인

### 3.1 자산
- **절차 생성(주력, 라이선스 리스크 0)**: 캐비닛/서랍/힌지문/슬라이딩문을 파라메트릭 USD로 직접 생성 — 판 크기, 손잡이 위치·형태(바/노브/컵형), 조인트 타입(prismatic/revolute), 조인트 한계·마찰·댐핑을 무작위화. Infinigen-Articulated(BSD-3-Clause, 2025, princeton-vl/infinigen 7.3k★)의 절차 생성 방법론(관절 자산을 MJCF/URDF/USD로 export)을 참고해 자체 생성기를 구현한다 — 코드는 참고만, 자산 자체를 가져오지 않으면 라이선스 이슈 없음.
- **라이선스 보유 완성 자산(다양성 보강)**: **ArtVIP**(Apache-2.0, 2025-06/08, 435~476개 관절 자산 + 6개 실내 장면, USD 네이티브) — 그대로 사용 가능. 출처/날짜/라이선스를 자산별로 `docs/book`에 기록.
- **명시적으로 사용하지 않음**:
  - PartNet-Mobility 원본: SAPIEN 라이선스가 "비상업 연구·교육 목적 전용"으로 명시 — 하드 룰(NC 금지) 위반, 사용 안 함.
  - GAPartNet: CC BY-NC 4.0 — NC 위반, 사용 안 함.
  - PartNet-Mobility 파생 재배포(HuggingFace의 CC-BY 라벨 버전들): 원본 데이터베이스 자체가 NC 조건부 배포였던 자산이라 재라이선싱의 적법성이 불확실 — 보류, 쓰지 않음. (게이트 데이터 알림 규칙에 따라: 이후 필요성이 생기면 사용자에게 먼저 제안하고 동의받는다.)

### 3.2 절차 생성기 설계 (자체 구현)
- 가구 패밀리별 파라메트릭 템플릿 3종: (a) 서랍장(1~4단 prismatic), (b) 여닫이 캐비닛(1~2짝 revolute, 좌/우 힌지), (c) 슬라이딩 도어(prismatic, 레일).
- 손잡이 라이브러리(바/노브/오목홈) × 재질 랜덤화, 조인트 마찰·댐핑·한계각/거리 랜덤화(물리 안정성 확보가 핵심 — §5 위험 1).
- 다이얼/버튼은 독립 소품(스토브 노브, 벽 스위치, 가전 버튼판)으로 별도 템플릿.

### 3.3 스크립트 GT 플래너 (관찰자 모드, 룰베이스 — 기존 "손대지 않는 깃 메인" 원칙과 동일하게 플래너는 궤적만 생성)
- **당김(서랍/당김문)**: 손잡이 그립 → 조인트 축 방향으로 cuRobo 축 제약(linear axis locked except pull axis) 코스트 계획, 등속 당김, 끝에서 정지 유지(튐 금지 규칙 적용).
- **회전(힌지문/노브)**: 피벗 축 기준 원호 웨이포인트 생성(각속도 상한), cuRobo에 각 축만 열어둔 제약 계획 또는 소형 임피던스 제어로 접촉 추종.
- **버튼(press)**: 접근 후 수직 임피던스 압입(깊이 임계), 되돌림.
- **밀기(push/slide)**: 접촉점 선정(물체 무게중심 반대측) → 목적지점까지 직선/원호 가압 이동, 비파지(non-prehensile) 접촉 유지.
- 모든 궤적은 등속 접근·정착 후 판단·기록 복귀(기존 feedback_no_jumps_safety 규칙 그대로 적용).

### 3.4 성공/실패/복구 라벨
- **성공 판정**: 조인트형(서랍/문/노브)은 **조인트 각/거리 임계값**(예: prismatic ≥ 80% 목표 이동, revolute ≥ 목표각 90%) + 유지 시간. 버튼은 접촉+깊이 임계 통과 이벤트. 밀기는 **객체 변위**(목표점까지 유클리드 거리 ≤ 임계) + 전복/낙하 없음.
- **실패 모드 라벨**: (1) 접근 실패(접촉 전 충돌/경로 불가), (2) 파지 실패(그립 미스), (3) 축 이탈(조인트 범위 초과로 플래너 중단 — 기존 "단계별 분해 추론" 규칙과 동일하게 mm/° 단위로 세분 기록), (4) 과도 힘(조인트 걸림/경첩 고착), (5) 목표 미달(이동량 부족), (6) 완료 후 미끄러짐/재폐쇠.
- **복구 라벨**: 실패 유형별 재시도 전략 태그(재그립, 접근각 변경, 힘 임계 완화) — 데이터에는 "복구 성공 여부" 바이너리까지 포함해 향후 복구 정책 학습에 쓸 수 있게 남긴다.
- 모든 생성 판은 머리+양손목 영상(≥10fps, mp4)과 프레임 비교(f0·0.7초 지점)를 저장(기존 규칙 feedback_video_every_run, feedback_qdd_save_all_videos 그대로 계승).
