## 0. 결정과 요약

- **결정(사용자 + Claude 설계, 정본 §97 보충 1)**: 상위 VLM 학습(§96·§97, 가설 H-L)에서 **다양한 데이터는 선택이 아니라 필수다.** 지금 시뮬 과제는 탁자 높이(z = 0.850), 탁자(0.70 × 1.00 m), 물체(머그·병·쟁반·표지), 방해물이 모두 같다. 이것만으로 학습하면 모델은 "이 장면에서 이 좌표"를 외울 뿐 일반성을 얻지 못한다.
- **두 갈래로 채운다**:
  - (a) **공개 데이터를 우리 형식으로 변환**한다. 인식 QA와, 사용자 제안인 좌표계 명시 조종(C′)이다. 둘 다 '보조'에서 **필수**로 올린다.
  - (b) **자체 시뮬 생성기를 다양화**한다(1절).
- **일반성은 잰다**: DEV만으로는 일반성을 말할 수 없다. 학습에 절대 쓰지 않는 OOD 평가 세트 넷(OOD-H·O·D·X, 3절)에서 L8과 같은 지표로 잰다. 프레임 누수율은 0이어야 한다.
- **필수의 뜻**: E-XEMB8(4절)은 다양한 데이터를 **넣을지**를 정하지 않는다. **어떤 형태로, 몇 %를** 넣을지를 정한다. 어떤 스트림이 DEV를 해치면 그 스트림의 변환(형식·표시)을 고치거나 다른 원천으로 바꾼다. 다양화한 자체 시뮬은 어떤 경우에도 남는 바닥이다.
- **순서**: L8 1단계 결과 → 생성기 다양화와 공개 변환 시제품(무료, CPU와 렌더 GPU) → OOD 세트 생성 → E-XEMB8 사전 등록 → 실행(8B, 무료, GPU만).

## 1. 자체 시뮬 다양화 명세

현재 상태를 코드에서 확인했다.
- `harvest/sim/scene.py`:
  - `TABLE_TOP_Z = 0.85`는 모듈 상수다. 주석에 따르면 머리 카메라(피치 고정)가 x ≥ 약 0.35 m를 보고 오른팔이 x 약 0.50 m까지 위에서 닿도록 고른 값이다. 0.76에서는 보이는 띠와 닿는 띠가 x 0.385–0.47로 겨우 겹쳤다.
  - `TABLE_SIZE = (0.70, 1.00, 0.04)`, 중심 `(0.50, −0.10)`이다.
  - 물체는 `OBJ_GEOM`의 원시 도형 6개다.
  - 작업 상자는 `WS_X (0.36, 0.48)`, `WS_Y (−0.40, −0.06)`다.
- `harvest/sim/tasks.py`: 과제는 `mug_tray`·`bottle_tray`·`mug_marker` 셋이고, `box_marker`는 실험용이다(DEV 0/3).
- `harvest/sim/randomize.py` + `randomization_pools.json`: RoboDojo 5축 무작위화를 한다(탁자·바닥 재질, 조명 종류·세기·색온도, HDR, 방해물 1–3개). train 풀(dr)과 test 풀(random)은 자산도 수치 띠도 겹치지 않는다(정본 §34 D35).
- 참값 모델은 `astra_motion/truth.py`의 `TruthModel`이다. 탁자 높이는 `world.table_z`(= `env.table_top_z`)에서 읽는다. 잡기점은 윗면 − 1.8 cm(`GRASP_BELOW_TOP_M`, 머그 테두리에 맞춘 값), 운반 높이는 탁자 + 22 cm, 놓기 높이는 놓을 물체의 `obj_height` 윗면 + 4 mm다. 실행기 `SAFE_DZ`, 프롬프트, 격자 덧그림도 `table_z`를 인자로 받는다.

**머리 각도는 고정한다**(실물 45°). 무작위화 축이 아니다. 아래 표의 '카메라 흔들림'은 장착 보정 오차만 뜻하고, 머리 관절은 건드리지 않는다.

- **학생 입력 쪽 주의**: 다양화의 목적은 모델이 영상과 측정값에서 장면을 읽게 하는 것이다. 그러므로 학생 프롬프트에 새로 생기는 장면 수치(탁자 z, 물체 크기)는 §97의 자동 경로(깊이 평면·군집)에서 나와야 한다. 자산 표를 그대로 복사하면 외우기가 된다. L8 레시피처럼 탁자 z를 글로 주는 판은 E-XEMB8 A–E 모두 같게 두고, 자동 맥락 판(`astra-solo@v3-auto`)은 §97 순서대로 따로 간다.
- **시드와 분할**: 다양화 생성은 R2_TRAIN(10000–59999) 안의 새 연속 구간을 쓴다(L8의 20000대와 겹치지 않게, 예 30000–34999). OOD는 새 보호 분할을 쓴다(3절).
- **개발 합계**: 약 6–8일(에이전트 작업, CPU) + 렌더 GPU 약 10–12 프로세스-h(관문·선별). 유료 0.

- **C′ 선택 기준**:
  - 탁자 위 집어 놓기 편만 쓴다;
  - 잡는 순간 접근 축이 중력 방향에서 30° 안(거의 위에서)이어야 한다;
  - 보정(내부·외부값), 말단 자세, 그리퍼 상태가 프레임마다 있거나 계산할 수 있어야 한다;
  - 성공 편만 쓴다;
  - 양팔 편은 한 팔만 움직이는 구간만 쓴다;
  - 대상이 머리 영상에 보이는 프레임만 쓴다.
- **단계 자르기**: 그리퍼 사건(닫힘·열림 전환)에서 편을 우리 단계 어휘로 자른다. 이 어휘는 L8 라벨(`teach_l8/labels.py`)의 단계와 같다. 각 단계의 라벨은 그 단계 끝의 말단 자세(그 로봇 기저의 절대 목표) + 그리퍼 {keep, close, open}이고, 마지막은 stop이다.

  | 우리 단계 | 공개 편에서 뽑는 점 |
  |---|---|
  | above_target | 닫힘 전 접근 정점 |
  | descend_close | 닫힘 사건 |
  | lift | 닫힘 뒤 최고점 |
  | above_place | 열림 전 정점 |
  | place_open | 열림 사건 |
  | retreat | 열림 뒤 상승 |

- **로봇별 자기 정보 블록**: 사람이 쓰지 않는다. 각 데이터셋이 공개한 로봇 기술(URDF·MJCF — R1Pro는 OmniGibson, RBY1은 MolmoSpaces, aloha-agilex는 RoboTwin)과 프레임 보정에서 **§97과 같은 틀로 자동 생성**한다. 들어가는 것은 좌표계 정의, TCP 정의, 그리퍼 최대 폭, 작업 범위(데이터 말단 위치의 1–99 분위), 카메라 내부값, 카메라 → 기저 외부값이다. 모델이 숫자를 외우지 않고 블록을 읽게 하는 것이 목적이다. 모든 표본의 첫 줄은 `source: <데이터셋>/<기체>`, `frame: base_<기체>`다(규칙 2). 우리 표본은 `source: qdd_sim/ffw_sg2`, `frame: base_ffw_sg2`다.
- **라이선스**:
  - MIT, Apache-2.0, CC BY 4.0, ODC-BY를 먼저 쓴다.
  - 게이트 데이터(InternData-A1·M1, RoboInter, AgiBot, Galaxea)는 **사용자가 HF 약관 동의를 한 뒤에만** 받는다. 에이전트가 대신 동의하지 않는다.
  - NC·ND 조항이 있는 데이터는 내부 학습 검토 전까지 보류하고, Astra에 보내지 않는다.
  - **라이선스 표기가 없는 데이터(SynGrasp-1B 등)는 내부 전용이고, Astra로 절대 보내지 않는다.**
  - OXE 파생(S6·S7)은 원천별 목록을 적는다.
- **비용**(교차 기체·조사 문서 값, [추정]):
  - 변환 CPU: S4 1–2일, S3 2–3일, S5 0.5–1일, S9·S6 반나절씩, C′ 추가 1–2일.
  - 내려받기: 과제·설정 부분 집합만 받는다(전체 합계는 12 TB 이상).
  - 유료 0, GPU 0(변환은 CPU; 겹쳐 그리기 확인은 눈으로).

## 3. OOD 평가 세트 — 절대 학습하지 않는다

- **분할**: 새 보호 분할 `ood`의 시드는 70000–70999다. 지금 어떤 분할과도 겹치지 않는다. R2_TRAIN 상한은 59999이고, `gen.check_r2_seed`는 60000 이상을 거부한다. `eval/splits.py`의 `RANGES`와 `PROTECTED`에 추가하고, 생성에는 `--confirm-ood`를 요구한다. 데이터 빌드 시드 검사에 `ood`를 넣는다(DEV와 같은 거부).
- **자산 분리**: OOD 자산(물체 범주·방해물·재질·높이 띠)은 **학습 생성 전에** 이름 해시로 뽑아 목록 파일로 고정하고 커밋한다. 학습 풀은 그 목록을 뺀 나머지다.

| 세트 | 무엇이 새로운가 | 구성(과제 × 편) | 스냅숏 |
|---|---|---|---|
| **OOD-H** | 본 적 없는 탁자 높이: 사이값 [0.815, 0.835] ∪ [0.865, 0.885], 바깥값 [0.74, 0.77] ∪ [0.94, 0.97](관문 G-H를 통과한 쪽만) | 시드 70000–70099: mug_tray 20 + 새 과제(1) 20편 × standard·dr | 약 350 |
| **OOD-O** | 본 적 없는 물체: 물체 **범주**의 20 %를 통째로 빼서 쓴다(같은 범주의 다른 인스턴스가 아님) + 본 적 없는 놓을 곳 2종 | 70100–70299: 새 물체 → 쟁반·그릇 40편 | 약 350 |
| **OOD-D** | 본 적 없는 방해물 배치: test 풀 방해물·재질·조명(정본 §34 D35 — 원래 학습 금지 풀), 개수 4–6, 혼동체 비율을 높임, 새 지시 표현 | 70300–70499: mug_tray·속성 고르기 40편 | 약 350 |
| **OOD-X** | 공개 기체 보류분: RoboTwin의 한 기체(예: aloha-agilex 밖 하나) 통째로, MolmoBot 집(house id 해시 10 %), BEHAVIOR 과제 5개. C′는 **한 기체를 통째로** 빼서 쓴다(예: C′ 학습 R1Pro + RBY1 → OOD-X는 Franka) | 원천별 편 | 인식 약 500 + C′ 약 300 |

- **지표**(L8 4.4절과 같다, 같은 검사기):
  - 유효 JSON률;
  - 그리퍼 행동 정확도;
  - **접근 목표 xy 오차**(중앙·p90·≤ 20 mm 비율·편별 중앙의 중앙)와 운반 목표 xy 오차;
  - 인식 보조 QA 오차(종류별);
  - **프레임 누수율 = 0**(우리 런타임 요청(`frame: base_ffw_sg2`)에 대한 답에 `frame` 칸, 픽셀 좌표, 다른 기체 좌표가 섞인 비율. 한 건이라도 있으면 그 팔은 실패로 보고 변환을 고친다);
  - 일반화 간격 = OOD 중앙 ÷ DEV 중앙.
- **OOD-X 전용 지표**: 인식은 픽셀 오차와 카메라 3D 오차(mm), C′는 그 기체 기저에서 목표 오차(mm)와 `frame` 표시 정답률이다.
- 생성 비용: OOD-H·O·D 각 40편, 편당 약 12–30 s → 합 약 0.5–1 렌더 프로세스-h. OOD-X는 변환의 부산물이다.

## 4. E-XEMB8 개정 (8B, 무료, GPU만 — 사전 등록 전, L8 1단계 결과 뒤)

- **질문**: 같은 계산량에서, 다양한 데이터(자체 다양화·공개 인식 QA·C′)를 섞으면 DEV를 해치지 않고 **OOD 오차가 줄어드는가?** 어떤 형태가 가장 나은가?
- **공통**:
  - L8 레시피를 복제한다: Qwen3-VL-8B, LoRA r 16·α 32, 같은 하이퍼파라미터, 2 에폭.
  - **모든 팔이 같은 총 스텝과 같은 표본 수**를 쓴다. 에폭당 L8 실측 6,521(조종 4,025 + 보조 2,496)이다.
  - 코드는 고정 사본을 쓴다(P109·P114).
  - L8 파일은 건드리지 않는다. 복제는 새 폴더(`harvest/xemb/`, `tools/xemb/`)에 둔다.
  - 행 수는 로더가 실제로 붙인 수로 보고한다(P115).

| 팔 | 조종 몫(4,025) | 보조·인식 몫(2,496) |
|---|---|---|
| **A** 자체만 | L8 그대로(L8 어댑터를 재사용하고 OOD 평가만 더함) | L8 그대로 |
| **B** + 공개 인식 QA | 자체 그대로 | 자체 1,248 + 공개 인식 QA 1,248(S4·S3·S5·S6·S9 균등, 규칙 1–3) |
| **D** + 공개 C′ | 자체 약 3,020 + C′ 약 1,005(25 %) | 자체 그대로 |
| **E** 다양화 전부 | 다양화 생성기 자체 약 3,020 + C′ 약 1,005 | 다양화 자체 1,248 + 공개 인식 QA 1,248 |
| (선택) **E′** 자체 다양화만 | 다양화 생성기 자체 4,025 | 다양화 자체 2,496 |

- E′는 생성기 효과와 공개 데이터 효과를 가르기 위한 팔이다. GPU 여유가 있을 때만 돈다.
- 다양화 자체 데이터는 L8과 같은 수집기·교란(DART식)·라벨 규칙을 쓴다. 장면만 새 생성기(1절)에서 나오고, 편 수는 L8과 같은 300편이다.
- **평가**: DEV(L8과 같은 약 350 스냅숏) + OOD-H·O·D(각 약 350) + OOD-X(B·D·E에서 인식·C′).
- **판정 초안**(등록 때 고정):
  1. **관문**(모든 팔):
     - 유효 JSON률 ≥ 0.95;
     - **프레임 누수 0건**;
     - DEV 접근 xy 중앙 ≤ A × 1.1(비열등).
     관문을 못 넘은 팔은 채택하지 않는다. 그 스트림은 변환을 고친 뒤 다시 잰다(버리지 않는다 — 필수 원칙).
  2. **주 지표**: OOD-H·O·D 접근 xy 중앙의 기하 평균. 한 팔의 값 ≤ A × 0.8이고, 스냅숏 짝 부트스트랩(10,000회) 95 % 구간이 0을 넘지 않으면 → **일반성 향상**으로 본다.
  3. **35B 혼합 선택**: 관문을 넘은 팔 중 주 지표가 가장 좋은 팔의 구성을 35B 1차 혼합(교차 기체 문서 3.2)의 출발점으로 쓴다. 기대는 E다.
     - D < B이면 C′의 몫을 올린다.
     - B·D가 관문에서 떨어지고 E′만 통과하면, 공개 스트림은 변환을 다시 설계한다. 그동안 35B는 자체 다양화 + 일반 공간(S9)으로 시작한다.
  4. **아무 팔도 향상이 없으면**: 다양화 자체는 그대로 필수로 유지한다. 원인을 분해해 보고한다(탁자 z를 글로 주는 판이 높이 일반화를 이미 덮는지, 물체 인식 실패인지). 그다음 §97 자동 맥락 판으로 다시 잰다.
- **선행 조건**:
  - L8 1단계가 TREND일 것(NO_TREND면 입력 설계 §97을 먼저 한다);
  - 생성기 다양화 + G-H·물체 선별 관문 통과;
  - 공개 변환 관문 통과(howto 문서);
  - OOD 목록 파일 커밋;
  - **사전 등록**(`docs/stage3/prereg_xemb8.md`)을 실행 전에 커밋한다.
- **한계**: 8B이고 DEV·OOD가 오프라인 스냅숏이라 폐루프 일반성과 35B 결과를 예측하지 않는다(L8 8절과 같다). OOD-H 바깥값은 관문을 통과한 높이만 쓴다.

## 6. 문헌 (1.5년 규칙 + 신뢰도 규칙)

사용자 규칙 원문: "신뢰도 낮은 논문과 깃 저장소는 최대한 쓰지 않는다. 쓰느니만 못하다." / "신뢰도가 무조건 있어야 하고, 스타도 어느 정도 있어야 하고, 논문도 좋아요(반응)를 많이 받은 것이어야 한다."

이번에 새로 검색하지 않았다. 아래는 모두 선행 문서가 API로 학회·별을 확인한 것이다.
- **Vlaser**(2510.11027, ICLR 2026 poster): 목표 영역 데이터가 조종을 올리고(62.6–65.1 %), 남의 영역 데이터만으로는 이득이 없다(43.2 %) → 자체 다양화가 바닥이어야 하는 근거.
- **π0.5**(2504.16054, CoRL 2025 Oral, openpi 13,999★): 다른 환경(ME)·교차 기체(CE) 데이터를 빼면 성능이 "크게" 떨어진다 → 다양한 환경 데이터가 필수라는 근거.
- **X-VLA**(2510.10274, ICLR 2026 poster, 734★): 출처별 표시 → `source`·`frame` 줄.
- **InternVLA-M1**(2510.13778, 기술 보고서, 432★): 공간 그라운딩 공동학습이 SimplerEnv +14.6·+17.0 %p → B팔.
- **RoboTwin 2.0**(ICML 2026, 2,914★): 방해물·질감·조명 무작위판을 따로 공개했다(카드 확인). 수치 효과는 이 문서에서 인용하지 않는다.
- **도메인 무작위화 원형**(Tobin 외 2017): **[기초]**, 방법의 정의로만 쓴다. 우리 5축 정의는 RoboDojo(`EVAL-evaluation-design.md` §2.1)를 따른다.
- '탁자 높이·물체 범주 보류 OOD로 상위 VLM의 일반성을 잰' 직접 선례는 확인하지 못했다. 세트 구성은 우리 설계다.
