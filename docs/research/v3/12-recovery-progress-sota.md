## 3. 질문별 답과 모듈별 최고 후보

### 3.1 질문 1: 복구 기법끼리 같은 벤치마크에서 직접 비교한 결과가 있나? → **로봇에서는 여전히 없다**

- LIBERO-RECOVER v2(09-14 개정)도 기본 VLA/WAM 6개만 평가했다. REBOOT(09-18)는 비교를 미래 과제로 남겼다. FRAMES는 복구 루프를 아직 평가하지 않았다.
- 각 복구 논문은 여전히 자기 기준 모델 위의 자기 설정이다: FaRe(RoboTwin 2.0, LingBot-VA), CorrectVLA(LIBERO-90, 사람 교정 1회), FLARE(RoboMimic 등), B2FF(자체 실패 주입 LIBERO), FailSafe(ManiSkill).
- 사용한 검색어: "LIBERO-RECOVER benchmark failure recovery methods comparison 2026", "robot failure recovery benchmark compare recovery methods FailGen RoboFail 2026", "VLA failure recovery CoRL 2026 accepted training-free recovery", "\"CoRL 2026\" failure recovery manipulation VLM accepted arXiv", 그리고 CVPR 2026 전체 목록 제목 검색(Failure / Recover / Progress / Reward Model). RoboFail, FailGen(AHA의 실패 생성기), RoboFAC는 실패 **데이터·분류** 자원이고 복구 방법 비교 벤치마크는 아니었다(검색 요약 기준, 원문 미확인).
- **LLM 에이전트 쪽에는 같은 표 비교가 있다**: RIR이 같은 백본·같은 예산에서 Reflexion, LATS, Self-Refine, GA-Rollback을 이겼다(자기 논문 안의 비교, 심사 전). ReflexGrad는 계산량을 맞춘 LATS를 ALFWorld에서 이겼다(워크숍). 두 논문은 백본과 조건이 달라 서로 비교할 수 없다.
- **"정말 최고인가"에 대한 정직한 답**: 로봇 복구에서 "가장 좋은 방법"은 수치로 정할 수 없다. 우리가 할 수 있는 말은 "심사를 통과했고 우리 구조에 옮길 수 있는 것 중 가장 근거가 강한 구조"까지다. 그래서 아래 순위는 "공유 벤치마크 1위"가 아니라 "근거 등급 × 이식 가능성" 순위다.

### 3.3 질문 3: "계획대로"의 정의 (2026 VLA)

| 출처 | "계획대로"의 정의 | 벗어남 판정 | 되돌아갈 곳 |
|---|---|---|---|
| π*0.6 RECAP (HIGH) | 성공까지 남은 스텝 수(정규화), 실패는 큰 음수 | 가치 하락, 우위가 작업별 임계값 아래 | 정의 없음(정책 학습용) |
| π0.7 (HIGH) | 하위 작업 지시 + 부분 목표 이미지 + 속도·품질·**실수 구간** 메타데이터 | 사람이 표시한 "실수 구간"(학습 라벨) | 정의 없음 |
| R²VLM (CVPR 2026, HIGH) | 진화 CoT에 적힌 **단계 목록과 각 단계 완료 상태** | 완료 상태가 기대와 다름 | 해당 단계 |
| Robo-Dopamine 1/2 (CVPR 2026 / MED) | 단계 인식 상대 진행, 2.0은 **유효 진행 / 허용 변화 / 실패 / 복구**의 부호 있는 공간 | 부호가 "실패"로 | 정의 없음 |
| FaRe (MED-LOW) | 누적 진행과 국소 진행 | **연속 정체 N스텝 또는 최고점 미갱신 M스텝 + 잡기 전환 중 아님** | **현재 물리 상태와 맞는 과거 기준점**, 세 가설 비교 후 확정 |
| RIR (LLM, MED-LOW) | 목표 + 이정표 | 에이전트 요청 또는 적응 주기 검토 | 실패 제거와 진행 보존을 저울질한 체크포인트(거친 → 세밀) |

- 공통점: **2026년의 두 독립 연구(FaRe는 로봇, RIR은 LLM)가 같은 달에 복구를 "언제 / 어디로 / 무엇을 남길지" 세 결정으로 나눴다.** 사용자가 원한 "어디로 되돌아갈지" 틀의 가장 직접적인 근거다. 둘 다 심사 전이다.
- 물리 세계의 차이: RIR은 환경을 체크포인트로 **복원**할 수 있다. 로봇은 못 한다(Safe to Resume?가 지적한 "기록되지 않은 부수 효과" 문제와 같다). FaRe는 이 점을 맞게 다룬다: 세계를 되돌리지 않고, **현재 세계와 맞는 과거 지점을 찾아** 거기서부터 다시 한다.

### 3.4 질문 4: LLM 에이전트 쪽(로봇 미적용) 최고 근거

- 되돌림: RIR(같은 표 비교에서 1위, 심사 전) > WebRollback(EACL 2026, 웹 한정) > AgentRewind(자기 벤치마크).
- 트리 탐색: LATS는 RIR 표에서 ReAct보다도 낮은 경우가 많았다(Qwen3-14B 37.62 대 ReAct 39.20, DeepSeek-V3 53.28 대 62.86). **예산이 제한된 순차 실행에서 트리 탐색은 이득이 없었다** → 되돌릴 수 없는 로봇에는 더 불리하다(추론).
- 자기 교정: "외부 피드백 없이는 스스로 고치지 못한다"(Huang 외, ICLR 2024, **기간 밖 기초 문헌**)가 여전히 기준. 외부 검증자가 있을 때만 이득 → 우리 설계의 "센서 술어가 외부 검증자" 원칙과 맞다.
- 반성 메모리: VRL-Bench가 반성이 단순 재시도보다 나쁠 수 있음을 보였다(§4).
- 빠른/느린 경로: ReflexGrad의 "진행 점수 5회 연속 낮음 → 느린 진단"은 Jev(빠름)/Astra(느림) 구조와 모양이 같다. 워크숍 논문이라 근거가 아니라 설계 참고.

### 3.5 M9 복구: 후보 순위 [제안]

1. **복구 = 되돌림 경계 제어(언제 / 어디로 / 무엇을 남길지)** — 근거: FaRe(로봇, 학습 없음, 절제로 세 부분 모두 기여 확인) + RIR(LLM, 같은 표 1위) + FLARE(CVPR, ID/OOD). 셋 다 심사 전이거나 부분 근거라 **HIGH 단독 근거는 없다.**
   - 언제: 코드가 정체를 계산한다(FaRe 두 통계: 연속 정체, 최고점 미갱신). **잡기·놓기 전환 중(그리퍼 변화 + 팔 이동)에는 개입하지 않는다**(허용 게이트). 스킬 경계에서만 복구를 연다(FaRe도 행동 청크 경계에서 다시 판단).
   - 어디로: "되돌아갈 곳" = **현재 측정 상태에서 사전조건 술어가 모두 참인 가장 늦은 계획 체크포인트**(FaRe의 "현재 상태와 맞는 기준점"을 술어로 옮긴 것). 코드가 후보 목록을 만든다.
   - 무엇으로: 보기 = {계속, 체크포인트 k에서 재개, 리셋 스킬, Astra 재계획}. Jev가 Choice로 고른다. FaRe의 "세 가설 비교 후 확정"은 우리에겐 **코드의 사전조건 검사 + Jev 확률 + 낮은 확신이면 Astra** 순서로 옮긴다(가설 검증을 빼면 91.2로 떨어졌다).
   - 무엇을 남길지: RIR 규칙대로 목표, 환경 지식, 이전 시도 이정표, 실패 분석은 남기고 **"현재 상태" 주장은 버린다** → 재개 뒤 상태는 센서로 다시 읽는다. M10 메모리와 같은 규칙.
2. **FLARE ID/OOD 분류**(CVPR 2026, HIGH): v3 유지. 위 1의 보기 선택을 거르는 첫 질문으로 쓴다(자세 오류면 재시도·재개, 환경이 바뀌었으면 리셋 또는 재계획).
3. **스킬 파라미터 보정층**(CorrectVLA, MED): 실행 어긋남(목표는 맞고 크기만 틀림)은 전체 OOD 실패의 약 22~23%. 이 부분만 Jev 재선택(M9 사다리 2단)으로 고친다는 **범위 근거**. 작업 오해·인식 실패는 이 층에서 못 고친다 → Astra로 올린다.
4. **실패한 선택을 부정 조건으로**(REACH, CVPR 2026, 개념만): 재질의 때 직전 실패 보기를 표시하거나 뺀다. FAR의 "같은 실수 반복" 문제에 대한 학습 없는 대응.
5. **빠른/느린 진단 분리**(ReflexGrad, 워크숍): 참고만.

### 3.6 M7 진행 판별: 후보 순위 [제안]

1. **센서·술어 완료 + 진행도 = 남은 시간**(π*0.6 정의 원문 확인, HIGH): 우리 판에서는 M2가 준 예상 소요 시간 대비 남은 시간. v3 유지.
2. **단계 원장(ledger)**(R²VLM, CVPR 2026의 형식만): Astra가 "단계 목록 + 각 단계 완료 상태"를 들고 다니며 갱신한다. R²VLM은 학습형이므로 **형식만** 가져온다. Jev에는 긴 CoT 대신 "지금 참인 단계 완료 술어" Choice로(v3/05 ReflAct 제안과 같은 방향).
3. **벗어남 규칙 = FaRe식 두 통계 + 허용 게이트**(코드, 학습 없음): "계획대로가 아님"을 (a) 진행이 N번 연속 멈춤, (b) 최고 진행을 M번 동안 못 넘음 으로 정의한다. 매 스텝 판정은 오히려 해롭다는 절제 결과(91.0 < 91.5)를 M8 설계 근거로 함께 쓴다.
4. **범주형 진행 라벨**(Robo-Dopamine 2.0의 부호 있는 공간, MED): Jev 질문 보기로 {유효 진행, 허용되는 변화, 실패, 복구 중}. Jev는 수치에 약하므로 연속 진행 % 대신 이 범주가 맞다.
5. **학습된 진행 모델을 옆 센서로**(Robo-Dopamine GRM, CVPR 2026, 8B 공개 가중치): 우리가 학습할 필요는 없지만 GPU 로컬 추론이 필요하다. "API 모델만"이라는 틀과 맞는지는 [결정 필요]. 넣는다면 GVL(Astra) 확인과 비교하는 조건으로.
6. GVL 방식 Astra 확인(기간 밖 기초 문헌): v3 유지. RoboReward는 "어떤 VLM도 모든 작업에서 뛰어나지 않다"고 했으므로 단독 판정기로 쓰지 않는다.

## 4. 반대 증거와 위험

1. **복구 기법의 이득은 작고 조건부다.** FaRe 시뮬 +1.7%p, 트리거 없이 쓰면 기준보다 나빠짐. LIBERO-RECOVER에서 복구 데이터 학습은 표준 성공률을 떨어뜨렸다(OFT 0.945 → 0.916).
2. **반성 메모리가 단순 재시도보다 나쁠 수 있다**(VRL-Bench, LOW). 그래서 기준 방법에 "같은 스킬 단순 재시도(메모리 없음)"를 반드시 넣는다. v3/plan의 2606.15017(메모리 없는 기본 방법이 이김)과 같은 방향이다.
3. **RIR의 전제(환경 복원 가능)는 로봇에서 성립하지 않는다.** RIR 수치를 로봇 근거로 쓰면 안 된다. 가져오는 것은 "무엇을 남길지" 규칙과 재개점 선택 기준뿐이다.
4. **트리 탐색은 예산 제한 순차 실행에서 약했다**(RIR 표의 LATS). 로봇에서 여러 복구 분기를 실제로 시도해 보는 방식은 비용이 크다.
5. **CorrectVLA의 19/20은 사람이 작업마다 교정 문장을 한 번 준 결과**다. 자동 교정이 아니다. Astra가 그 문장을 대신 쓸 수 있는지는 검증되지 않았다.
6. **진행 판별기 자체가 틀린다**: RoboReward(어떤 VLM도 모든 작업에서 우세하지 않음), AgentRewardBench(v3/05). FaRe의 트리거는 8B 학습형 진행 모델에 의존했다. 우리가 술어와 시간으로 대신할 때 같은 효과가 날지는 모른다.
7. **"계획대로"의 PI 정의(π*0.6, π0.7)는 학습 신호**다. 실행 중 복구 판정에 쓴다는 서술은 원문에서 찾지 못했다. "PI도 이렇게 벗어남을 판정한다"고 쓰면 과장이다.
