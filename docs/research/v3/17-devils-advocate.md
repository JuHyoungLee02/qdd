## 2. 사용자 의도 충실도

### A2 [치명] 복구 사다리가 "실패 → Astra 개입" 원칙을 뒤집었다
- 사용자: user-log 3 "실패할 때마다 Astra가 개입해서 진행하는 방식을 원한다". user-log 11(6) "적어도 실패 판정이 났을 때는 Astra를 부른다". plan L18도 [사용자]로 "실패하면 GPT-6 Astra가 개입한다"고 적었다.
- plan L194: "복구 사다리: 스킬 내부 재시도 → Jev 재선택 → 리셋 스킬 → Astra 재계획. 실패를 층으로 나눠 아래에서 먼저 처리하고, **못 고친 것만** … Astra에." §2.5 L239도 같다. L204는 Jev가 {계속, 체크포인트 재개, 리셋, Astra 재계획} 중 고르게 한다 → Jev가 Astra를 부르지 않기로 정할 수 있다.
- 사용자가 정한 연구의 정체성(대주제)을 조사 근거로 바꿨는데 [결정 필요] 표시가 없다. draft-log v3.6의 교훈("사용자 방향과 반대되는 증거는 방향을 바꾸지 않고 [결정 필요] + 비교 조건으로 올린다")과도 맞지 않는다.
- 제안: 기본안을 사용자 원칙에 맞춘다. **실패 판정 순간 Astra를 항상 비동기로 호출하고, Astra가 생각하는 동안(수 초~수십 초) 아래 층(스킬 재시도·Jev 재선택)이 로봇을 움직이게 한다.** Astra 응답이 오면 확정 또는 덮어쓴다. 이렇게 하면 "실패 시 Astra"와 "웬만하면 멈추지 않는다"를 함께 지킨다. 현재 사다리(Astra 마지막)는 비교 조건으로 내린다. [결정 필요]로 올린다.

### B4 [중요] M1 변환 방법이 사실상 정해졌다
- CLAUDE.md: "바꾸는 방법은 아직 정해지지 않았으므로 사용자가 정하기 전에는 임의로 정하지 않는다." plan L72 [사용자] "변환 방법은 사용자가 정한다", L90 [결정 필요].
- 그런데 L234 "카메라 → 인식 → 코드 기하 → 술어·범주 텍스트", L99 "코드가 매 프레임 평가해 Jev에는 술어로", L125 "측정 상태를 코드로 비교 → 범주", L176 코드 규칙, L204 "사전조건 술어가 모두 참인 가장 늦은 체크포인트"가 모두 M1 후보 1(술어 표현)을 전제한다. M1 결정이 다른 쪽(예: Astra 설명 텍스트, 장면 그래프)으로 나면 M2·M4(b)·M7·M9가 함께 바뀐다.

### B5 [중요] 호출 방식 3번과 다중 프레임 형식이 바뀌었다
- 사용자(user-log 11(6)): 비교할 세 방식 중 하나가 "'이때쯤 결과가 나왔어야 하는데 안 나오네'라는 **자체 판단**". plan L183: "시간 초과는 코드가 계산 … LLM 자기 판단으로 두지 않는다." §5 L292의 결정 항목도 "예상 시간 × 계수 대 conformal" 두 코드 방식뿐이다.
  - "자체 판단"이 시스템 전체의 판단(코드 포함)인지, 모델의 판단인지는 발언만으로 정할 수 없다. plan의 근거(Learning When to Plan의 정성 서술, Jev 시간 비교 약점)는 합리적이지만, 해석을 바꾼 것 자체는 사용자에게 물어야 한다.
  - 제안: [결정 필요] "3번 방식 = 코드 마감(제안) / 모델 자기 판단(원문 그대로)". 비용이 크지 않으니 둘 다 비교 조건에 넣는 것도 방법이다(모델 판단판은 Jev Noul "지금쯤 끝났어야 하는가?" + 경과 시간을 범주로).
- 사용자(user-log 11(6)): "한 장이 아니라 연속 프레임, 예: 이미지 하나에 사진 10개." plan L185: 기본값 "개별 이미지 6~10장", "격자 한 장은 비교 조건".
  - 사용자는 "예"라고 했으므로 바꿀 여지는 있다. 그러나 기본값을 사용자 예시와 다르게 정했으면 [결정 필요]여야 한다. 근거(MIMIC, Grid2Matrix: 일관된 승자 없음)는 오히려 "사용자 예시를 기본으로 두고 개별 이미지를 비교 조건으로"도 똑같이 허용한다.
  - 제안: 기본값을 사용자 예시(격자)로 되돌리거나 [결정 필요] 표시.

### B10 [중요] "기존 스킬"과 "스킬 생성"이 정의되지 않았다
- 사용자(user-log 3): "물체를 보고 **스킬을 생성해서** 잡는 방법들이 많지만 실패할 때가 있다." 사용자가 고치려는 대상은 스킬 생성 방식의 실패다.

### B8 [중요] 약한 근거가 핵심 결정에 쓰였다
- **effort 입장**(L186 이유 (2)): "AGP·Show-Harness에서 effort 차이가 성공률에 거의 영향이 없었다." AGP는 L52 원문 그대로 "실물 조립 1과제 5회", 5/5 대 5/5다. 표본 5로는 차이가 없다는 결론을 낼 수 없다(천장 효과). 이 근거는 L186의 입장(effort를 낮추지 않는다)을 지지하지도 않는다. "차이 없음"은 오히려 낮은 effort가 괜찮다는 쪽으로도 읽힌다. 입장의 실제 근거는 사용자 발언(다른 프로젝트) 하나다.
  - 제안: 이유 (2)를 "근거 약함(n=5, 천장)"으로 표시하거나 뺀다. effort 입장은 사용자 발언만을 근거로 적고 [결정 필요] 유지.

### 5.3 A1 [치명] 가장 약한 고리: 3번 — "Jev의 촘촘한 결정이 같은 텍스트 위의 코드보다 낫다"
- 왜 약한가 (모두 plan 안의 사실)
  1. **정보의 순환**: Jev가 보는 것은 코드가 계산한 술어·범주다(L75, L82). PIVOT 텍스트판(L111)은 후보 행동과 예상 결과까지 코드가 만든다. 그러면 Jev의 선택은 코드 출력의 함수다. 기하·거리·크기처럼 코드가 이미 계산한 것에 대해서는 규칙 한 줄이 Jev와 같은 결정을 더 빠르고 결정적으로 낼 수 있다. Jev가 더할 수 있는 것은 의미(지시 해석, 상식, 예외 상황)인데, 촘촘한 이동은 의미가 가장 적은 결정이다.
  2. **적용 범위가 가장 쉬운 곳으로 좁혀졌다**: L164 "접촉 구간은 스킬에 맡긴다", L235 "이동 단위·스텝 크기(이동 구간만)". 빈 공간 이동은 모션 플래너·IK가 이미 잘하는 영역이다. 정밀도가 필요한 곳(접촉)은 스킬로 보냈으니, Jev의 촘촘한 결정은 필요성이 가장 낮은 곳에 남았다.
  3. **반대 증거**: SPF(L115, 후보 선택 40% 대 목표 지정 87~100%), GUI-Cursor(L116, 학습 없는 반복 미세 이동 25.5%), Show-Harness의 오류가 세밀한 잡기·놓기에 몰림(L164), jev-drone 저자 "3시드 비교에서 Jev 이점 없음"(L251). Jev 공식 약점(수치 비교·산술, L36).
  4. **M4·M5가 여기에 조건부다**(B1). 3이 틀리면 4·5의 대상이 사라지고, 남는 것은 "Astra + 스킬 + Jev 스킬 선택기"로 Jev_SO101·Show-Harness와 겹친다.
- 틀리면 무엇이 무너지나: §4 후보 2(M4), M3 원안, M5, 그리고 "Jev가 몇십 배 빠른 순간 판단을 한다"(user-log 6)의 실익. 사용자가 경고한 "처음이 틀어지면 끝까지 틀어진다"에 정확히 해당한다.

### 5.4 조기 검증 실험 (모듈 설계 초기, 1~2일 규모 제안)
실험 순서는 plan L295(보정 + 지연 + M1 형식)를 유지하되 E2를 **첫 주 안에** 붙인다. 판정 기준은 실행 전에 적어 둔다(사후 해석 방지).

- **E0 지연 (반나절)**: 한국에서 Jev `jev-1.13.0` 지연 p50/p95/p99, 3Hz 연속 호출·병렬 질문 수별. 같은 날 Astra effort별 TTFT. → M4의 고정 구간 길이(L131), LocalAgreement 확정 지연(약 2배, L124·L138)을 숫자로. **판정**: p95 + 확정 지연이 1초를 넘으면 "1초에 3번 겹침"의 실익(반응 시간)이 1초 1회 호출과 비슷해진다 → M4 설계 재검토.
- **E1 보정 (plan L295 그대로)**: 질문 유형별 ECE/Brier/AUROC, Noul 대 Choice, 보기 이름 형식. **판정**: 보정이 나쁘면 M4·M3·M10의 확률 게이트를 끄고 최빈값만 쓰는 판으로 설계(B9).
- **E2 "마차 시험" (핵심, 1~2일)**: 단일 pick-and-place + 방해물·배치 변화 2~3종, 시뮬, 정답 상태 조건과 인식 상태 조건 둘 다.
  - 팔(arm) 4개, 모두 **같은 M1 텍스트 상태**: (i) 같은 술어 위의 규칙 정책(룰베이스, 범주 4), (ii) Jev 촘촘한 객관식(원안), (iii) Jev 목표 지정형 + 코드 경로, (iv) (ii)에 M4 겹침을 켠 것 대 1스텝 1호출.
  - 지표: 성공률, 완료 시간, 결정 수, jerk, 규칙 작성 시간(적응 예산, L165).
  - **판정(사전 등록)**: (ii)가 (i)과 (iii)을 넘지 못하면 M4의 대상을 "촘촘한 이동"에서 "결정 지점(다음 스킬·전이 시점·critic 수락, L235)"으로 옮긴다. (iv)에서 겹침이 1호출보다 나아지지 않으면 M4 문구를 다시 쓴다.
- **E3 의미 과제 (E2 직후)**: 규칙을 손으로 짜기 어려운 변화(모호한 지시, 처음 보는 물체 범주, 비슷한 방해물 속 목표 선택)에서 (i) 대 Jev. Jev·Astra의 가치가 나타날 곳이 여기라면, 평가 주장(§3)과 M4의 자리도 여기로 맞춘다.
- **E4 일반화 교란 분리 (평가 설계 전)**: 같은 인식 앞단 위에서 룰 결정 층 대 LLM 결정 층의 standard → random 하락폭. 인식 앞단 자체의 하락(정답 상태 대 인식 상태 차이)을 따로 보고. → B7.
