## 1) 조사 방법과 한계

- WebSearch 11회 사용(한도 15회). arXiv API(`export.arxiv.org`)와 Semantic Scholar 검색 API는 다른 에이전트와 공유하는 IP 한도로 429가 나서 쓰지 못했다. 대신 arXiv abs/html 페이지를 직접 읽고, Semantic Scholar는 batch 조회(인용 수, 학회)만 썼다.
- 원문을 읽은 논문
  - 본문 해당 절까지 읽고 수치를 표/문장에서 확인: 11편(2503.03064, 2510.13054, 2501.09747, 2402.07872, 2512.16909, 2510.03342 + Gemini API 문서, 2412.04455, 2510.05381, 2510.16643, 2506.06072, 2507.07644)
  - 초록과 제출일, 코멘트(학회)만 확인: 약 16편
- GitHub 스타: API 비인증 한도가 공유 IP에서 바닥나서, 1개만 API로, 나머지 7개는 github.com 페이지의 스타 카운터로 읽었다(2026-09-24 기준).
- 한계
  - "평균 대 최빈값"의 핵심 LLM 근거(2503.03064, TRACT, RAIL)는 모두 **기간 기준(2025-03-23)보다 조금 이르다.** 아래에 표시했다. [결정 필요] 참고.
  - Jev에서 직접 실험한 결과는 하나도 없다. 아래의 모든 "Jev 적용"은 추론이며 실험으로 확인해야 한다.
  - 로짓에 접근하는 논문(평균 디코딩 등)은 "토큰 확률"을 쓴다. Jev의 Choice 확률이 그와 같은 성질인지는 확인하지 못했다(업체 설명뿐).

## 3) 새로 찾은 것과 모듈별 최고 후보

### M3. 선택지 확률 → 연속 행동

#### M3-1. 분포를 한 값으로 읽는 규칙 (가장 중요)
- **어디서 최고였나**: LLM-as-judge. 점수 토큰 분포의 **평균이 최빈값(탐욕 디코딩)보다** 48개 조건 중 42개에서 낫다(2503.03064, EMNLP 2025 Findings). 이유: 최빈값은 동점을 많이 내고 단계 수에 민감하다. 제곱오차 기준으로는 기댓값이 베이즈 최적이다(RAIL).
- **반대 방향의 증거(로봇)**: 행동 분포가 여러 봉우리면 평균은 두 모드 사이의 엉뚱한 동작이 된다(RTC 논문의 temporal ensembling 실패, v2 02 보고서). GUI 좌표에서도 여러 예측의 평균이 아니라 **가장 밀집한 군집의 중심**을 쓰는 방식(MVP, LOW~MED)이 쓰인다.
- **둘을 합친 규칙 [제안]** (어느 논문에도 이 조합 그대로는 없다. 두 결과를 합친 추론이다)
  1. Jev Choice(순서 있는 구간 보기)나 Score의 확률 벡터를 받는다.
  2. 작은 가우스 커널로 평활한다(HL-Gauss의 "이웃 구간에 확률을 나눈다"는 발상을 추론 쪽에 옮김).
  3. 국소 최댓값 수를 센다.
     - 한 봉우리 → **확률 가중 평균**(2503.03064).
     - 여러 봉우리 → 확률 질량이 가장 큰 봉우리를 고르고, **그 봉우리 구간 안에서만 평균**(MVP식 "최빈 군집 → 군집 내 평균").
  4. 분산이 크면 크기를 줄인다(2503.03064의 위험 회피가 자주 이득이었다는 관찰을 "불확실하면 작게 움직인다"로 옮김).
  5. 방향처럼 **순서 없는** 범주 보기는 평균하지 않는다. 최빈값 + 확률은 게이트로만.
- **Jev에 옮길 때 주의**
  - 판정 논문들은 토큰 로짓을 온도 1로 softmax한 값을 썼다. Jev Choice 확률이 같은 성질인지 모른다. **먼저 측정**(M3-4).
  - CoT는 분포를 뾰족하게 해서 평균의 이득을 줄인다(2503.03064 Table 2, 표준편차가 CoT에서 항상 작음). Jev는 바로 답하는 모델이라 이 점에서는 유리할 수 있다(추론, 미확인).

#### M3-2. 해상도: 몇 단계면 되나
- **어디서 확인됐나**: VLA-0(NVIDIA, 인용 53, 스타 492). 행동을 텍스트 정수로 낼 때 LIBERO 평균이 해상도 1000에서 94.7, **250에서 93.2(−1.5점)**, 4000에서 94.2.
- **Jev 접목**: Choice 보기 최대 255개 = 차원당 약 250 구간. VLA-0 기준으로는 **한 번 호출로 차원당 255단계면 1000단계 대비 1.5점 정도 손해**다. 단, VLA-0은 미세조정 모델이고 LIBERO 한 벤치마크다. Jev에 그대로 옮겨진다는 근거는 없다.
- **촘촘함을 더 원하면 [제안]**: PIVOT/UI-Zoomer식 coarse-to-fine.
  - 1차 호출: 넓은 범위 255 구간 → 봉우리 찾기. 2차 호출: 봉우리 주변만 255 구간.
  - 대가: 호출이 직렬이 되어 지연이 2배. M4(계단식 겹침 호출)와 충돌한다.
  - 대안 [제안]: 한 요청 안에 **같은 축에 대해 두 척도 질문을 병렬로** 넣는다(넓은 범위 + 직전 행동 주변 좁은 범위). 좁은 범위의 중심은 이전 호출 결과로 정해 두므로 직렬 의존이 없다. 선행 연구는 찾지 못했다(검색어: "GUI grounding iterative zoom-in training-free coarse-to-fine", "coarse-to-fine discrete action selection").
  - UI-Zoomer처럼 **불확실할 때만** 2단계 줌을 켜는 방식도 후보. 다만 근거 신뢰도는 LOW~MED.
- **PIVOT의 교차 엔트로피 구조를 텍스트로 [제안]**: PIVOT은 후보를 그림에 표시하고 VLM이 고르게 했다. Jev는 그림을 못 보므로, 코드가 후보 행동 K개(≤255)를 만들고 각 후보의 **예상 결과를 범주 술어로 계산해** 보기 텍스트로 준다(예: "후보 17: 그리퍼가 컵 손잡이 위 1구간, 충돌 없음"). Jev는 보기마다 확률을 주므로 PIVOT의 "상위 몇 개 선택"보다 정보가 많다. 확률로 가중해 분포를 다시 맞추면 된다. 이것은 기하는 코드, 판단은 Jev라는 CLAUDE.md 제약과도 맞는다.

#### M3-3. 무엇을 고르게 하나: 스텝 대 제어점
- BEAST(NeurIPS 2025): 조각을 **B-스플라인 제어점**으로 표현하면 binning 대비 토큰 4~8배 적고 조각 사이가 매끄럽게 이어진다. CALVIN ABC 4.61, LIBERO 92.5%.
- FAST: 스텝별 binning은 고주파에서 나쁘다. 다만 이것은 **학습 신호** 문제로 제시되었다.
- **Jev 접목 [제안]**: v2의 "저주파 제어점을 객관식으로 고른다"를 유지한다. 근거가 v2의 추론에서 **학회 논문(BEAST) 하나**로 올라갔다. 제어점 수가 적으면 한 요청 안의 질문 수(= 제어점 × 차원)도 줄어든다. M5(B-스플라인)와 표현을 공유한다.
- 앙상블: VLA-0에서 예측 앙상블을 빼면 −2.0점. M4의 겹침 호출 결과를 합치는 규칙이 성능에 직접 걸린다는 간접 근거.

#### M3-4. 보정과 재보정 (다른 모든 M3 규칙보다 먼저)
- **왜 측정부터인가**: 후훈련(RL 지시 조정)과 CoT는 보정을 깬다(Nakkiran 외, Apple, MED). 대화형 LLM의 MSP는 일관되게 보정이 틀렸지만, 정답 판별(AUROC)에는 여전히 쓸 만하다(Plaut 외, TMLR).
- **가져올 것과 Jev 접목**
  1. **측정**: 우리 로그로 신뢰도 곡선(reliability diagram), ECE, Brier, MSP의 정답 판별 AUROC를 질문 유형별(방향, 크기, 완료 여부)로 잰다.
  2. **온도 스케일링**: Jev 확률 p에 대해 p^(1/T) 재정규화로 T 하나를 질문 유형별로 맞춘다. 표준 사후 보정이며 로짓 없이도 확률의 로그로 할 수 있다(표준 기법, 특정 논문 근거가 아니라 [제안]).
  3. **보기 위치 편향 제거(PriDe, ICLR 2024)**: 소수 표본에서 보기 순서나 ID를 바꿔 사전 편향을 추정하고 뺀다. 순서형 보기에서는 순서를 섞을 수 없으므로, **ID 표기만 바꾸는 방식**이 편향을 드러내는지 먼저 시험해야 한다(미확인).
  4. **Conformal 보기 집합(KnowNo, CoRL 2023)**: 보정 집합에서 임계값을 정해 1−α 신뢰의 보기 집합을 만든다. 집합이 한 개면 실행, 여러 개면 **사람 대신 Astra 호출**(M7/M8 트리거). KnowNo를 Astra 호출 규칙으로 옮긴 선행 연구는 찾지 못했다(검색어: "conformal prediction LLM multiple choice robot planning calibration"). 2025~26의 후속(CoFineLLM, CURE)은 미세조정이나 내부 특징이 필요해 Jev엔 안 맞고 신뢰도도 LOW다.
  5. **MSP 기권**: 라벨 몇백 개로 MSP 임계값을 정해 "확신 없음 → 기존 스킬 유지/감속"(Plaut 외).

### M1. 상태 표현 (이미지 → Jev 텍스트). **확정하지 않는다. 후보와 근거만.**

#### M1-1. 가장 근거가 많은 원칙: "무엇을 넣느냐"가 "어떤 문법이냐"보다 크다
- 길이만으로 13.9~85% 하락(2510.05381, EMNLP 2025 Findings, HIGH). 무관 토큰을 가려도 하락한다. → 문법 압축보다 **내용 선별**이 먼저.
- 3D 장면 그래프도 전체를 넣으면 큰 그래프에서 0.33, 관련 부분만 가져오면 0.77(2510.16643, MIT, MED).
- JSON↔XML ±3%p(FloorplanQA, ICML 2026). 반대로 낯선 압축 문법(TOON/TRON)은 최대 9~14%p 손실 보고(LOW).
- Jev 입력 비용은 $0.042/1M이라 토큰 절감의 돈 가치는 작다. **정확도 때문에 짧게** 한다.

#### M1-2. 후보 순위 (사용자가 정할 때 참고)
1. **ID 기반 객체 목록 + 코드가 미리 계산한 범주 관계 + 참/거짓 술어, 작업 관련 객체만** (v2 1순위 유지, 근거 보강)
   - 근거: FloorplanQA(물리 제약·기하 계산 약함 → 코드로), 2510.05381·GSM-DC(무관 내용 제거), TSG-Bench(LLM은 그래프 생성은 못해도 이해는 잘함 → 지각 코드가 만들고 Jev는 읽기만).
   - 문법은 JSON 한 가지로 시작하고, YAML/표는 절제 실험 변수. 낯선 압축 문법은 쓰지 않는다.
2. **작업 지향 장면 그래프 부분 그래프** (노드 = 객체·부품, 간선 = 공간 + 기능 관계, 노드 속성 = 상태)
   - 근거: MomaGraph(MED) 공간+기능+상태 통합, 그래프를 먼저 만들면 폐쇄형 모델 +4.1~+5.1%p(자체 벤치). ConceptGraphs/HOV-SG(기초).
   - 여러 단계, 관절형 물체(서랍, 손잡이)가 있는 작업에 맞다. 단순 pick-and-place엔 1번과 차이가 없을 것(추론).
3. **Astra가 쓴 자연어/구조 설명을 그대로 전달**: 느리다. 계획 시점에만. 형식은 1·2번과 같게 맞춘다.
- 텍스트판 Set-of-Mark: SoM의 핵심은 "번호로 가리키고 번호로 답하게 한다"이다. 텍스트에서 이에 해당하는 것은 **지각 단계가 붙인 안정된 짧은 객체 ID**다. Astra에게는 같은 ID를 이미지 위 표시로 보여 주고, Jev에게는 같은 ID를 텍스트 키로 준다(M2 참고).
- 배치: 관련 증거를 질문 바로 앞에 두는 것만으로는 길이 손실이 없어지지 않았다(2510.05381). "위치"보다 "길이"를 줄인다.

### M2. Astra → Jev 전달

1. **Astra 출력 = 객체 ID 참조 + 완료 조건 술어 + 제약 요소 정의** [제안]
   - Astra는 SoM 표시(ID 번호)가 있는 연속 프레임 격자를 보고, **ID로** 하위 목표를 말한다. 번역 오류(이름 ↔ 객체) 위험을 줄인다.
   - 점이 필요하면 Gemini Robotics-ER 형식(`[{"point":[y,x],"label":...}]`, 0~1000 정규화)을 스키마로 빌린다. 코드가 깊이로 3D로 올리고 가장 가까운 객체 ID에 붙인다. Astra가 이 형식으로 얼마나 정확한지는 모른다(측정 필요).
2. **CaM식 제약 요소 → 코드 평가 → Jev에는 술어로** (CVPR 2025, 기간 밖이라 개념 차용)
   - Astra가 "컵 입구 원(면)과 주전자 부리(점) 사이 거리 < 임계값" 같은 제약을 **코드로** 정의한다. 코드가 매 프레임 평가해 `spout_above_cup_mouth: true` 같은 술어를 Jev 상태에 넣는다.
   - 효과 근거: 심한 방해 조건에서 +28.7%p(CaM). 같은 코드가 M7(진행 감시)의 실패 신호도 된다.
   - ReKep의 비용 함수 대신 **만족 여부 술어**로만 넘기는 v2 방침과 같다.
3. **작업 관련 부분 그래프만 전달** (2510.16643의 질의 인터페이스 발상)
   - Astra(또는 코드)가 전체 장면에서 이번 하위 목표에 필요한 노드만 골라 Jev 상태를 만든다. 큰 그래프에서 0.33 → 0.77, 입력 582,202 → 2,395 토큰.
   - Astra는 느리므로, 선택 자체는 계획 시 한 번 하고 이후는 코드가 ID 목록으로 유지한다 [제안].

## 4) 반대 증거와 위험

1. **평균 디코딩 근거가 판정(평가) 과제에서 나왔다.** 판정 점수는 대체로 한 봉우리이고, 로봇 행동은 여러 봉우리일 수 있다. "평균이 낫다"를 행동에 그대로 쓰면 안 된다. 그래서 봉우리 검사 규칙을 붙였지만, 이 결합은 **검증되지 않은 제안**이다.
2. **기간 문제**: 2503.03064(03-04), TRACT(03-06), RAIL(2024)은 기간 밖이다. 기간 안에서 같은 결론을 낸 신뢰도 높은 LLM 논문은 이번 검색에서 찾지 못했다.
3. **해상도 결과는 미세조정 VLA 결과다.** VLA-0의 250 대 1000 비교는 학습된 모델이 해당 해상도로 행동을 **생성**할 때의 차이다. Jev가 255개 보기를 받아 **고를 때**, 보기가 많을수록 확률이 퍼지거나 위치 편향이 커질 수 있다(PriDe). 보기 수 자체가 실험 변수다.
4. **Jev 확률의 정체 불명**: 로짓 softmax인지, 별도 보정층(RLCD)을 거친 값인지 모른다. 보정층을 거쳤다면 온도 스케일링이 이미 된 것일 수 있고, 반대로 순서형 구조를 무시하는 보정일 수 있다.
5. **coarse-to-fine은 지연을 늘린다.** M4 계단식 호출과 겹치면 호출 수가 늘어난다. 병렬 두 척도 질문은 선행 연구 없음.
6. **장면 그래프 이득의 크기**: MomaGraph의 +4~5%p는 자체 벤치마크, 심사 전이다. 2510.16643의 PDDL 작은 그래프에서는 전체 문맥과 같았다(0.65). 작은 장면에서는 그래프 구조 이득이 없을 수 있다.
7. **SoM이 최신 모델에서도 이득인지** 확인한 신뢰할 연구를 못 찾았다. Astra가 표시 없이도 ID를 잘 맞힐 수 있다. 이것도 비교 실험 대상.
8. **텍스트 기반이 이미지보다 낫다는 주장의 한계**: FloorplanQA는 구조화 텍스트만으로도 LLM이 물리 제약을 자주 어긴다고 보였다. 텍스트화만으로 공간 추론이 해결되지 않는다. 기하는 코드에 둬야 한다.
9. 압축 문법 반대 증거(TOON/TRON)는 LOW 신뢰도다. 결론(쓰지 말자)은 FloorplanQA의 "문법은 부차적"과 함께 볼 때만 의미가 있다.

### [제안]
- M3 읽기 규칙을 "한 봉우리면 평균, 아니면 최빈값"에서 **"평활 → 봉우리 검사 → 한 봉우리면 평균, 여러 봉우리면 주 봉우리 안 평균 → 분산 크면 크기 축소"**로 구체화한다. 근거: 2503.03064(기간 밖, HIGH), MVP(개념, LOW~MED), RTC(v2).
- M3 해상도: 차원당 **≤255 보기 1회 호출을 기본**으로 하고, 2단계 줌과 병렬 두 척도 질문을 비교 실험 변수로 둔다. 근거: VLA-0(250 대 1000, −1.5점).
- M3 행동 단위: 제어점 객관식 유지, 근거에 BEAST(NeurIPS 2025) 추가.
- M3 보정 순서: (1) 측정(ECE, Brier, AUROC) → (2) 질문 유형별 온도 스케일링 → (3) 위치 편향 점검(PriDe) → (4) conformal 집합으로 Astra 호출 트리거(KnowNo를 사람 대신 Astra로). 첫 실험(Jev 보정 측정)에 그대로 붙인다.
- PIVOT의 반복 후보 선택을 텍스트화: 코드가 후보 행동과 **예상 결과 술어**를 만들어 보기로 주고, Jev 확률로 분포를 다시 맞춘다.
- M1: "문법보다 내용" 원칙 명시. 작업 관련 객체만, 기하는 코드. 문법 비교는 JSON/YAML/표 정도로 한정하고 압축 표기는 제외.
- M2: Astra 출력 스키마 = 객체 ID + 완료 술어 + CaM식 제약 요소(코드) + 필요 시 0~1000 정규화 점. 작업 관련 부분 그래프만 Jev에 전달.
- 참고 문헌에서 2505.13478(가상 결과)은 쓰지 않는다.

### [결정 필요]
