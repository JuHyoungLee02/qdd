## 3) 새로 알게 된 것 (plan에 영향)

- **AgileThinker 축소판(최종 출력만 참조)의 실제 수치** (Table 10): 압박이 셀 때만 이득이 있다(8k: 0.31 대 0.25, 4k: 0.26 대 0.05). 압박이 약하면 계획기 단독과 같다. Astra 지연이 Jev 결정 주기보다 훨씬 긴 우리 설정은 "압박이 센" 쪽이라 방향은 지지된다. 다만 근거는 게임 1개, 난이도 1개다.
- **WAM의 sync 72.5점**: 정밀 끼우기에서는 "멈추고 기다린 뒤 전환"이 비동기 + 블렌딩(37.5)보다 훨씬 좋았다. 동적 과제(컨베이어)에서는 sync가 20점이다. 사용자 방향("웬만하면 멈추지 않는다")에 대한 반대 증거로, 접촉·정밀 구간에 한정해 보고한다(README 규칙 7).
- **Zetta Orchestrator = 온라인 LLM 승인자일 수 있다.** 방법 절 기준으로는 "고주기 코드 critic + 사건마다 LLM 승인"이 이미 원문 구조다. 그러면 plan §2.5의 "여섯 편 모두 모델이 기다리거나 루프 밖"이라는 관찰에 Zetta를 넣을 때 단서가 필요하다. 원문은 승인 중 로봇이 멈추는지 말하지 않는다. 다만 Algorithm 1은 "청크 하나 실행 → 판정"을 차례로 도는 구조다.
- **GUI-Cursor**: 붕괴는 "좌표 직접 출력으로 과하게 미세조정된 7B + 상대 이동" 조합이다. 학습 안 한 범용 모델(GPT-4o)은 상대 이동으로 17.5 → 25.5로 **올랐다**. "학습 없는 증분 제어는 약하다"의 근거로 쓸 때, Jev에 더 가까운 쪽은 GPT-4o 결과(작지만 이득)다.
