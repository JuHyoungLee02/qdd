## 0. 요약

**한 줄 판정**: MolmoAct에서 가져올 것은 **"표현(손끝 2D 궤적 형식)과 라벨 만드는 법, 그리고 궤적을 조건으로 따르게 만드는 학습법"**이지, **"실행 때 깊이·궤적 토큰을 생성하는 추론 사슬"이 아니다.** 근거는 셋이다. (i) MolmoAct는 스텝마다 약 200토큰(깊이 102 + 궤적 약 45 + 문장 틀 약 50 + 행동 7–56)을 자기회귀로 만든다 — 우리 decide 예산 p95 ≈ 0.3 s에 들어갈 수 없다. (ii) MolmoAct 논문에는 **깊이 없음·궤적 없음 절제가 하나도 없다** — 세 단계 사슬 각각의 이득은 입증되지 않았다. (iii) 같은 연구진의 후속작 MolmoAct2(2026-05, 772★)는 **궤적을 버렸고**, 깊이는 "바뀐 칸만 다시 예측"하는 적응형으로 줄였으며(그래도 1회 0.787 s 대 깊이 없이 0.179 s, H100), 기본 배포 경로는 깊이 없는 연속 expert다 — 그리고 그 기본 구조가 **우리 융합 VLA와 거의 같다**(Qwen3-4B LLM + 흐름 정합 expert + 이산 행동 토큰 병행 학습 + KI).

## 2. MolmoAct(1) 분해

### 2.1 구조와 행동 토큰화
- 백본 = Molmo(ViT → 2층 MLP 연결부 → 디코더 LLM). 두 판: **MolmoAct-7B-D** = SigLIP2 SO400M/14-384 + **Qwen2.5-7B**(주력), MolmoAct-7B-O = OpenAI CLIP ViT-L/14-336 + OLMo2-7B(가장 개방). 연결부: ViT 뒤에서 셋째(또는 넷째)·열째 층 특징을 이어 붙여 2×2 주의 풀링 → MLP. 다중 이미지는 이미지마다 "Prefix i" 표지를 붙여 이어 붙인다(부록 A.5).
- 행동: 차원마다 데이터 1–99 분위 사이를 **256 등폭 구간**으로. 구간을 Qwen2 어휘 **마지막 256개 토큰**에 순서대로 대응시키되, 이웃 구간이 바이트 BPE 기호가 비슷한 토큰에 가도록 골라 "초기화가 부드럽다"고 주장(§2.2). "GR00T N1.5의 50,000 GPU시간 대비 사전학습 9,216 GPU시간, 5배 이상 감소"는 모델·데이터가 다른 비교라 **이 토큰화의 효과 근거가 아니다**(절제 없음).
- 손실은 행동 토큰(과 추론 토큰)에만. 고유감각 입력 없음, 관측 이력 없음(부록 표 7·10–14 "Use Proprioception No", "Observation History No").

### 2.2 세 단계 "공간 추론" 사슬 (식 4)
p(d, τ, a | I, T) = ∏ p(d_i | I, T, d_<i) × ∏ p(τ_j | I, T, d, τ_<j) × ∏ p(a_k | I, T, d, τ, a_<k) — 깊이 → 궤적 → 행동을 **모두 자기회귀로 생성**.

1. **깊이 인식 토큰 d**: 어휘 = `<DEPTH_START>`, `<DEPTH_END>` + 코드 128개. 이미지 한 장마다 **M = 100** 코드(10×10 격자). 만드는 법(§3.1): (1) RT-1·BridgeData V2·BC-Z 탁상 영상 **1천만 장**에 **Depth Anything V2**(단안, RGB만)로 깊이 지도를 만들고, (2) 그 깊이 지도로 VQ-VAE를 20 에폭 학습(LLaVA-AURORA 설정, 배치 64·lr 1e-3), (3) 모든 영상은 320×320으로 줄여 **이미지당 100토큰**. VLA는 **원래 RGB만 보고** 이 코드열을 예측하도록 증류("specialist-to-generalist"). 어휘 확장은 Qwen2.5의 빈 토큰 130개를 깊이 토큰으로 바꾸고 임베딩·lm head를 푼다(부록 B.1). 즉 **실행 입력은 RGB뿐**이고 깊이 모델은 라벨 생성에만 쓴다.
2. **시각 추론 궤적 τ**: 첫(측면) 영상 위 손끝의 2D 폴리라인 **1 ≤ L ≤ 5점**, 좌표는 영상 크기로 정규화한 **정수 0–255**. p₁ = 지금 손끝, 나머지 = **현재부터 에피소드 끝까지** 미래 손끝 위치에서 고르게 뽑은 점(현재점·끝점 + 중간 최대 3점). 라벨(§3.1, 코드 `preprocess/processors.py`·`line_utils.py` 확인): **Molmo-7B-D-0924에 프레임마다 "point to the robot gripper"**(양팔은 "…on the left/right")를 물어 손끝 픽셀을 얻고 이어 붙인다 — **카메라 보정·FK 불필요**. 실패 프레임(None)은 빼고 평활화는 없다.
3. **행동 토큰 a**: 7-DoF(이동 3 + 회전 3 + 그리퍼 1) 256구간. 사후학습(미세조정)에서는 **청크 8**(8스텝 × 7토큰)을 자기회귀로 예측하고 LIBERO에서는 8스텝을 열린 고리로 다 실행한 뒤 다시 추론(부록 D.2).
- 다시점: 미세조정 입력은 보통 측면 1 + 손목 1(양팔은 손목 2). 깊이·궤적은 **측면 영상에서만** 만들고 손목은 "추가 정보"(§4.2).

**스텝당 생성 토큰(실측, 공개 토크나이저 `allenai/MolmoAct-7B-D-0812/tokenizer.json`)**: 깊이 문자열 102(100 + 시작·끝, 토큰당 1개), 궤적 5점 `[[242, 115], …]` **45토큰**(숫자가 자리마다 쪼개짐), 문장 틀("The depth map of the first image is … the action that the robot should take is …") **50토큰**, 행동 7(단일) 또는 56 + 구두점(청크 8, 구두점 수는 추정). 합계 **약 200–260토큰/스텝**. 공개 예제의 `max_new_tokens=256`과 맞다.

### 2.5 추론: 매 스텝 전부 생성, 캐시 없음, 지연 미보고
- 논문은 **지연·제어 주기 수치를 하나도 보고하지 않는다.** 한계 절(부록 G) 원문: "our model exhibits a mismatch between its control inference frequency and the control frequency used during data collection … the additional time required to predict a larger number of reasoning tokens".
- 깊이·궤적은 **매 추론마다 새로 생성**한다(캐시·재사용 없음). 서빙은 HF transformers·vLLM 0.8.5(README).
- 같은 연구진의 후속 논문 원문(MolmoAct2 §1): "hundreds of tokens or entire predicted frames must be generated before a single action is emitted … The very mechanism intended to make policies more reliable thus renders them too slow for closed-loop control." — 스스로 MolmoAct를 느린 예로 든다.
- 실측 참고값(MolmoAct2 §6.8, H100 1장, LIBERO, 행동 지평 10; 지연 = 10 / 제어율로 환산): 깊이 없는 연속 경로 원본 0.434 s → 캐시 0.365 s → CUDA 그래프 **0.179 s**; 적응형 깊이(Think) 원본 1.244 s → 1.029 s → **0.787 s**; 이산 행동 토큰 경로(자기회귀) 0.706 s, Think 이산 1.466 s. MolmoAct(1)은 7B에 스텝당 약 200토큰을 **적응 없이** 만들므로 이보다 느리다고 보는 것이 합리적이다(추정, 실측 없음).

### 2.6 조종(steerability) — 무엇을, 얼마나
- 방법: 사용자가 카메라 영상에 **다섯 점**을 찍어 궤적 τ를 그리면 I⁺ = I ⊕ τ(영상에 선을 그린 것)와 지시문으로 **행동만** 바로 생성(식 5 — 이때는 깊이·궤적을 생성하지 않는다). 매 스텝 반복하면 폐루프 조종. 이것이 되려면 학습에 **궤적 조건 행동 데이터**가 있어야 한다(사전학습 10.5M, 중간학습 1M, 사후학습 시연도 같은 방식 변환).
- 평가(§5.6, 부록 D.7·표 23): `pick_up_bowl` 한 과제, 깨끗한 그릇·더러운 그릇 둘. 모호한 지시("pick up the bowl")로 한쪽을 향하게 한 뒤 반대 그릇으로 조종. 시연은 그릇별 50 + **다른 경로를 탐색하며 같은 목표로 가는 시연** 그릇별 50 = 200개(본문은 100 — 2.10절). 진행 점수: 맞는 방향 0.5, 맞는 그릇 쥠 0.85, 들어 올림 1.0. 모델당 **15회**, 언어 조종은 참가자 10명이 동사·명사·형용사만 바꾼 지시.
- 결과(표 23 재계산, 15회 평균 **진행 점수**): **궤적 조종 MolmoAct 0.747**, 언어 조종 MolmoAct 0.413, 언어 조종 π0-FAST 0.133 → 본문 "success rate 0.75", "+33 %", "+29 %"(재계산 +0.28)와 맞다. **단 이 "성공률"은 진행 점수 평균이다**: 점수 1.0(완전 성공) 횟수는 궤적 7/15, 언어 2/15, π0-FAST 0/15.
- 조종 그림(그림 9): 모델이 예측한 궤적(노랑)을 사용자 궤적(청록)으로 바꿔 교정.
- 궤적 생성 품질(§5.5): 인터넷 영상 30장·지시 87개에 대한 블라인드 투표 1,000표 이상의 Elo에서 MolmoAct가 Gemini-2.5-Flash·GPT-4o·HAMSTER보다 높고 95 % 구간이 겹치지 않음 — **Elo 값은 그림에만 있음(근사도 옮기지 않음)**.

### 2.8 절제(ablation) — 핵심 발견: **사슬 구성요소 절제가 없다**
- MolmoAct 논문에서 "절제"라 부르는 것은 **중간학습 유무**(+5.5 pt, 위)와 조종 방식 비교뿐이다. 깊이 토큰 없음·궤적 없음·둘 다 없음, 보조 데이터 없음, 궤적 조건 데이터 없음 조건은 **어디에도 없다**(원문 전체 "ablat" 검색 1건 = 조종 절).
- 따라서 "깊이 → 궤적 → 행동 사슬이 성능을 올린다"는 주장은 **기준선 대비 전체 시스템 비교**로만 뒷받침된다(데이터·백본·학습량이 모두 다른 비교).
- 사슬 요소의 유일한 통제 근거는 후속작 MolmoAct2-Think의 깊이 절제(3.3절: LIBERO 97.2 → 98.1)뿐이다. **궤적 절제는 후속작에도 없다**(궤적 자체를 버림).

### 2.9 한계·실패 양상 (부록 G 원문 요지 + 독립 자료)
- **손끝 가림**: 공간 추론이 측면 카메라에 의존 — 측면에서 손끝이 가려지면 궤적 예측과 전체 성능이 떨어진다.
- **궤적 조종의 깊이 방향 부정확**: "it often follows the intended path within the image plane (in-plane motion) but exhibits unintended or imprecise translation along the camera's depth axis (out-of-plane)". 조종 때는 궤적을 그린 영상으로 행동만 바로 내므로 "MolmoAct의 공간 추론 능력을 쓰지 못한다", 복잡한 과제는 조종으로 따르지 못한다.
- **궤적 라벨 품질**: 상자 검출기(Detectron 등)로 만든 점은 상자 중심으로 뭉쳐 다양성이 사라진다 — VLM 포인팅(Molmo·RoboPoint)이 정확하고 조종을 "markedly" 개선.
- **조종 데이터 요구**: 조종이 되려면 사후학습 데이터가 "as many action compositions as possible"을 덮어야 한다(과제는 완수하되 여러 경로를 탐색하게 수집).
- **속도**: 2.5절.
- **깊이 해상도**: 100토큰 고정이라 정밀 조작에는 거칠다.
- **독립 자료(주의용)**: Harness VLA(2607.08448, 학회 없음, D10a) 표 3 LIBERO-Pro 8칸 800회 재인용에서 MolmoAct 전체 **1.5 %**(π0.5 11.0, π0 0.3) — 원 조건(어느 체크포인트·어느 교란) 미확인이라 근거가 아니라 "분포 밖 강건성 주장은 교란 종류에 따라 무너질 수 있다"는 주의로만.

### 3.2 궤적은 버렸고, 깊이는 "바뀐 칸만"으로 줄였다
- MolmoAct2 본문 전체에 **시각 궤적(trace)·조종(steer)이 한 번도 나오지 않는다**(검색 0건). 버린 이유는 적혀 있지 않다. 추론 비용에 대한 문제의식(§1 인용)만 있다.
- **MolmoAct2-Think**: 깊이 10×10 = 100코드(같은 DA-V2 → MolmoAct VQ-VAE). 연속 프레임에서 RGB 32×32 칸의 코사인 유사도 < **0.996**인 칸만 다시 생성하고 나머지는 앞 프레임 코드를 재생(식 10). 학습은 행동 / 깊이 / 깊이+행동 세 형식을 고르게 섞고, 미세조정에서는 **깊이 입력 토큰 10 %를 무작위 코드로 바꿔 넣는 잡음**(실행 때 자기 예측 깊이를 쓰기 때문)과 **층별 깊이 게이트**(편향 −4로 시작 = 처음엔 깊이를 거의 안 봄)를 쓴다.

## 4. Harvest에 대응

공통 지연 기준: decide 설계값 p95 ≈ 0.28 s(§59, 문턱 0.33 s). HF 순전파 실측 FULL p95 0.0946–0.0983 s(E-TC, H200, 머리 + 손목, 프롬프트 약 470토큰, 시각 토큰 356). **우리 디코드 1토큰 지연은 잰 적이 없다** — 4B HF 디코드는 토큰당 수십 ms로 추정되므로, 궤적 45 + 틀 문장을 생성하면 +0.5 s 이상, 깊이 102토큰이면 +1 s 이상(추정). 참고 실측은 MolmoAct2 H100 CUDA 그래프에서 깊이 생성 0.787 s 대 없음 0.179 s.

### 4.1 (a) 손끝 궤적 덧그림 — Astra와 VLA (§13)

**MolmoAct에서 가져오는 형식**
- 폴리라인 1–5점, p₁ = 지금 손끝, 좌표는 이미지 정규화(0–255 정수 또는 [0, 1]). 그리기: MolmoAct는 예측 궤적 노랑·사용자 궤적 청록(그림 9); PEEK는 **시간에 따라 진한 빨강 → 옅은 빨강**으로 선분을 그려 방향·시간을 표시하고 과제 관련 영역만 남기는 마스크를 함께 준다(PEEK III-C).
- §13 네 요소에 대응: (1) 현재 손끝 = p₁ 표지, (2) 최근 2–3 s 이력 = 과거 방향 폴리라인(시간에 따라 옅어짐 — PEEK 방식을 과거 쪽으로), (3) 확정 청크 예정 방향 = 짧은 화살표, (4) 직전 Astra 편향 = 다른 색 화살표. 각 요소는 **숫자 폴리라인(≤ 5점)으로도 직렬화**해 Astra 요청 JSON에 함께 넣을 수 있다(5점 약 45토큰 — MolmoAct 토크나이저 실측, Astra 토크나이저는 다를 수 있음). 가는 선이 원근·압축으로 안 보일 위험을 숫자가 보완한다.

**Astra 쪽**
- 장점: 무상태 API가 한 장 안에서 흐름을 본다(§13 가설). 추가 이미지 없음. 비용은 좌표 텍스트 수십 토큰.
- 단점·위험: 선이 물체·접촉부를 가림(§13이 이미 지적) → 손목 영상엔 가장자리에만. 머리 영상에서 손끝이 팔에 가려지는 자세에서는 투영점이 가려진 곳을 가리킴(MolmoAct 한계 1과 같은 문제).
- 근거 수준: 덧그림이 **프런티어 VLM 판정**을 돕는다는 기간 안 통제 근거는 이번에 찾지 못했다 → 탐침(E-Astra-motion 안 {덧그림 없음, 덧그림} 스냅숏 비교)으로만 판단.

**Astra `edit`을 궤적으로? — 사용자 선택과의 관계**
- 사용자 선택(user-log 83): "목표를 공간에 표현하는 것 조차 안하고 그냥 일반적 아스트라 조종법" → `edit` = 손끝 기준 이동 ≤ 5 cm·회전 ≤ 0.35 rad·그리퍼. **Astra가 영상 위에 궤적을 직접 그리는 방식은 이 선택과 충돌한다**(공간 목표 표현). 주 설계에 넣지 않는다.
- **충돌 없는 호환 형태(권고)**: Astra는 지금대로 수치 `edit`만 낸다. **코드가** 그 명령(손끝 기준 변위)을 FK + 카메라 투영으로 2점 화살표로 그려 (i) 다음 Astra 요청의 영상(흐름 상태의 시각판)과 (ii) VLA 입력 영상(선택, E-MA2)에 보인다. 공간 정보의 출처는 여전히 사용자가 승인한 수치 명령이다.
- 선택 탐침 변형(**[사용자 결정 필요]** — 다시 열 때만): Astra가 ≤ 5점 궤적을 직접 출력. 근거는 약하다: 범용 프런티어 모델은 포인팅이 약하다(Molmo2-ER 표 3: GPT-5 Point-Bench 43.6·Where2Place 37.0·RoboSpatial-Point 19.0, Gemini 2.5 Pro 62.7·37.0·8.3 대 Molmo2-ER 77.3·54.0·32.0; 단 Qwen3-VL-4B는 RoboSpatial-Point 62.3·Where2Place 63.0으로 오히려 높음). 반대로 SPF(CoRL 2025)는 영점 VLM이 수치 쓰기(7 %)보다 점 지정(100 %)을 훨씬 잘한다고 했다(드론). 어느 쪽이든 Astra의 포인팅 정확도를 먼저 재야 한다.

**VLA 쪽** — MolmoAct의 핵심 교훈은 "그려 주면 따른다"가 아니라 **"그린 것을 따르도록 학습시켜야 따른다"**이다.
- MolmoAct는 궤적 조건 데이터를 행동 추론 데이터와 **같은 양**(사전학습 10.5M 대 10.5M, 중간학습 1M 대 1M) 넣었고, 조종 과제에서는 시연 절반을 **다른 경로로 가는 시연**으로 모았다. HAMSTER(ICLR 2025)는 저수준이 경로를 무시하는 실패(RVT 실패의 72 %)를 보고했다.
- **이력 덧그림과 미래 궤적 덧그림은 다르다.** MolmoAct·PEEK·HAMSTER의 덧그림은 모두 **미래 계획**(어디로 갈지)이다. 과거 이력을 그리는 것은 TraceVLA(기간 밖)이고, MolmoAct 표의 TraceVLA 인용값은 SimplerEnv VM 42.0(OpenVLA 27.7) 대 **LIBERO 74.8(OpenVLA 76.5, 오히려 낮음)**이다 — 학습 조건이 달라 통제 비교는 아니다. 우리 E-TC에서 움직임 줄(과거 속도 한 줄)이 이미 +0.025를 냈으므로 이력 덧그림의 추가 이득은 **작을 수 있다** → E-MA1에서 움직임 줄을 켠 채로 잰다.
- **누수 주의(§13 (3))**: 학습 때 "다음 청크 예정 화살표"를 정답 미래로 그리면 모델은 화살표를 베낀다(정답 누수). 실행 때 그 화살표는 앞 스텝 자기 예측이므로 틀린 결정을 스스로 강화한다. VLA 입력에는 **인과 정보(과거 이력, 이미 확정된 앞 스텝 결정, Astra 명령)만** 그린다. 예정 화살표는 Astra 영상에만 둔다.
- 지연: 이미지 토큰 수 불변(같은 해상도에 선을 그림), 텍스트 +0. 비용은 FK·투영·그리기 CPU 수 ms(추정) — E-TC의 video2가 CPU 전처리로 FULL p95 +20 %를 낸 전례가 있으니 **FULL p95로 판정**한다.
- 정본 영향: 이미지 내용이 바뀌므로 카메라 배치 표지 새 판(예 `D27v1+eetrace@v1`) → `question_id@vN` 해시(§59: 카메라 구성 포함) 전부 바뀜 → 보정 파일·카나리 기준 재생성(§77 규칙). 런타임 `harvest/runtime`에 FK·투영·그리기 추가, Astra 쪽은 프롬프트 판본(astra_prompt_id) 새 판.

### 4.2 (b) 궤적 예측을 융합 VLA의 보조·중간 과제로

| 방식 | 내용 | 실행 지연 | 근거 |
|---|---|---|---|
| **학습 때 보조 손실(권고)** | 기존 `AuxGeomHead`(학습된 질의 주의 풀링)에 회귀 출력 추가: 머리 영상 위 미래 손끝 **5점**(p₁ = 현재, 나머지 = 구간 끝까지 등간격; 점마다 영상 안/밖 마스크), 좌표 [0, 1]. 기울기는 백본까지(§58 "기하를 이미지에서 배운다") | **0**(실행 때 머리를 안 돌림; 진단용으로 돌려도 수 ms) | VLA-OS(NeurIPS 2025) 통합-암묵(계획 = 보조 손실만): 시각 계획(상자·말단 궤적·어포던스) 71.0 대 언어 68.0 대 없음 66.0(LIBERO-Long). ECoT-Lite(CoRL 2025 Oral): 추론을 학습 때만 써도 전체 ECoT와 같음(76.4 대 76.6) |
| 실행 때 생성(MolmoAct식) | 결정 전에 궤적 토큰 약 45 + 틀 생성 | +0.5 s 이상(추정) — 예산 밖 | VLA-OS: 계획을 먼저 생성하고 행동 머리가 원 입력을 못 보면 42.7–67.5로 **떨어짐**. MolmoAct2도 버림 |

- **라벨**: MolmoAct는 Molmo 포인팅(보정 불필요)으로 만들었다. 우리는 **FK 투영이 더 낫다** — R2 시뮬은 카메라가 정확하고, S-E2E는 `se2e_data.py`에 URDF FK가 이미 있다. 필요한 것은 머리 카메라 모델: 내부 = ZED Mini VGA 672×376 명목값(§47: fx ≈ 367, 화각 85°), 외부 = URDF 카메라 링크(+ RB2는 상태에 `head_joint1/2`·`lift_joint`가 있어 자세마다 계산, RB1은 상태 16차원에 머리 관절이 없음 → 고정으로 가정). 명목 보정의 오차는 모르므로 **관문 G0**(6절)로 확인하고, 필요하면 MolmoAct식 VLM 포인팅(Molmo2-ER, Apache-2.0, 4B)으로 얻은 손끝 픽셀과 FK 3D 점으로 외부 파라미터를 PnP 보정한다. 포인팅을 라벨로 직접 쓰지 않는 이유: 프레임별 독립 추정이라 떨리고 실패(None)가 빠진다(MolmoAct 코드에 평활화 없음).
- **지평**: MolmoAct는 "에피소드 끝까지" — 긴 에피소드에서는 5점이 너무 성기다. PEEK처럼 **물체를 다루는 구간 단위**로 자른다: 다음 그리퍼 사건(열림/닫힘 변화) 또는 에피소드 끝, 상한 3 s. §6의 되짚기 라벨(단계 경계·그리퍼 사건에서 끊음)과 같은 규칙이라 한 라벨 파이프라인으로 둘 다 만든다.
- **깊이 방향**: 2D 궤적은 카메라 깊이 축 움직임을 못 담는다(MolmoAct 한계). 우리 조이스틱 `dir_z`·`mag`가 그 몫을 맡으므로 보완 관계(steering 문서와 같은 결론). 보조 목표에 카메라 좌표계 손끝 변위 3D(dx, dy, dz)를 같이 넣는 것은 싸다(FK에서 바로).
- **정본 영향**: `stageb_data.py`는 프롬프트 파일 목록(§71 `PROMPT_FILES_B`)에 들어 있어 `AUX_REG`를 고치면 기존 체크포인트 `files_sha`가 전부 어긋난다 → E-TC처럼 **새 옵션 파일**(예 `harvest/train/se2e_trace.py`)로 보조 목표를 더하고 `prompt_config`에 `aux: trace5@v1`를 기록. 프롬프트·직렬화기·`question_id@vN`은 그대로(입력 불변) → 채택 시에도 보정 파일은 새 체크포인트라서 다시 만드는 것뿐(§77).
- steering 문서 권고 1("공간 궤적 보조 손실")·E-SR1의 궤적 요인과 같은 것이다 → **E-MA1이 E-SR1의 궤적 요인과 §13 E-TRACE를 하나로 합친다**(중복 실행 방지). E-SR1의 "결정 강건 학습" 요인은 따로 남는다.

### 4.3 (c) RGB만으로 깊이 인식 토큰
- **MolmoAct가 실제로 하는 것은 RGB 단독이다**: 실행 입력은 RGB, 깊이는 단안 깊이 모델(DA-V2)이 만든 라벨을 VQ-VAE로 100코드로 줄여 **예측 목표**로만 쓴다. 사용자가 거부한 것(깊이 센서 입력 — 범용성)과 충돌하지 않고, 수용한 "RGB만으로 3D" 방향과 맞는다.
- **실행 때 생성은 불가**: 102토큰 + 틀. MolmoAct2의 적응형도 H100 CUDA 그래프에서 0.787 s/회(깊이 없는 경로 0.179 s) — 우리 0.3 s 예산의 2배 이상.
- **보조 목표로(생성 없이)**: 백본 은닉 상태 → 보조 머리 → 10×10 격자 (a) 로그 깊이 회귀 또는 (b) MolmoAct VQ-VAE 코드 128-분류(공개 `vae-final.pt` 재사용 가능). 실행 지연 0.
- **근거의 약함**: MolmoAct(1)은 깊이 절제가 없다. MolmoAct2-Think의 이득은 LIBERO +0.9 pt(천장 근처), 생성형·게이트·잡음까지 다 넣은 결과다. "깊이를 보조 손실로만" 쓴 판은 MolmoAct 계열에 없다 → 기대 이득 낮음·불확실.
- **우리 데이터에 맞는 교사**: DA-V2 단안 깊이는 상대 깊이(척도 없음). S-E2E는 머리 스테레오 쌍(`cam_head` + `cam_head_right`, RB1 718편·RB2 657편)이 있으므로 **학습 라벨만** 스테레오로 만들면 척도 있는 깊이를 얻는다(실행 입력은 여전히 왼쪽 RGB 한 장). R2 시뮬은 정확한 깊이가 공짜. DA-V2 Base는 CC-BY-NC(2.11절).
- 비용: 라벨 생성 39k 머리 프레임 — GPU 1장 수십 분 이내(추정). 보조 머리 학습은 무시할 만함. **우선순위 4** — E-MA1 결과(궤적 보조 효과)를 본 뒤 별도 등록.

### 4.4 (d) MolmoAct 가중치·데이터를 직접 쓰기
- **MolmoAct(1) 7B**: 단일 팔 Franka·7-DoF 델타 말단·자기회귀 약 200토큰/스텝 → 우리 양팔 AI Worker(팔 7 + 그리퍼, 머리·리프트) 0.3 s 결정 구조에 맞지 않는다. **쓰지 않는다.**
- **MolmoAct2**: 쓸 가치가 있다 — 단 **백본 교체가 아니라 외부 기준선 행**으로.
  - 백본 교체(Qwen3-VL-4B → Molmo2-ER)는 근거가 섞여 있다: 13개 체화 추론 평균 Molmo2-ER 63.8 대 Qwen3-VL-4B 59.0이지만, 포인팅 계열에서 Qwen3-VL-4B가 앞서는 칸이 있다(RoboSpatial-Point 62.3 대 32.0, Where2Place 63.0 대 54.0). 백본 절제(표 10)는 Molmo2 대 Molmo2-ER뿐이다. 교체하면 프롬프트·직렬화기·서빙·보정·카나리 전부 새 판 → 지금은 비권고.
  - 기준선 행: 가장 가까운 공개 체크포인트는 **MolmoAct2-BimanualYAM**(카메라 top + 왼손목 + 오른손목 = AI Worker 머리 + 두 손목과 같은 배치, 절대 관절 자세, 30 Hz, 상태 14 = 팔마다 7). AI Worker는 상태 16/19·10 Hz라 미세조정 필요. LeRobot 공식 통합이고 ROBOTIS Cyclo Intelligence가 MolmoAct2를 학습 가능 정책으로 올려 두었다(D21) → "같은 로봇·같은 데이터에서 가장 가까운 공개 융합형 VLA" 비교 행으로 적합. 배치 비용: 체크포인트 약 22 GB, bf16 추론 < 16 GB(YAM 카드). 미세조정: 논문 실물 과제 미세조정 = H100 8장·배치 16·50k 스텝(GPU시간 미표기). 주의(LOW 근거): 다른 기체 영점 배치에서 팔이 움직이지 않은 사례 보고(Robocurve, D22 — 등급 LOW).
- **데이터로 S-E2E·R2 보강**:
  - MolmoAct Dataset(CC-BY-4.0, 단일 팔 Franka, 외부 카메라 시점)은 우리 머리 시점(자기 중심, 위에서 내려봄)과 기체가 달라 **행동 청크 학습에는 부적합**. 결정 토큰(손끝 변위 방향·크기)은 말단 궤적만 있으면 만들 수 있어 이론상 섞을 수 있지만, 시점 차이로 이득 불확실.
  - MolmoAct2-BimanualYAM(Apache-2.0, 34.5k 시연·720 h, 양팔 + 손목 2)이 훨씬 가깝다. 쓸 곳: (i) 궤적 보조 손실·결정 토큰의 **다기체 사전학습**(YAM FK로 손끝 궤적·변위 라벨) — MolmoAct2 방식(설정·제어 문장 `<setup_start>…`, 32차원 패딩)을 따르면 행동 청크도 섞을 수 있다. 이득 근거는 MolmoAct 중간학습 +5.5 pt(같은 기체, 3과제 × 11회 — 약함)뿐 → 지금은 **보류**, 본 학습 설계 때 검토.
  - R2 시뮬 보강 용도는 없음(시뮬은 오라클 계획기 데이터로 충분).

## 6. 사전 등록 준비 실험

두 실험 모두 **등록 문서로 옮기기 전 초안**이다. 문턱·표본은 결과 전에 고정하고, E-TC(`prereg_se2e_temporal.md`)와 같은 형식·판정 스크립트 방식을 따른다. 실행은 사용자 승인 뒤.

### 6.1 E-MA1 — MolmoAct식 손끝 궤적: 미래 궤적 보조 손실 × 이력 덧그림 (S-E2E `se2e_c1`)

**질문**: (A) 미래 손끝 궤적을 보조 목표로 배우면 결정 정확도가 오르는가(실행 비용 0). (O) 과거 손끝 궤적을 머리 영상에 그려 주면 움직임 줄(§83) 위에 추가 이득이 있는가.

**관문 G0(학습 전, 결과 전 고정)** — 머리 카메라 투영 검증
- 표본: 검증 분할에서 머리 프레임 120장(RB1 60 + RB2 60, 활성 팔 좌우 반반, 시드 0).
- 기준점: Molmo2-ER에 "point to the right/left robot gripper"(MolmoAct 프롬프트) — 실패는 사람이 한 번 표시로 대체하고 그 수를 기록.
- 투영: `se2e_data` URDF FK의 활성 팔 손끝(그리퍼 중심) → URDF 카메라 링크 + ZED Mini VGA 명목 내부값.
- **통과** ⇔ 픽셀 오차 중앙값 ≤ 12 px 그리고 90분위 ≤ 30 px(672×376 기준). 실패 → 60장으로 외부 파라미터 6자유도 PnP 보정 후 나머지 60장에서 재검사(같은 문턱). 그래도 실패 → E-MA1을 R2 시뮬 데이터로 옮긴다(카메라 정확).

**요인과 칸(2×2, 모든 칸 움직임 줄 `se2e-motion@v1` 켬)**

| | O = none | O = 이력 덧그림 |
|---|---|---|
| **A = none** | 기준(se2e_c1로 새로 학습 — 옛 `single_motion` 체크포인트는 옛 데이터판이라 재사용 불가) | O만 |
| **A = trace5** | A만 | 둘 다 |

- **A = trace5**: 보조 회귀 10 + 마스크 5. 점 = 현재 손끝 + 구간 끝(다음 그리퍼 사건 또는 에피소드 끝, 상한 3 s)까지 등간격 4점, 머리 영상 [0, 1] 좌표, 영상 밖이면 마스크 0. 손실 = 마스크 smooth-L1 × λ 0.1(기존 aux와 같은 λ). 새 옵션 파일에서 기존 `AuxGeomHead` 출력만 늘림.
- **O = 이력 덧그림**: 머리 영상에만. 프레임 k−20…k(10 Hz, 2.0 s, **과거만**)의 활성 팔 손끝 투영 폴리라인, 두께 2 px, 오래된 점일수록 투명(PEEK식 색 변화), 현재점 작은 고리. 원 JPEG을 풀어 그린 뒤 같은 q90로 다시 저장(E-TC 과거 프레임과 같은 경로). 학습 때만 드롭아웃 p 0.3(그리지 않음 — MolmoAct2 "행동만 형식 섞기"와 같은 목적), 평가 때는 항상 그림.
- 공통: Qwen3-VL-4B@`ebb281ec` + LoRA r32 + expert + aux·확인 헤드, KI stop, **2,000스텝**, 배치 8, lr 1e-4, 워밍업 3 % + 코사인, **시드 0**, 검증 300 스냅샷(`--val-per-kind 150 --val-seed 0`) × 3질문 = 900항목, 500스텝마다 평가.

**지표**
- 주: 결정 정확도 `dec_acc` — **전체**와 **전이 층**(E-TC와 같은 정의, 라벨 규칙만으로 결과 전 계산).
- 지연: 결정 **FULL p95**(이미지 읽기·FK·투영·그리기·토큰화·GPU; H200 1장, 묶음 1, 네 형식 번갈아, 워밍업 30 + 형식당 200회). A는 실행 때 보조 머리를 돌리지 않으므로 기준과 같은 경로.
- 판정 밖: 결정 NLL, 질문별 정확도, **확정 보기 대신 예측 보기로 조건을 준 expert 청크 L2**(steering 문서 E-SR1 주 지표), 궤적 보조 오차(픽셀, A 칸의 조작 확인), O 칸을 덧그림 없이 평가했을 때 하락폭(덧그림 의존도), 스냅샷 군집 부트스트랩 10,000회 95 % 구간.

**채택 규칙(고정, E-TC와 같은 틀)**
- 주효과 A = ½[(a(A, none) − a(none, none)) + (a(A, O) − a(none, O))], O도 같은 식.
- 요인마다 **채택** ⇔ (1) 전체 정확도 주효과 **≥ +0.02** 그리고 (2) 전이 층 주효과 **≥ −0.01** 그리고 (3) FULL p95 증가 **≤ 10 %**. 비교는 §74·§77 CMP_EPS 1e-12.
- 잡음: E-TC와 같은 규모(표준오차 ≈ 0.02–0.03) → **통과한 요인은 시드 1로 한 번 더 돌리고 두 시드 평균으로 최종 판정**(이 규칙도 지금 등록). 통과 못 한 요인은 시드 1을 돌리지 않는다.
- 추가 경고(판정 밖이지만 보고 의무): O 칸 덧그림 제거 평가 하락이 0.05를 넘으면 "덧그림 의존 — 런타임 투영 실패 시 위험"으로 표시.

**비용**: 4칸 × 약 40분(E-TC 칸당 2,119–2,450 s, H200) ≈ 2.7 GPU시간 + (통과 시) 시드 1 칸 2개 + 지연 측정 + G0(Molmo2-ER 내려받기 /data, 120장 수 분). 유료 API 없음. GPU 0·1 사용 금지(렌더 전용), `/data`만 사용.

**정본·해시 영향**: 옵션 파일과 새 표지(`aux: trace5@v1`, 카메라 배치 `D27v1+eetrace@v1`)가 `files_sha`·`prompt_config`에 들어가 기본 체크포인트와 섞이지 않는다. 기본 경로·`PROMPT_FILES`·`harvest/runtime`은 건드리지 않는다(체크포인트 내부용, 폐루프 미사용). 채택되면: A는 학습 코드만(프롬프트 불변), O는 카메라 배치 새 판 → `question_id@vN` 재계산·보정·카나리 재생성(§77), 런타임에 FK·투영·그리기 추가.

### 6.2 E-MA2 — Astra `edit`을 VLA가 따르는가: 명령 없음 / 문장 / 그린 화살표 (R2 시뮬)

**질문**: §11은 Astra `edit`을 VLA 조이스틱 기준에 **코드로 편향을 더해** 반영한다. VLA가 명령을 보지 못하면 0.33 s마다 자기 목표 쪽으로 되돌리려 해 편향과 "싸울" 수 있다. MolmoAct 조종 결과(그린 궤적 0.747 대 언어 0.413)는 **영상에 그린 조건이 문장보다 잘 따라진다**고 말한다. 우리 구조에서도 그런가.

- 데이터: R2 시뮬(정확한 카메라, 오라클 계획기). 명령 c = **되짚기**: 다음 1.0 s 실제 손끝 변위를 Astra `edit` 범위(축마다 ≤ 5 cm)로 자른 값. 학습 표본의 50 %에만 명령을 준다(MolmoAct 궤적 조건 데이터 = 행동 데이터와 같은 양).
- 칸: **C0** 명령 없음(기준) / **C1** 문장 한 줄 `edit: dx=… dy=… dz=… cm`(손끝 기준) / **C2** 머리 영상에 현재 손끝에서 명령 끝점까지 **2점 화살표**(Astra 편향 색, 두께 3 px) / (선택) C3 둘 다. 같은 스케줄(2,000스텝, 시드 0).
- 평가(R2 DEV 스냅샷, 결과 전 고정 개수):
  - (i) 명령 없는 입력의 결정 정확도(비열등).
  - (ii) **반사실 준수율**: 참 명령을 xy 평면에서 90°·180° 돌린 명령(크기 유지, ≤ 2 cm로 제한 — 탁자 충돌 방지)을 줬을 때, 예측 `dir_xy`가 명령 방향과 같은 칸이고 expert 청크 0.5 s 변위와 명령 방향의 코사인 > 0.5인 비율.
- **채택 규칙**: C2 채택 ⇔ 준수율(C2) − 준수율(C1) **≥ +0.10** 그리고 명령 없는 정확도 C2 − C0 **≥ −0.01** 그리고 FULL p95 증가(대 C1) **≤ 10 %**. C1·C2 모두 준수율 < 0.6이면 → VLA는 명령을 보지 않고 §11 코드 편향만 쓴다(설계 유지).
- 사용자 결정과의 관계: 명령은 Astra의 **수치** `edit` 그대로이고 화살표는 코드가 그린다 — "일반 조종법만" 선택과 충돌하지 않는다. 결과에 따라 "VLA 입력에 명령을 넣을지"는 구현 계획 때 **[결정 필요]**.
- 비용: 3–4칸 × R2 학습(칸당 시간은 R2 데이터 크기에 따름 — 등록 때 추정), 유료 API 없음.

## 7. 하지 않을 것 / 보류
- 실행 때 깊이·궤적 토큰 생성(MolmoAct식 사슬 그대로) — 지연.
