## 0. 한눈 요약

### 0.1 보통은 이렇게 한다
1. **한 모델에 여러 기체 데이터를 섞어 사전학습하고, 쓸 기체·벤치마크마다 미세조정한다.**
   - π0.5는 첫 단계 표본의 97.6 %가 목표 기체가 아니었다.
   - GR00T N1.7, X-VLA, SmolVLA, MolmoAct2 모두 LIBERO·SimplerEnv 등은 벤치별 미세조정 체크포인트로 보고한다.
2. **행동 공간 통일**은 두 갈래다.
   - (a) 차원을 최대값으로 맞추고 0 채움 + 1–99 % 분위 정규화를 쓴다(π0.5, MolmoAct2).
   - (b) 기체별 입출력 층이나 출처별 소프트 프롬프트를 둔다(GR00T의 기체별 MLP, X-VLA, HPT·CrossFormer [기초]).
   - 2025–26년에는 **말단(EEF) 표현, 특히 상대 EEF**로 모인다. GR00T N1.7은 상대 EEF를 교차 기체 성능의 '핵심 요인'이라 했다. X-VLA는 절대 EEF + Rotate6D, TRI LBM은 EEF + 6D다.
3. **카메라는 '이름 붙은 고정 칸'에 여러 장을 동시에 넣는 것이 표준이다.**
   - 보통 주 시점 1–2장 + 손목이고, 없는 칸은 0이나 마스크로 채운다.
   - 카메라 내·외부값을 입력으로 넣는 주류 VLA는 거의 없다.
   - 그래서 시점이 바뀌면 크게 무너진다. LIBERO-Plus(CVPR 2026)에서 π0는 94.2 → 15.8 %, OpenVLA-OFT는 97.1 → 59.7 %로 떨어졌다.
4. **시점 강건성은 2025–26년에 따로 생긴 연구 갈래다.** 대표 방법은 다섯 가지다.
   - 카메라 조건 입력(Plücker 광선, ICRA 2026)
   - 카메라 좌표계 행동(OC-VLA)
   - 기하 기반 특징(GeoAware-VLA, Spatial Forcing ICLR 2026)
   - 짝 시점 일관성 손실(2026-08)
   - 시점 합성 데이터(EgoDemoGen)
   - 공통 결론은 **시점을 그냥 섞기만 하면 거의 이득이 없다**는 것이다. Ego2ExoVLM(ECCV 2026)은 +0.3 %, 같은 상태의 짝 시점 + 명시적 교차 시점 감독은 +8.5 %였다.
5. **점·궤적을 내는 공간 VLM은 우리와 같은 구조다.** Gemini Robotics-ER 1.5, MolmoAct, Embodied-R1, RoboPoint [기초], HAMSTER [기초]가 여기에 든다.
   - 출력은 '들어온 그 이미지의 좌표'로 낸다. 3D로 바꾸는 일은 깊이 + 카메라 보정(코드·플래너)이 맡는다.
   - 이 구조 덕분에 기체와 시점에서 자유롭다. 시점 차이는 학습 데이터의 시점 다양성으로 흡수한다. 카메라 값은 모델에 주지 않는다.

### 0.2 우리에게
- 방식 D(머리 영상 점 → 코드가 깊이·보정으로 3D)는 이미 문헌의 **'관측 중심(observation-centric)' 설계**다.
  - 3D 변환이 모델 밖에 있다. 그래서 기체를 바꿀 때 바뀌는 것은 '영상이 어떻게 보이나'뿐이고, '좌표를 어떻게 사상하나'는 코드가 맡는다.
  - 범용성은 **머리 카메라 기하(높이·피치·화각)와 기체 외형의 다양성**으로 얻는 것이 문헌과 가장 잘 맞는다(권장 A).
- 3인칭을 꼭 넣어야 한다면 '그냥 섞기'는 문헌상 이득이 거의 없다. E-VIEW8 결과와도 맞는다. 대신 세 가지를 함께 쓴다(권장 B).
  - 같은 상태의 **짝 시점**(시뮬은 공짜로 만들 수 있다)
  - **시점 표시 + 카메라 값**
  - **물체·놓을 곳 점만**
- 벤치마크용 3인칭 점수는 업계 관행대로 **본 LoRA와 분리된 벤치 전용 어댑터**로 내는 것이 머리 성능에 손해가 없는 길이다(권장 C). 단, NOW §4 '3인칭 금지'의 예외이므로 사용자 결정이 필요하다.

## 3. 시점(3인칭·손목·머리)을 어떻게 다루나

### 3.1 여러 카메라를 동시에 넣나, 이름을 토큰으로 쓰나
- **동시 입력이 표준이다.** π0.5 4대, TRI LBM 6대, GR00T RoboCasa 3대, MolmoAct2 3대, OpenVLA-OFT 3인칭 + 손목.
- **칸 이름(고정 순서)이 사실상의 '카메라 토큰'이다.** 없는 칸은 0이나 마스크로 채운다(LBM 원문, RDT [기초]).
  - SmolVLA는 이름이 제각각인 커뮤니티 데이터를 사람이 top·wrist·side로 다시 붙였다.
  - MolmoAct2는 반대로 SO-100 카메라 순서를 **에피소드마다 섞어** 이름에 기대지 않게 했다.
- **주 시점만 VLM에 넣는 설계도 있다.** X-VLA는 "현재 VLM은 다중 시점 인식이 제한적"이라며 고정 주 시점만 VLM에 넣고, 손목은 별도 경량 인코더로 처리했다.
  - 우리 상위가 머리 한 장(+ 손목)만 보는 설계와 같은 판단이다.
- **손목 카메라가 시점 강건성을 준다.** LIBERO-Plus는 손목 카메라를 쓰는 모델(OFT)이 시점 변화에 더 강하다고 보고했다. 손목만 쓴 절제에서도 43.6–67.3 %가 남았다.

### 3.5 점·궤적 공간 VLM은 시점 차이를 어떻게 처리하나 (질문 2 마지막)
- **출력 좌표계를 입력 이미지에 묶는다.** Gemini-ER은 [y, x] 0–1000, Embodied-R1·MolmoAct·RoboPoint도 그렇다. 시점이 바뀌어도 '정답을 만드는 규칙'(투영)이 같다.
- **3D 변환은 모델 밖에서 한다.** Embodied-R1은 핀홀 + 깊이 → 플래너, HAMSTER는 하위 3D 정책, Gemini-ER은 사용자 코드가 맡는다.
- **시점 다양성은 데이터로 넣는다.** RoboPoint는 카메라 무작위 합성, MolmoAct는 외부 카메라 두 대를 짝 표본으로, HAMSTER는 시뮬 + 실물 투영 궤적을 쓴다. 카메라 값 입력은 없다.
- **에고/엑소 비율이나 둘을 섞은 손해를 보고한 공간 VLM 논문은 찾지 못했다.** 이 부분은 공백이다. E-VIEW8이 우리 쪽 첫 실측이다.

## 5. 우리에게 주는 시사점 (질문 4)

### 5.1 머리 시점 원칙을 지키면서 범용성을 얻는 길
1. **이미지 공간 출력은 그대로 둔다.** 이것이 문헌의 기체·시점 무관 설계(OC-VLA, 공간 VLM 계열)와 같다. 기체가 바뀌면 코드(역투영·IK)만 바뀐다.
   - 근거 강도: **중**(공간 VLM 관행은 강, 카메라 좌표 행동의 우위 수치는 프리프린트).
2. **머리 카메라 기하를 무작위화한다.** 높이·피치·화각·해상도를 실제 후보 로봇(FFW-SG2, Franka 받침대, GR1, R1 Pro) 범위 + 여유로 뿌리고, 자르기·크기 증강 때 내부값을 함께 고친다.
   - 근거: CA-MLLM(ICLR 2026 Oral, 한 카메라 기하 과적합), Do You Know(ICRA 2026, 자르기 = 가상 카메라), RoboPoint [기초].
   - 근거 강도: **중**.
3. **카메라 값을 글로 준다.** `camera:` 줄에 내부값·높이·피치를 적는다. 런타임 camera_info에서 자동으로 만든다(선행 문서 규칙 3).
   - 근거 강도: **중**. VLM에 글로 넣은 직접 선례는 못 찾았다. 광선 임베딩·Plücker의 글 버전이라 **[가설 포함]**.
   - 상위 출력 형식은 바뀌지 않는다. 입력 줄 추가는 다음 본 학습(P2)에 넣는다(NOW §1-0e '상위 불변'과 충돌 없음).
4. **머리 카메라가 달린 기체를 늘린다.** L9의 Franka·GR1·R1 Pro, 공개 BEHAVIOR(R1 Pro 머리)·RoboTwin(aloha 머리)·MolmoBot RBY1.
   - 근거: π0.5 P1, GR00T(GR-1 머리 에고), X-VLA 출처 표시.
   - 근거 강도: **강**(교차 기체 공동학습 자체).
   - 출처 표시 줄은 함께 둔다.
5. **손목 영상은 계속 함께 둔다.** 시점 강건성의 값싼 원천이다(LIBERO-Plus).
   - 근거 강도: **중**.

### 5.2 3인칭을 넣어야 한다면 — E-VIEW8 손해를 피하는 방법
- **하지 말 것**: 시점 표시 없이 공개 3인칭을 그냥 섞기. Ego2ExoVLM +0.3 %, E-VIEW8 BEHAVIOR 악화, Cross-View(그냥 섞기 < 짝 일관성)가 근거다.
- **할 것**(근거 강도 순):
  1. **벤치 전용 어댑터**(본 LoRA 불변) — 머리 성능 손해 0이 구조로 보장된다. 업계 관행(벤치별 미세조정)과 같다. **강**(관행), 단 NOW §4 예외라 사용자 결정 필요.
  2. **시뮬 짝 시점 + 시점 표시 + 카메라 값** — 같은 상태·같은 3D 목표를 머리와 외부 카메라에서 동시에 가르친다. **중**.
  3. **물체·놓을 곳 점만, 손 점 제외** — **약**(우리 1건).
  4. **비율 ≤ 10 %에서 시작해 짝 비교** — **약–중**.
- **판정 방법부터 고친다.** E-VIEW8 A/A에서 같은 모델끼리도 '평균 +2 mm 안'을 35/35 통과하지 못했다. 그러므로 다음 시점 실험은 세 가지를 지킨다(NOW §6 4번과 같음).
  - 시드 ≥ 4
  - 중앙값과 '접근 > 20 mm 실패율'로 판정
  - 비열등 여유를 같은 팔 시드 쌍의 95 % 폭으로 보정
  - TRI LBM(과제·조건당 50–200회, 블라인드 A/B, 베이즈 판정)이 같은 취지의 업계 근거다.

### 권장 A — 머리 시점 유지 + 카메라 기하 무작위화 + 카메라 값 글 조건 ("시점은 넓히되 머리 안에서")
- **무엇**: L9 생성기에 머리 카메라 기하 무작위화를 넣는다.

  - Franka 받침대·GR1·R1 Pro 기체는 그대로 쓴다.
  - 모든 행에 `camera:` 줄(내부값·높이·피치)과 `source:` 줄을 넣는다.
  - 자르기·크기 증강은 내부값과 함께 고친다. 출력 형식은 바꾸지 않는다.

- **사전등록 초안 E-HCAM8**
  - 질문: 머리 카메라 기하를 무작위화하고 카메라 값을 글로 주면, 처음 보는 머리 기하·기체에서 접근 오차가 줄고 표준 FFW-SG2 머리 성능은 유지되는가?

    - H2 = 무작위 기하만(줄 없음, 조건 효과 분리)

  - 시험 세트:
    - (i) 표준 L8-X dev·OOD 세트
    - (ii) **보류 기하 세트**: 학습에 없는 피치·높이, Franka 받침대·GR1·R1 Pro 머리. L9 보류 편으로 만든다.

    - (ii) 중앙 접근 오차 H1 ≤ H0 × 0.9 그리고 > 20 mm 실패율 감소

### 권장 B — 3인칭을 넣는다면: 시뮬 짝 시점 + 시점 표시 + 물체 점만 ("그냥 섞기 금지")

### 권장 C — 벤치 전용 어댑터 ("본 LoRA는 머리 전용으로 잠그고, 3인칭 점수는 따로")
