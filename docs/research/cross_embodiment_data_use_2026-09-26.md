## 0. 결론 요약

1. **남들은 맞지 않는 로봇 데이터를 '행동 라벨'로 그대로 쓰지 않는다.** 두 갈래로 바꿔 쓴다.
   - (a) **기체와 무관한 영상 공간 표현으로 변환**: 그리퍼 끝의 2D 궤적·점, 물체·빈 자리 점, 깊이. MolmoAct는 OXE(RT-1·Bridge·BC-Z) 1,050만 표본을 "그리퍼를 가리켜라"로 뽑은 2D 궤적 + 깊이 토큰으로 바꿨다. HAMSTER[기초]는 시뮬 32만 경로와 Bridge·DROID 궤적을 FK + 카메라 값으로 영상에 투영했다.
   - (b) **QA·추론 문장으로 재라벨**: 말단 자세·그리퍼 폭·힘·보정값으로 질문과 정답을 자동 생성한다. Robo2VLM은 실물 17.6만 궤적에서 68만 문항을 만들었다. Cosmos-Reason1[경계]은 Bridge·RoboVQA·AgiBot에서 145만 주석을 만들었다. RoboBrain 2.0·InternVLA-M1은 로봇 데이터를 상자·점·궤적 QA로 바꿨다.
   - **실제 제어 라벨은 자기 기체 데이터가 맡는다.** VLA 쪽에서 여러 기체를 한 모델에 넣을 때는 출처별 표시를 둔다: π0.5는 행동 0 채움 + 과제 표시, X-VLA(ICLR 2026)는 출처별 소프트 프롬프트로 검증 오차를 0.11 → 0.041로 줄였다.
2. **공개 데이터만으로는 안 된다는 직접 증거가 있다.** Vlaser(ICLR 2026)는 인터넷·일반 구현체 추론 데이터로 사전 학습한 판(Vlaser-OOD)이 SimplerEnv WidowX 평균 41.8 → **43.2 %**로 거의 그대로였다. 같은 시뮬 플랫폼(SimplerEnv·RoboTwin)에서 만든 in-domain QA로 학습한 판은 **62.6–65.1 %**였다. 반대로 π0.5(CoRL 2025 구두)는 첫 단계 학습 표본의 **97.6 %**가 목표 기체가 아닌 데이터였고, 교차 기체(CE)·다른 환경(ME) 데이터를 빼면 성능이 "크게" 떨어졌다. → **남의 데이터는 '우리 데이터와 섞을 때' 돕고, 우리 데이터를 대신하지 못한다.** 선행 판정(자체 시뮬 주)은 유지한다. 다만 공개 데이터의 몫을 '보조'에서 **학습 표본의 약 40–50 %**로 키울 근거가 있다(3절).
3. **우리 실패(영상에서 물체 위치 읽기)에 가장 가까운 공개 변환은 '깊이 + 보정으로 만든 3D·점 QA'다.** 데이터: BEHAVIOR 깊이 + 분할 + 카메라 자세, MolmoBot 물체·그리퍼 영상 점 + 프레임별 보정, RefSpatial 점 + 깊이. 근거: RoboRefer는 깊이 전용 인코더로 CV-Bench 91.24 → 94.77 %, InternVLA-M1은 공간 그라운딩 공동학습으로 SimplerEnv +14.6 %p(Google)·+17.0 %p(WidowX).
4. **범용성 유지**: 문헌의 일반 데이터 몫은 5–25 %다. MolmoAct는 표집의 5 %가 웹 데이터, RoboRefer는 지시 조율 데이터를 RefSpatial QA의 1/20, InternVLA-M1은 300만 중 70만(약 23 %) 일반 멀티모달, HAMSTER[기초]는 66만 VQA를 함께 썼다. 권고는 **일반 VQA 5 % + 일반 공간 VQA 10 %**다.
5. **양**: 7–56B 구현체 특화 미세조정의 보고 규모는 수만–수백만 표본이다. SIMS-V 7B는 시뮬 2.5만, Robo2VLM은 LLaVA에서 1만 → 5만, Embodied-R1 3B는 약 30만, RoboBrain 2.0 7B/32B는 2단계 22.4만(1단계 480만), Cosmos-Reason1 7B/56B는 구현체 145만, InternVLA-M1은 300만, MolmoAct 7B는 사전 학습 2,630만을 썼다. 35B-A3B LoRA 특화(형식·좌표 사상·위치 읽기)는 **약 30–50만 표본**을 1차 목표로 잡는다 [추정]. 구성은 자체 시뮬 약 50 %(조종 25 % + 인식 25 %) + 공개 변환 약 50 %(인식 25 % + 추론·평가 10 % + 일반 공간 10 % + 일반 5 %)다.
6. **먼저 할 무료 시험**(설계만, 실행 안 함): E-TEACH-L8 레시피 그대로 8B에 대해 (A) 자체만 대 (B) 자체 + 공개 변환 인식 스트림 하나(같은 스텝·같은 표본 수)를 비교한다. 지표는 DEV 스냅숏 접근 xy 오차 중앙이다. 이득이 없거나 나빠지면(부정 전이) 공개 몫을 늘리지 않는다(5절).

## 2. 우리에게 어떻게 적용하나 — 변환 규칙 네 가지

우리 표본 종류: **(C) 조종 JSON**, **(P) 인식 QA**(물체 2D·3D 위치, 말단 점·방향, 탁자 평면), **(R) 추론·평가**, **(G) 일반 공간 VQA**.

- **규칙 1 — 공개 데이터는 우리 로봇 좌표로 답하게 하지 않는다.** 우리 출력의 좌표는 "우리 로봇 기준 절대 EEF"다. 남의 로봇 기준 좌표를 같은 칸에 넣으면 좌표 뜻이 섞인다. 공개 표본은 **영상 좌표(픽셀, 0–1000 정규화)** 또는 **그 카메라 기준 3D(m)**로 답하게 한다. 문헌(MolmoAct·Embodied-R1·HAMSTER)이 기체 무관성을 얻은 방법이 바로 이것이다.
- **규칙 2 — 출처·좌표계 표시.** 모든 표본의 글 블록 첫 줄에 `source: <데이터셋>/<기체>`, `frame: pixel | cam_<이름> | base_<기체>`를 적는다(X-VLA 소프트 프롬프트의 글 판; lit_sweep 2.2의 ICML 2026 기전 분석 '영역 구별성 유지'). 우리 런타임 표본은 `source: qdd_sim/ffw_sg2`, `frame: base_ffw_sg2`.
- **규칙 3 — 카메라 값을 글로 준다.** 공개 표본에는 그 카메라의 내부값(fx·fy·cx·cy·W×H)과, 3D 답이면 카메라 → 기저 외부값을 적는다(CA-MLLM). 자르기·크기 바꾸기 증강 때는 내부값을 같이 고친다. 우리 표본에도 같은 줄을 넣는다(§97 자동 맥락과 일치 — 사람이 쓴 값이 아니라 camera_info에서).
- **규칙 4 — (C) 조종 JSON은 자체 시뮬이 주 원천이다.** 공개 데이터로 만드는 (C)는 **'좌표계 명시 조종'** 한 종류만 허용하고 실험 팔로만 쓴다. 그 기체의 기저 좌표로 상태·이력을 적고, 목표도 그 기저 좌표로 답하며, `frame: base_<그 기체>`를 표시한다. 이것은 "영상 + 보정 → 3D → 기저 좌표" 사상을 여러 기체로 연습시킨다(우리 실패 지점). 대신 좌표 혼동 위험이 가장 크다(4절). 첫 무료 시험(5절)에는 넣지 않는다.

| S2 자체 인식 (P) | 25 % | 우리 실패(위치 읽기)를 우리 카메라로 직접 |
| S3–S6 공개 인식 (P) | 25 % | 장면·물체·카메라 다양성, 공간 그라운딩 공동학습(InternVLA-M1 +14.6·+17.0 %p) |
| S7–S8 공개 추론·평가 (R) | 10 % | 평가 칸(Robo2VLM 1만 → 5만 향상) |
| S9 일반 공간 (G) | 10 % | 공간 일반성 유지(RoboRefer) |
| S10 일반 VQA (G) | 5 % | 잊음 방지(MolmoAct 5 %, RoboRefer 1/20) |

- 자체 : 공개 = 50 : 50은 InternVLA-M1의 행동 : 멀티모달 4 : 1보다 공개 몫이 크다. 우리 공개 스트림은 대부분 '인식 QA'라 멀티모달 쪽에 해당하고, 자체 인식(S2)도 영상 QA이므로 **조종(C) : QA(P·R·G) = 25 : 75**다. 이 비율은 3.3의 무료 시험 결과로 조정한다.
- 8B 단계(L8 크기 약 7,000/에폭)에서는 공개 스트림 **하나**만, 같은 크기로(5절).
- **데이터를 받기 전** 선행 문서 2.2의 크기(BEHAVIOR 2 TB·MolmoBot 8.9 TB·RoboTwin 2.5 TB)를 기억한다. 과제·설정 부분 집합만 받는다(파드 `/data`).

### 3.3 변환 작업 순서 (무료, CPU)
1. S4 MolmoBot RBY1 val 샤드(이미 파드 `data/upper_vlm_survey/raw/`)에서 점 QA 변환기를 만든다. 겹쳐 그리기로 내부값·해상도를 확인한다(관문: 그리퍼 점이 그리퍼 위에 떨어짐 ≥ 95 %, 20프레임 눈 확인).
2. S3 BEHAVIOR 편 1개(이미 받음)에서 분할 ∩ 깊이 → 3D 중심을 구하고, `task_info` 물체 자세와 대조한다(관문: 중앙 오차 ≤ 2 cm).
3. S9 RefSpatial·S7 Robo2VLM은 형식만 바꾼다.
4. 모든 변환 표본에 규칙 2·3 줄을 붙이고, 검사기로 JSON·좌표 범위를 점검한다.

## 5. 먼저 할 작은 무료 검증 — E-XEMB8 (설계만, 실행 안 함, 사전 등록 전)

- **질문**: 공개 데이터를 기체 무관 인식 QA로 바꿔 섞으면, 같은 계산량에서 8B의 **DEV 접근 xy 오차**가 자체만보다 줄어드는가?
- **팔**(E-TEACH-L8 레시피 복제: Qwen3-VL-8B, LoRA r 16, 같은 하이퍼파라미터, 같은 총 스텝·같은 표본 수):
  - A = L8 자체만(L8 결과 재사용 가능 — L8 등록의 코드 판 고정, P109·P114);
  - B = 자체 조종 그대로 + 자체 인식 QA 절반을 **S4 MolmoBot 점 QA**(규칙 1–3 적용)로 교체(총 표본 수 같음);
  - (선택) C = B의 S4 자리에 **S9 RefSpatial**(일반 공간) — 영역이 가까운 변환(S4)과 일반 공간(S9)을 가른다.
- **지표**(L8 4.4절 그대로, 같은 DEV 스냅숏 약 350): 접근 xy 오차 중앙·p90·≤ 20 mm 비율, 유효 JSON률, 인식 보조 QA 오차(종류별). 추가로 **공개 형식 누수 검사**를 한다: 우리 답에 `frame`·픽셀 좌표가 섞인 비율(0이어야 함).
- **판정 초안**(등록 때 고정): B 중앙 ≤ A × 0.9 **그리고** 스냅숏 짝 부트스트랩 95 % 구간이 0을 넘지 않음 → 공개 인식 스트림 채택, 35B 혼합(3.2)으로. B ≥ A × 1.1 → 부정 전이로 보고 공개 몫을 G(일반 유지)만으로 줄인다. 그 사이면 차이 없음 → 다양성 목적(실물·새 물체)으로만 소량 유지.
- **비용**: 유료 0. 변환 CPU 반나절 + GPU 약 2 h(팔당 L8 1.8 GPU-h 급), x2 GPU 0 하나.
- **선행 조건**: L8 결과(TREND 여부)가 나온 뒤에 한다. L8이 TREND가 아니면 이 시험보다 입력 설계(깊이·§97)를 먼저 고친다. **L8 파일·도구는 건드리지 않는다**(복제는 새 폴더).
- **한계**: 8B·좁은 DEV라 35B 결과를 예측하지 않는다(L8 8절과 같은 취지). 폐루프는 재지 않는다(오프라인 방향만).
