# L8-X 새 과제 설계 — 밀기·쌓기·서랍/수납장 열기·넣고 닫기 (2026-09-28, 설계만)

작성: L8X-assets(L8D 보조). 근거: user-log 160(통제자 전달) "새 과제 설계 문서: 밀기, 쌓기, 서랍·수납장 열기(관절 자산 필요), 넣고 닫기 … 과제별로 참값 모델 가능성, 필요한 명령 어휘, 성공 판정기 … 구현은 설계를 승인받은 뒤에 합니다."
**구현 0, GPU 0, 유료 0.** 승인 뒤 과제마다 사전 등록 → 참값 관문(깨끗한 참값 편 ≥ 0.8) → 생성 순서로 간다.

## 0. 지금 있는 것(출발점)

- **명령 한 개** = 절대 TCP 목표 `{"mode": "eef", "position_m": [x, y, z], "gripper": "keep|close|open"}` + `stop`. 방향은 늘 **위에서 아래**(top-down)이고, 잡는 축(손가락이 닫히는 방향)은 월드 x다(`grasp_yaw`로 물체마다 돌림).
- **참값 단계**(teach_l8 labels): above_target → descend_close → (reopen / lift_clear) → carry_up → carry_over → lower_open → retreat.
- **판정**: 강체 접촉 센서 `on()` + L8-D의 가상 지지(`surfaces.supported_by`: 밑면이 받침면 top ± 4 mm, 중심이 xy 상자 안). 정적 가구 면과 Objaverse 물체는 접촉 힘이 0으로 나오는 문제가 있어 기하 판정이 기본이다.
- **자산**: 파라메트릭 가구 10종, THOR 가구(관절을 고정한 정적 사본), cyclo 탁자·바구니, Objaverse 물체 150개(세운 안정), 실물 물체(GSO·THOR 소품, 이번 작업).

**공통 원칙**
- 새 어휘는 최소로만 더한다. 기존 모델의 출력(`eef` + gripper)을 바꾸지 않고, 새 필드는 **선택**이며 없으면 지금과 같게 읽는다.
- 모든 과제는 참값 모델이 먼저 풀어야 데이터가 된다(P105: 기준선의 참값 상한부터).
- 성공 판정은 시뮬 상태만 쓰고, 모델 출력 문장은 보지 않는다.

## 1. 밀기 (push_to_region)

지시 예: "Push the red cup to the blue marker." / "Slide the box next to the bowl."

**참값 모델 가능성: 높음.** 위에서 내려온 자세를 그대로 쓴다.
- 닫은 손가락 끝을 물체 밑동 높이(윗면 기준 z = top + 0.02–0.03)에 두고, 밀 방향의 반대쪽 뒤(물체 반경 + 3 cm)에서 출발해 목표까지 직선으로 민다.
- 단계: `above_start`(시작점 위 10 cm) → `lower_behind`(시작점, 손가락 끝 높이) → `push`(목표 − 반경, 5 mm 걸음) → `lift_away`.
- 물체가 옆으로 새면 새 시작점을 다시 계산한다(되먹임 참값, 최대 2회).
- 대상 물체: 원통·상자형, 밑면 반경 ≥ 3 cm, 높이 ≥ 5 cm, 세운 안정. 공은 굴러가므로 뺀다.
- 위험:
  - 원통이 회전하며 빗나가는 경우 → 첫 관문에서 성공률을 재고, 필요하면 마찰을 올린다(재질값만 바꾸고 모양은 둔다).
  - 반대쪽 뒤가 로봇 쪽(−x)이면 팔 도달이 막힌다. 밀 방향은 ±y와 +x만 허용하고, 목표는 작업 상자 안에 둔다.

**명령 어휘**: 기존 `eef` + gripper `close`(닫은 채 유지) 그대로 쓴다. 새 필드는 필요 없다. 다만 학습 표본의 단계 이름에 `lower_behind` / `push` / `lift_away`를 더한다(라벨 문장용). 선택으로 `"contact": "push"` 힌트 필드를 둘 수 있으나, 1단계에서는 넣지 않는다.

**성공 판정기**
- 물체 중심이 목표 원(반경 3 cm; 표지가 있으면 표지 원) 안에 있다.
- 기울기 ≤ 10°(넘어지지 않음).
- 물체가 그리퍼에 쥐어지지 않았다: 손가락 접촉 없음, 또는 마지막 1 s 동안 손가락 사이 거리 < 물체 폭.
- 1 s 정지 뒤 속도 < 1 cm/s.
- 실패 사유 분해: 빗나감 / 넘어짐 / 쥐어버림 / 도달 실패.

**비용**: 참값 구현 0.5–1일, 관문 렌더 약 1 프로세스-h.

## 2. 쌓기 (stack_on)

지시 예: "Put the small green block on the yellow box." / "Stack the cup on the plate."

**참값 모델 가능성: 높음(물체 제한).** 기존 집어 놓기와 같고, 놓기 높이만 달라진다.
- 놓기 높이 `place_top = 아래 물체 윗면 z(시뮬 참값) + 위 물체 밑면 오프셋 + 4 mm`.
- 아래 물체: 윗면이 평평하고 넓어야 한다(윗면 받침면 폭 ≥ 위 물체 밑면 지름 + 2 cm).
  - 파라메트릭 블록·상자, 실물 중 이름 검사가 box / book / block / plate이고 윗면 받침면이 추출되는 것.
  - 물체 메시에도 `surfaces.mesh_support_surfaces`를 그대로 써서 윗면을 뽑는다.
- 위 물체: 세운 안정 + 잡는 폭 조건.
- 위험:
  - 탑 높이가 오르면 운반 높이도 올라야 한다. 운반 z = max(아래 물체 윗면 + 위 물체 높이 + 3 cm, 지금 값).
  - 놓은 뒤 기울어짐 → 성공 판정에 2 s 안정을 넣는다.
  - 3층 쌓기는 1단계에서 뺀다(2층만).

**명령 어휘**: 기존과 같다(eef + open). 라벨 문장의 place 대상 이름만 물체가 된다("above the yellow box").

**성공 판정기**
- 위 물체가 아래 물체에 가상 지지된다: 밑면이 아래 물체 윗면 ± 5 mm이고, 중심이 윗면 xy 상자 안이다.
- 위 물체 기울기 ≤ 10°, 아래 물체 이동 ≤ 2 cm(안 넘어뜨림).
- 그리퍼를 떼고 2 s 안정.
- 강체끼리는 접촉 센서도 보조로 쓴다. 다만 Objaverse 쪽은 힘이 0으로 나와 기하 판정이 우선이다.

**비용**: 0.5일(참값 거의 재사용) + 아래 물체 윗면 표(CPU) + 관문 약 1 프로세스-h.

## 3. 서랍·수납장 열기 (open_drawer / open_door)

지시 예: "Open the top drawer." / "Open the left cabinet door."

**자산: 관절 자산이 필요하다.**
- THOR 서랍장·수납장·협탁은 원래 관절(서랍 = 직선 관절, 문 = 회전 관절)을 갖는다. 지금은 `usd_import.make_static`이 관절을 끄고 정적 사본을 쓴다.
- **관절판 가져오기**를 새로 둔다: 뿌리 고정(fixed base), 관절 유지, 손잡이 링크 표시(`*_handle_*` 이름), 관절 한계·마찰·감쇠 설정.
- 문·서랍 링크의 질량이 1e-8로 들어 있으므로 실제 값(0.5–3 kg)으로 바꾼다.

**참값 모델 가능성: 서랍은 중간, 문은 낮음.**
- **서랍**
  - 손잡이가 앞면에 있어 **옆에서 잡는 자세**(그리퍼 축이 +x를 향함)가 필요하다. 지금 IK·실행기는 위에서 아래 자세만 쓰므로 자세 종류 `approach: "front"`를 더해야 한다.
  - 참값 단계: 손잡이 앞 8 cm → 손잡이로 전진 → close → 서랍 축을 따라 당김(개방량 목표 20–30 cm, 5 mm 걸음) → open → 후퇴.
  - 서랍 높이는 리프트로 맞춘다(서랍 윗단 0.4–0.9 m).
  - 위에서 잡을 수 있는 대안: 윗단 서랍의 앞판 윗 모서리를 위에서 집어 당긴다. 손잡이가 앞판 위쪽에 있고 윗판과 틈이 ≥ 3 cm일 때만 가능하고, 자산 표에서 거른다.
- **여닫이 문**
  - 손잡이가 호를 그리며 움직여 참값 궤적이 곡선이다.
  - 로봇 오른팔 하나로 60–90° 여는 동안 팔 도달·충돌이 잦을 것이다.
  - 1단계에서는 **뺀다**. 서랍의 첫 관문을 통과한 뒤 다시 본다.

**명령 어휘(추가)**
- `"approach": "top" | "front"`: 선택, 기본 top. front는 TCP z축이 +x를 향하는 고정 자세다.
- 당기기는 기존 eef 목표를 연속으로 주는 것으로 표현한다(새 모드 없이). 라벨 단계 `above_handle`(front에서는 `before_handle`) / `grip_handle` / `pull` / `release`를 더한다.

**성공 판정기**
- 서랍 관절 위치 ≥ 목표 개방량의 80 %(관절값 = 시뮬 참값).
- 서랍장 몸체 이동 ≤ 1 cm(고정 뿌리라 0이어야 함 — 검사용).
- 그리퍼가 손잡이를 놓았다.
- 실패 분해: 손잡이 못 잡음 / 당기다 놓침 / 관절 한계 충돌 / 도달.

**선행 구현**(승인 뒤):
1. 관절 자산 가져오기(관절 표·손잡이 자세 추출).
2. IK·실행기에 front 자세.
3. 관절값 읽기.
4. 참값 관문.

**비용**: 3–4일, 관문 약 2 프로세스-h.
**위험**: THOR 관절 설정(한계·구동)이 PhysX에서 그대로 동작하는지 먼저 확인해야 한다 → 관절 자산 5개로 스폰·수동 당김 시험부터 한다.

## 4. 넣고 닫기 (put_in_drawer_and_close)

지시 예: "Put the red cup in the open drawer and close it."

**참값 모델 가능성: 중간(3에 의존).** 여러 단계 과제다.
- 초기 상태는 **서랍을 연 채** 시작한다. 여는 부분을 빼 3의 실패와 섞이지 않게 한다.
- 단계:
  1. 물체를 집는다(기존).
  2. 서랍 안 바닥에 놓는다. 서랍 안 바닥은 열린 상태에서 받침면으로 뽑는다: 관절 자세를 적용한 뒤 `mesh_support_surfaces`를 쓰면 container=True, 윗판에 덮이지 않은 앞부분이다.
  3. 서랍을 민다. 1의 밀기 참값과 같은 모양이며, 서랍 앞판 중앙에 닫은 손가락을 대고 −x 방향으로 민다. 로봇 쪽으로 미는 게 아니라 로봇에서 멀어지는 방향이라 도달은 괜찮다.
- 위험:
  - 물체 높이 > 서랍 안 높이면 닫을 때 걸린다. 물체 높이 ≤ 서랍 안 높이 − 1 cm로 거른다.
  - 닫는 동안 물체가 앞으로 쏠린다(속도를 제한한다).

**명령 어휘**: 3의 추가분 + 1의 밀기 단계 이름. 새 모드는 없다.

**성공 판정기**
- 물체가 서랍 링크 안에 있다: 서랍 링크 좌표계에서 안쪽 상자 안, 밑면이 서랍 바닥 ± 1 cm.
- 서랍 관절 ≤ 개방량의 10 %(닫힘).
- 물체가 서랍 밖으로 튀지 않았다.
- 2 s 정지.

**비용**: 3 위에 1.5–2일.

## 5. 우선순위와 승인 요청

| 순서 | 과제 | 이유 | 선행 |
|---|---|---|---|
| 1 | 쌓기 | 참값·어휘 거의 재사용, 실물 물체(상자·책·접시)와 바로 결합 | 물체 윗면 표 |
| 2 | 밀기 | 새 어휘 없이 새 기술(비파지 조작) | 없음 |
| 3 | 서랍 열기 | 관절 자산 + front 자세가 필요한 큰 일 | 관절 가져오기, IK 자세 |
| 4 | 넣고 닫기 | 3과 1 위에 쌓임 | 3 |
| 보류 | 여닫이 문 | 곡선 궤적·한 팔 도달 | 3 통과 뒤 재검토 |

- **이름 검사(user-log 160 (2))는 모든 과제 판정 단계에 들어간다**: 지시문에 들어가는 물체 이름은 `objects_real.name_check`와 `task_name`(크기·색·명사)을 거친 이름만 쓴다.
- 지시문 표현은 과제마다 10–20가지로 하고, 일부는 OOD용으로 남긴다(다양화 계획 1절과 같은 규칙).
- **승인 요청**: 1·2는 바로 사전 등록 → 구현 → 참값 관문으로 가도 되는지, 3·4는 먼저 관절 자산 5개 스폰·당김 시험(설계 검증, 약 0.5일)부터 해도 되는지.
